# A3 frontend production-readiness checks

These tests import the production Vue components and Axios transport. The browser runner temporarily copies its entry point into ignored `web/node_modules/.a3-prod-readiness`; no test route or synthetic data enters the production bundle. It starts Vite and Playwright in the same process tree, then removes the temporary entry point and stops Vite.

## Run

```sh
pnpm --dir web install --offline --frozen-lockfile
pnpm --dir web typecheck
pnpm --dir web lint
pnpm --dir web test
pnpm --dir web build
node --test tests/prod-readiness/a3-browser/core.test.mjs
python3 tests/prod-readiness/a3-browser/run.py
```

`run.py` uses Playwright's installed Chromium by default. `SCM_UI_CHROMIUM=/absolute/path/to/chromium-headless-shell` selects an existing compatible executable without changing sandbox settings. Install Python Playwright and its browser in environments that do not already provide them.

Artifacts are written to ignored `target/test-artifacts/a3/`: JSON results, screenshots, and the local Vite log. They must not be committed. All request bodies and users in the runner are synthetic.

## Integration prerequisites

- A1's decimal-string ID responses, idempotent route list and `/api/stock-logs/seek` must be integrated with this frontend. The whitelist deliberately does not infer idempotency from the presence of a UUID header.
- Cookie refresh remains explicitly disabled in production until A2's agreed server session rotation is installed. Root owns enabling and validating that integration.
- Financial visibility, source projection company IDs and explicit draft company changes belong to the separate A2 integration change described below. The performance branch remains independently frozen.

## A2 frontend integration checks

`SecurityFixture.vue` mounts the existing order/purchase forms, production editor, supplier/material dialogs, price history, source inventory dialog and TechPackTab. `security_checks.py` supplies synthetic API responses with protected financial/contact fields physically absent. These tests check the actual rendered controls and the outgoing Axios bodies; they do not substitute for A2's server authorization and SQL tests.

- Sales prices use `order:price:query`, production/PROCESS archive prices use `production:price:query`, material/purchase/inventory/BOM cost fields use `techpack:cost:query`. Each grant is tested independently. Public tag price remains available as a sales input hint.
- The actual order-change editor hides fee notes and price controls without the order-price grant, and omits both `feeNote` and the entire `prices` array on a quantity-only resubmission. Global cost and production-price grants do not enable them. An authorized sale-price editor preserves both fields, and the ensuing submit uses the refreshed version and original company.
- Supplier contact/address and bank details use their separate existing/new permissions. Hidden write fields are omitted, including BOM price tax/freight metadata. Ordinary document tax terms and approval thresholds remain under their existing rules.
- Real order, purchase and production draft editors switch from company A to B. Each PUT keeps `expectedCompanyId=A` and `X-Company-Id=A`, while `body.companyId=B`. Missing/mismatched expectations and unrelated routes cannot use the exception. Existing purchase line IDs remain decimal strings.
- Source inventory dialogs and source APIs obtain `companyId` from the warehouse-authorized prefill endpoint. No ordinary purchase/production detail request is made. The API snapshots the write body before a missing-scope prefill lookup.
- Real TechPackTab receives duplicate material/part and process/category/name business keys, reorders both sets, adds a new process and saves. Original row IDs follow their rows, new rows omit IDs, and inaccessible prices/costs never become zero-valued writes.
- Purchase "save and submit" reloads saved detail before submitting because the server rebuilds line IDs. A deliberately rejected submit leaves the editor usable; a second save must send the refreshed line ID, version and saved company. A detail reload failure blocks stale-row saves and offers a visible reload action.

`ExportFixture.vue` mounts the actual stock page at its log view. `export_checks.py` verifies that exporting uses the last successful filter snapshot, queues one task on a double click and sends a UUID. It exercises polling, a processing cancellation that waits for worker acknowledgement, retry of failed/cancelled/expired jobs, server-supplied download filenames through the fixed authenticated same-origin file route, close-time read/download cancellation, original-key/body replay after an unknown create result, per-job history in two tabs, owner-scoped reload recovery, and manual lookup after optional history storage fails. An unresolved create keeps only whitelisted stock-log filters and the transport's actual selected UUID in the current tab's sessionStorage; it never contains price, file, contact, bank or credential data, and a definite result clears it. Reloading with different filters cannot issue a new action. Two tabs recover the same original key even after one has confirmed the result and cleared the shared write receipt. The file bytes are synthetic transport data; A2 owns validating the actual XLSX generator, queue worker, limits, ownership and current permissions against the server.

For a targeted integration run use `SCM_UI_SECURITY_ONLY=1` with the normal browser command; it runs permission and export workflows and writes `security-results.json`. `SCM_UI_EXPORT_ONLY=1` runs just the export workflow and writes `export-results.json`. The default command runs all suites and retains the complete console/page-error audit in `results.json`. All screenshots and request examples contain synthetic data only.

## Real backend session integration

`real-session.py` is a separate runner for A2's deployed cookie/session implementation. Start the real backend in the same process/network namespace, set `SCM_UI_API_BASE` to its explicit loopback origin and supply `SCM_UI_USERNAME` / `SCM_UI_PASSWORD` for the isolated regression account, then run:

```sh
python3 tests/prod-readiness/a3-browser/real-session.py
```

`SCM_UI_CHROMIUM` selects the existing Chromium executable, as above. The runner starts its own Vite proxy with `VITE_API_TARGET=SCM_UI_API_BASE`, copies its minimal entry into a unique ignored `web/node_modules` directory and removes it on exit. The shared Vite configuration preserves the browser's Host, including its port, so the server receives the original matching Host/Origin pair for its strict same-origin checks. It does not install any browser route handlers or mock any API. The entry imports the production `request.ts` cookie handler/single-flight logic, `token.ts` synchronization and the actual user-store login/logout actions. The test entry explicitly enables the same cookie handler used by production `main.ts`. It activates only when Web Locks are available; other browser origins use the access-only session contract described above.

The actual login must issue both HttpOnly, SameSite=Strict cookies at `/api/auth`, with a non-cacheable response. Two tabs then receive an invalid access token under their existing session epoch and each issue eight reads of the existing, authenticated `/api/companies/options` endpoint. A temporary hold of the production Web Lock lets all 16 real HTTP 401 responses arrive before release. Both page-local flights must be waiting; afterward exactly one real refresh must produce 16 successful replays, with no identity/epoch change. No network response is delayed or fabricated.

The runner checks that the refresh cookie actually changes, the browser binding remains stable and the fixed family deadline does not slide. One additional invalid-access read proves the successor cookie works for the next rotation; this separate check expects one additional refresh. Logout is then sent with invalid access and the real cookies. It must clear both cookies, invalidate the other tab and block its next production-transport read before network I/O. Direct negative checks also prove that the server rejects the previously valid access token and the server-issued cookie retained in a separate browser context after logout.

`target/test-artifacts/a3/real-session-results.json` contains only stages, controlled failure identifiers, booleans and counts. It includes the two-tab burst's refresh count separately from the successor/revocation checks. It never contains credentials, token/cookie values, response bodies, business records, browser storage, traces or screenshots. The deliberate real HTTP 401 console messages are counted as expected only for their exact probe resource and phase; any other console error, uncaught page error or browser request outside the local Vite origin fails the test. Failure is reported without raw Playwright call logs, which could otherwise expose credential arguments.
