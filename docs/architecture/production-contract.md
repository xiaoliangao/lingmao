## 2. HTTP 与身份

| 契约 | 冻结规则 |
|---|---|
| 返回体 | 保留 `R {code,msg,data}`。既有业务码 1000–1005 不重编号。安全异常不返回 SQL、栈或原始请求体。 |
| 追踪 | `X-Request-Id` 为规范名，保留 `X-Trace-Id` 兼容别名；响应、MDC、审计、异步事件共享同值。仅接纳有界安全字符的输入，非法值重新生成。 |
| 幂等 | JSON 核心建单/记数写操作使用 UUID `Idempotency-Key`。已有 `clientActionId` 保留，两者同传必须一致。唯一键限定到可信部署租户、用户、动作；主体和有效请求内容一并绑定摘要，修改主体头不得生成第二次动作。处理中 HTTP 409；成功原样重放；异体重用 1002。失败事务不得留下成功记录。 |
| 幂等重试 | 一次动作持有同一个键及请求体，结果未知时保持原键；完成或明确新动作才换键。写请求不作无条件自动重试。 |
| 主体上下文 | `X-Company-Id` 表示当前页面单据主体，不能在发送时从另一个标签的可变全局值替换。后端校验与请求单据一致；此头不是授权来源。 |
| 租户 | 现有数据库无 tenant_id，不宣称支持共享库多租户。可信部署租户作为命名空间，拒绝与部署不符的外来租户；跨公司授权如未全量接入须明确阻断该部署模式，不能仅靠传头宣称隔离。 |
| 登录刷新 | 现有登录为 JWT + 服务器会话。A2 若增加刷新，使用服务器可吊销的刷新凭据、HttpOnly Cookie、原子轮换及有效期；A3 只使用明确协商的接口，不能编造已有 refresh API。认证失败只允许一次刷新/重放，不自动重试无幂等键的写请求。 |
| 代理 | 客户端 IP / 协议仅从明确可信代理链读取；默认不信任转发头。 |
| 网关错误 | 409 / 413 / 429 / 503 返回有界 R 和追踪头；客户端同时支持既有业务码与 HTTP 状态。 |

草稿显式换主体的唯一例外：现有订单、采购单、生产单的草稿 `PUT` 可带 `expectedCompanyId`。它与 `X-Company-Id` 都必须等于数据库中当前主体；`companyId` 是用户明确选定的新主体。后端在锁定原单后校验当前版本、草稿状态、目标公司存在且启用，以及既有来源一致性约束。缺少 `expectedCompanyId` 时请求体与主体头仍必须一致；新建、批量动作和其他路由不接受这一例外。页面必须冻结原主体，不能把新选择或其他页签的主体当作原主体。

### 字段权限收紧（A2）

本次生产加固明确覆盖旧 PRD Q30 的默认开放规则。`supplier:supplier:contact` 控制供应商联系人、电话、微信和联系地址；预置仅给采购、财务、管理层及管理员。`supplier:supplier:bank` 控制银行、账号、收款户名，无权限时字段从 JSON 物理移除，不返回掩码或 null 占位。价格按业务域分权，避免查看销售报价或生产成交价时一并获得全部 BOM 成本；列表、详情、嵌套快照、系统生成摘要、价格档案、Excel 和 PDF 同口径。

|---|---|---|
| `techpack:cost:query` | 物料/SKU 参考价、MATERIAL 价格档案、款式/BOM/资料包成本、采购和物料库存的单价金额 | 开发主管、采购、财务、管理层；保留既有分配 |

### 登录刷新与日志导出接线（A2 → A3）

- 登录保持 `R<string>` access token。客户端通过 `X-Session-Mode: cookie|access-only` 明确会话模式；不支持 Web Locks 的浏览器使用 access-only，不创建刷新家族、不读写刷新 Cookie，access 到期后重新登录。非法模式在任何会话写入前拒绝。cookie 模式另设 `scm_refresh` 与浏览器绑定凭据 `scm_browser`，均为 HttpOnly / SameSite=Strict、路径 `/api/auth` 的 Cookie；HTTPS 或可信代理确认 HTTPS 时加 Secure，认证响应 `Cache-Control: no-store`。登录的 access 注册与刷新会话在同一数据库事务内提交。
- `POST /api/auth/refresh` 发送 `{}`、`X-Session-Mode: cookie` 和 `X-Requested-With: XMLHttpRequest`，使用 Cookie 原子轮换，返回 `R<string>`；跨站请求拒绝。浏览器使用同源固定 Web Lock `lingmao:auth-cookie`，串行覆盖登录、退出、刷新、改密的 HTTP 响应接收与本地 Token 发布；不得按不同 epoch 分锁而让旧 Set-Cookie 覆盖新账号。锁内重读共享 access token，同页请求用 SingleFlight 合并。仅对只读或后端明确支持幂等的原请求重放一次，保留原 body、主体和动作键；重放后的业务错误保持原码。等待期间切换账号，旧任务发出前拒绝；已发出的旧 `/auth/me` 或业务请求在响应副作用前检查身份，不得覆盖资料、清除新 Token 或丢弃原账号的未决写入收据。
- 服务端仅为同一 family、浏览器绑定、当前用户版本提供固定 3 秒、最多 2 次的上一凭据重放；返回同一个 successor，不再次轮换，不延长窗口。超过窗口/次数、绑定不符、账号停用或版本失效返回 401；过期旧凭据的拒绝不能删除已经有效的新 Cookie。刷新凭据只存摘要，successor 由用途隔离的 HMAC 与随机 nonce 重建，刷新会话总寿命 7 天。
- `POST /api/auth/logout` 同样发送 `{}` 和上述自定义头；access 已过期时仍允许受同站校验保护的 Cookie 登出，撤销该 family 并清 Cookie。改密、重置密码、停用、删除即时提升用户会话版本；已有 access/refresh 随即失效。旧 Redis access 注册没有用户版本，升级后统一要求重新登录，不接受无版本旧会话。
- `POST /api/export-jobs/stock-logs` 接收库存日志筛选 JSON，不接受 page/size/cursor，要求固定 `Idempotency-Key`，成功返回 HTTP 202 / `R<ExportJobView>`。`GET /api/export-jobs/{id}` 查状态，`GET /api/export-jobs/{id}/file` 下载；`POST /api/export-jobs/{id}/cancel`、`/retry` 取消或重推，均返回 `R<ExportJobView>`。
- `ExportJobView`：`id:string`、`kind:STOCK_LOGS`、`status:PENDING|PROCESSING|RETRY_WAIT|SUCCEEDED|DEAD_LETTER|CANCELLED|EXPIRED`、`rows:number`、`attempts:number`、`requestId:string`、`createdAt:ISO`、`expiresAt:ISO|null`、`errorCode:string|null`、`downloadUrl:string|null`。错误码不带原始异常或内部路径。
- 所有任务操作要求 `inventory:stock:export` 且仅本人。任务冻结列权限上限；下载、重推另查当前有效身份和权限。原文件包含后来撤销的财务字段时拒绝下载，要求重建。
- 同步日志导出最多 1 万行，在开始响应前用有界查询判断，超限受控提示改用任务；前端日志导出统一使用任务。异步上限 100 万行 / 250MB / 15 分钟，每用户最多 2 个未终结任务，文件 24 小时过期。按 500–1000 行 seek 取数，不做全表 COUNT；达到限额、取消、失败须清理半文件。
- 任务租约 60 秒、每 10 秒心跳，指数退避，最多 5 次执行失败后进入死信；事务内登记任务、事务外生成文件，完成后以租约持有者条件更新。当前没有第三方集成业务，不将此导出消费宣称为第三方回调治理。

### 旧业务 Excel 导出（P09 / P37）

- 物料、款式、供应商、订单、采购、生产、物料出入库/库存/汇总/盘点、成品单据/库存/按款/日志统一使用同步请求线程中的 `ExcelDownloads`。保留现有权限、标签 AND、审批/数据范围、主体、所选 ID 完整性、隐藏敏感列和业务排序；不切换异步线程丢失请求上下文。
- 同一只读 `REPEATABLE_READ` 事务中先预检、再写出，轻量父编号/主体最多 50001 条。为保留旧 Java UTF-16 SKU 顺序，物料另按 seek 分页收集最多 50000 条轻量 `(id,materialId,code)` 排序键，排序后只保留 ID；不累计 SKU 实体。关联预算使用 `COUNT FROM (SELECT 1 … LIMIT 剩余预算+1)`，不把完整子行加载到应用后才检查；实际业务数据、关联和补充信息每批最多 500 行。父/子预算全程累计，单工作表最多 50000 行，成品日志保持 10000 行，矩阵保持原有颜色/轴/列/总格数预算。
- 预检只遍历有界批次，校验每个实际输出单元格（含公式转义）≤32767 字符；检查未压缩 XML 的保守资源估计≤250MiB（基础 1MiB、每行 64 字节、每个非空值 128+8×UTF-16 长度）。这不是允许无限扩大的压缩文件上限。预期边界错误在响应头之前返回原 JSON 业务错误；不产生损坏的正常下载。
- 使用直接 ZIP/XML 多工作表写入，数字/日期/编码类型和公式防护保持。两遍使用同一列定义和已固定的小型字典映射；每次下一批查询前先清 MyBatis 一级缓存，再写合法 XML 空白并 `SYNC_FLUSH` 到连接。断连异常立即停止后续查询；不 finish 失败的 ZIP、不在 XLSX 后追加 JSON，不生成工作表临时文件。
- 写入器按工作表复用 8192 字符缓冲及 UTF-8 编码缓冲，列名只计算一次，避免逐单元格建立完整 XML 字符串和字节数组。物料 SKU 实体页使用一个 `bigint[]` 参数读取原来最多 500 个冻结 ID；仍按原 ID 列表恢复 Java UTF-16 顺序，不扩大筛选范围或返回规模。
- `HeavyIoFilter` 继续在解析/查询前限制每 JVM 2 个重型 I/O；公共下载器另有每 JVM 2 个无排队许可，所有成功/失败/断连路径释放。快照事务/查询有 120 秒预算，行/批检查同一 deadline；不承诺在 JDBC 或 socket 已阻塞时抢占它们。响应保留 UTF-8 中文 `filename*`、`Cache-Control: no-store`，并关闭代理响应缓冲。
- 盘点表在预检成功后、响应头提交前，用独立短写事务记录导出准备；审计写入失败仍返回 JSON，不能把错误追加到已提交的工作簿。日志沿用原发送前语义，不表示客户端已经接收全部字节。
- 兼容的内部 `export(...): byte[]` 仅供已有内部调用/测试；HTTP 业务导出调用 `exportPlan` 并直接写响应。导入模板仍可用小型 `byte[]`。库存流水已存在的 seek/异步任务和其 100 万行/250MB/15 分钟预算不变。
- 断连、每页实际返回行数、合法 5 万行完整性、单/双并发峰值、超额 429、并发改数时快照一致性分别记录真实 PG/HTTP 证据；方法级输出流故障测试只作为补充，不替代实际 TCP RST。预检阶段尚未发送响应，不能宣称此阶段可以即时感知客户端断连。
- 完整 CI 显式启用 `prod-readiness,ci-export-capacity`：通用 IT 与两个导出容量测试类全部执行，容量类各用独立 JVM，避免将不同测试应用的累计占用混入同一实例的测量。两个容量场景先完成固定一次 50000 行下载及完整性校验，再在同一应用内测量；保留 `Xmx1200m`、5ms 采样及整个 JVM 峰值严格小于 600MiB 的断言，包含 HTTP 客户端和探针，不扣除基线、不在测量窗口主动 GC、不按结果重试。该门禁只说明规定负载窗口，不保证任意运行历史下的瞬时堆占用；共享测试 JVM 的历史超限仍保留为失败记录。
- 完整 CI 命令不得传 `-Dit.test` 缩小全量验证范围，因为该参数覆盖 Failsafe 的类筛选。开发定向测试继续只使用 `-Pprod-readiness -Dit.test=...`；两个 CI 执行组分别保存 summary，测试 XML 保留在同一目录，核验时按实际测试身份检查完整、唯一及零跳过。

## 3. 数据与查询

- 数据库 BIGINT ID 的规范 JSON 表示为十进制字符串。前端不得用 Number / parseInt / 一元加号解析主键，版本、数量、页码保持数字。后端支持输入十进制字符串并校验范围；滚动升级须验证旧前端兼容性，否则明确安排同版本前后端切换，不能称零停机兼容。
- `version` / `planRevision` 维持当前数字契约；冲突保留本地内容，不偷偷换版本覆盖。
- 金额与数量后端用 BigDecimal / NUMERIC 重算；前端预览没有入账权威性。有效零值（例如允许的免费单价、盘点实盘 0）按领域语义处理，不能一刀切全部 >0。
- 库存多键按现有完整库存键统一排序，先来源累计，再库存，正反向相同顺序。不能把按 sku_id 排序单独替换成破坏既有来源锁序的实现。
- 一次最多查 100 个不同编码，完整输入最多 8192 字符，前后端同口径；有界文本、排序白名单、参数化 SQL。单个单号/编码和名称按字面包含匹配（编码列有 pg_trgm 索引），`%`、`_`、反斜杠不充当用户通配符；批量接口按完整编码精确匹配。采购历史订单/款号快照按存储值查询，不换成当前主档值。少于三个字符的包含查询用不上 trigram 索引，仍可能扫描，受语句超时与分页限制；不能将它列为“全范围禁左模糊已完成”。本轮 11-22 的 100 上限覆盖 11-18 的 200 决策，历史记录保留在 PRD 变更表。
- 纯日期为 YYYY-MM-DD，不转时区；事件时间以带偏移的 ISO-8601 输出。时间戳筛选用东八区业务日半开区间，DATE 列可用含首尾比较。
- 普通列表保留 `{list,total}`。高增长流水新增 seek 契约 `{list,nextCursor,hasMore}`，游标绑定排序、筛选与授权范围；统计单独查询，不让游标页隐含 COUNT。
- sys 表现有 PostgreSQL 存活行部分唯一索引可满足软删除重建，无须机械改成 deleted_token。业务主数据外键 RESTRICT + 停用保留。
- 已在 main 发布的 V1–V56 不改；当前 dev 工作树只含 V1–V36，不能据此推断 main 最高版本。新增版本须先核对 main 已占用编号及缺失低版本的整合风险；独立 repeatable 迁移须幂等。大表约束先在短事务中以 NOT VALID 安装并释放强锁，再验证；在线索引按 Flyway 非事务迁移处理，避免在业务锁上无限等待。

## 4. 物理写边界
