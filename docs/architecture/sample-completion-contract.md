# 样衣完整链补齐契约

主控冻结日期：2026-11-22。依据已定 `docs/rfc/007-研发打样.md` 全文、PRD §6.3、本轮用户要求及现有 style/techpack/biz 服务。本文是待实现契约，不是验收证明；实际销项写入 `full-audit-ledger.md`。

## 1. 范围与迁移

本增量必须交付完整链：样衣及首版→内外派单→节点→送样→改版评审→新版本通过→真实款式/SKU→研发资料包移交与生产V1草稿。不得仅建样衣CRUD。样衣导入、外部工厂登录、手机上报、打样费结算沿RFC007留到相应独立领域，界面不提供假按钮。

已再次读取远端 `main@c04e3b46`，版本迁移最高V56。V57成品、V58标签已分配，本增量使用 **V59__dev_sample.sql**；不改历史迁移，不默认开启outOfOrder。迁移先建父表及必要唯一键，再建子表/FK，再扩展资料包owner，最后字典、菜单与模板授权。新建表不在命名空间启动初始化之前插入业务种子。

## 2. 真实对象、数量与身份

样衣新增明确的主体 `company_id`，由用户当前选择传入、服务器校验；一旦派单或已有研发资料包，不可换主体。样衣下所有打样单、节点和评审继承实际主体，不能从请求头重写。此决定是本轮跨主体防串单要求的补充，不冒充旧RFC字段。

新业务表使用可信 `DeploymentNamespace.tenant()`，命名空间外键、父子复合FK与查询条件保持一致，不接收客户端tenant。当前仍是一个数据库一个可信部署命名空间；公司成员ACL和共享库多租户另见M01，不能据此销项。

在RFC列出的六张表外，使用 `dev_sample_order_color`、`dev_sample_order_size` 两个有序关联表保存所选颜色和尺码，避免逗号字符串被当关系；共八张表。颜色记录真实color_id，尺码保存受来源尺码组校验的size_code。父版本保存选择时的显示快照，已派单版本不因主档改色而变。

打样单 `qty` 为整版实际总件数，正整数，最大99999999；RFC没有规定各色码分配，不能把总数复制进每格。选择颜色/尺码只表示本版打样范围。转大货按样衣档案的完整颜色×尺码组生成唯一SKU，不把打样数量当生产订单量。颜色、尺码各最多100，组合最多10000；超限明确失败，不截断。普通首版默认第一颜色、基码、qty=1。

样衣和打样单各有整数 `version`；已存在的打样单动作请求带其 `version` 和 `sampleVersionLock`，主档动作带主档 `version`。节点计划、节点完成/撤回也使用打样单和主档版本，覆盖旧RFC“不带version”的做法。ID输出字符串，金额/价格新DTO使用十进制字符串，日期直接 `YYYY-MM-DD`。 `SampleOrder.sampleVersion` 始终表示业务版次；`sampleVersionLock` 专指父样衣乐观锁值，不能混用。

## 3. 状态与事务

状态、派单方可用规则、节点逆排、送样允许跳节点并给warning、评审及恢复流程全部沿RFC007 §3。两张状态机独立保存，但一个事务同时改变；始终保持“DEVELOPING iff 当前版处于WAIT_ASSIGN/MAKING/WAIT_REVIEW”。

节点稳定码固定为 `RECEIVE/PATTERN/CUT/SEW/SEND`，显示名依次接单/纸样/裁剪/车版/送样，默认天数1/2/1/3/1。每版保存节点码、名字和天数快照；送样语义只认 `SEND`，不比较可编辑显示名。派单时校验字典恰有一个启用的SEND且为最后节点，配置错误明确400；倒排扣减后一个节点的天数，沿RFC007计算。 本轮资源边界明确：启用节点最多100、评审人原始列表1–100且去重后至少1，均在入库前拒绝超限。

统一锁序：**样衣 → 当前打样单 → 节点按id升序 → 必要资料包按id升序**。每次取得真实父锁后重新核对公司、DataScope、状态与两个版本，再CAS。改版/恢复只在父锁内取下一版次，唯一(sample_id,sample_version)兜底；业务单号沿用原子SerialNoGenerator，禁止无锁MAX+1。当前版之外的旧版本只能读。

转大货沿RFC同一事务：锁样衣→复用style建款/取号/建色码和附件关联→techpack移交→样衣CONVERTED。不通过HTTP调用自己的Controller，不开REQUIRES_NEW。任何一步失败，样衣、款式、SKU、资料包和业务号全部回滚。预览只读、不取号。一样衣只可转一款。

改版评审REVISE意见最多500个UTF-16代码单元，原样复制进下一版reason；PASS/ELIMINATE最多1000，终止/恢复reason最多500。后端在取得业务锁和写入前独立检查，前端切换结果保留超限原文并提示，不截断。

允许换主体的初版草稿PUT，以query和X-Company-Id携带原主体、DTO携带新主体；通用幂等注解显式指定Controller原主体参数，完整DTO仍参与指纹。成功重放以当前对象重新授权，已失去SELF可见性返回404，不因旧请求主体获得旁路。

每个写入口接入当前HTTP幂等与重放授权；业务成功后再次重放仍先检查当前账号、主体、对象可见性与动作权限，不重新执行已成功动作。20同键请求只产生一张首版/下一版/款式。状态和服务端金额字段不进入可写DTO。

动作成功使用包含父子ID、两个CAS版本、业务版次、实际主体与状态的轻量收据，不在已提交后依赖重新查询详情来组装成功结果。前端随后的刷新如果因改派或改主体失去SELF可见性，应明确提示权限变化并返回列表，不把成功写入误报为失败或自动重发。

派单后主档删色不改旧版快照。REVISE/reopen创建新版本时，在同一父锁内取旧选色与当前主档颜色的交集；有移除时在动作warning中明确列出受影响颜色code/name，交集为空则选当前主档第一色并明确提示。未变化时完整复制，尺码沿不可更换的尺码组原样复制；不得在SQL层静默截断或改写历史选择。

初版待派单、没有资料包、没有实际节点/评审/其他下游时允许删除业务草稿；样衣使用deleted_token保留身份并支持编码唯一。所有字段审计和操作审计保留，不执行旧RFC“连操作记录一起删”。已评审记录只增不改，数据库拒UPDATE/DELETE/TRUNCATE；改版通过新版本、新评审表达。已引用主档禁物理删除。

## 4. 资料包owner与依赖

`tp_tech_pack.style_id` 放宽，增加真实sample_id FK；数据库保证未转款owner为“sample非空、style空、stage=DEV”，款式owner为style非空（允许保留sample来源）。两个owner都空非法；样衣研发版本/有效版本唯一。旧款式包保持原值，不批量伪造sample。

techpack定义 `SamplePackOwner`，dev单独实现，只依赖dev自己的DAO和下层基础服务，不注入TechPackService形成循环。样衣上所有资料包读取（包括已生效快照、核价、PDF、附件、日志、标签）**先验证真实样衣可见性**，再读取快照；冻结内容不构成权限旁路。写入还验证样衣未淘汰/未转大货。无provider不能默认放行。

所有仍挂样衣的资料包写入先读取owner身份，再取得样衣锁，最后锁资料包并重查owner/version。禁止“先锁资料包，再等样衣锁”与转款形成反向等待。如果等待期间已经移交，返回1002刷新，不反向取得另一owner锁。新版本、保存、生效、修订、删除、核价保存、图片替换都按此规则。PDF渲染、文件读取在短授权/数据快照读取之后、事务外完成。

涉及样衣或TECH_PACK的对象标签读取，在同一个有界REPEATABLE_READ快照内解析真实owner、授权和读取标签，并绕过对象标签缓存；标准标签选项与其他对象缓存仍保持原策略。资料包详情/核价/日志/PDF输入也需同一授权快照，PDF输出IO在事务外。现有7天签名文件URL不会随权限变更撤销；元数据授权测试不得据此声称已完成文件下载撤权，该缺口列P53单独修复。

移交由techpack自己的方法修改tp表，全部原研发版本保留内容并提高versionLock；有生效DEV时复用既有内容复制和生产价格重取生成PROD V1草稿。订单、MRP和生产仍只允许真实款式PROD资料包，样衣DEV不得绕过生产资料校验。既有“按款成本/款式草稿”列表明确只列款式owner，样衣资料包从样衣详情进入，不能用错误共享全表列表泄露SELF范围。

前端owner使用明确款式/样衣联合类型，保留既有styleId调用兼容并加sampleId分支；样衣资料包DocRef kind=SAMPLE，parentId=样衣id，带companyId。转款后按款式owner读取，不再受未转样衣状态阻断。

## 5. 权限、列表和可观测性

`dev:sample:*`沿RFC：dev/dev_lead全部，manager仅list/review，其他不自动授予。SELF可见范围为建档人、设计师或当前版版师；公司条件与之取交集。派单工厂用现有SAMPLE用途校验，启用内部版师，禁止任意ID穿透。

列表和counts分别查询，普通分页有界；关键字≤100批量编码精准查询，单词按既有索引规则；按实际显示状态、当前节点/延期筛选，在SQL中授权、排序后分页。当前版、节点和评审人批量预加载，不每行单查。 历史版本采用`sample_version DESC`、`beforeVersion`与`size≤100`游标分页，显式返回下一游标/hasMore，不静默截断。所有排序白名单、日期半开区间、真实执行计划继续满足生产契约。

保留原型列表/详情/四类弹窗视觉，补真实loading/空态/失败/重试；写入互斥、稳定幂等键、IME防误触、来源身份隔离的草稿恢复和迟到确认防护沿已修公共组件。接入真实Home样衣待审/延期、CommandPalette、DocRef、附件、ReferrerProvider、字段Diff和操作时间轴。样衣标签provider仅在真实样衣域存在后注册，沿真实编辑规则，不提前放空实现。

## 6. 最低验收与写边界

V58标签交付保持不变。V59追加 `SAMPLE` 到标签类型约束、父对象守卫、删除清理和审计根映射；Java枚举以单独增量交付。`TECH_PACK` 仅在style为空、sample非空时继承样衣主体；移交后有真实style即沿款式域，registry主体同步恢复为空，不因保留sample来源永久套用样衣权限。同步需遵守样衣→资料包→标签registry锁序，移交前后授权均有真实回归。

必须有真实PG/HTTP的首版持久化、内外派单、漏节点warning、改版自动下一版、两人评审/终止竞争、20同键只一次、过期版本拒绝、三色五码转款15SKU、V2研发→PROD V1及现价、注入转换故障全回滚、SELF/跨主体资料包/PDF/标签拒绝、历史审计不可变。真实生产Vue打开列表、详情、派单/节点/评审/转款弹窗与BOM浮窗，截图由主控亲自检查。
