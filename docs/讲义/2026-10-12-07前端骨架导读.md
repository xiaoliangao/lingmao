## 2. 一个请求的全过程

以"用户管理页面点查询"为例。打开任何一个页面，都按这条线去读。

```
点"查询"按钮
  → views/system/user/index.vue  的 search() → load()
  → api/system.ts                的 userApi.page({ page: 1, size: 20, ... })
  → utils/request.ts             的 http.get<PageResult<User>>('/api/users', params)
      请求拦截器：从 localStorage 取 token，加 Authorization: Bearer xxx
  → Vite 代理 → 8080 → JwtAuthFilter → UserController.page → Service → Mapper → PostgreSQL
  ← R { code: 0, msg: "ok", data: { list: [...], total: 3 } }
      响应拦截器：code 是 0 → 把 data 交出去；不是 0 → 弹出 msg，抛 ApiError
  ← load() 拿到 { list, total }，赋给 list.value 和 total.value
  ← 表格 <el-table :data="list"> 发现 list 变了，自动重新渲染
```

页面里的代码就是这样：

```ts
const query = reactive({ page: 1, size: 20, username: '', status: undefined as number | undefined })
const list = ref<User[]>([])
const total = ref(0)

async function load() {
  loading.value = true
  try {
    const result = await userApi.page({ ...query, username: query.username || undefined })
    list.value = result.list
    total.value = result.total
  } finally {
    loading.value = false
  }
}
```

- **`ref` / `reactive`**：响应式数据。它们的值一变，模板里用到它们的地方自动重新渲染。你不用像 jQuery 那样手动去改 DOM
- **`list.value = ...`**：`ref` 包了一层，在 `<script>` 里读写要加 `.value`；在模板里 Vue 自动解包，直接写 `list`
- **`username: query.username || undefined`**：输入框清空后是空字符串 `''`。传 `undefined` 时，axios 不会把这个参数拼到 URL 上，后端收到的是"没传"，不会按空字符串去模糊查
- **`try ... finally`**：请求失败也要把转圈关掉。失败的提示拦截器已经弹过了，这里不用管

**加一个字段要动哪三处**（比如用户加"邮箱"，后端已经加好）：

1. `types/system.ts` 的 `User` 接口加 `email: string | null`。这是"后端返回的 JSON 长什么样"的声明，写错了编译就报错
2. `api/system.ts` 的 `userApi.create` / `update` 参数加 `email`
3. 页面：表格加一列 `<el-table-column prop="email" label="邮箱" />`，弹窗表单加一个输入框，`form` 对象加 `email: ''`

## 3. 为什么这么设计

### 3.1 侧边栏和路由由后端决定

登录以后，前端调一次 `/api/auth/me`。下面是张三（只有"用户管理"和"新增"权限）调它的真实返回，删了几个不相关的字段：

```json
{
  "code": 0,
  "data": {
    "id": 3,
    "username": "zhangsan",
    "nickname": "张三",
    "roles": ["keeper"],
    "perms": ["system:user:add", "system:user:list"],
    "menus": [
      {
        "id": 1, "name": "系统管理", "type": 1, "path": "/system", "component": null, "icon": "Setting",
        "children": [
          { "id": 2, "name": "用户管理", "type": 2, "path": "user", "component": "system/user/index", "icon": "User", "children": [] }
        ]
      }
    ]
  },
  "msg": "ok"
}
```

`menus` 拿来做两件事：

- **侧边栏**：`layout/SideMenuItem.vue` 是一个递归组件。目录（type 1）渲染成可展开的子菜单，里面再渲染自己的 children；菜单（type 2）渲染成一项
- **路由**：`router/index.ts` 的 `addMenuRoutes` 把每个菜单变成一条路由。菜单表里的 `component` 字段（`system/user/index`）就是 `views/` 下面的文件路径（`views/system/user/index.vue`）

```ts
/** views 下所有页面，按文件路径索引 */
const pages = import.meta.glob('../views/**/index.vue')

function addMenuRoutes(menus: MenuNode[], parentPath = '') {
  for (const menu of menus) {
    const fullPath = joinPath(parentPath, menu.path ?? '')        // '/system' + 'user' → '/system/user'
    if (menu.type === 2 && menu.component) {
      const page = pages[`../views/${menu.component}.vue`]
      if (page) {
        router.addRoute('layout', { path: fullPath.slice(1), name: `menu-${menu.id}`, component: page, meta: { title: menu.name } })
      }
    }
    addMenuRoutes(menu.children, fullPath)
  }
}
```

- **`import.meta.glob`**：Vite 提供的。编译时把 `views/` 下所有 `index.vue` 找出来，变成 `{ '../views/system/user/index.vue': () => import(...) }` 这样一张表。值是函数，用到这个页面时才去下载它的代码（懒加载）
- **`router.addRoute('layout', ...)`**：把路由加到名字叫 `layout` 的路由下面，页面就显示在侧边栏右边的内容区里

**为什么不在前端写死路由表**：权限在后端的 `sys_role_menu` 里，前端再写一份就是两处真相，迟早对不上。现在加一个新页面只要两步：在菜单管理里加一行菜单，在 `views/` 下放对应的文件。角色勾不勾这个菜单，决定谁能看到它。

**张三直接在地址栏输入 `/system/role` 会怎样**：他的路由表里没有这条，落到兜底的 404 页面，"地址写错了，或者你没有这个页面的权限"。

### 3.2 按钮：`v-perm` 只管"看不看得见"

```html
<el-button v-perm="'system:user:add'" type="primary" icon="Plus" @click="openCreate">新增</el-button>
```

```ts
export const vPerm: Directive<HTMLElement, string | string[]> = {
  mounted(el, binding) {
    const store = useUserStore()
    const needed = Array.isArray(binding.value) ? binding.value : [binding.value]
    if (!needed.some((perm) => store.hasPerm(perm))) {
      el.parentNode?.removeChild(el)
    }
  },
}
```

自定义指令：元素挂到页面上（`mounted`）时检查一次，没有权限就把它从页面上拿掉。张三登录后，用户页面只有"查询"和"新增"两个按钮，操作列是空的。

**这只是体验，不是安全**。张三绕过页面，直接用 curl 调角色列表，挡住他的是后端的 `@PreAuthorize`，真实返回：

```json
{"code":403,"data":null,"msg":"没有权限"}
```

前端藏按钮，是为了不让人点了以后才被告知"没有权限"。

### 3.3 拦截器：后端的 R 在前端只处理一次

后端所有接口都返回 `R { code, msg, data }`，而且 HTTP 状态码都是 200（401、403 也是：401 由 `SecurityConfig.writeUnauthorized` 写出，403 由 `GlobalExceptionHandler` 写出）。所以前端要看的是 body 里的 `code`：

```ts
instance.interceptors.response.use(
  (response) => {
    const body = response.data as R<unknown>
    if (body.code === 0) {
      return response
    }
    if (body.code === 401) {
      clearToken()
      if (!location.pathname.startsWith('/login')) {
        location.href = `/login?redirect=${encodeURIComponent(location.pathname + location.search)}`
      }
    } else {
      ElMessage.error(body.msg || '请求失败')
    }
    return Promise.reject(new ApiError(body.code, body.msg))
  },
  ...
)

export const http = {
  get: <T>(url: string, params?: object) => request<T>({ url, method: 'get', params }),
  ...
}
```

- **code 0**：成功。`request<T>` 再剥一层，调用方直接拿到 `data`。所以页面里写的是 `const result = await userApi.page(...)`，`result` 就是 `{ list, total }`，不用每次写 `.data.data`
- **code 401**：token 过期或无效，清掉 token，带着当前地址跳登录页，登录成功再跳回来
- **其他**：弹出后端的 `msg`。"用户名已存在""不能删除超级管理员"这类提示，页面一行代码都不用写
- **最后都抛 `ApiError`**：让调用方后面的代码（`ElMessage.success('已保存')`、关弹窗）不再往下走

**抛出去以后谁接**：页面的函数一般不 catch（消息已经弹过了），错误一路冒到 Vue。`main.ts` 里装了一个全局的 `app.config.errorHandler`：`ApiError` 和"确认框点了取消"（Element Plus 抛出字符串 `'cancel'`）都是正常流程，不打印；其他的才 `console.error`。不装它的话，输错一次密码，控制台就出一条黄色警告：

```
[Vue warn]: Unhandled error during execution of component event handler
Error: 用户名或密码错误
```

真正的程序错误（比如读了 `undefined` 的属性）照样打印出来，不会被吞掉。

### 3.4 登录成功后整页刷新

```ts
await store.login(form.username, form.password)
location.href = (route.query.redirect as string | undefined) ?? '/'
```

用 `location.href`，不用 `router.push`。路由和侧边栏是按"当前这个人"的菜单生成的，换一个人登录，最简单可靠的做法是整页重新加载：内存里的路由、store 全部清空，按新的人重新生成。退出登录不用刷新，是因为接下来只能去登录页，登录成功又会刷新一次。

| 库 | 用的版本 | 没用的新大版本 |

| pinia | 3.0 | 4 |

新的大版本都是这几个月才发布的，Element Plus 等周边库、网上的资料和问答还跟不上。这个项目要的是两个月后稳定交付，不是尝鲜。`package.json` 里写死了精确版本，`pnpm-lock.yaml` 锁住了所有间接依赖，换台电脑装出来也一模一样。

## 5. 新方法（TS、Vue、库）

只列项目里用到的，已补进 `docs/方法速查.md` 第 6 节。右边一列是 Java 里大致对应的东西。

| 写法 | 干什么 | Java 里像什么 |
|---|---|---|
| `interface User { phone: string \| null }` | 声明一个对象长什么样。`\|` 是"或者"，这里是"字符串或者 null" | DTO 类，只有字段 |
| `type: 1 \| 2 \| 3` | 只能是这三个值之一 | 枚举 |
| `phone?: string` | 可以不传 | 字段允许为 null |
| `a ?? b` | a 是 null 或 undefined 就用 b | `Objects.requireNonNullElse(a, b)` |
| `a?.b` | a 是 null 就整体得 undefined，不报错 | `a == null ? null : a.b` |
| `x as User` | 告诉编译器"我知道它是 User"，不做任何转换 | 强制类型转换（但运行时不检查） |
| `http.get<PageResult<User>>(...)` | 泛型：声明返回的 data 是什么类型 | `List<User>` 的尖括号 |
| `async` / `await` | 等这个异步操作完成再往下走，写起来像同步代码 | 同步调用（Java 这边本来就是同步的） |
| `Promise.all([a(), b()])` | 两个请求同时发，都回来了再继续 | `CompletableFuture.allOf` |
| `{ ...query, username: 'x' }` | 复制 query 的所有字段，再覆盖 username | 拷贝构造再 set |
| `ref(0)` / `reactive({})` | 响应式数据，变了模板自动更新。`ref` 要 `.value` | 无 |
| `computed(() => ...)` | 由别的数据算出来的值，依赖变了自动重算 | 无 |
| `onMounted(load)` | 页面挂到浏览器上以后执行 load | 无 |
| `defineProps<{ menu: MenuNode }>()` | 组件接收的参数 | 构造方法参数 |
| `defineStore('user', () => {...})` | Pinia：全局共享的状态，任何页面 `useUserStore()` 拿到同一个 | 单例 Bean |
| `router.beforeEach(async (to) => ...)` | 每次跳转之前执行。返回 true 放行，返回一个地址就改跳过去，返回 false 取消 | Filter |
| `router.addRoute('layout', {...})` | 运行时加路由 | 无 |
| `import.meta.glob('../views/**/index.vue')` | Vite 编译时按通配符找文件，生成"路径 → 懒加载函数"的表 | 类路径扫描 |
| `app.directive('perm', vPerm)` | 注册自定义指令 `v-perm` | 自定义注解 + 处理器 |
| `axios.create()` + `interceptors.request/response.use` | 建一个 HTTP 客户端，装请求前、响应后的拦截器 | RestTemplate + Interceptor |
| `ElMessage.success/error('...')` | 页面顶部弹一条提示，几秒后消失 | 无 |
| `ElMessageBox.confirm(...)` | 确认框。点确定继续往下走，点取消抛出 `'cancel'` | 无 |
| `formRef.value?.validate()` | 按 rules 校验表单，不通过抛错，下面的代码不执行 | `@Valid` |

## 7. 已知问题

- **Element Plus 整包 1MB**（gzip 后 335KB）。内部管理系统、局域网用，第一次打开慢一点，之后浏览器缓存住。以后需要再改成按需引入

- **停用一个菜单，它下面的按钮权限还在**（04-05 导读里记过）
- **没有标签页、面包屑**：业务页面多了再加
- **token 过期时悄悄跳回登录页，没有任何提示**：见第 8 节练习

## 8. 练习：登录过期时提示一句（20 分钟）

**需求**：token 失效（过期，或者 Redis 里的会话没了）跳回登录页时，登录页弹出黄色提示"登录已过期，请重新登录"。自己点"退出登录"回到登录页时**不弹**。

**为什么**：token 两小时过期。现在用户正在填一张单子，点保存突然回到登录页，什么提示都没有，会以为系统出了 bug。

**提示**

- 跳登录页的地方在 `utils/request.ts` 的 401 分支
- 不能在跳转之前 `ElMessage.warning(...)`：`location.href` 是整页跳转，页面重新加载，刚弹的提示跟着没了。得把"是因为过期才来的"这个信息带到登录页去，想想 URL 上已经带了什么
- 登录页怎么读 URL 上的参数，`views/login/index.vue` 里已经有现成的写法
- `ElMessage` 要从 `element-plus` 里 import

**怎么造一个失效的 token**：登录后，浏览器按 F12 → Application → Local Storage → `http://localhost:5173`，把 `lingmao-token` 的值改成 `abc`，然后刷新页面，或者点一下"查询"。

**完成标准**

- 刷新页面、点按钮两种情况，都跳到登录页并弹出提示；重新登录后回到原来那一页
- 点"退出登录"回到登录页，不弹
- `pnpm build` 通过
- 提交，说"前端练习好了"

## 9. 🎤 今天的面试题

**问：前端已经把没权限的按钮藏起来了，后端还要校验吗？**

**答**：必须校验，前端的权限控制只是体验。我们项目前端用 `v-perm` 指令按权限标识删掉按钮，用动态路由让没权限的页面打不开，但浏览器里的代码和数据都在用户手里，他可以改 JS，也可以不用浏览器，直接用 curl 或 Postman 调接口。真正的门是后端：每个管理接口贴了 `@PreAuthorize("hasAuthority('system:user:add')")`，权限是 JWT 过滤器每次请求从数据库查出来的。我验证过，只有"新增用户"权限的账号直接调角色列表接口，返回 `{"code":403,"msg":"没有权限"}`。

**问：token 存在 localStorage 还是 Cookie？**

**答**：我们存 localStorage，请求时由 axios 拦截器放进 `Authorization: Bearer` 请求头。好处是不会被浏览器自动带上，天然不受 CSRF（跨站请求伪造）影响，前后端分开部署也方便。坏处是页面上的任何 JS 都能读到它，一旦有 XSS（页面被注入脚本），token 会被偷走。Cookie 加 `HttpOnly` 能防 JS 读取，但浏览器会自动带上，要另外防 CSRF。我们的应对：Vue 模板默认会转义用户输入，降低 XSS 风险；token 两小时就过期（`lingmao.jwt.ttl: 2h`），而且会话在 Redis 里，退出、停用账号能立刻让它失效（停用是每次请求查库判断的）。
