# 讲解 P1 · 单表 CRUD（字典类型样板）

> 代码在 `~/yyy/repo/projects/SCM`（GitHub：xiaoliangao/lingmao）。本文回答三个问题：每个包是干什么的、为什么这么分、新增一个模块的固定套路是什么。这是唯一的完整样板，之后的模式讲解都照这个格式。

## 1. 一个请求是怎么走的

```
浏览器 / Swagger / 前端
   │  GET /api/dict-types?page=1&size=10&name=季
   ▼
DictTypeController          收参数 → @Valid 校验 → 调 Service → 包成 R 返回       （HTTP 适配层，三行一个方法）
   ▼
DictTypeService (接口)       这个模块对外的"能力清单"
DictTypeServiceImpl         业务规则：编码唯一、不存在就 404、@Transactional        （业务层，规则只写在这里）
   ▼
DictTypeMapper              继承 BaseMapper，单表 CRUD 不写 SQL                     （数据访问层，只跟表打交道）
   ▼
MyBatis-Plus 拦截器          分页插件拼 LIMIT；逻辑删除自动加 deleted = false；审计字段自动填时间
   ▼
HikariCP 连接池 → PostgreSQL（服务器上的 lingmao 库）
```

出错时反着走：Service 抛 BizException → 一路抛到 GlobalExceptionHandler → 变成 `{code: 1000, msg: "编码已存在"}`。Controller 里永远没有 try/catch。

## 2. 包结构和每个包的理由

```
com.lingmao.scm
├── common/        所有模块共用的东西，不含任何业务
│   ├── result/R                统一返回体 {code, msg, data}
│   ├── exception/BizException  业务异常
│   ├── exception/GlobalExceptionHandler  统一把异常变成 R
│   ├── page/PageQuery, PageResult        分页入参、分页出参
│   └── entity/BaseEntity       6 个公共字段：id、createBy/Time、updateBy/Time、deleted
├── config/        框架级配置：MyBatis-Plus 分页插件、审计字段自动填充；以后加 Security、Redis、Swagger 信息
└── module/
    └── system/    一个业务域一个包；域内按层分
        ├── controller/
        ├── service/ + service/impl/
        ├── mapper/
        ├── entity/
        └── dto/
```

**为什么按"域"再按"层"分。** 系统管理、基础数据、采购、库存是四个业务域，各自演进、各自有人负责。域内按层分是因为每层职责不同、依赖方向固定：controller 依赖 service，service 依赖 mapper，反过来绝不允许。改表只动 entity 和 mapper；改接口形状只动 dto 和 controller；改规则只动 service。

**为什么 DTO 和实体分开。** 实体是表的镜像，有 id、createTime、deleted 这些前端不该传的字段；DTO 是接口的形状，带校验规则。两者分开后，表加一列不会把接口撑大，接口加一个入参也不用动表。

**为什么 Service 要有接口。** Controller 只依赖接口。以后给 Service 加缓存、换实现、写测试替身都不用动 Controller。这是依赖倒置，也是 Spring 能做 AOP 代理（事务、权限）的基础。

**为什么事务标在 Service 上。** 一个业务动作可能写多张表（入库单审核：写入库单、改库存、写库存日志、回写采购单）。事务边界必须包住整个动作，而这个动作只有 Service 知道全貌。Controller 太靠外，Mapper 太靠内。

**为什么有 BaseEntity 和自动填充。** 审计字段每张表都要，手写 setCreateTime 总有人忘。MetaObjectHandler 在每次 insert/update 前回调一次，填一处管全部。

**为什么逻辑删除。** 业务数据删了要能追溯，单据之间互相引用，物理删除会留下悬空引用。MyBatis-Plus 接管后，代码里照样调 deleteById，它改成 UPDATE；所有查询自动带 deleted = false，你感觉不到它的存在，这就是框架该干的事。

## 3. 两条今天真实踩到的坑

1. **MyBatis-Plus 3.5.9 起分页插件拆到了 `mybatis-plus-jsqlparser`**，只引 starter 找不到 PaginationInnerInterceptor。教训：第三方库大版本升级，先看它的安装文档，别凭记忆。
2. **TIMESTAMPTZ 只能映射成 OffsetDateTime。** 实体用 LocalDateTime，查询直接报 "Cannot convert the column of type TIMESTAMPTZ"。PostgreSQL 有带时区和不带时区两种时间列，驱动对应两种 Java 类型，项目里必须统一一种。我们约定：列一律 TIMESTAMPTZ，Java 一律 OffsetDateTime。

## 4. 新增一个模块的固定套路（照这个写字典数据）

| 步 | 做什么 | 放哪 | 样板 |
|---|---|---|---|
| 1 | 建表脚本（已有） | `db/migration/V1__init.sql` 里的 `sys_dict_data` | — |
| 2 | 实体：字段对应列，继承 BaseEntity，`@TableName` | `entity/DictData` | `DictType` |
| 3 | Mapper：`@Mapper` 接口继承 BaseMapper | `mapper/DictDataMapper` | `DictTypeMapper` |
| 4 | DTO：查询条件继承 PageQuery；保存入参带校验注解 | `dto/DictDataQuery`、`DictDataSaveReq` | 同名两个 |
| 5 | Service 接口 + 实现：分页、详情、新增、修改、删除，业务规则写在实现里 | `service/`、`service/impl/` | `DictTypeService(Impl)` |
| 6 | Controller：五个方法，路径 `/api/dict-data` | `controller/DictDataController` | `DictTypeController` |
| 7 | 启动，Swagger 里把五个接口各点一遍 | `/swagger-ui.html` | — |

字典数据和字典类型的差别，也就是你要自己想的部分：
- 查询条件是 `typeCode`，按 `sort` 升序而不是按 id 倒序。
- 新增时要检查 `typeCode` 对应的字典类型存在，不存在抛 BizException。这需要在 DictDataServiceImpl 里注入 DictTypeMapper，这是第一次出现"一个 Service 用另一个模块的 Mapper"。
- 同一个 typeCode 下 value 不能重复。
- 多一个接口：`GET /api/dict-data/by-type/{typeCode}`，不分页，给前端下拉框用。

## 5. 约定速查

- 路径：资源用复数名词；GET 查、POST 增、PUT 改、DELETE 删；动作类才用 `POST /{id}/audit` 这种。
- 返回：永远是 R；分页 data 是 `{list, total}`；成功 code 0。
- 错误码：400 参数、401 未登录、403 无权限、404 不存在、500 程序错误、1xxx 业务错误。
- 命名：表 `sys_` / `biz_` / `pur_` / `inv_` 前缀按域；类名 `XxxController / XxxService / XxxServiceImpl / XxxMapper / Xxx(实体) / XxxQuery / XxxSaveReq`。
- 时间：列 TIMESTAMPTZ，Java OffsetDateTime，JSON `yyyy-MM-dd HH:mm:ss` 东八区。

## 6. 🎤 这个模式的八股（面试怎么问，用刚写的代码怎么答）

- **为什么要分 Controller / Service / Mapper 三层？** 三层各自只因一个理由变：接口形态、业务规则、存储方式。举例：分页从别的插件换成 MyBatis-Plus 分页只动了 Service 和 Mapper，Controller 一行没改。
- **Service 为什么要接口加实现？** 为了测试里能 mock 和 AOP 能代理。举例：`DictTypeController` 的接口测试用 `@MockitoBean DictTypeService` 替掉实现，不连数据库。
- **@Transactional 什么时候失效？** 同类内部自调用、方法不是 public、异常被 catch 吞掉、受检异常默认不回滚。举例：`create()` 里调私有的 `ensureCodeUnique()` 没事务没关系，因为事务在外层 `create()` 上。
- **MyBatis 的 #{} 和 ${} 有什么区别？** #{} 是预编译参数，防注入；${} 是字符串拼接，只能用于列名排序这类不可参数化的地方。举例：LambdaQueryWrapper 生成的全是 #{}。
- **逻辑删除和物理删除怎么选？** 逻辑删保留审计和被引用的数据，代价是唯一约束要考虑已删除行。想一想：`uk_sys_dict_type_code` 现在删掉一个 code 后能不能再建同名的？PG 的部分索引怎么解。
- **分页 limit offset 翻到后面很慢怎么办？** offset 大时数据库要扫完再丢弃，改成游标分页（where id > 上一页最后的 id）。字典表小无所谓，库存日志表要注意。
