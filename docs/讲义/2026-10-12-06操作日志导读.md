## 2. 为什么这么设计

### 2.1 用切面（AOP），不在每个方法里写日志代码

要记日志的方法有 20 个（用户、角色、菜单、字典的增删改，加上登录、退出）。在每个方法里写"记开始时间、try、catch、拼参数、插库"，就是 20 份几乎一样的代码。

切面的做法：在方法上贴一张标签，

```java
@OperLog(module = "用户管理", action = "新增")
public R<Long> create(@Valid @RequestBody UserCreateReq req) {
```

`OperLogAspect` 统一负责"所有贴了这张标签的方法，执行前后都记一条"：

```java
@Around("@annotation(operLog)")
public Object around(ProceedingJoinPoint joinPoint, OperLog operLog) throws Throwable {
    long start = System.currentTimeMillis();
    Throwable error = null;
    try {
        return joinPoint.proceed();          // 执行真正的 Controller 方法
    } catch (Throwable t) {
        error = t;
        throw t;                             // 记下异常，照样抛出去，全局异常处理器照常工作
    } finally {
        save(joinPoint, operLog, error, System.currentTimeMillis() - start);
    }
}
```

- **`@Around("@annotation(operLog)")`**：环绕所有贴了 `@OperLog` 的方法。`operLog` 参数就是那张标签，从它读出 module 和 action
- **`joinPoint.proceed()`**：执行被包住的那个方法，拿到它的返回值
- **`finally`**：成功、失败都会走到这里，所以失败的操作（比如"用户名已存在"）也有记录
- **原理**：和 04-05 讲的 `@PreAuthorize` 一样，Spring 给 Controller 套了一层代理，外面的调用先到代理，代理里执行这段 around

**新依赖**：pom 里加了 `spring-boot-starter-aspectj`。Spring Boot 4 把以前的 `spring-boot-starter-aop` 改成了这个名字。

### 2.2 写日志失败，不能连累业务

`save` 里整个包在 `try { ... } catch (Exception e) { log.warn(...) }` 里。日志表满了、库连不上，业务照样成功，只在应用日志里留一条 warn。测试 `logInsertFails_businessResultStillReturned` 钉住了这一点。

反过来，日志写在 Controller 这一层、Service 的事务**之外**：业务回滚了，"失败"这条日志不会跟着被回滚掉。

### 2.3 密码打码

参数是"参数名 → 参数值"转成的 JSON。转之前，`maskPasswords` 递归地找名字叫 `password` 的字段，把值换成 `******`。登录、新增用户、重置密码的参数里都有密码，日志表的读权限比用户表宽，明文绝不能进来。测试 `success_savesLogWithMaskedPassword` 断言参数里**没有** `123456`。

请求对象、响应对象、上传的文件、当前用户（`LoginUser` 里有 jti）这几种参数不记。

### 2.4 操作日志表为什么不继承 BaseEntity

日志**只追加、不修改、不删除**，没有 update_by、update_time、deleted。`create_time` 不在代码里赋值，插入时用表的默认值 `now()`。INSERT 语句里确实没有这一列：

```
INSERT INTO sys_oper_log ( module, action, method, request_method, request_uri, params, success, cost_ms, ip ) VALUES ( ?, ?, ?, ?, ?, ?, ?, ?, ? )
==> Parameters: 认证(String), 登录(String), AuthController.login(String), POST(String), /api/auth/login(String), {"req":{"password":"******","username":"admin"}}(String), true(Boolean), 781(Integer), 0:0:0:0:0:0:0:1(String)
```

（IP `0:0:0:0:0:0:0:1` 是 IPv6 的本机地址。上线以后，前面有 Nginx 转发，IP 从 `X-Forwarded-For` 请求头里取。）

username 冗余存一份：用户被删了，日志里照样看得出是谁。

### 2.5 两个现象

- **没权限被拒绝的请求不记**：权限检查（`@PreAuthorize`）的代理在日志切面**外面**，没权限的请求在外层就被挡回去了，到不了日志切面。张三新增用户被 403 那一次，日志里没有
- **登录日志的操作人是空的**：登录的时候还没认出人。见第 6 节练习

## 7. 🎤 今天的面试题

**问：AOP 是什么？你们项目里哪里用了？**

**答**：AOP 是面向切面编程，把"很多方法都要做、但和业务无关的事"从业务代码里抽出来，集中写在一个切面里。Spring 的做法是给目标对象生成一个代理，调用先进代理，代理里执行切面逻辑，再调真正的方法。我们项目里有三处：一是操作日志，我们自己写了 `@OperLog` 注解和 `@Around` 切面，记录操作人、模块、参数（密码打码）、成败和耗时，20 个接口不用各写一遍；二是 `@PreAuthorize` 权限检查；三是 `@Transactional` 事务。后两个是 Spring 自带的切面，原理一样。代理有两种：目标类实现了接口可以用 JDK 动态代理，否则用 CGLIB 生成子类，Spring Boot 默认用 CGLIB。

**问：为什么操作日志不放进业务的事务里？**

**答**：两个原因。一是业务失败回滚时，"失败"这条日志也会被回滚掉，可失败恰恰是最需要留痕的。二是日志写失败不该让业务失败。所以我们的切面在 Controller 层、事务之外执行，写日志的代码整体 try-catch，出错只打 warn。
