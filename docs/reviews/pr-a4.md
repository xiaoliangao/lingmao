## 为什么需要

原有追踪、字段改价审计及后台线程退出证据不完整；应用日志脱敏也覆盖不到 PostgreSQL 原始错误和 Nginx 签名 URL。滚动停止若只发送线程中断就关闭数据库池，会在后台事务仍执行时销毁资源。

## 本次改变

统一请求、慢 SQL、审计与 Outbox 的 request ID；应用和部署日志分别限制载荷及敏感值。28 张实际业务表在同事务记录字段 old/new，并保留草稿删除历史；BOM/采购删除重建按原行身份生成关联 diff，读取按独立价格、联系人和银行权限投影，敏感读取失败关闭。

大 BOM 审计增加四个部分索引，避免每个 SKU 反复扫描整版事务历史；500/1000 SKU 的真实触发器计划和逐行 diff 回归检查访问量与身份准确性，首尺寸查询明确限制到对应旧父行的候选。新增索引的写入成本和极大单父矩阵边界已写入 RFC。

生产启动拒绝弱密钥和不安全配置；live 与实际数据库 readiness 分离，探针额度跟随真正的 JDBC 执行结束。SIGTERM 先摘流、停止领取，再等待真实 HTTP/导出/worker/心跳/清理 SQL，确认线程退出后关池；超时保留持久租约供重启接管。Spring 的 pause/restart 与永久停机分开。

所有阶段门禁只接入已有 `.github/workflows/ci.yml`，保留备份只读、恢复演练、原型与业务浏览器检查。测试产物上传前脱敏，失败时禁止上传；原始 PG 日志和线程转储不作为 Artifact。

## 迁移与运行取舍

V37 为扩展式审计迁移，短锁/语句预算；旧版删除草稿仍保留历史。应用回滚不删除已提交审计或业务数据，生产管理员仍能更改触发器，append-only 不是对 DB owner 的密码学防篡改。

PostgreSQL 常规原始错误日志和 Nginx 含原请求的错误流关闭，详细诊断改用应用错误类型、语句指纹、安全访问日志和探针；完整原始诊断应在隔离数据环境复现。Compose 预留 90 秒退出预算。

仓库没有完整收付款/财务月结、共享库租户 ACL、全部原系统页面和私有字段清单，本 PR 不补造这些模块或验收结论。所有实际代码维持现有单体及 PostgreSQL/Redis 部署，无新增重型外部集群。`main` 不作为本次写入或合并目标。
