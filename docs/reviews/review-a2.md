## 结论与阶段依赖

A2 采用现有 PostgreSQL、Redis 和单体进程，不引入新的外部集群。共享状态以部署命名空间绑定；业务公司头用于校验页面目标，角色数据范围负责授权，两者不能混称租户 ACL。生产 Cookie 刷新已在真实后端联调通过后启用。

后端专项与最终运行复核通过：58 项浏览器检查、20 项真实业务 UI、7 项真实会话检查及生产双 JVM 门禁全部通过。Outbox 的 SIGTERM 排空、审计和统一 CI 属于 A4。

## 主控实际复验

- 限内存完整回归：478 项单元测试通过；225 项 IT 中 211 项通过，剩余 14 项集中在两组 A1 旧夹具缺少新增主体或成本权限。没有把该次结果标成全量通过。
- 夹具改为真实角色授权、明确主体上下文和 HTTP 头；保留原有 20/50 并发、版本竞争、回放和落库次数断言。严格 DTO 拒绝客户端 amount 后，增加零写验证，再以合法输入验证服务端金额重算。
- 主控复验发现 V31/V33/V36 的 `RESET lock_timeout` 污染池内连接，导致锁等待退回无限。三份尚未发布的新迁移改为 `SET LOCAL`，测试同时借出所有池连接核对 statement、lock、idle transaction 超时。
- 最终该增量的 6 项架构单测与 32 项 IT 全部通过：A1 并发/数据库 15、创建与回放 HTTP 6、导出 HTTP 11。该运行使用实际 PostgreSQL 16.11、Redis 8.0.2，JVM 限制 768 MB、4 个处理器。
- 先前独立验证包括真实 Excel/PDF、17 项上传单测 + 14 项上传/Schema IT，以及恶意内容和符号链接回归。最终完整回归覆盖了 A2 的缓存、会话、业务权限、导入、BOM、导出选择范围、上传、任务和存储 IT。
- PDF 1 色/50 色均为 33 条 SELECT；相同首色成本 8.10，不随颜色数增长。库存导出与 seek 使用同一索引化候选范围，5 份实际 EXPLAIN 通过。
- 两个独立生产 JVM 的门禁由 A2 先执行通过：100 个任务同时就绪、PG 实际回源 1 次，固定期限和次数上限的轮换重放、改密吊销、过期 access 下 Cookie 登出均通过。主控随后也在独立全新数据库、SCRAM 密码认证和带密码 Redis 上执行同一门禁通过。
