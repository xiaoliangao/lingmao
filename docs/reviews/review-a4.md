## 亲自核对的关键证据

- 采购真实 API 的 `REPLACE`：旧行 ID 和新行 ID 均为字符串，单价 `10 → 12`、数量 `10 → 12`、金额 `100 → 144`，同一根采购单、actor、IP、request ID 和事务 ID 完整。
- BOM 相同物料/部位和重复工序名调序后，按旧 ID 分别追踪 `20 → 22`、`10 → 12`，SKU 覆盖价 `200 → 202`、`100 → 102`；同事务有 6 条 REPLACE、6 条 DELETE、6 条 INSERT，未靠重复自然键猜配。
- 大表单专项使用 10 个真实 BOM 父行、500/1000 个 SKU；每档的 DELETE、INSERT、REPLACE 分别各为 510/1010 条，逐行核对旧新身份、根单据、事务、价格 `10 → 12` 和父行用量 `20 → 22`。主控从真实 JDBC NOTICE 读取四条触发器内部 generic SPI 计划；最后一行采样分别访问 1/1/0/1 行，首尺寸额外 EXPLAIN 分别检查同一旧父行的 50/100 个候选。未关闭外键、审计或任何 planner 方法，也没有用绝对毫秒门槛掩盖访问量。
- 无权限查询物理剥离受控字段；ORDER、PRODUCTION、COST 独立授权。银行历史读取必须先成功记录 actor、查询目标和 trace，日志失败时不释放全号。
- 实际 PostgreSQL 16.11 日志门禁触发唯一约束错误、非法类型主错误及超过一秒的含字面量 SQL；确认客户端错误确含合成哨兵，关闭数据库并等待正常退出后再读完整日志，服务端日志无该值。
- 原生 Nginx 1.26.3：9 项网关检查和 8 项部署日志检查通过；签名下载/不存在/无效签名/符号链接、TLS、跳转和上游断连均覆盖。安全访问记录保留状态/路径/耗时/追踪码，不保留参数或凭据。

## 打回与修复记录

主控拒绝过：价格域被通用 COST 投影二次误删、银行历史读取无留痕、删除重建明细历史失联、数字追踪码被错误遮罩、带转义引号的秘密值漏尾、循环空栈 cause 无界、任意子 logger DEBUG 绕过、心跳未计入排空、取消 Future 过早释放探针额度、仅发中断就宣称线程已退出，以及 PG/Nginx 绕过应用日志脱敏。

全量执行另发现 Spring 7 的上下文 pause/restart 与一次性停机控制器不兼容，复用上下文返回 503；已按框架生命周期修复，并由两轮实际 pause/restart 与最终关闭回归验证通过，没有停用测试生命周期或放宽 503 断言。两处旧测试仍期待删草稿时清除业务历史，已按 append-only 契约改为历史保留和 DELETE 字段审计，保留原业务删除及外键回滚断言。

CI 审查还要求：100 个 HTTP 请求完成后写入实际 PG 日志屏障，再统计回源次数；会话测试失败断言不携带 Cookie/JWT 原值；临时认证值在 Artifact 中二次脱敏；双 JVM 门禁超时时清理整个进程组。

补充规模审查抓到审计关联只使用根单据/事务索引时反复回扫历史：在实际 V1–V37 和外键全部启用的独立 PostgreSQL 中，500/1000 SKU 重建样本约为 0.813/3.022 秒。三索引候选仍有父行查找或旧 diff 回扫，未被接受；最终四个部分索引覆盖四类定位，并由上述真实 SPI 计划和逐行审计断言复验。普通物理 INSERT/UPDATE 不增加这四个索引的条目，DELETE 和 REPLACE 有明确写放大；同一旧父行下的色码候选仍需筛选，不承诺任意大小矩阵固定耗时。

另将大数据夹具改为每张十万行表装载后立即 ANALYZE，再加载依赖表。定向 PostgreSQL 复现确认：先在小表上缓存的 FK 查询可能在扩至十万行后继续顺扫；更新统计后恢复主键访问。没有减少夹具行数、关闭约束、修改 planner 或放宽查询断言。夹具清理仍保留全部 append-only 审计。
