# RFC 005 款式

状态：**已定**（2026-11-15 用户审过；"等用户定的问题"一节标了结论）。

对应：PRD §5.2、§6.2、§6.9.2、§10、Q28、Q43；架构 §3.1、§3.2、§4.5、§14.4；数据库设计 §3.3、§8.1–§8.3。第 2 批共用的规则见 RFC 003 §2。

## 1. 解决什么

款式档案、颜色、一键生成 SKU、款号自动编号和设计师编号、花名、图片和设计附件、Excel 导入导出，以及第 3 批需求订单、资料包要调的方法。

不做（第 3 批随资料包、需求订单做）：

- 详情的"资料包""订单"页签；"新颜色未配料"提示（PRD §6.2 规则 4）。款式不能查资料包（架构 §3.2），到时由前端调资料包的接口拿。
- `tech_pack_status` 这一批一直是"无"，由资料包生效、作废时回写。
- "价格"页签里资料包定的价和实际成交价的对比（11-18 起没有研发 BOM，不比研发估）；这一批只有加工价的现价和历史（RFC 006 §9）。

## 2. 表结构

照数据库设计 §8.1–§8.3，不另加列。

- `sty_style` 的 `code`、`status`、`tech_pack_status` 标 `NEVER`：款号只在插入时写；状态走动作。
- `uk_sty_style_code` 是普通唯一索引。
- 图片、设计附件挂 `biz_attachment`（`STYLE`），`category` 分 `IMAGE`、`DESIGN`。
- 迁移一个文件，排在 RFC 003 §11 的第 5 个：`sty_style` → `sty_style_color` → `sty_style_sku`。`sty_style` 指向 `bas_category`、`bas_size_group`、`bas_material`、`bas_customer`、`sup_supplier`、`sys_user`，所以排在 basic 两个文件和 supplier 之后。

## 3. 款号和设计师编号

### 3.1 自动编号

规则照架构 §4.5：大类 + yyMMdd + 设计师编号 + 2 位流水，如 `FS2611080701`。

- 点"自动编号"调 `GET /api/styles/code-preview?styleClass=FS&designerId=`，**只看不取**：`SerialNoGenerator.peek(key)` 读当前流水 + 1，再跳过已经被手填占了的号。页面上显示这个号，款号框变成"保存时生成"。
- 保存时才在建款的事务里真取：`next("FS26110807", 2)`，取到的号已有款式用了就再取下一个；超过 99 → 1000"今天的流水用完了，请手填款号"。保存成功返回实际的款号；和预览不一样（同一时间别人也建了）时，前端提示一句"款号是 FS2611080703"。
- 设计师没有编号 → 1000"设计师某某还没有设计师编号，请超级管理员在 管理后台 › 用户 里填；也可以手填款号"（PRD §6.2 规则 5）。
- 日期取注入的 `Clock`，东八区。
- 以后换设计师，款号不变：款号建好不改（RFC 003 §2）。

### 3.2 手填

- 新建时手填：转大写，`^[A-Z0-9-]{3,20}$`（原型的规则）；重复 → 1000"款号重复"，唯一索引兜底。
- 导入时照用老款号，只要求不含空格、不超过 32 位：老款号印在吊牌和对方的账上，格式不一定合我们的规则（数据库设计附录 C.1 第 18 条）。
- 手填的号不推流水。以后自动编号撞上它，跳过就是。

### 3.3 设计师编号

`sys_user.designer_no` 在管理后台的用户页填（RFC 003 §3.2）：

- 两位数字 `01`–`99`；全表唯一，重复 → 1000"编号 07 已经给了某某"。
- 第一次用它自动编号时，style 在同一个事务里调 system 的 `UserService.lockDesignerNo(userId, designerNo)`：`UPDATE sys_user SET designer_no_locked = true WHERE id = ? AND designer_no = ?`。0 行说明编号刚被改了 → 1002"设计师编号刚被改过，请重新编号"，整个建款回滚。比较的是编号本身，不是只看 id：不然管理员刚把 07 改成 08，款号用的是 07，锁住的却是 08。
- 用户页改编号：条件带 `designer_no_locked = false`，0 行 → 1000"编号已经用来编过款号，不能改"。锁了以后也不能清空。
- 导入的款式不锁编号：导入的是老款号，没用设计师编号。

## 5. 颜色、尺码组和 SKU

- **颜色**只追加。生成过 SKU 的颜色只能停用，没生成过的可以去掉（Service 查同域的 `sty_style_sku`，因为 SKU 的外键指向 `bas_color`，不指向 `sty_style_color`）。顺序能拖。停用颜色不连带停用它的 SKU，`checkOrderable` 两边都看：重新启用颜色时不用逐个启用 SKU。
- **尺码组**新建时选；已经有 SKU 的不能换（1000"已生成 SKU，不能换尺码组"）。PRD 说的是"有订单以后不能换"，款式查不到订单，就提早到"有 SKU 以后"；没下过订单的，删掉 SKU 就能换。
- **一键生成** `POST /api/styles/{id}/skus/generate`：启用的颜色 × 尺码组里全部尺码，按颜色顺序、尺码顺序插入，已有的跳过（`ON CONFLICT (style_id, color_id, size_code) DO NOTHING`），返回新建了几个。调几次结果都一样；加了颜色、尺码组追加了尺码，再点一次只补新的（PRD §6.2 规则 1、验收 6）。
- SKU 码 = 款号-颜色码-尺码（`FS2611080701-KQ-M`），生成时拼好，不能改。
- SKU 能改条码（有值时全表唯一）、吊牌价（空 = 用款式的），能启用、停用；删除由外键管（PRD 验收 5 的"已有订单使用，只能停用"就是 1005）。
- 前端"颜色尺码"页签：上面选颜色（`ColorSelect` 多选）、显示尺码组，下面实时出颜色 × 尺码的表格，已有的 SKU 和要新建的分开标。

## 6. 字段校验

- 品类必须是启用的叶子：调 basic 的 `CategoryService.checkLeaf(id)`。
- 尺码组、颜色、主力面料新选的必须启用；默认加工厂、主力面料只是默认值（架构 A23），存的时候不查供应商状态。
- 字典列（大类、品牌、季节、波段、风格、系列、性别、来源、执行标准、安全类别）：新选的值必须是启用的字典项；保存时没变的旧值，即使字典项已经停用也照收。
- **TRADE 关时**（RFC 003 §3.3）：来源是 `CUSTOMER_SAMPLE` → 400；`customer_id`、`customer_style_no` 必须为空 → 400。
- 年份 2000–2099；吊牌价、参考成本价 ≥ 0。
- 花名选填，不查重（Q43 的默认做法：俗称，可能几款叫一样的）；列表关键字能搜它。
- 参考成本价手填，资料包算出来的不写回（PRD §6.2）。

## 10. 关键流程和并发

| 场景 | 怎么保证 |
|---|---|
| 同一设计师同一天两人同时建款 | `sys_serial` 这一行的锁排队，号不重复 |
| 自动编号撞上手填的号 | 取号后查一次，已有就再取；唯一索引兜底 |
| 管理员改设计师编号时正好有人用它建款 | `lockDesignerNo` 比较编号（§3.3），用户页改编号带 `locked = false`，两边谁后到谁失败 |
| 同时点两次"生成" | `ON CONFLICT DO NOTHING`，只建一份 |
| 同时给一款加同一个颜色 | `uk_sty_style_color` → 1000"已经有这个颜色了" |
| 删一个被资料包引用的款式 | 外键 → 1005，SKU、图片都还在 |

## 11. 取舍

- **款号预览不占号**：点"自动编号"就取号的话，取了不保存会留空号，而且同一个人多点几次就跳号。代价是预览的号偶尔和最后的不一样，保存后告诉用户。
- **生成 SKU 只补缺、不删**：颜色、尺码只追加，所以"该有的 SKU"只会多不会少；只补缺天然幂等，不用对比删除。
- **"有 SKU 以后不能换尺码组"代替"有订单以后不能换"**：款式查不到订单（架构 §3.2）；没下过单的删掉 SKU 就能换，代价是多一步。
- **停用颜色不连带停用 SKU**：重新启用时不用逐个找回；下单检查两边都看。
- **导入先用自己的模板**：没有领猫样例，猜它的列名不如等样例。

## 13. 等用户定的问题

1. 设计师编号照 Q28 的默认做法：开发主管定、超级管理员在管理后台 › 用户里填，从 01 起，离职不回收；大类先只有 FS、XZ。
2. ✅ 导入的款式默认"启用"（11-15 用户定）：搬过来的老款大多在用。导入模板有"状态"列，个别要草稿的逐行填；导完要改的，列表勾选后批量启用、停用（§9）。
3. 款式导入先用自己的模板。甲方能不能从领猫导出一份款式表给我们？有了就照它改。
4. 花名不查重（Q43）。
5. 手填款号的规则 `^[A-Z0-9-]{3,20}$`（原型）；导入的老款号不受它限制。
