状态：**已定**（11-21 用户说"先完成不需要确认的模块"）。设计取舍由 Claude 定，理由写在各节；要甲方答的二期问题另见 `docs/二期确认问题.md`。

对应：PRD §6.5.7（06.05、06.07）、§2.2 的 01.08 和 02.05、§6.6 的二期（07.07 进销存汇总表）；架构 §14.2；数据库设计 §10.1、§3（`biz_doc_log`）、§13.4。

做的顺序：订单进度总览 → 翻单补单 → 改动记录 → 进销存汇总，做完一块提交一块。迁移：V50 进度总览的菜单，V51 翻单加一列，V52 改动记录加一列。

## 1. 订单进度总览（06.07）

### 1.1 解决什么

需求订单列表能看排产、回货、齐料各一个数，生产看板能看每张生产单的节点。但要回答"这张订单的每个款到哪一步了"，得先打开订单，再一张张点生产单。总览把这件事放进一屏：一行是一张订单里的一个款，后面列出这个款的各张生产单现在在哪个节点。

### 1.2 页面

菜单：订单 › 进度总览，`/order-progress`，权限 `order:progress:list`（V50）。凡是有 `order:order:list` 的角色模板都给（包括生产经理、业务主管）。

照列表页：`PageHeader` → `FilterBar` → 表。

- `#left` 分段：全部、未排完、临期、已逾期、生产有风险，每段带数。
  - 临期：还剩 ≤ 7 天。
  - 生产有风险：这个款的生产单里有逾期、临期、节点延期或没关闭的异常。
- 筛选：品牌、订单类型、业务员、跟单、交期；关键词搜订单号、款号；"我的 / 全部"。
- 只看在手的订单：已审核、生产中。
- 列：
  - 订单号（固定左）、款式（缩略图 + 款号，款名小字）、品牌 / 类型、数量。
  - 交期：承诺交期，没有就用要求交期；行交期更早的用行交期。下面小字"还剩 n 天"或"逾期 n 天"。
  - 排产：进度条，已排 / 数量。
  - 齐料：订单的齐料状态（03 的 `kitting`）。
  - 生产：每张生产单一个小块，写"工厂 · 当前节点"，颜色按它的风险。鼠标移上去看单号、节点点阵、回货数；点了去生产单详情。没排的写"没排单"。
  - 回货：进度条，已回 / 数量。
  - 跟单。
  - 风险：标签，固定在右边。
- 排序照生产看板的打分（docs/api/05 §2.3）：逾期 8、生产有节点延期 4、有异常 2、临期 1，相加从高到低，同分按交期从早到晚。
- 点订单号去订单详情。

### 1.3 接口

后端放在 production 域：排产、生产单、节点、异常都在这里，订单表只读 JOIN（`ProductionOrderMapper` 已经这么做，架构 §3.2 规则 4）；齐料调 purchase 的 `MrpService.kitting`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/order-progress` | `PageParams & OrderProgressQuery`，返回 `PageResult<OrderProgressRow>` |
| GET | `/api/order-progress/counts` | 同样的条件，返回各分段的数 `OrderProgressCounts` |

`OrderProgressRow`：`orderId`、`orderNo`、`orderType`、`brand`、`status`、`styleId`、`styleCode`、`styleName`、`image`、`qty`、`scheduledQty`、`returnedQty`、`dueDate`、`daysLeft`、`kitting`、`merchId`、`merchName`、`risk`（`overdue`、`nearDue`、`nodeDelayed`、`openIssue`、`unscheduled`），以及 `productions: ProductionBrief[]`。`ProductionBrief` 是 `ProductionRow` 的一部分：id、单号、种类、工厂简称、状态、件数、已回、当前节点、节点点阵、风险。

数据范围照需求订单（本人 = 制单、业务员、跟单是自己）和品类线。生产单的小块跟着订单显示，不再按生产单的数据范围筛。只出进度，不出价格。

### 1.4 取舍

- **一行一个款，不是一行一张订单**：一张订单常有几个款，各款排给不同工厂、进度差很远，合成一行看不出卡在哪个款。
- **不做顶上的数字卡**：分段带数已经是同一回事，列表页都这样。
- **不按生产单的数据范围筛小块**：能看到订单的人本来就能在订单详情的"下游单据"里看到这些生产单。

## 2. 翻单、补单（06.05）

### 2.1 解决什么

卖得好的款再下一次（翻单），或者上一单少了要补一些（补单）。现在要重新新建、再一个个款、一格格填。

### 2.2 怎么做

- 订单详情页头的"更多"里加"翻单""补单"。除了草稿，什么状态都能点，作废的也能。
- 点了打开新建页 `/orders/new?from=<id>&type=REPEAT|REPLENISH`，照原单填好：
  - 单头：类型（翻单 / 补单）、主体、品牌、业务员、跟单、币种、备注。
  - 不带：合同号、要求交期、承诺交期、附件。
  - 明细：同样的款、同样的颜色尺码和件数，单价带原单的。没有看销售价权限的人看到的单价是空的，就带空。
- 页面顶上一行"从 DD… 翻单，改好数量和交期再保存"。款式停用了、SKU 停用了的，照新建时的规则拦，提示是哪个款。
- 资料包不复制：新单审核时锁当时已生效的生产 BOM，和普通新建一样。页面上写一句"按现在生效的资料包"。原单锁的版本可能已经作废了，照旧版本做反而不对。
- 存的时候带 `sourceOrderId`：新单 `source = 'REPEAT'`，`source_order_id` = 原单。后端查原单存在、调用人看得到（看不到 404）。
- 新单详情的属性里显示"翻单自 DD…"或"补单自 DD…"，点了去原单。原单不反过来列新单。

### 2.3 表（V51）

```sql
ALTER TABLE ord_order ADD COLUMN source_order_id BIGINT REFERENCES ord_order (id);
CREATE INDEX idx_ord_order_source ON ord_order (source_order_id);
ALTER TABLE ord_order ADD CONSTRAINT ck_ord_order_source
    CHECK ((source = 'REPEAT') = (source_order_id IS NOT NULL));
```

原单被引用了就删不掉；原单只有草稿能删，草稿又不能翻单，所以碰不到。

### 2.4 取舍

- **补单不按"没回齐的数"带件数**：补单不一定是补短装，也可能是加一点货；件数照原单带，用户改。少一条规则，少一个要解释的地方。
- **复制在前端做，后端只记来源**：新建页本来就要能改，前端拿原单详情填表最直接；后端不用多一个"复制"接口。

## 3. 基础资料、款式的改动记录（01.08、02.05）

### 3.1 解决什么

物料、款式、供应商的"操作记录"现在只写"谁、什么时候、修改"，看不出改了什么。

### 3.2 怎么做

- `biz_doc_log` 加一列 `diff JSONB`（架构 §14.2 预留的），存 `[{ field, label, before, after }]`。`before`、`after` 存显示用的文字：字典存中文，人存花名，金额按格式。字典以后改名，历史还是当时的叫法。
- 写的地方：物料、款式的"修改"，供应商的直接修改和改动审批通过时。只记单头字段。SKU、颜色尺码、资质这些子表，记成一条概括，比如"SKU：加 2 个（…）、停用 1 个（…）"。
- 一个 `FieldDiff` 工具：给每种档案列一张字段表（字段名、中文名、怎么转成文字），比较改前改后，只出变了的。没变就不写 diff。保存了但什么都没改，也照旧记一条"修改"。
- 价格类字段（物料参考单价）照看成本的权限遮：没有权限的人看到"参考单价：已修改"，看不到数。
- 前端 `DocLogList` 在每条下面列出"字段：改前 → 改后"，超过 5 条折叠。

### 3.3 表（V52）

```sql
ALTER TABLE biz_doc_log ADD COLUMN diff JSONB;
```

### 3.4 取舍

- **存文字，不存原始值再现翻译**：字典、人名、单位都会改，现翻会把历史变成现在的叫法；操作记录要的是当时看到的样子。
- **不做通用的"所有表自动记"**（触发器、拦截器）：自动记会把版本号、更新时间这些没意义的列也记进去，中文名和格式还得另配；只有三种档案有"操作记录"页签，一种配一张字段表就够了。

## 4. 进销存汇总表（07.07）

### 4.1 怎么做

库存页的视图分段（明细 / 按物料 / 日志）加一个"进销存"。

- 条件：期间（默认本月，`DateRange`）、仓库类型页签、仓库、关键词。
- 一个物料 SKU 一行：物料编码、名称、颜色、规格、单位、期初、入库、出库、期末。
  - 入库、出库可以拆开看。"显示列"里能勾出这几列，默认藏着：采购入库、退料入库、其他入库、调入、盘盈、期初录入；领料出库、采购退货、其他出库、调出、盘亏、耗料核销（RFC 015 做了以后才有）。
- 只列期初、入、出、期末不全是 0 的行。能导出。

### 4.2 口径

从库存日志现算（数据库设计 §1 说过不建表）：

- 期初 = 业务日期早于期间开始的变动数之和。
- 入库、出库 = 期间里的变动数，按类型和方向分到各列。反审核写的反向日志算进原来那一列（采购入库反审核是"采购入库"那列减，不算出库）：方向 = 变动数的正负 ×（反向日志取反）。
- 期末 = 期初 + 入库 − 出库。
- 选了几个仓库（比如"物料仓"页签下全部），它们之间的调拨会同时出现在调入、调出里，合计不变。
- 按业务日期算期间：反审核的反向日志用原单的业务日期（`StockLedger.Posting.reversed`），所以反审核会改动过去期间的数，和单据对得上。

### 4.3 接口

`GET /api/stocks/movement`（`inventory:stock:list`），参数 `bizDateFrom`、`bizDateTo`（必填，最多一年）、`warehouseType`、`warehouseId`、`keyword`、分页，返回 `PageResult<StockMovementRow>`。`GET /api/stocks/movement/export`（`inventory:stock:export`）。

不出金额：库存日志里有很多没价格的（期初、盘点记成 UNKNOWN，RFC 010），金额加起来会误导人。等成本模块定了计价方法再加。

## 5. 测试点

- 进度总览：
  - IT：一张订单两个款，一个款排给两家工厂。检查行数、排产、生产小块、风险打分的顺序、分段条数。
  - 数据范围：本人只看自己的订单。品类线：鞋类的人看不到服装的订单。
- 翻单：
  - 单测：带 `sourceOrderId` 存成 `REPEAT`，看不到原单时 404。
  - IT：V51 的约束，`source` 和 `source_order_id` 要一起有。
  - 页面：从一张已完成的订单翻单，数量、款都带过来，交期是空的。
- 改动记录：
  - `FieldDiff` 单测：只出变了的、字典转中文、空值。
  - 物料、款式、供应商各改一次，操作记录里有对的 diff；没看成本权限时单价被遮。
- 进销存：
  - IT：期初入库、本月采购入库、领料、调拨、盘亏，再反审核一张。期初、各列、期末和库存表对得上。
