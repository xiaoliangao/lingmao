# RFC

一个模块或一个机制写一份，写在代码之前，用户审过再动手。PRD 管做什么，`架构设计.md` 管全局怎么做，RFC 管这一块具体怎么做。

按发版滚动写：每次发版前写好那一批要用的。

## 状态

- **草案**：写好了，等用户审
- **已定**：用户审过，可以写代码
- **已实现**：代码进了 main。之后接口以 Swagger（`openapi.json`）为准，RFC 不再逐条跟着改；设计上有变化，在 RFC 末尾加一行说明

## 每份写什么

1. 解决什么：对应 PRD、架构的哪几节；不做什么
2. 表结构：DDL 草稿，迁移文件以实现为准
3. 接口：路径、参数、返回、错误码
4. 关键流程和并发
5. 取舍：考虑过的其他做法，为什么没选
6. 测试点：对应 PRD 的验收
7. 等用户定的问题（有就写）

不相关的节可以省掉。
