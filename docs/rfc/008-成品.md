# RFC 008 成品

状态：**已定**（11-17：第 6–9 条按推荐，Q44 按默认，成品上线前要甲方答）。

对应：PRD §6.12、§2.5 的 M10、§4.2、§5.1–§5.4、§6.7.5、Q01、Q09、Q44；架构 §3、§4.2、§4.4、§4.10、§5.1–§5.3、§8、§14.1–§14.3；数据库设计 §18、§13（照它）、§14.6–§14.7。原型 `docs/原型/src/6-pages-later.js` 的"成品（二期）"一段（`fgReceive`、`fgShip`、`fgOtherOut`、`fgPage`）。

PRD §6.12 原来说"二期第一周开工前把这一节补全"：补全稿在本文附录，11-17 已贴进 PRD。

## 1. 解决什么

成品入库单（回货的良品入成品仓、其他入库）、成品出库单（按需求订单发货、其他出库）、成品库存和库存日志。规则照物料：审核即过账，库存只能由单据改，不能为负。

不做：

- 推聚水潭（Q01、Q44 没答）。要推时走发件箱（架构 §14.3），推送状态那时在 `fg_doc` 上加列。
- 入库前验货（M09 待定）：原型里"没验货、不合格的不能入"先不做，以后质检模块实现一个检查接口接上（§6.1）。
- 成品盘点（10.07）、调拨和退换货（10.04）、条码装箱（10.02）：待定。退回的货先走"其他入库"。
- 次品入库：次品不进成品仓；以后有"不良品仓"再说（架构 §14.2）。

## 2. 表结构

迁移一个文件 `V?__fg.sql`：四张表、两个字典（`fg_in_reason` 期初 / 返修合格 / 退回 / 其他，`fg_out_reason` 样品 / 报废 / 其他）、`sys_config` 的 `fg.receipt_from`（§3.3）、菜单和授权。

```sql
CREATE TABLE fg_doc (                            -- 公共列：单头（no = CR / CC，按 kind 取）
    kind              VARCHAR(8)   NOT NULL,     -- IN 成品入库单 / OUT 成品出库单，建单时定
    doc_type          VARCHAR(16)  NOT NULL,     -- IN：RECEIPT_IN / OTHER_IN；OUT：SHIP_OUT / OTHER_OUT
    from_warehouse_id BIGINT REFERENCES bas_warehouse (id),   -- 出库单用
    to_warehouse_id   BIGINT REFERENCES bas_warehouse (id),   -- 入库单用
    prd_receipt_id    BIGINT REFERENCES prd_receipt (id),     -- 回货入库
    order_id          BIGINT REFERENCES ord_order (id),       -- 发货出库
    doc_date          DATE         NOT NULL,     -- 实际日期，默认今天，不能晚于今天
    reason            VARCHAR(64),               -- 其他入库、其他出库必填：字典 fg_in_reason / fg_out_reason
    ship_to           VARCHAR(255),              -- 发货出库：发到哪，默认订单的送货要求
    logistics_no      VARCHAR(64)
);
CREATE UNIQUE INDEX uk_fg_doc_no      ON fg_doc (no);
CREATE UNIQUE INDEX uk_fg_doc_receipt ON fg_doc (prd_receipt_id)
    WHERE prd_receipt_id IS NOT NULL AND status <> 'VOIDED';  -- 一张回货单入一次，作废的不算
CREATE INDEX idx_fg_doc_kind ON fg_doc (kind, status);
-- 外键列各一个索引：from、to、order_id、company_id

CREATE TABLE fg_doc_item (                       -- 公共列：明细（doc_id、seq）
    style_sku_id        BIGINT NOT NULL REFERENCES sty_style_sku (id),
    qty                 INT    NOT NULL,         -- > 0
    prd_receipt_item_id BIGINT REFERENCES prd_receipt_item (id),  -- 回货入库：对应的回货明细
    order_item_id       BIGINT REFERENCES ord_order_item (id),    -- 发货出库：对应的订单行
    price               NUMERIC(14,4),           -- 发货出库：订单行单价；别的为空
    amount              NUMERIC(14,2),
    remark              VARCHAR(255)
);
CREATE UNIQUE INDEX uk_fg_doc_item_sku ON fg_doc_item (doc_id, style_sku_id);  -- 一张单一个 SKU 一行
-- idx (doc_id, seq)；style_sku_id、prd_receipt_item_id、order_item_id 各一个索引

CREATE TABLE fg_stock (
    id           BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    warehouse_id BIGINT NOT NULL REFERENCES bas_warehouse (id),
    style_sku_id BIGINT NOT NULL REFERENCES sty_style_sku (id),
    location_id  BIGINT NOT NULL DEFAULT 0,      -- 货位，0 = 不分；二期货位用
    qty          INT    NOT NULL DEFAULT 0,      -- 不能为负（条件更新保证）
    update_time  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_fg_stock ON fg_stock (warehouse_id, style_sku_id, location_id);
CREATE INDEX idx_fg_stock_sku ON fg_stock (style_sku_id);

CREATE TABLE fg_stock_log (                      -- 公共列：只插（create_by = 操作人）
    fg_doc_id    BIGINT      NOT NULL REFERENCES fg_doc (id),
    change_type  VARCHAR(16) NOT NULL,           -- 单据的 doc_type
    doc_no       VARCHAR(32) NOT NULL,
    biz_date     DATE        NOT NULL,
    warehouse_id BIGINT      NOT NULL REFERENCES bas_warehouse (id),
    style_sku_id BIGINT      NOT NULL REFERENCES sty_style_sku (id),
    location_id  BIGINT      NOT NULL DEFAULT 0,
    change_qty   INT         NOT NULL,           -- 入正出负
    balance_qty  INT         NOT NULL            -- 变动后结存（RETURNING 拿到的）
);
-- idx (warehouse_id, style_sku_id, id)；idx (fg_doc_id)；idx (biz_date)
```

`BizType` 加 `FG_DOC("成品出入库单", …)`，前缀和中文名按 `kind` 取：CR 成品入库单、CC 成品出库单（架构 §4.4、§4.10）。附件挂 `biz_attachment`（`FG_DOC`）。

和数据库设计 §18 草案的出入：

| 出入 | 理由 |
|---|---|
| 去掉 `customer_id` | 发货挂需求订单，客户在订单上（TRADE 开时也一样），不存两份 |
| 去掉 `jst_status`、`jst_push_time` | 推不推聚水潭还没定（Q01、Q44）；要推时走发件箱，到时加列（架构 §14.1 第 4 条） |
| 加 `reason`、`ship_to` | 其他入库、其他出库要原因（原型 `FG_OUT_REASONS`）；发货要写发到哪 |
| 明细加 `prd_receipt_item_id`、`order_item_id` | 回货入库按回货明细限数，发货按订单行限数、算已发，都要对上行 |
| `fg_stock` 加 `location_id` 进唯一键；不加物权 | 理由同 `inv_stock`（架构 §5.1）：以后再加就要改唯一键和过账的排序键。物权是客供料的事，成品没有 |
| `fg_stock_log` 不指向明细 | 一张单一个 SKU 一行，单据 + SKU 就能对上明细；不指向明细，反审核回草稿以后删行、改行（整单覆盖若实现成删了重插）才不会被外键拦住 |
| 状态加 `VOIDED` 已作废 | 过过账又反审核回来的单不能删、只能作废（用户 11-17 定，§3.2） |

## 3. 规则

### 3.1 类型

前端的 `FG_DOC_TYPE` 照 `INV_DOC_TYPE` 的写法，表单出哪几格都从它取：

| 类型 | 单据 | 仓 | 挂什么 | 原因 | 手工新建 |
|---|---|---|---|---|---|
| `RECEIPT_IN` 回货入库 | 成品入库单 | 入仓 | 回货单（必填） | — | 不能，从"待入库"生成 |
| `OTHER_IN` 其他入库 | 成品入库单 | 入仓 | — | `fg_in_reason` 必填 | 能 |
| `SHIP_OUT` 发货出库 | 成品出库单 | 出仓 | 需求订单（必填） | — | 能 |
| `OTHER_OUT` 其他出库 | 成品出库单 | 出仓 | — | `fg_out_reason` 必填 | 能 |

仓库只能选启用的成品仓（`bas_warehouse.type = 'PRODUCT'`），调 basic 的 `WarehouseService.getById` 查。

### 3.2 状态

照物料入库单（`docs/api/04` §2.1）：草稿 `off` → 已审核 `active`，审核即过账，反审核回草稿。没有待审核、没有多级审批。

用户 11-17 定（物料入库单、出库单一样）：**过过账的单不能删，只能作废**。没过过账的草稿（库存日志里没有这张单）直接删；过过账又反审核回来的草稿删 → 1000"这张单过过账，只能作废"，`actions` 里给 `void` 不给 `remove`。作废 = 草稿 → 已作废 `void`，原因必填，只读；作废的单不算"已入库"，回货单能再入一次、能作废（`uk_fg_doc_receipt`、`ReferrerProvider` 都不算作废的）。库存日志一条不删。

### 3.3 回货入库

- **待入库**：已登记（没作废）、还没有成品入库单（草稿也算有）的回货单。只列 `sys_config` 里 `fg.receipt_from` 以后登记的：迁移写成装这一版的日期，之前的回货当作已经在成品仓里，走"其他入库 · 期初"录。
- 带出：一行一个 SKU，数量 = 全部良品（回货 − 次品），逐行必须相等；入仓默认回货单的收货仓（是启用的成品仓时），否则第一个启用的成品仓；一个成品仓都没有 → 1000"还没有成品仓，先在 基础 › 仓库 建一个"。
- 能改：日期、入仓、备注。数量只读：每行必须等于良品数，良品为0的行不建；少入或超入均1004。
- 一张回货单只入一次（`uk_fg_doc_receipt`，作废的不算）：再入 → 1000"回货单 HH… 已经入过库：CR…"。
- 回货单作废前要先处理它的成品入库单：fg 实现 `ReferrerProvider`，production 作废时查到就 1005（§6.2）。

### 3.4 发货出库

- 选需求订单：已审核、生产中、已完成、已结案的才能发（PRD §6.5.3 的状态），别的 → 1000。
- 带出：订单的每个 SKU 一行，显示订单数、已发（本单以外已审核的发货出库）、出仓库存、最多还能发 = ⌊订单数 × 1.03⌋ − 已发（溢装比例借 Q09 回货的 3%，原型 `fgShip`）。单价 = 订单行单价，金额 = 件数 × 单价。
- 只能发订单上的 SKU（400）。超过最多还能发 → 1004；超过出仓库存 → 审核时 1001。
- `ship_to` 默认订单的送货要求，能改。
- 已发货只在 fg 里算，不回写需求订单：订单的状态不看发货（PRD §6.7.5 规则 3 只看回货），订单详情要看已发货时前端来 fg 取（§6.3）。

### 3.5 其他入库、其他出库

- 明细：从款式库挑款（`DataPick kind="style"`），每款一个颜色 × 尺码矩阵（`SkuMatrix`）填件数；出库的矩阵每格下面小字"库存 n"。
- 其他入库能导入明细（期初用）：Excel 两列 SKU 码、数量，再加备注；按 SKU 码对上，停用的 SKU 也收（老款的期初库存）；有一行对不上整批不导（1003）。导入只加到草稿上，审核才进库存。

### 3.6 过账

照 `StockLedger`（架构 §5.2），fg 里写一份 `FgLedger`：

1. 单据变成变动清单：入库 +，出库 −。
2. 相同的（仓库, SKU, 货位）合并，按这个组合排序，防死锁。
3. 逐条：`INSERT … ON CONFLICT DO NOTHING` 保证有这一行，再 `UPDATE fg_stock SET qty = qty + #{d} … WHERE … AND qty + #{d} >= 0 RETURNING qty`（`@Select` + `@Options(flushCache = TRUE)`）。
4. 没返回行的收集起来，整张单试完一起抛 1001（`FgShortRow[]`），事务回滚。
5. 每个仓每个 SKU 写一条日志；写操作记录。全部一个事务。

反审核走相反的变动，日志再记反方向的一条，不删原来的。反审核扣不回来（入的货已经发走了）→ 1001。

按钮：`fg:doc:add`、`:edit`、`:remove`、`:audit`、`:export` 挂在成品入库单下（两种单共用，照 V17）；`fg:stock:export` 挂在成品库存下。详情 `/fg-in/:id`、`/fg-out/:id` 进 `DETAIL_ROUTES`，共用 `views/fg/doc/detail.vue`，地址和 `kind` 对不上时 `router.replace`（照 04 §1.3）。`docRoute` 加 `FG_DOC`。

角色模板（PRD §3.1 没有这一行，照"物料入库单、出库单、库存"那一行定）：仓管给全部；业务、生产跟单、财务、管理层给 `fg:doc:list`、`fg:stock:list`；开发、采购不给。

**成品入库单 `/fg-in`**（照原型 `fgPage('in')`）：页头"其他入库"（`add`）。两个页签：

- "待入库"（`?tab=pending`，有 `add` 时默认）：筛选加工厂、回货日期、关键字（回货单号、生产单号、款号）。列：勾选、回货单（`fixed="left"`）、生产单、款式（缩略图 + 款号）、加工厂、回货、次品、良品、收货仓、回货日期、操作（"入库"，`fixed="right"`）。点"入库"开对话框（矩阵，每格只读显示全部良品数），按钮"存草稿""入库并过账"（后一个要 `audit`）。勾选后批量条"入库并过账"：逐条调生成接口（`items: null`、`post: true`），没成的留着勾、列原因。空表格："回货都入库了"。
- "入库单"（`?tab=docs`）：分段（全部 / 回货入库 / 其他入库）；筛选状态、日期、仓库、款式。列：勾选、单号、类型、入仓、来源（回货单号，或原因）、款式（第一款 + "等 n 款"）、件数、日期、状态；默认不显示：加工厂、生产单、制单人、审核人、备注。批量条：审核过账、导出选中。

**成品出库单 `/fg-out`**（照原型 `fgPage('out')`、`FgShip`、`FgOtherOut`）：页头"其他出库"、"发货出库"（主按钮）。分段（全部 / 发货出库 / 其他出库）；筛选状态、日期、仓库、需求订单。列：勾选、单号、类型、出仓、需求订单或原因、发到、款式、件数、物流单号、日期、状态；默认不显示：金额、制单人、审核人。批量同上。空表格："还没有出库单：成品仓有货以后点「发货出库」，拿样品、报废点「其他出库」"。

- 发货出库对话框：需求订单（能搜的下拉，`ship-orders`）、出仓、发到、物流单号；每款一个矩阵，每格下面"订单 120 · 已发 0 · 库存 80"，上限 = 最多还能发和库存里小的那个（标红不拦）。
- 其他入库、其他出库对话框：仓、原因（`DictSelect`）、备注、挑款 + 矩阵；其他入库多一个"从 Excel 导入"（先存草稿再导，`ImportDialog`）。

**成品库存 `/fg-stock`**：仓库下拉；视图分段：明细 / 按款 / 日志。明细：仓库、款式（缩略图 + 款号 + 款名）、颜色、尺码、SKU 码、数量、最近变动，点一行弹它的日志；按款：一款一行（款号、款名、合计），展开是只读的颜色 × 尺码矩阵（原型就是矩阵）；日志：日期、类型、单号（点了开单据）、仓库、SKU、变动（入绿出红）、结存、操作人。导出按当前视图。

**详情**：页头按 `actions`（编辑、审核过账、反审核、删除或作废）；正文属性（类型、仓、回货单 / 需求订单（链接）、原因、发到、物流单号、日期）+ 每款一个只读矩阵（数量），下面合计；侧栏附件、操作记录。草稿出库单的格子库存不够标红。

## 7. 关键流程和并发

| 场景 | 怎么保证 |
|---|---|
| 两张单同时审核、动到同几个 SKU | 合并后按（仓库, SKU, 货位）排序再更新，锁的顺序一样，不死锁；条件更新用最新的数判断，不会扣成负 |
| 同一张单点两次审核 | 比较并交换 草稿 → 已审核（带 `version`），第二次 1002 |
| 两个人同时入同一张回货单 | `uk_fg_doc_receipt`，后到的 1000 |
| 一边入库、一边作废回货单 | 入库 `forStock` 拿 `FOR SHARE`，作废先比较并交换（行锁）再查引用：谁先拿到锁谁成，后到的要么看到已作废（1000），要么查到成品入库单（1005） |
| 两张发货单同时审核、发同一张订单 | 审核时按订单 id 加事务级咨询锁（`pg_advisory_xact_lock`），在锁里重算已发再比上限，超了 1004。只有同一张订单的发货排队 |
| 发货时订单被取消 | `shipView` 拿 `FOR SHARE`，取消先锁订单再查引用 |
| 反审核一张入库单，货已经发走了 | 条件更新扣不回来，1001 |

## 8. 取舍

- **`FgLedger` 照写一份，不把 `StockLedger` 参数化**：`fg_stock` 只能 fg 写（架构 §3.2 第 3 条），表名拼进 SQL 又过不了 `TableOwnerTest`；物料那边还有物权、缸号、盘点，成品都没有。共同的只有十几行算法，可以抽到 `common`（§6.2）。
- **已发货在 fg 里算，不回写订单**：订单状态不看发货，回写只为了显示，前端来 fg 取就够；需求订单不知道有成品模块，藏起来也不留痕迹。代价是上限校验要自己加锁（咨询锁）。
- **待入库按启用日期截断**（§3.3）：不截断的话，上线前几周的回货全堆在待入库里，和期初录的库存重复。
- **发货必须挂需求订单**：自营的订单就是"哪个渠道要多少"，按订单发、按订单限数（原型 `fgShip`）；不挂订单的出库走"其他出库"。
- **一张回货单只入一次**：须一次处理全部良品，不能部分入库后把尾数隐藏；源良品有误先按真实逆向流程处理，不拆成几张入库单；以后对账、追溯回货都是一对一。

### 6.12 成品（M10 的一部分，12 月二期第一周）

做什么：回货的良品入成品仓，按需求订单发货，成品库存按仓库 × 款 × 颜色 × 尺码记（甲方 11-14 要求单独成一个模块）。侧边栏一组"成品"：成品入库单、成品出库单、成品库存。规则照物料：审核即过账，库存只能由单据改，不能为负（Q08）。成品库存以本系统为准、一期二期不推聚水潭（Q01、Q44 的默认做法）；要推时再加。

**成品入库单**（单号 CR）

| 单号 | ⚙ | CR + 年月日 + 4 位 |
| 类型 | ● | 回货入库（从回货单生成）/ 其他入库（原因：期初、返修合格、退回、其他） |
| 入仓 | ● | 启用的成品仓；回货入库默认回货单的收货仓 |
| 回货单 | 回货入库必填 | 一张回货单只入一次；带出生产单、款式、加工厂 |
| 日期 | ● | 实际入库日期，默认今天 |
| 明细 | ● | 款式 SKU × 件数；回货入库必须等于每行全部良品数（回货 − 次品），少入或超入均拒绝 |
| 原因 | 其他入库必填 | |
| 备注、附件 | ○ | |

**成品出库单**（单号 CC）

| 字段 | 必填 | 说明 |
|---|---|---|
| 类型 | ● | 发货出库 / 其他出库（原因：样品、报废、其他） |
| 出仓 | ● | 启用的成品仓 |

**成品库存**：按仓库 × 款式 SKU 看结存和最近变动；按款看颜色 × 尺码矩阵；点一行看流水（日期、类型、单号、变动、结存、操作人）；能导出。

规则：

1. 状态有草稿、已审核、已作废；审核即过账，反审核把库存改回去，改不回去（货已经发走）不让反审核。没过过账的草稿能删；过过账又反审核回来的不能删，只能作废（用户 11-17 定，和物料入库单、出库单一样）。
2. 回货单入过成品仓以后不能作废，要先反审核、作废成品入库单；发过货的需求订单不能取消。
3. 整张单一次检查完，库存不够的行一起列出来（哪个仓、哪个 SKU、库存多少、差多少）。
4. 首页"其他提醒"给仓管：回货待入成品仓 n。
5. 上线前登记的回货不进"待入库"，上线时成品仓里的货用"其他入库 · 期初"录（可以从 Excel 导入）。
6. 次品不入成品仓；入库前验货、调拨、退换货、成品盘点、条码装箱、聚水潭对接还是待定（§2.5）。

验收（用 §4.3 的例子）：

1. 03-08 回货 HH… 400 件、次品 4，"待入库"里有这张；点"入库并过账"生成 CR…，入成品仓 396 件，27CF001-KQ-M 等 SKU 的库存加上，日志各一条。同一张回货单再点入库，提示已经入过库。
2. 这张回货单再点作废，提示"已入成品仓 CR…"，回货单不变。
3. 给这张需求订单发货出库，卡其 M 订单 120 件：填 124 件提示最多还能发 123 件；从另一个只有 100 件的成品仓发 110 件，审核提示"库存不够：27CF001-KQ-M 库存 100，差 10 件"，库存不变。
4. 一张出库单两行都不够，审核时两行一起列出来。
5. 其他出库"样品"2 件，库存减 2，日志记"其他出库"。
6. 发过货以后反审核那张成品入库单，提示库存不够、不让反审核。
7. 两个人同时给同一张订单发同一个 SKU，加起来不会超过上限，库存不会变成负数。
8. 验收 1 的入库单反审核以后点删除，提示只能作废；作废以后这张回货单回到"待入库"，库存日志里入、出两条都在。
