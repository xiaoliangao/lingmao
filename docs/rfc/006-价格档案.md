# RFC 006 价格档案

状态：**已定**（2026-11-15 用户审过；"等用户定的问题"一节标了结论）。

对应：PRD §3.1、§6.10、Q25；架构 §3.1、§3.2、§5.5、§8；数据库设计 §7.1、附录 A.2"物料信息多供应商"。第 2 批共用的规则见 RFC 003 §2。

## 1. 解决什么

物料价、加工价的手工录入和作废；按日期取现价；物料、供应商、款式详情里的"价格记录"页签。另外把第 3、4 批要调的 `PriceService` 方法定下来：资料包的参考单价、排单的加工费、采购单的默认单价、单据审核时记价，都走这几个方法。

不做：

- 单据审核时记价（`recordFromDoc`）：签名这里定，第一张审核时记价的单据开工时实现（§5）。
- 成交记录（审核过的采购单、生产单，一单一行）：第 4 批随采购单。
- 款式"价格"页签里研发、生产 BOM 的对比：第 3 批随资料包。
- 跨款的核价、实际成本报表：跟着 M05 核价（待定）。
- 偏离现价要不要审批（Q25）：默认不审批，只留痕。

## 2. 表结构

照数据库设计 §7.1，一张 `prc_price`，不另加列。

- 只插不改。只有 `voided`、`void_reason`、`void_by`、`void_time` 四列能更新，Mapper 里只写作废这一条 `UPDATE`。
- 实体只有 `create_by`、`create_time` 两个审计列（数据库设计 §1.2 只插表），不继承带 `update_*` 的基类。
- 外键指向 `sup_supplier`、`bas_material`、`bas_material_sku`、`sty_style`。所以有价格记录的供应商、物料、SKU、款式都删不掉，只能停用（作废的也算）。
- 加检查约束 `ck_prc_price_type`（数据库设计 §7.1）：物料价、加工价各自的必填列由数据库保证，Java 漏了也写不进脏数据。
- 迁移一个文件，排在 RFC 003 §11 的第 6 个，在 supplier、basic、style 之后。

## 3. 录价和作废

规则照 PRD §6.10 规则 1、5 和原型 `5e-price.js` 的 `recordPrice`、`voidPrice`。

**录一条**（`POST /api/prices`）：

- 物料价：选供应商、物料，SKU 选填（空 = 这个物料所有颜色）。加工价：选工厂、款式、加工方式（字典 `process_mode`）。
- 供应商要能"打样"（`SupplierService.checkUsable(id, SAMPLE)`，RFC 004 §7）：待准入、审批中、合作中能录，停用、黑名单不能。还没准入的供应商先报价很常见。
- 停用的物料、SKU、款式不能录；SKU 必须属于这个物料。
- 单价 > 0，4 位小数。
- 单位自动定：物料价取物料现在的采购单位，加工价是"件"，不收参数。
- 税率默认带供应商的（供应商没填就必填）；含税、含运默认都是"是"。
- 生效日期默认今天，可以填以后的（下个月起调价），也可以补录以前的。
- 和"同一层级"的现价比（物料价分 SKU 层和物料层，原型 `recordPrice` 的口径）：
  - 一样 → 1000"11-01 起的现价已经是 18.50，不用再录"；
  - 不一样且有现价 → 调价原因必填；
  - 没有现价（第一次报价、第一次给这个 SKU 单独定价）→ 原因可以不填。

**作废**（`POST /api/prices/{id}/void`，原因必填）：`UPDATE … SET voided = true, … WHERE id = ? AND NOT voided`，0 行 → 1002"这条已经作废了"。从单据记进来的也能作废（架构 §5.5：反审核不删档案，要撤销就作废）。作废后取价自动退到上一条。

## 4. 取现价

```java
public interface PriceService {

    /** 物料现价：先找这个 SKU 的，没有再找物料层的（material_sku_id IS NULL）。
     *  只认 unit 等于物料现在采购单位的记录。没有返回 empty，调用方退回到 SKU 单价、物料参考单价（PRD §6.10 规则 3） */
    Optional<PriceRef> currentMaterial(long supplierId, long materialId, Long materialSkuId, LocalDate date);

    /** 批量版：采购单、资料包一次带出几十行，一条 SQL。key 带供应商，因为资料包每行的默认供应商不一样 */
    Map<MaterialPriceKey, PriceRef> currentMaterials(Collection<MaterialPriceKey> keys, LocalDate date);

    /** 加工价现价：工厂 × 款式 × 加工方式。核价按成品采购算时 processMode = FULL */
    Optional<PriceRef> currentProcess(long supplierId, long styleId, String processMode, LocalDate date);

    /** 单据审核时记价，见 §5 */
    List<PriceRef> recordFromDoc(PriceSource source, LocalDate effectiveDate, List<PriceLine> lines);
}

public record MaterialPriceKey(long supplierId, long materialId, Long materialSkuId) {}

public record PriceRef(long id, BigDecimal price, String unit, BigDecimal taxPct,
                       boolean taxIncluded, boolean freightIncluded, LocalDate effectiveDate,
                       Long materialSkuId) {}   // materialSkuId 为空 = 物料层的价

public record PriceSource(BizType type, long id, String no) {}

public record PriceLine(PriceType type, long supplierId, Long materialId, Long materialSkuId,
                        Long styleId, String processMode, BigDecimal price, String unit,
                        BigDecimal taxPct, boolean taxIncluded, boolean freightIncluded, String reason) {}
```

- SQL 照架构 §5.5：`effective_date <= ? AND NOT voided ORDER BY effective_date DESC, id DESC LIMIT 1`，走 `idx_prc_price_mat`、`idx_prc_price_proc`。批量版用 `DISTINCT ON`。
- **只认现在的采购单位**：物料改了采购单位（RFC 003 §7.2），旧单位的价不再当现价，页签里照样显示、标"单位已变"。不然一条"18.50 元/米"会被当成"18.50 元/公斤"带进采购单。
- 采购单位从 basic 的物料方法取（price → basic 允许）。
- 返回的价按采购单位。资料包的参考单价按库存单位（数据库设计附录 C.1 第 3 条），除以换算系数由资料包做。
- 含税、含运的口径原样返回，和单据的口径不一样时怎么处理由单据的 RFC 定。

## 5. 单据记价

`recordFromDoc` 这一批只定签名和规则，第一张审核时记价的单据开工时实现（不提前写没人调的代码）。调用方在审核的同一个事务里调（架构 §5.5）。

- 逐行取现价（日期 = 单据日期）。和现价一样的跳过。
- 记在哪一层：
  - 现价是这个 SKU 单独定的 → 记到 SKU；
  - 现价是物料层的或者没有，而这张单里**同一物料各 SKU 的价都一样** → 记到物料层，记一条；
  - 同一物料各 SKU 的价不一样 → 偏离的 SKU 各记一条。原型这种情况记到物料层，后记的盖掉先记的，别的颜色的现价也被改了。
- 同一组（供应商、物料、SKU、单价）在一张单里只记一条。
- 调价原因 = 行上填的改价原因；没有现价的写"第一次报价"。有现价而原因为空，说明单据保存时漏了检查，抛 500。
- 行上的单位和物料现在的采购单位不一样（单据建好后物料改了采购单位），这一行不记，写进返回值，由单据写进操作记录。
- 来源 = 这张单（`source_type` 存 `BizType` 的名字，`source_no` 冗余单号）；生效日期 = 单据日期。
- 返回记了哪些，单据写一条操作记录"单价记进价格档案：……"。

## 6. 导入

领猫物料导出里的"物料信息多供应商"表（数据库设计附录 A.2）该进价格档案。basic 不能写 price（架构 §3.2），所以这张表不在物料导入里处理。

这一批**不做**价格档案的导入：甲方给的样例里这张表是空的。物料导入遇到这张表有数据时，不拦，进提示"物料信息多供应商有 n 行没导"。甲方说有这种数据，就加 `POST /api/prices/import`：读同一个文件的这张表，按附录 A.2 的列对照，每行一条物料价，生效日期 = 导入当天、原因"领猫导入"；按钮放在物料列表的导入菜单里。估计半天。

## 7. 接口

| 接口 | 权限码 | 说明 |
|---|---|---|
| `GET /api/prices` | `price:price:list` | 分页。筛选：类型、供应商、物料、SKU、款式、加工方式、"只看现价"、"含作废"。供应商、物料、款式的名称由各域的 Service 批量取，不跨域 JOIN（表主人测试） |
| `POST /api/prices` | 按类型：`price:material:edit` 或 `price:process:edit` | §3 |
| `POST /api/prices/{id}/void` | 同上，按那条的类型 | §3 |

"只看现价"按 §4 的口径：每组（供应商 × 物料 × SKU，或工厂 × 款式 × 加工方式）今天的现价一条。

按类型校验权限：方法上 `@PreAuthorize("hasAnyAuthority('price:material:edit', 'price:process:edit')")` 先挡住两个都没有的，Service 里再按 `type` 查具体的那个，不符 → 403。

## 8. 权限和菜单

PRD §3.1 按类型给权限：物料价采购能改，加工价生产跟单能改，管理层都能改。所以分两个码（架构 §8 已跟着改）：

| 码 | 干什么 | 给谁（RFC 003 §13.2 的模板） |
|---|---|---|
| `price:price:list` | 看三个详情页的价格记录页签 | 开发、开发主管、业务、生产跟单、采购、财务、管理层 |
| `price:material:edit` | 录、作废物料价 | 采购、管理层 |
| `price:process:edit` | 录、作废加工价 | 生产跟单、管理层 |

录和作废不分开：原型就是一个"能改"（`canEditPrice`），能录的人录错了要能自己作废。

没有单独的价格页面（原型、PRD §6.10"在哪看"都只有三个页签）。三个码挂在"资料"目录下一个 `visible = false` 的"价格档案"菜单下面，只为了在角色页里能勾。

## 9. 前端

两个组件，放 `components/price/`：

| 件 | 干什么 |
|---|---|
| `PriceHistory` | 页签内容。传 `supplierId` / `materialId` / `styleId` 之一。上面是现价（每组一行），下面是全部历史；作废的划掉、显示作废原因；单位已变的标出来；来源单号能点（第 4 批起有）。右上角"录价格"、每行"作废"，按类型看权限 |
| `PriceForm` | 录价对话框。从哪个页签打开就预填哪一项（物料页签预填物料，供应商页签预填供应商）；物料、SKU 用 `DataPick`，款式用 `DataPick`，供应商用 `SupplierSelect`。填了单价就显示"现价 18.50（11-01 起）→ 19.00"，有现价时原因框变必填 |

用在：物料详情的"价格记录"、供应商详情的"价格记录"、款式详情的"价格"（这一批只有加工价）。没有 `price:price:list` 的人看不到这个页签。

## 10. 关键流程和并发

| 场景 | 怎么保证 |
|---|---|
| 两人同时作废同一条 | 条件更新 `AND NOT voided`，后到的 1002 |
| 两人同时录同一组、同样的价 | 不拦，多一条一样的价不影响取价（取最后录的那条，价一样）。为这个加锁不值得 |
| 取价时有人刚作废了现价 | 读已提交，下一次取价就退到上一条；已经带进单据的价不变 |
| 物料改了采购单位 | 旧单位的价自动不参与取价（§4） |

## 11. 取舍

- **权限按类型分两个码**，跟 PRD §3.1 和原型：采购不该改工厂的加工费，生产跟单不该改面料价。多一个码，角色页多一个勾。
- **取现价只认现在的采购单位**，不做单位换算：价格档案的单位是"记录时"的，换算系数也可能一起改了，按新系数换旧价不一定对。宁可取不到，让人重新录一条。
- **`recordFromDoc` 同一物料各 SKU 价不一样时按 SKU 记**：修原型的一个口子（§5）。
- **多供应商导入等有数据再做**（§6）。

## 13. 等用户定的问题

1. **甲方领猫里有没有"一个物料几家供应商的报价"**：有就加价格档案的导入（§6），没有就不做。
2. 偏离现价不审批，只留痕（Q25 的默认做法）。
3. 生效日期可以补录以前的、也可以填以后的（§3）。补录以前的会改变"那一天的现价"，但已经建好的单据不受影响。
