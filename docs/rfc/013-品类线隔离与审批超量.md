| 问题 | 甲方答 |

## 2. 品类线隔离（Q13、Q30）

### 2.1 什么是品类线

字典 `product_line`，三项内置：`APPAREL` 服装、`FOOTWEAR` 鞋类、`GENERAL` 百货。value 不能改、不能删，label 能改；以后再加品类线在字典里加。

### 2.2 谁能看哪几条

- **人**：`sys_user` 加 `product_lines VARCHAR(16)[]`，一个人可以有几条。管理后台 › 用户里多选，至少选一条。超级管理员看全部。
- 迁移时已有的用户都给三条（看到的和现在一样），管理员再按人收窄。
- 登录加载权限时多给几个权限标识 `line:APPAREL`……（和数据范围的 `data:all` 一样，不另外查库）。
- 品类线和数据范围（全部 / 本人）是两道，叠在一起：鞋类的采购员只看鞋类里自己的单。

### 2.3 哪些数据带品类线

| 数据 | 品类线从哪来 | 迁移时已有的 |
|---|---|---|
| 款式 `sty_style.product_line` | 大类定：字典 `style_class` 每一项设一个品类线（存 `text_value`），TS、FS → 服装，XZ → 鞋类；建款时按大类写进去，大类不能改所以它也不变 | 按大类回填 |
| 资料包、按款看成本 | 跟款式 | — |
| 需求订单 `ord_order.product_line` | 明细里的款；一张单只能有一个品类线的款，混了报错 | 按第一个款回填 |
| 订单变更 | 跟订单 | — |
| 算料单 `mrp_calc.product_line` | 选的订单；一次只能算一个品类线的订单 | 按订单回填 |
| 采购单 `pur_order.product_line` | 从算料单来的跟算料单；手工建的选一个（只有一条的人自动带上），供应商要做这条线 | 按算料单回填，没有的给服装 |
| 外发加工单、成品采购单 `prd_order.product_line` | 跟款式 | 按款式回填 |
| 回货、报工、生产看板、进度、异常 | 跟生产单 | — |
| 供应商 `sup_supplier.product_lines VARCHAR(16)[]` | 新建、编辑时多选，至少一条；导入时一列"品类线"，空着给导入人自己的全部品类线 | 三条都给 |
| 价格档案 | 物料价跟供应商，加工价跟款式 | — |

**不分品类线、大家共用的**：物料（同一种料两条线都可能用；价格还是看成本权限管）、颜色、尺码组、仓库、物料出入库单、库存、盘点（仓库一个团队管）、主体公司。甲方以后要分，再照上面的办法加。这条要告诉甲方。

### 2.4 怎么筛

照数据范围的做法（`DataScope`，架构 §8），显式加条件，不用 MyBatis-Plus 的数据权限插件：

```java
LineScope lines = LineScope.current();
lines.apply(wrapper, Style::getProductLine);          // product_line IN (我的几条)；全部时不加
lines.applyAny(wrapper, "product_lines");             // 供应商：product_lines && 我的几条
lines.check(style.getProductLine());                  // 详情、动作：不在我的线里 → 404
```

- 列表、详情、导出、下拉选项、⌘K 搜索、首页和看板的统计都要过它；详情不在范围里返回 404，和数据范围一样不区分"不存在"。
- 建单时校验：选的款、订单、供应商都要在自己的线里；跨线的组合（鞋类订单配只做服装的供应商）报 1000 说清楚。
- Mapper XML 手写的查询把 `LineScope` 当参数传进去，`<if test="lines.limited">` 加条件。

### 2.5 页面

- 用户表单：品类线多选。
- 设置 › 字典 › 款式大类：多一列"品类线"。
- 供应商表单、详情：品类线多选；列表多一列（`hidden: true`）。
- 只有一条线的人页面上不显示品类线；有几条的，款式、订单、采购单、生产单列表能按它筛，列表多一列。

### 2.6 做的时候定的（11-19）

- **不建索引**（§5 原来写了建）：品类线只有三个值，区分度低，单据列表照旧靠状态、日期、单号、关键字的索引；供应商的数组也不建 GIN。数据量上来、真成了瓶颈再加。
- **`DataScope` 带着 `LineScope`**（`scope.getLines()`，XML 里 `scope.lines`）：已经过数据范围的列表、详情、导出顺手就有品类线，不用每个 Mapper 多传一个参数。价格档案没有数据范围，单独传 `lines`。
- **一条都没有就什么都看不到**：权限里没有任何 `line:` 的人（漏配）看到的是空列表、详情 404，不是全部。超级管理员给 `line:all`。
- **单据上显示供应商的名字不过滤**（`SupplierService.getRef`）：单据能看到，上面的供应商就该能显示出来；下拉、列表、详情、导出照线过滤。
- **改供应商时看不到的线原样留着**：只做服装的采购改一家"服装 + 鞋类"的供应商，下拉里只有服装，保存时鞋类不会被去掉；也不能给它加自己看不到的线。表单上提示"还做鞋类：你看不到这条线，保存时原样留着"。
- **供应商导入**多一列"品类线"，几条用逗号、顿号隔开，空着 = 导入人能看的全部线。
- **价格档案**：物料价跟供应商（线有交集就看得到），加工价还要款在我的线里。
- **仓管的账号要给全部线**：库存、出入库单、盘点不分线，但"待到料"是采购单的行、由采购单生成入库单要看得到采购单，所以照采购单的线过滤。
- **前端**：`useProductLines()` 读登录信息里的 `line:*`；新组件 `LineSelect`；`SupplierSelect` 收 `product-line`，采购单、补货、算料改供应商、排单、生产单换厂都传。订单挑过款以后选款式只列这条线的；手工建采购单几条线的人要选一条（只有一条的后端带上），从算料单生成的不能改。
- **测试**：`LineScopeTest`（全部、几条、没有）；集成测试：鞋类的人看不到服装的款式（`StyleServiceImplIT`）、供应商（`SupplierServiceImplIT`，含看不到的线保存后留着）、订单（`OrderIT`，含一张单混线报错）、采购单（`PurchaseIT`，含供应商不做这条线报错）、生产单（`ProductionIT`，含加工厂不做这条线时排单报错）；列表、详情 404 都测了。导出和 ⌘K 走同一个列表查询，没单独测。迁移回填由 `SchemaConventionsIT` 查大类的品类线。

## 3. 一级审批和生产经理（Q10）

- 多级审批的规则表（`biz_approval_rule`）从来没预置过数据，所以现在就是一级审批，不用改。PRD §5.1 里"默认采购单超过 5 万、生产单超过 10 万再给总经理审"的话去掉。
- 加一个角色模板"生产经理"（`prod_manager`，数据范围全部）：生产跟单的权限，加上需求订单、外发加工单和成品采购单、采购单、物料盘点单的审核；看加工价、看生产价格。管理层的审核权限不动（甲方可以在角色里去掉）。
- 自己做的单能不能自己审：甲方没答，照默认允许。

做法（11-18 实现，V43）：角色模板 `prod_manager` 照抄生产跟单当时的全部授权，再加 `order:order:audit`、`order:change:audit`、`production:order:audit`、`purchase:order:audit`、`inventory:count:list`、`inventory:count:export`、`inventory:count:audit` 和它们的上级菜单；`SchemaConventionsIT.roleTemplates` 核对权限码和侧边栏。原型的默认多级规则去掉，流程说明改成一级审批。

## 4. 排单、回货超 5%（Q09）

- 排单、回货的溢装从 3% 改成 5%：`ProductionRules.OVER_PCT`。短装（回够 97% 算完成）甲方没说，不动。
- **裁床数**：外发加工单、成品采购单明细加 `cut_qty INT`（空 = 没登记）。生产单详情"更多 › 登记裁床数"，按 SKU 填；已下单、生产中能登记、能改；不能超过 ⌊件数 × 1.05⌋。
- 有裁床数的 SKU，回货上限 = ⌊裁床数 × 1.05⌋，完成判定也按裁床数（回够裁床数的 97% 算回齐）；没登记的照旧按件数。
- 排单没有裁床数（还没裁），照旧按订单件数 × 1.05。
- 手机报工报"裁剪完成"时不强制填裁床数，页面提示一句"去生产单上登记裁床数"。

做法（11-18 实现，V43）：`ProductionRules.OVER_PCT` 5，`basis` / `maxReturn` / `minCut`，`byProgress` 按 `basis` 加总；`PUT /api/production-orders/{id}/cut-qty`（`ProductionReceiptServiceImpl.registerCut`，动作 `cut`，权限 `production:node:edit`）：锁订单和生产单，逐行查上下限，只写改了的行，记操作记录，按新基数重算状态（可能直接已完成，订单跟着回写）。明细 VO 加 `cutQty`、`maxCutQty`、`minCutQty`。前端 `ProdCutDialog.vue`，回货对话框小字带"裁 n"。
