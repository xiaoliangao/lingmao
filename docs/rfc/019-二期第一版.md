# RFC 019 二期第一版：照甲方 11-27 的答复先做出来

状态：**做着**（11-27 起）。用户 11-27 说："根据回复，把能做的都做了先，争取 12 月之前先出一个第一版齐全功能的让甲方测试，然后我们再去优化"。
所以这份是边做边记：每块做完补一节，写做法、为什么这样做、没定的按什么默认。甲方 12 月试用时有意见再改。

对应：PRD §12 Q53、Q60、Q61、Q65、Q66、Q67、Q68、Q02；甲方答复原件在 `docs/private/`（不进仓库）。工厂料账（Q55）单独写在 RFC 015。

顺序（一块做完提交一块）：工厂料账（RFC 015）→ 二次加工节点 → 工厂产能 → 报表和预警中心（含呆滞料、供应商绩效）→ 手机审批和钉钉推送 → 供应商对账 → 质量记录 → 工厂账号。
要外部账号的先不做：聚水潭（Q01）、大模型服务（Q45）、PDA 扫码（Q67）、企查查。

## 1. 二次加工节点（Q61，V61，已实现 11-27）

甲方答：加工厂自己找人做印花、绣花、洗水，发成衣，不跟数量，费用含在加工费里；"在加工单上多跟一个二次加工节点就够"。

- **不放进默认节点**：节点是从交期往前倒排的，多一个节点，所有单的开裁、要料日期都往前挪，可多数单没有二次加工。
- 改成生产节点字典多一个"用法"（文字值，字典 `node_usage`）：每张单都有 / 按单选。V61 加"二次加工"（排在车缝后面，默认 3 天，按单选）。管理员以后在字典里还能加别的按单选节点（如压胶）。
- 外发加工单草稿的编辑对话框多一行"加节点"勾选；`prd_order.optional_nodes` 记勾了哪些，审核生成节点时和每张单都有的一起倒排。
- 算料按承诺交期倒推要料日期时不算按单选的节点：还没排单，不知道这张单加不加。

## 2. 工厂产能（Q60，V62，已实现 11-27）

甲方答：按品类分开算（外套和 T 恤差很多）；理单和跟单每月维护一次；排单时排满了拦住，不让排。

**登记**（生产 › 工厂产能，`prd_factory_capacity`）：每家加工厂 × 品类一个日产能（件 / 天），从某个月起算。

- **哪个月没再登记，沿用前面最近一次的**，页面上标"本月没更新"。不这样的话，忘了更新的那个月就一张都不拦了。
- 品类可以挂在任何一级：挂在"外套"上管外套和它下面的，挂在"女装"上管整个女装；一个款归几条管就都查。不填品类 = 这家厂所有款合计。
- 同一家厂、同一个品类、同一个月只有一条，再登记就是覆盖。
- 日产能按自然日算（含周末），填平均每天能出多少件：做排班日历太重，甲方也是按月估一个数。
- 理单、生产跟单、生产经理能登记，管理层能看。

**查**：排单（需求订单排单生成草稿）和改草稿的加工厂、交期时查。

- 排一张交期 D 的单，要保证排进去以后，对 D 和每个交期在 D 之后的单的交期 T：交期在 T 及之前、还没做完的件数 ≤ 从今天到 T 能做的。
  先到期的先做，新单交期早会挤占后面那些单的时间，所以 T 不只看 D。
- "还没做完" = 没作废、没完成、没结案的生产单（草稿也算，排了就占产能）的数量 − 良品。
- 一次排几块，后一块把前一块也算上。排不下的每块一句：到哪天能做多少、已经排了多少、这次多少、超了多少，"改交期、换工厂，或者先改产能"。
- 没登记产能的厂不查。
- 排单对话框选了加工厂和交期，下面一行显示"到 12-20 还能排 N 件"，这块件数超了变红（提交时后端再查一次，以后端为准）。

**没定的，按默认做**：

- 拦住以后谁能放行：不做放行。理单、跟单自己就能改产能，真要排就先把产能改上去（改动记在更新人、更新时间上）。
- 只在排单、改草稿时查；提交、审核不再查（排的时候已经查过，之后别的单排进来，是别的单被拦）。
- 甲方试用时觉得拦得太死，可以改成"只提示"，或加一个放行权限。

## 3. 报表和预警中心（Q66、Q67、Q53，V63，已实现 11-27）

甲方答：每周看采购到货及时率、工厂交期达成率和次品率、订单毛利；每月看各品类线在做的件数、呆滞料；要一个统一的预警中心，暂时不加新的预警。
Q53 的供应商绩效要准时率、次品率、价格打分；Q67 要呆滞料分析，多久没动算呆滞待定。样表没给，先照系统里有的数做，甲方看了再调。

侧边栏加"报表"目录，五页：预警中心、供应商绩效、在做件数、订单毛利、呆滞料（V63 建菜单、按钮，按角色给）。
都是后端现算的只读 SQL（`board` 域，架构 §14.2），不建汇总表：数据量一年几万行，现算够快；以后慢了再加汇总表，接口不用变。
数据范围按品类线（PRD §3.2）：只算自己能看的品类线的单。

### 3.1 供应商绩效（每周看）

**物料供应商：采购到货及时率**，按采购行算（一张单几种料，到得有早有晚）。

- 交期 = 行上的交期，没有用单头的交期；交期落在选的时间段里的行才算。只算审核过的单（已审核、进行中、已完成、已结案）。
- 到齐日 = 采购入库单（已审核）按单据日期累计，够了"采购数 − 被别的单超收冲抵的"的那天。到齐日不晚于交期是准时，晚了算逾期，记晚几天。
- 交期过了还没到齐：算逾期，晚的天数算到今天。交期还没到、也没到齐：不算，单列"还没到期"。
- 单子已完成、已结案却没到齐（少收了就结了）：按最后一次到货的日子判；一次都没到的是取消掉的行，不算。全被冲抵的行算准时。
- 及时率 = 准时 ÷（准时 + 逾期）；另给逾期的平均晚几天。

**加工厂：交期达成率、次品率**，外发加工单和成品采购单都算。

- 按单：回货（没作废的）按回货日累计良品，够了生产数的那天是回齐日，和约定交期比，规则同上。
- 按件：交期当天及以前回的良品 ÷ 应交件数（多回的也只算到应交数为止）。部分交了的厂按单是逾期、按件能看出交了多少。
- 次品率 = 选的时间段里回货的次品 ÷ 回货件数（按回货日，不按交期）。
- 一页两个分段：物料供应商、加工厂；时间段默认"上周"，能选本周、上月、本月、自己选（最长一年）。及时率低于 95% 标琥珀、低于 80% 标红；次品率 2% 以上琥珀、5% 以上红（甲方没给线，先这样，以后放进设置）。

**价格打分没做**：要先定拿什么比（同一物料几家报价比、跟上次成交价比、跟核价比），甲方没给口径，价格档案和成交记录一期都有，定了再加一列。

### 3.2 各品类线在做件数（每月看）

- 在做 = 外发加工单、成品采购单里还没回的件数（生产数 − 已回良品），草稿到生产中都算（排了就占产能，和 §2 一样）；完成、结案、作废的不算。
- 按品类线 × 一级品类分行（款的品类往上找到第一级），同一品类线排在一起，最后一行合计。
- 另给"其中逾期"（预计交期，没有用约定交期，早于今天的）和选的那个月"新排了多少""回了多少良品"，看这个月是在消化还是在积压。

### 3.3 呆滞料（每月看）

- 物料仓里有库存、最后一次出入库早于 N 天前的物料，按仓库 × 物料 SKU 一行。工厂仓的料不算（归工厂料账，RFC 015）；盘点调整不算"动过"。
- N 默认 90 天，甲方还没定。页面上能临时换个天数看；有"改呆滞天数"权限的人（生产经理、管理层）能"设为默认"，存在系统设置 `report.stale_days`。
- 金额 = 库存 × 最近一次入库的单价（估个量级）。能导出。
- 首页"其他提醒"多一个"呆滞料 n"（有看呆滞料权限的人），点了打开这一页。

### 3.4 订单毛利（每周看）

- 按下单日期筛审核过的需求订单。销售额 = 订单明细金额；成本 = 每个款的件数 × 那一版资料包核价的单件成本（RFC 014 的核价页签，面料 + 辅料 + 加工 + 其他）；毛利 = 销售额 − 成本。
- 这是**估算**：按核价，不是实际耗料和实际加工价。实际成本要等工厂料账核销（RFC 015）和对账（§6 供应商对账）都跑起来，以后再加"实际毛利"。
- 资料包没有生效版、核价算不出来的款：这部分件数不算成本，行上标出来，合计上方写"n 张单有款算不出成本，毛利偏高"。
- 外币订单：一期没有汇率（PRD §7 币种），不算毛利、不进合计，行上写"外币单"。
- 要同时有"看订单毛利""看订单价格""看成本"三个权限（成本和售价都是敏感的），默认只给管理层、财务。一次最多算 2000 张单，超了让缩小日期范围。

### 3.5 预警中心

- 不加新的预警（甲方答的），把分散在首页待办、待到料、生产看板里的收到一页：上面按模块（生产、物料、订单和供应商）列各种预警的条数，点了打开已经筛好的列表；下面每种预警列出具体单据（最多 20 条，多的去对应列表）。
- 数据就用首页待办的接口，不要"待我审核"那组（审核不是预警）；权限、数据范围、"全部 / 我负责的"和首页一样，所以两边的数永远对得上。
- 呆滞料的数也进来（§3.3）。

**没定的，按默认做**：呆滞天数 90；及时率、次品率的标色线；毛利按核价估；价格打分不做。甲方试用后给了样表再调列和口径。

## 4. 手机审批和钉钉推送（Q65，V64，已实现 11-27）

甲方答：用钉钉；推"单据被驳回""货期预警"两种（"轮到我审"没选，不推）；手机上点开消息要能直接审。

### 4.1 怎么发

- 钉钉"企业内部应用"的工作通知（`asyncsend_v2`，卡片下面一个"打开"按钮）。三个参数 AppKey、AppSecret、AgentId 放部署配置（`.env` 的 `SCM_DINGTALK_*`），不进库、不进页面；三个都有才发，没配时什么都不入队。试用环境不配，所以试用期间不发消息。
- 收件人按用户档案上的**手机号**去钉钉查 userid（`getbymobile`，要开"根据手机号获取成员基本信息"权限），查到记在 `sys_user.dingtalk_user_id`，手机号改了重新查。不另建"钉钉账号绑定"页：甲方的人都在钉钉里，手机号一样就行。
- 发送走 V32 的后台任务队列 `sys_outbox`（`kind = DINGTALK_MESSAGE`）：驳回和入队在同一个事务里（驳回回滚了消息也没有），后台 worker 去发，网络问题、钉钉报错按队列的规则重试（30 秒起翻倍，5 次后进死信）；没配置、找不到收件人不重试，直接进死信。同一件事只入队一次（去重键）。
  - 为什么不照架构 §14.3 另建 `biz_outbox`：钉钉消息只是通知，不需要外部单号映射、回执；`sys_outbox` 已经有同事务入队、租约、退避重试、死信、去重。`biz_outbox` 留给三期往聚水潭推单据。
  - 发送放在 worker 线程（和库存日志导出共用两个名额），不卡每秒一轮的缓存失效。
  - 钉钉同一天给同一个人内容一样的消息只送一条，所以驳回消息里带驳回时间，同一张单一天驳回两次也都收到。
- `scm.public-url`（`SCM_PUBLIC_URL`）是用户打开系统的地址，"打开"按钮用它拼链接；没配时消息照发，不带按钮。
- 发完、发不出去的消息留 90 天（`SessionHousekeeping` 清）。

### 4.2 推什么

- **单据被驳回**：在写操作记录的地方（`DocLogServiceImpl`）看到 `reject`、`change-reject` 就发，所以所有能驳回的单据都覆盖了：需求订单、订单变更单、采购单、外发加工单、成品采购单、盘点单、供应商准入和资料改动。发给这张单最近一次"提交"的人（`change-reject` 是最近一次提改动的人）；自己驳回自己的不发。内容：单号、驳回的人和时间、原因，"打开"到手机待办的这张单。
- **货期预警**：每天早上 8:30 以后一人一条（`DueWarningTask`，挂在后台任务每分钟一轮的定时清理上，整个部署只一个实例在跑；去重键"人 + 日期"，重启了也不多发）。跟单员：他跟的生产单逾期几张、7 天内到期几张、节点延期几张；采购员：他的采购单到料逾期几行。口径和首页待办、预警中心一样。全是 0 的人不发。"打开"到手机待办的"预警"页签。
- 管理后台 › 系统管理 › 消息推送（只给超级管理员）：钉钉配好没有、两种消息各自开关（`sys_config` 的 `notify.events`，默认两种都开）、给自己发一条测试消息（当场发，不通的报钉钉的原话）、最近的消息和没发出去的原因、重发。

### 4.3 手机待办

- 单独成页（和手机报工一样用 `MobileLayout`，没有侧边栏、页签），地址 `/mobile-todo`，在侧边栏"报表"里，给各业务岗位（和预警中心一样）。手机上登录：有手机报工的进手机报工，没有的进手机待办。钉钉应用的移动端首页也填它（部署手册第 11 节）。
- 两个页签：**待我审核**（首页待办的"待我审核"那组）、**预警**（首页待办里预警类的几组和数）。数据就是首页待办接口，权限、数据范围一样。
- 点一张单进 `/mobile-todo/:id?type=…`：要点（谁、多少、交期、金额）、明细摘要、审批进度，底下"驳回""审核通过"。能在手机上审的四种：需求订单（要填承诺交期）、采购单、生产单（外发加工、成品采购）、订单变更单。能不能审照各自详情接口的 `actions`（后端按状态、权限、轮没轮到我算好），审核、驳回也走各自原来的接口，所以和电脑上一样的校验、一样的多级审批。
- 别的种类（资料包、出入库、盘点、供应商准入）提示"要在电脑上处理"，给电脑版的链接。需求订单的评审信息（资料包、缺料、产能）只在电脑上看，手机上审后端照样校验。

**没定的，按默认做**：发送时间 8:30；临期 7 天；钉钉的应用由甲方的钉钉管理员建，参数交给部署方填。
