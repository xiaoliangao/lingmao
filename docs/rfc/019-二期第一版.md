# RFC 019 二期第一版：照甲方 11-27 的答复先做出来

状态：**第一版做完了**（11-27，§1-§7 都已实现，等甲方 12 月试用）。用户 11-27 说："根据回复，把能做的都做了先，争取 12 月之前先出一个第一版齐全功能的让甲方测试，然后我们再去优化"。
所以这份是边做边记：每块做完补一节，写做法、为什么这样做、没定的按什么默认。甲方 12 月试用时有意见再改。

对应：PRD §12 Q53、Q60、Q61、Q65、Q66、Q67、Q68、Q02；甲方答复原件在 `docs/private/`（不进仓库）。工厂料账（Q55）单独写在 RFC 015。

顺序（一块做完提交一块）：工厂料账（RFC 015）→ 二次加工节点 → 工厂产能 → 报表和预警中心（含呆滞料、供应商绩效）→ 手机审批和钉钉推送 → 供应商对账 → 质量记录 → 工厂账号。
要外部账号的先不做：聚水潭（Q01）、大模型服务（Q45）、PDA 扫码（Q67）、企查查。

## 1. 二次加工节点（Q61，V61，已实现 11-27）

甲方答：加工厂自己找人做印花、绣花、洗水，发成衣，不跟数量，费用含在加工费里；"在加工单上多跟一个二次加工节点就够"。

- **不放进默认节点**：节点是从交期往前倒排的，多一个节点，所有单的开裁、要料日期都往前挪，可多数单没有二次加工。
- 改成生产节点字典多一个"用法"（文字值，字典 `node_usage`）：每张单都有 / 按单选。V61 加"二次加工"（排在车缝后面，默认 3 天，按单选）。管理员以后在字典里还能加别的按单选节点（如压胶）。
- 外发加工单草稿的编辑对话框多一行"加节点"勾选；`prd_order.optional_nodes` 记勾了哪些，审核生成节点时和每张单都有的一起倒排。
- 算料按承诺交期倒推要料日期时不算按单选的节点：还没排单，不知道这张单加不加。

## 2. 工厂产能（Q60，V62，已实现 11-27）

甲方答：按品类分开算（外套和 T 恤差很多）；理单和跟单每月维护一次；排单时排满了拦住，不让排。

**登记**（生产 › 工厂产能，`prd_factory_capacity`）：每家加工厂 × 品类一个日产能（件 / 天），从某个月起算。

- **哪个月没再登记，沿用前面最近一次的**，页面上标"本月没更新"。不这样的话，忘了更新的那个月就一张都不拦了。
- 品类可以挂在任何一级：挂在"外套"上管外套和它下面的，挂在"女装"上管整个女装；一个款归几条管就都查。不填品类 = 这家厂所有款合计。
- 同一家厂、同一个品类、同一个月只有一条，再登记就是覆盖。
- 日产能按自然日算（含周末），填平均每天能出多少件：做排班日历太重，甲方也是按月估一个数。
- 理单、生产跟单、生产经理能登记，管理层能看。

**查**：排单（需求订单排单生成草稿）和改草稿的加工厂、交期时查。

- 排一张交期 D 的单，要保证排进去以后，对 D 和每个交期在 D 之后的单的交期 T：交期在 T 及之前、还没做完的件数 ≤ 从今天到 T 能做的。
  先到期的先做，新单交期早会挤占后面那些单的时间，所以 T 不只看 D。
- "还没做完" = 没作废、没完成、没结案的生产单（草稿也算，排了就占产能）的数量 − 良品。
- 一次排几块，后一块把前一块也算上。排不下的每块一句：到哪天能做多少、已经排了多少、这次多少、超了多少，"改交期、换工厂，或者先改产能"。
- 没登记产能的厂不查。
- 排单对话框选了加工厂和交期，下面一行显示"到 12-20 还能排 N 件"，这块件数超了变红（提交时后端再查一次，以后端为准）。

**没定的，按默认做**：

- 拦住以后谁能放行：不做放行。理单、跟单自己就能改产能，真要排就先把产能改上去（改动记在更新人、更新时间上）。
- 只在排单、改草稿时查；提交、审核不再查（排的时候已经查过，之后别的单排进来，是别的单被拦）。
- 甲方试用时觉得拦得太死，可以改成"只提示"，或加一个放行权限。

## 3. 报表和预警中心（Q66、Q67、Q53，V63，已实现 11-27）

甲方答：每周看采购到货及时率、工厂交期达成率和次品率、订单毛利；每月看各品类线在做的件数、呆滞料；要一个统一的预警中心，暂时不加新的预警。
Q53 的供应商绩效要准时率、次品率、价格打分；Q67 要呆滞料分析，多久没动算呆滞待定。样表没给，先照系统里有的数做，甲方看了再调。

侧边栏加"报表"目录，五页：预警中心、供应商绩效、在做件数、订单毛利、呆滞料（V63 建菜单、按钮，按角色给）。
都是后端现算的只读 SQL（`board` 域，架构 §14.2），不建汇总表：数据量一年几万行，现算够快；以后慢了再加汇总表，接口不用变。
数据范围按品类线（PRD §3.2）：只算自己能看的品类线的单。

### 3.1 供应商绩效（每周看）

**物料供应商：采购到货及时率**，按采购行算（一张单几种料，到得有早有晚）。

- 交期 = 行上的交期，没有用单头的交期；交期落在选的时间段里的行才算。只算审核过的单（已审核、进行中、已完成、已结案）。
- 到齐日 = 采购入库单（已审核）按单据日期累计，够了"采购数 − 被别的单超收冲抵的"的那天。到齐日不晚于交期是准时，晚了算逾期，记晚几天。
- 交期过了还没到齐：算逾期，晚的天数算到今天。交期还没到、也没到齐：不算，单列"还没到期"。
- 单子已完成、已结案却没到齐（少收了就结了）：按最后一次到货的日子判；一次都没到的是取消掉的行，不算。全被冲抵的行算准时。
- 及时率 = 准时 ÷（准时 + 逾期）；另给逾期的平均晚几天。

**加工厂：交期达成率、次品率**，外发加工单和成品采购单都算。

- 按单：回货（没作废的）按回货日累计良品，够了生产数的那天是回齐日，和约定交期比，规则同上。
- 按件：交期当天及以前回的良品 ÷ 应交件数（多回的也只算到应交数为止）。部分交了的厂按单是逾期、按件能看出交了多少。
- 次品率 = 选的时间段里回货的次品 ÷ 回货件数（按回货日，不按交期）。
- 一页两个分段：物料供应商、加工厂；时间段默认"上周"，能选本周、上月、本月、自己选（最长一年）。及时率低于 95% 标琥珀、低于 80% 标红；次品率 2% 以上琥珀、5% 以上红（甲方没给线，先这样，以后放进设置）。

**价格打分没做**：要先定拿什么比（同一物料几家报价比、跟上次成交价比、跟核价比），甲方没给口径，价格档案和成交记录一期都有，定了再加一列。

### 3.2 各品类线在做件数（每月看）

- 在做 = 外发加工单、成品采购单里还没回的件数（生产数 − 已回良品），草稿到生产中都算（排了就占产能，和 §2 一样）；完成、结案、作废的不算。
- 按品类线 × 一级品类分行（款的品类往上找到第一级），同一品类线排在一起，最后一行合计。
- 另给"其中逾期"（预计交期，没有用约定交期，早于今天的）和选的那个月"新排了多少""回了多少良品"，看这个月是在消化还是在积压。

### 3.3 呆滞料（每月看）

- 物料仓里有库存、最后一次出入库早于 N 天前的物料，按仓库 × 物料 SKU 一行。工厂仓的料不算（归工厂料账，RFC 015）；盘点调整不算"动过"。
- N 默认 90 天，甲方还没定。页面上能临时换个天数看；有"改呆滞天数"权限的人（生产经理、管理层）能"设为默认"，存在系统设置 `report.stale_days`。
- 金额 = 库存 × 最近一次入库的单价（估个量级）。能导出。
- 首页"其他提醒"多一个"呆滞料 n"（有看呆滞料权限的人），点了打开这一页。

### 3.4 订单毛利（每周看）

- 按下单日期筛审核过的需求订单。销售额 = 订单明细金额；成本 = 每个款的件数 × 那一版资料包核价的单件成本（RFC 014 的核价页签，面料 + 辅料 + 加工 + 其他）；毛利 = 销售额 − 成本。
- 这是**估算**：按核价，不是实际耗料和实际加工价。实际成本要等工厂料账核销（RFC 015）和对账（§6 供应商对账）都跑起来，以后再加"实际毛利"。
- 资料包没有生效版、核价算不出来的款：这部分件数不算成本，行上标出来，合计上方写"n 张单有款算不出成本，毛利偏高"。
- 外币订单：一期没有汇率（PRD §7 币种），不算毛利、不进合计，行上写"外币单"。
- 要同时有"看订单毛利""看订单价格""看成本"三个权限（成本和售价都是敏感的），默认只给管理层、财务。一次最多算 2000 张单，超了让缩小日期范围。

### 3.5 预警中心

- 不加新的预警（甲方答的），把分散在首页待办、待到料、生产看板里的收到一页：上面按模块（生产、物料、订单和供应商）列各种预警的条数，点了打开已经筛好的列表；下面每种预警列出具体单据（最多 20 条，多的去对应列表）。
- 数据就用首页待办的接口，不要"待我审核"那组（审核不是预警）；权限、数据范围、"全部 / 我负责的"和首页一样，所以两边的数永远对得上。
- 呆滞料的数也进来（§3.3）。

**没定的，按默认做**：呆滞天数 90；及时率、次品率的标色线；毛利按核价估；价格打分不做。甲方试用后给了样表再调列和口径。

## 4. 手机审批和钉钉推送（Q65，V64，已实现 11-27）

甲方答：用钉钉；推"单据被驳回""货期预警"两种（"轮到我审"没选，不推）；手机上点开消息要能直接审。

### 4.1 怎么发

- 钉钉"企业内部应用"的工作通知（`asyncsend_v2`，卡片下面一个"打开"按钮）。三个参数 AppKey、AppSecret、AgentId 放部署配置（`.env` 的 `SCM_DINGTALK_*`），不进库、不进页面；三个都有才发，没配时什么都不入队。试用环境不配，所以试用期间不发消息。
- 收件人按用户档案上的**手机号**去钉钉查 userid（`getbymobile`，要开"根据手机号获取成员基本信息"权限），查到记在 `sys_user.dingtalk_user_id`，手机号改了重新查。不另建"钉钉账号绑定"页：甲方的人都在钉钉里，手机号一样就行。
- 发送走 V32 的后台任务队列 `sys_outbox`（`kind = DINGTALK_MESSAGE`）：驳回和入队在同一个事务里（驳回回滚了消息也没有），后台 worker 去发，网络问题、钉钉报错按队列的规则重试（30 秒起翻倍，5 次后进死信）；没配置、找不到收件人不重试，直接进死信。同一件事只入队一次（去重键）。
  - 为什么不照架构 §14.3 另建 `biz_outbox`：钉钉消息只是通知，不需要外部单号映射、回执；`sys_outbox` 已经有同事务入队、租约、退避重试、死信、去重。`biz_outbox` 留给三期往聚水潭推单据。
  - 发送放在 worker 线程（和库存日志导出共用两个名额），不卡每秒一轮的缓存失效。
  - 钉钉同一天给同一个人内容一样的消息只送一条，所以驳回消息里带驳回时间，同一张单一天驳回两次也都收到。
- `scm.public-url`（`SCM_PUBLIC_URL`）是用户打开系统的地址，"打开"按钮用它拼链接；没配时消息照发，不带按钮。
- 发完、发不出去的消息留 90 天（`SessionHousekeeping` 清）。

### 4.2 推什么

- **单据被驳回**：在写操作记录的地方（`DocLogServiceImpl`）看到 `reject`、`change-reject` 就发，所以所有能驳回的单据都覆盖了：需求订单、订单变更单、采购单、外发加工单、成品采购单、盘点单、供应商准入和资料改动。发给这张单最近一次"提交"的人（`change-reject` 是最近一次提改动的人）；自己驳回自己的不发。内容：单号、驳回的人和时间、原因，"打开"到手机待办的这张单。
- **货期预警**：每天早上 8:30 以后一人一条（`DueWarningTask`，挂在后台任务每分钟一轮的定时清理上，整个部署只一个实例在跑；去重键"人 + 日期"，重启了也不多发）。跟单员：他跟的生产单逾期几张、7 天内到期几张、节点延期几张；采购员：他的采购单到料逾期几行。口径和首页待办、预警中心一样。全是 0 的人不发。"打开"到手机待办的"预警"页签。
- 管理后台 › 系统管理 › 消息推送（只给超级管理员）：钉钉配好没有、两种消息各自开关（`sys_config` 的 `notify.events`，默认两种都开）、给自己发一条测试消息（当场发，不通的报钉钉的原话）、最近的消息和没发出去的原因、重发。

### 4.3 手机待办

- 单独成页（和手机报工一样用 `MobileLayout`，没有侧边栏、页签），地址 `/mobile-todo`，在侧边栏"报表"里，给各业务岗位（和预警中心一样）。手机上登录：有手机报工的进手机报工，没有的进手机待办。钉钉应用的移动端首页也填它（部署手册第 11 节）。
- 两个页签：**待我审核**（首页待办的"待我审核"那组）、**预警**（首页待办里预警类的几组和数）。数据就是首页待办接口，权限、数据范围一样。
- 点一张单进 `/mobile-todo/:id?type=…`：要点（谁、多少、交期、金额）、明细摘要、审批进度，底下"驳回""审核通过"。能在手机上审的四种：需求订单（要填承诺交期）、采购单、生产单（外发加工、成品采购）、订单变更单。能不能审照各自详情接口的 `actions`（后端按状态、权限、轮没轮到我算好），审核、驳回也走各自原来的接口，所以和电脑上一样的校验、一样的多级审批。
- 别的种类（资料包、出入库、盘点、供应商准入）提示"要在电脑上处理"，给电脑版的链接。需求订单的评审信息（资料包、缺料、产能）只在电脑上看，手机上审后端照样校验。

**没定的，按默认做**：发送时间 8:30；临期 7 天；钉钉的应用由甲方的钉钉管理员建，参数交给部署方填。

## 5. 供应商对账（Q68，V65，已实现 11-27）

甲方答：现在理单用 Excel 跟供应商、加工厂对账；先做"按月拉出这家的入库、回货、扣款，生成对账单，双方确认"和"上传工厂的对账单，自动比对"。工厂发来的有手写照片、Excel、PDF；识别用第三方服务（按页收费）。用不用财务软件没答。

这一版做：对账单、扣款登记、导出对账单发给对方、上传对方的 **Excel** 对账单自动比对。侧边栏加"对账结算"目录（PRD §2.5 和原型的叫法），两页：供应商对账、扣款登记（V65）。照片和 PDF 要第三方识别服务的账号，等甲方开通（§5.4），付款计划、发票、单款毛利甲方没选，不做。

### 5.1 对账单

- 一张对账单 = 一个**主体** × 一家**供应商或加工厂** × 一段**期间**（默认上个月 1 号到月底，能改）。主体分开对（各自付各自的款，和单据的主体一致）。
- 生成时把这段时间里这家**还没进对账单**的拉进来，一行一条：
  - **采购入库**（已审核的物料入库单，类型采购入库）：一行一条入库明细，数量、单价按**采购单位**（供应商按采购单位开单），金额就是入库时算好的金额。
  - **采购退货**：一行一条明细，数量、金额记负数。
  - **回货**（已登记的回货单，生产单的加工厂是这家）：一张回货单一行，数量是件数（含次品），单价取生产单的单价（外发加工单是加工费，成品采购单是成品价），次品按单价扣（扣款列），所以实付 = 良品 × 单价。
  - **扣款**（§5.2 登记的）：一行一条，记在扣款列。
  - 日期分别按入库日期、回货日期、扣款日期算进哪个期间。没有单价的入库（采购单没填单价）金额是 0，行上标"缺单价"。
- 合计：货款 = 各行金额之和（退货是负的），扣款 = 各行扣款之和，**实付 = 货款 − 扣款**，都存在单头，明细变了重算。
- 状态：草稿 →（发送）已发送 →（确认）已确认；已发送能撤回到草稿；**只有草稿能作废**（作废后里面的单据、扣款回到"待对账"）。已确认的不能改、不能作废：差错和原型一样另开单冲回（入多了开采购退货、少扣了登记扣款），进下个月的对账单。"已付款"留着，付款计划做的时候再用。
- 草稿能：**刷新**（这段时间里后来审核的单据加进来）、**移出**某几行（比如供应商说那张算下个月，移出后回到"待对账"）、**加一笔扣款**（登记一条扣款并加进来）。
- **一条入库明细、一张回货单、一条扣款只能进一张没作废的对账单**：`stl_statement_item` 上的唯一索引 `(source_type, COALESCE(source_item_id, source_id)) WHERE active` 兜底，两个人同时生成也不会重复。"已对账"不在源单上另加列（数据库设计 §19 原来想加 `settled_qty`），从对账单明细查，一个地方说了算；也不做部分对账（一条明细要么整条进、要么不进）。
- 进了没作废的对账单的入库单不能反审核、回货单不能作废（1005，列出对账单；走 `ReferrerProvider`，回货单原来就查、入库单的反审核这次加上）。要改先把对账单作废或移出那几行。
- **导出**：对账单导成 Excel（类型、日期、单号、送货单号、摘要、单位、数量、单价、金额、扣款，最后一行合计），发给对方核对。导出的文件原样传回来也能比对。
- 列表页两块：**对账单**（筛状态、主体、供应商、期间）和**待对账**（按主体 × 供应商 × 月份列出还没对的单据数和金额，点"生成对账单"）。
- 权限：`settle:statement:list` 看，`settle:statement:edit` 生成、刷新、移出、发送、撤回、作废、比对，`settle:statement:confirm` 确认。给理单、财务、总经理；生产经理只看。对账单、扣款上的金额跟着对账权限走（`FieldPermissions.SETTLE`），不再看"成本、加工价"的字段权限：对账就是对钱。所以对账单不给跟单（上面有物料采购价，跟单本来看不到）；采购是"本人"范围又不能生成，给了也是空表，也不给（V66 收回了 V65 多给的这两处）。数据范围：对账单按制单人（理单是"本人"）；"待对账"和生成按供应商拉，不按入库单、回货单的制单人限（对账就是对整家的账），能对账的人都看得到。
- 品类线（RFC 013 §2，agy 复查 T-adeaba 补的）：对账单是整家的账，里面有这家各条线的单价，所以**这家做的品类线我都能看**，才能在待对账里看到它、生成、看对账单（列表、详情、导出）；只看得到其中几条的，生成时报 1000 说"还做鞋类，要找能看它全部品类线的人来生成"，已有的对账单当不存在（404）。回货只拉生产单在我的线里的（供应商后来去掉了某条线，那条线的旧单留给能看的人）。扣款登记和供应商一样，这家的线里有我能看的就行。

### 5.2 扣款登记

- 延期、质量问题这类要扣的钱，平时发生了就登记：主体、供应商或加工厂、日期、金额、原因、相关单号（选填，写字就行）。月底生成对账单时按日期拉进来。
- 回货的次品不用登记，生成时自动按单价扣（§5.1）。超耗不扣钱（甲方答 Q55）。
- 进了没作废的对账单的扣款不能改、不能删；对账单作废或移出后又能改。
- 在对账单上加扣款不写日期的，取期间止；当月的对账单期间止还没到，取今天（扣款日期都不能晚于今天）。
- 权限：`settle:deduction:list` 看，`settle:deduction:edit` 登记、改、删；看给理单、财务、总经理、生产经理、跟单，改给理单、财务、总经理、跟单（跟单是"本人"范围，看自己登记的）。

### 5.3 上传对方的对账单比对（Excel）

- 在对账单（草稿或已发送）上传对方的 Excel（.xls、.xlsx）。系统找表头：一行里有"金额"类的列（金额、小计、货款、总额、应付），再有单号、日期、品名、数量里的一个，就当表头；各列按常见叫法认（单号认"送货单号""出库单号""单据号""单号"，日期认"送货日期""日期"……），认不出表头报 1000 并说要哪几列。合计、小计、实付、应付、余额这类行跳过（我方导出的文件最后两行就是合计、实付）；有"扣款"类的列，或摘要里有扣款、扣除、罚款、索赔这类词的行算扣款（不认单独一个"扣"字，"纽扣"不算）；摘要里有退货、退回的，金额记负数。
- 两边都按**单据**合起来比（对方一张送货单写好几行、我方一张入库单好几行都没关系）：
  1. 对方的单号 = 我方的单号、入库单上的供应商送货单号，或只对得上一张的采购单号、生产单号；
  2. 对不上的，日期前后 3 天内、数量一样的；
  3. 再对不上的，日期前后 3 天内、金额一样的。
  每一处给结果：**一致** / **数量或金额不一致** / **对方有我方没有** / **我方有对方没有**；扣款合起来比一行。差 0.01 元以内算一致。
  对方单号写的是我方的采购单号、生产单号（一张订单分几次送货）时，按单号 + 日期分开比，几次送货各自对上各自的入库单。
- 读表的细节（agy 复查 T-adeaba 补的）：合计写在单号列、或者单号旁边写着"小计"的行也跳过；单号、日期、品名纵向合并的格子，取合并区第一行的值（金额、数量不取，免得重复算钱）；"扣款原因""扣款说明"当备注，"扣款金额"才是扣款；英文"No."（多半是序号）、"客户编号"不当单号，单号、送货单号都有时取左边先写了的；金额写了负数、数量还是正数的退货，数量也记负；没写年份的日期（"1-2"）取离对账期间最近的一年（12 月的账里是下一年）；有单号、有数量、金额是 0 的行（我方导出的"缺单价"）也读；金额按分四舍五入。
- 结果、对方的合计存在对账单上（`compare_result`、`their_amount`），原件存成对账单的附件。不一致的每处写一句说明（和对方谈的结果）；**有比对结果时，每处差异都写了说明才能确认**。明细变了（刷新、移出、加扣款）比对结果清掉，要重新上传。
- 不自动改我方的数：差错按 §5.1 另开单冲回，或者在草稿上移出、加扣款以后重新比。

### 5.4 照片、PDF 识别（没做，等第三方账号）

甲方选了第三方识别服务。做的时候：识别结果（表格）转成和 Excel 一样的行，走同一个比对（§5.3），识别任务、原值、人改过的地方记在数据库设计 §19.2 的 `stl_ocr_*` 表；手写的先拿样张试识别率。要甲方开通账号、同意对账单发给服务商。

**没定的，按默认做**：期间默认整月；回货次品按单价全扣（合同条款里"次品率超过 3% 的部分才扣"这种按条款算的，甲方给了规则再做，现在不一样的用扣款登记补）；对账单不分含税不含税，金额就是单据上的金额；按 0.01 元以内算一致。

## 6. 质量记录（Q53，V68，已实现 11-27）

甲方 11-27 答 Q53：质量管理要做（来料检验、产前样确认、中检尾检、质量扣款），先做哪个没说；**质检流程甲方没给**（PRD M09 写的是"甲方定质检流程"）。所以这一版照原型的"生产 › 质检"做"**记下来**"：每次检验记一条，不走审核；回货不合格能安排返修、返修回来再验；要扣钱的直接接到扣款登记（§5.2），月底进对账单。甲方试用后给了流程（谁检、抽多少、不合格怎么走），再加审核、返修单这些。接口和页面见 `docs/api/10-质量.md`。

### 6.1 质检记录

- 一条记录 = 一次检验，单号 `ZJ` + 日期 + 4 位流水（`BizType.QC_INSPECTION`；原型写的 QC，和别的单号一样用拼音首字母）。四种，来源不一样：
  - **来料检验**：对一张**已审核的采购入库单**，一张只验一次（部分唯一索引）。批量是采购数量合计（几种单位混在一起时不合计）。
  - **尾期验货**：对一张**已审核的回货单**（原型的位置：验的是每批回货，不是整张生产单），可以返修后再验。
  - **产前样确认**、**中检**：对一张生产单（外发加工单、成品采购单，已审核、生产中、已完成的），可以记多次；产前样的结论只有通过 / 不通过。
- 填：检验日期、抽检数（默认 AQL 2.5 一般检验水平 II 的建议，和原型一样；产前样可以不填）、不合格数（超过允收数结论自动变不合格）、结论（**合格 / 让步接收 / 不合格**）、问题类型（字典 `qc_defect_type`，多选：色差、尺寸、做工、污渍、破损、面料瑕疵、辅料、包装、其他，管理员能加）、问题（不是合格的必填）、照片、质量扣款。检验人是记的人。主体、供应商、品类线、货品、批量跟着来源单（快照）。
- 保存就算数，不审核；能改、能删（安排了返修的结论不能改、记录不能删；扣款进了对账单的不能删）。源单反审核、作废不受质检记录拦（质检记录不算"下游单据"）。
- 页面在"生产"目录下（`/qc`，原型的位置），四个页签：待检、不合格和返修、质检记录、供应商质量。**待检**列最近 30 天审核过的采购入库、登记的回货还没验的，加上返修完成等再验的回货：没人验的旧单不一直挂着，首页"其他提醒"也不会越积越多。页头「记产前样、中检」在对话框里选生产单。
- 权限：`quality:inspection:list` 看，`quality:inspection:edit` 验货、改、删、返修。跟单、仓管、生产经理、理单、总经理验货；财务、采购看。**不按检验人分范围**：仓管记的来料检验跟单、理单都要看，质检本身也不涉及价格（扣款金额照 §6.2 另管）。品类线按生产单过滤，来料检验不分线。

### 6.2 质量扣款

- 结论不是合格、填了扣款金额：同一个事务里登记一笔扣款（主体、供应商取记录的，日期是检验日期，原因"质检 ZJ…：尾期验货不合格，问题"，相关单号是质检单号），月底按日期进对账单。
- 改记录的金额、日期同步改那笔扣款，去掉金额就删扣款，删记录扣款一起删；**扣款进了没作废的对账单，金额、日期就不能动、记录不能删**（1000，和 §5.2 一样）；只改了问题的，扣款的原因不动（对账单上已经抄过去了）。
- 扣款登记页上这笔标"质检 ZJ…"，不给改、删（"到质检改"）：`stl_deduction` 加 `source_type`、`source_id` 记是哪条质检登记的，扣款登记的改、删接口回 1000；质检记录用 `deduction_id` 外键指回去。
- 记扣款要 `settle:deduction:edit`，金额跟着 `settle:deduction:list` 显示（`FieldPermissions.SETTLE_DEDUCTION`，和扣款登记一样）。仓管能记不合格，扣不扣钱由理单、跟单在记录上补；没有扣款权限的人改有扣款的记录，金额不动，只跟着改日期、原因。

### 6.3 返修、供应商质量

- **回货的质检状态由记录推出来**，回货单上不加列（数据库设计 §17.3 原来想加 `qc_status`）：没验 → 待检；最近一次合格、让步接收 → 验完了；不合格 → 「返修」（写返修说明：返修什么、多少件、哪天送回）→ 返修中 → 「返修完成」→ 待检，再验第 2 次，前面的记录留着。再验一次要先返修完成，所以前面几次都是"不合格、返修完成"，改哪条都推不乱状态。
- 不单独做返修单，返修记在那次验货记录上（原型就是这样）。来料不合格要退的，照常开采购退货。
- **供应商质量**页签按家统计（默认最近 90 天）：检验次数、合格率、不合格、让步接收、抽检不良率、常见问题（问题类型前 3）、质量扣款，不合格多的在前。回货的次品率在 报表 › 供应商绩效（§3.1）。
- 首页"其他提醒"、预警中心加两个数：待检的回货和来料、回货验货不合格待安排返修（有验货权限的人才有）。

**没定的，按默认做**：不审核、保存就算数；不分数据范围；照片选填（原型要求不合格必须拍，电脑上记的不一定有照片）；产前样不通过不拦生产单；**回货没验也能入成品仓**（原型画的是合格、让步接收以后才能入，流程没定前先不拦，拦了没人验货时入库就卡住）；返修不单独开单；供应商绩效报表先不加质检的数；待检只列最近 30 天的。

## 7. 工厂账号（Q02，V69，已实现 11-27）

甲方 11-27 答 Q02：要给加工厂开账号，工厂在系统里填实裁数量、报进度；暂定三家，手机、电脑都用。这一版只做这两样，接单、对账、预约送货以后再问。

### 7.1 账号

- 工厂账号 = `sys_user` 加一列 `partner_id`（外键到 `sup_supplier`）：空的是内部账号。管理后台 › 用户管理新增时选"工厂账号"、选哪家厂：只列合作中的成衣厂、加工厂（分类 GARMENT、PROCESSOR）。一家可以开几个（车间主任、厂里跟单各一个）。
- 工厂账号不分角色，没有品类线、部门、岗位、设计师编号、默认主体。建了以后**不能在内部、工厂之间互转，也不能换厂**（原来那家知道密码；换厂另建一个，旧的停用）。删工厂账号时清掉 `partner_id`，不然逻辑删除的账号一直引用着那家，供应商删不掉。
- 选人下拉、审批人、按昵称找人都不列工厂账号。
- 第一次登录照常先改初始密码（RFC 018 §2）；停用、删除、重置密码和内部账号一样。

### 7.2 能做什么

- 登录后只有"报工"这一页（`/mobile`，就是跟单员的手机报工；电脑上也是这一页，居中、最宽 560px），别的地址都回这里；顶上能改密码、退出。
- 列表：本厂已下单、生产中的外发加工单、成品采购单，按风险排（`GET /api/factory-orders`）。
- 点进一张单：款、件数、交期、跟单是谁、节点、颜色尺码明细；**不给单价、金额、需求订单、审批、条款、异常**（`GET /api/factory-orders/{id}`）。工厂用的 VO 单独写、字段一个个挑，内部详情以后加字段不会顺带给到工厂。已完成、已结案的单还能打开看（旧链接），不能报。
- 报进度：点节点报开始、报完成，和跟单员同一个接口，操作记录记的是工厂账号。
- 登记实裁数：按颜色尺码一行一个数，和电脑上"登记裁床数"同一个接口、同一套上下限（件数的 105%、不少于已回良品）。工厂账号另有两条：不能填 0（0 和空都当"没登记"）；登记后单子会变成"已完成"的不让登（外面的人一填，单和需求订单就都完了，填错了已完成的单改不回来），裁少了由跟单在电脑上登记。跟单员的手机报工也加了这个入口，裁剪节点的提示从"到电脑上登记"改成直接点。

### 7.3 怎么拦

- **后端默认拒绝**：工厂账号的权限只有一个内部标记 `scope:FACTORY:<厂 id>`（`CallerScope`；`scope:` 开头的权限码管理员在菜单管理里配不出来）。`FactoryScopeInterceptor` 只放标了 `@FactoryAccess` 的接口：登录、刷新、`me`、退出、改密码、版本、上传图片、本厂生产单的列表和详情、报进度、看报进度记录、登记裁床数；别的一律 403，包括"登录就能调"的选人、字典、首页、快捷跳转。以后新加的接口不标就自动挡住。
- **单子归不归这家**：`ProductionSupport.visible` 先看是不是工厂账号，是就只认 `factory_id` 是本厂、状态是已下单 / 生产中 / 已完成 / 已结案的，别的当不存在（404），不走品类线和数据范围。写操作照旧要带对的主体头。
- 上传和照片：工厂账号 `POST /api/files` 只收图片（10MB 以内）；报工照片只能挂自己刚传的（`sys_upload_file.owner_user_id` 是自己），不能把见过的别的 `/files` 地址挂上来续签。
- 不给工厂的字段在后端清掉：风险里的"有异常""订单有变更"、明细的订单行 id；列表按清掉以后的风险重排。钉钉推送不发给工厂账号。
- 弱网报工后核对提交结果的 `GET /api/http-actions/{key}` 也放给工厂（只查自己的）。
- 以上几条是 agy 审查（T-6c00a7）后补的。`FactoryAccountIT` 走真 HTTP：把路由表里每个没标的接口用工厂账号调一遍，全部 403；本厂的单能看、能报、能登记，别家的 404；内部详情 403；内部账号调工厂的接口 403。

**没定的，按默认做**：工厂不上报异常、看不到异常（还是跟单员报）；看不到单价；供应商停用、拉黑了不自动停账号，管理员手动停用；手机、电脑同一页，没有工厂自己的首页和消息提醒；一家开几个账号不限。原型的"跟单员 / 工厂"切换没跟着改。
