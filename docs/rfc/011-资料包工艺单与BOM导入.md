# RFC 011 资料包：工艺单改成上传文件、物料清单从 Excel 导入

状态：**已定**（11-18 用户说"先推进"，§10 四条照默认做；同日实现）。11-18 晚甲方答了 Q47–Q50，改了几处，见 §11；工艺单识别、导出 PDF 回来（Q47）另写 RFC 012。

对应：PRD §6.4（11-18 改，v0.23）、§10、Q37、Q43；架构 §4.9、§8；数据库设计 §9、附录 B；接口 `docs/api/01-资料包.md`。

## 1. 解决什么

用户 11-18 定的（PRD v0.23）：

1. **工艺单就是甲方现在用的 Excel**：上传一份挂到资料包上，系统不读里面的内容，要用时下载、预览。领猫里也是这样挂的：一份工艺单 Excel，几份纸样文件（`.prj`）。
2. **尺寸指示、导出 PDF 去掉**：尺寸表本来就在工艺单 Excel 里；发工厂就发上传的工艺单。
3. **工序工价改成一个加工费**：甲方的 BOM 表里加工费就是一个数。
4. **物料清单能从甲方的 BOM 表导入**：上传后系统认出每一行，认不出的当场挑物料或新建；导入不了的照样手工填。
5. **花名不管**（Q43）：系统里的用户都用花名当名字，工艺单表头由甲方自己的 Excel 写，系统不生成表头。

改完以后资料包三个页签：**物料清单、工艺单、核价**。版本、草稿、生效、修订、需求订单锁版本这些都不变（PRD §6.4.1）。

不做：

- 读工艺单 Excel 里的内容（尺寸、工艺文字）进系统。
- 一个 Excel 一次导很多款：一次导一个款，在这个款的资料包里导（§4.5）。
- 纸样文件预览：`.prj` 是打版软件的格式，只能下载。

## 2. 工艺单页签

### 2.1 挂什么

一个资料包版本挂几份文件，分三组：

| 组 | 能传什么 | 预览 |
|---|---|---|
| 工艺单 | xls、xlsx、pdf、jpg、jpeg、png、webp | Excel 在页面里看（§2.3），图片在新标签里看；PDF 下载 |
| 纸样和其他 | 上面那些，再加 prj | 同上；prj 只能下载 |
| 导入的 BOM 表 | xls、xlsx（导入时自动加，不能传） | 同上 |

- 一组最多 20 个。草稿能传、删、上移下移排顺序；已生效、已作废的只读。改工艺单 = 修订出新版本，和改物料清单一样。
- 修订时文件跟着带到新版本：复制附件记录，文件本身不复制（架构 §8，没人引用的文件由定时任务清掉）。
- 生效不要求有工艺单。没有工艺单时点"生效"，页面问一句"还没有工艺单，发工厂时没有文件可发。还是生效吗？"。
- 导入物料清单时用的 BOM 表也留一份在这个版本上（第三组"导入的 BOM 表"，§4.4），以后对得上是从哪份表导的。草稿里能删，不能传；没有就不出这一组。

### 2.2 文件类型和大小

- `prj` 加进允许的类型。它没有固定的文件头，查不了内容，只按扩展名收；Nginx 对所有不是图片的上传文件都按"下载"发（`Content-Disposition: attachment`，CSP `sandbox`），浏览器不会打开它。
- 大小：工艺单组照现在的规矩（Excel、PDF、图片 10MB）；`prj` 最大 100MB，和 AI、PSD 一样。
- 甲方还用别的打版格式（如 `dxf`、`plt`）时再加。

### 2.3 Excel 预览

后端用 POI（已经在用）把 xls、xlsx 读成表格数据，前端画成表：

- 每个 sheet 一个页签；保留合并单元格、列宽、行高、粗体、字号、字色、底色、对齐、自动换行、细边框。
- 公式取 Excel 存下的计算结果，不在服务器上算。
- 嵌在表里的图片（款式图、工艺图）按位置显示。
- 上限：20 个 sheet、每个 sheet 500 行 × 60 列、图片合计 10MB；超出的部分不画，表下面写"后面还有 N 行，下载看全部"。
- 返回的是数据，不是 HTML：单元格文字一律当文本画，不会执行表里的任何东西。

### 2.4 发工厂

- 导出 PDF 去掉。外发加工单、成品采购单详情"更多"里的"导出工艺单"改成"工艺单"：列出锁定版本的工艺单、纸样文件（导入的 BOM 表不列），Excel 能预览，都能下载。打印生产单只打这张单。
- 手机上点下载以后，用系统的分享面板发微信（PRD §6.4.4 规则 3）。

## 4. 物料清单从 Excel 导入

### 4.1 认哪种表

甲方现在的 BOM 明细表（11-18 给了两份，格式一样）。一个款一张 sheet：

- 第 1 行：款号、款名（中间几个空格）。
- 面料块：表头一行，下面"A 料""B 料"几行，再一行"小计"。
- 辅料块：又一行表头，下面按序号一行一种辅料，再一行合计。
- 汇总块：材料成本（面料、辅料&耗材）、制造成本（加工费）、面料运费、成本合计。

表头的列：项目、（类别）、物料名称、规格、色号/颜色、价格/含税、单位、单件用量、损耗、总单耗、预估价、工厂、备注。

**按表头的字认列，不按第几列认**：哪一行有"物料名称"和"单件用量"就是表头，列的位置挪了、中间插了列都认得出。认不出表头的 sheet 在下拉里标"不是 BOM 表"。

### 4.2 每一列怎么落

基本照数据库设计附录 B.2，下面是导入时具体怎么做：

| 表里的列 | 怎么认 | 认不出时 |
|---|---|---|
| 物料名称 + 规格 | 在没停用的物料里按名称找：只有一个就是它；有几个同名的，用规格去对 SKU 的规格 | "没找到物料"：挑一个，或按这一行新建 |
| 色号/颜色 | "/""-"、空：固定，用物料唯一的 SKU（或不带颜色的那个）。一个颜色：固定，用这个颜色的 SKU。几个颜色（顿号、斜杠、逗号分开）或写"顺色"：随款色，款式每个颜色配同色的 SKU | 哪个颜色找不到 SKU 就标出来，在格子里挑 |
| 价格/含税 | 参考单价（元 / 用量单位）。和价格档案的现价不一样时旁边写"档案 x.xx"，导进去的还是表里的价 | 空：按现在的规矩带档案价 |
| 单位 | 要等于物料的库存单位。表里是厘米、物料是米：用量 ÷ 100、单价 × 100，标"换算过" | 别的不一样：标出来，导入前要改 |
| 单件用量 | 统一用量 | 不是数：标出来 |
| 损耗 | 和物料导入同一个判断（Q31，`MaterialImport.factorColumn`）：整列不是 0 的数都在 1 到 2 之间（含 1、不含 2）、至少一个大于 1，就是系数，1.03 换成 3%；否则整列按百分数 | 按百分数算、但这一格在 1 到 2 之间：标"要看一下" |
| 工厂 | 按供应商简称、全称找 | 空或找不到：用物料的默认供应商，标"表里写的是 xx" |
| 备注 | "含税运"→ 含税、含运；"含运不含税"→ 不含税、含运；别的字进 BOM 行备注 | — |
| 项目、类别 | 部位：A 料 → 大身，B 料 → 里布，辅料 → 物料名称在部位字典里有就用它 | 部位空着，挑 |
| 总单耗、预估价、小计、合计 | 不导，系统自己算 | — |
| 汇总块的加工费 | 资料包的加工费（§3.1） | — |
| 汇总块的面料运费 | 核价的其他费用加一行"面料运费" | 空就不加 |

### 4.3 页面

1. 物料清单页签（草稿）点"从 BOM 表导入"，选文件（xls、xlsx，10MB 以内）。
2. 有几张 sheet 时，按第 1 行的款号对上现在这个款，对不上再按款名对；都对不上就选第一张能认的，下拉里能换。
3. 出一张预览表，每行一个状态：
   - **认出来了**：直接能导；
   - **要看一下**：能导，但有提示（换算过单位、价格和档案不一样、供应商用了默认的、部位没认出……）；
   - **没认出来**：要先处理：从物料库挑，或者这行不导（11-18 晚甲方答 Q49：导入不新建物料，§11）。挑了以后带上 `picks` 再解析一次，物料没变的行留着人改过的值。
4. 预览表上部位、用量、损耗、单价（有看成本权限才有）能直接改；来源、供应商、配色加进去以后在物料清单里改。
5. 点"加进物料清单"：物料清单是空的就直接放进去；已经有行时问"替换现有 n 行"还是"加在后面"。加工费、面料运费一起填到核价。
6. 这时只是改了页面上的草稿，和手工填的一样，点"保存"才存（整版保存，版本号防并发照旧）。保存时导入的 BOM 表作为附件一起存上。

导不了的（不是这个格式、一行都认不出）：提示"认不出这张表，物料清单照常手工填"，什么都不改。

没有"看成本"权限的人也能导：预览里不出单价、加工费、面料运费，这几样不导；新加的行保存时照常带档案价（和他手工加行一样，`PackFinancialAccess`）。

### 4.4 接口只读

`POST /api/tech-packs/{id}/bom-import` 只解析、不写库，返回 sheet 列表和每一行认出来的结果；写库走原来的保存草稿。

这样做是因为导进来的东西要人看过、改过才算数，只有一条写入的路，版本号、生效前检查、字段权限都不用另写一套。

### 4.5 以后可以加

- 一个 Excel 一次导很多款：按每张 sheet 的款号找款式，给每个款建草稿。甲方迁老款的 BOM 时有用，到时候再看要不要（Q03 要迁的是样衣、款式、物料、供应商，没有 BOM）。
- 从资料包导出成同样格式的 BOM 表。

## 5. 表结构（V39）

```sql
ALTER TABLE tp_tech_pack ADD COLUMN labor_price NUMERIC(14,4);   -- 加工费，元/件，按外发算时用
ALTER TABLE tp_tech_pack DROP COLUMN packing_mode;

DROP TABLE tp_process_image;
DROP TABLE tp_process;
DROP TABLE tp_craft_section;
DROP TABLE tp_spec_value;
DROP TABLE tp_spec_point;

-- 工艺指示插图、工艺标准文件的附件记录（文件由定时任务按"没人引用"清掉）
DELETE FROM biz_attachment WHERE doc_type = 'TECH_PACK' AND category NOT IN ('CRAFT_SHEET', 'PATTERN', 'BOM_SOURCE');
DELETE FROM biz_attachment WHERE doc_type = 'CRAFT_STANDARD';
DELETE FROM sys_config WHERE config_key LIKE 'techpack.%';
-- 工艺标准的菜单和按钮（V18 藏起来的那个），连同角色授权
```

资料包的文件挂 `biz_attachment`：`doc_type = TECH_PACK`、`doc_id` = 资料包 id，`category` 三种：`CRAFT_SHEET` 工艺单、`PATTERN` 纸样和其他、`BOM_SOURCE` 导入的 BOM 表。

迁移以实现为准；数据库设计 §9、附录 B 跟着改。

## 8. 取舍

- **预览在后端读、前端画**：浏览器端的 SheetJS，npm 上的版本停在有漏洞的 0.18，新版本只在它自己的网站上，社区版也不带样式和图片；LibreOffice 转 PDF 最像原样，但镜像要大几百 MB，还要管一个进程。POI 已经在用，读 xls、xlsx 都行，返回数据比返回 HTML 安全。
- **文件挂在版本上，不挂在款式上**：需求订单锁的是版本，工厂拿到的工艺单要和锁的物料清单对得上；改工艺单就修订，和改物料清单一个规矩。
- **导入只解析不写库**：见 §4.4。
- **按名称认物料**：甲方的 BOM 表里没有物料编码，只有名称、规格、颜色。同名的用规格区分，再不行让人挑。
- **按表头认列**：两份表的列一样，但甲方整理时插一列、挪一列很常见，按字认更经得住。

## 9. 测试点

- 解析（单测，测试里现造一个同样格式的 xls 和 xlsx，不用甲方的原件）：面料块、辅料块都认；损耗 1.03 → 3%；"含税运"→ 两个标记；"/"→ 固定；三个颜色 → 随款色；厘米 → 米换算；没有的物料 → 没认出来；汇总块的加工费、面料运费；列挪了位置照样认；不是 BOM 的 sheet 标出来。
- 选 sheet：按款号对上；款号对不上按款名；指定 `sheet` 时用指定的。
- 预览：合并单元格、公式取存下的值、xls 和 xlsx 都行、超过上限截断、坏文件 400。
- 文件：草稿能存、生效后改不了；修订带过去；`prj` 能传、下载时是附件；没有看的权限 403。
- 加工费：默认取清加工、再取半包；没有看成本权限的人看不到、改不了；按款看成本、排单用的都是它。
- 没有看成本权限的人导入：返回里没有单价、加工费、面料运费；保存后新行是档案价。
- V39：删的表和菜单都没了，`SchemaConventionsIT` 跟着改。
- 浏览器：导入一张表 → 处理没认出来的行 → 加进物料清单 → 保存 → 生效；工艺单预览打开不报错。

## 10. 要用户定的

11-18 定了三件：尺寸指示去掉、导出 PDF 去掉、工序工价改成一个加工费（PRD v0.23）。剩下四条用户说"先推进"，照下面做了：

1. 认不出的物料能在导入对话框里当场新建（§4.3）。
2. 一次导一个款；一个 Excel 导很多款以后再说（§4.5）。
3. 默认加工费先取清加工、再取半包（§3.1）。
4. 打版文件先只收 `.prj`（§2.2）。

要问甲方的：除了 `.prj` 还用不用别的打版文件格式（Q48）；默认加工费先取清加工对不对（Q50）。
