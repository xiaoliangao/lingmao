# 研发打样 API

依据 `sample-completion-contract.md` 与 RFC007；HTTP/DTO 契约已由主控于 2026-11-22 冻结；生产源曾独立javac通过；完整Service/HTTP/并发/生产UI验收仍在进行，不能据此销项。基线 `03ba1acbe08893363d1078a82e1c73d2d988e46d` 加主控已验证 FG 增量、冻结公共标签各 stage。实施只写 sample-backend-stage，不覆盖此前 FG / tags stage。

## 1. 公共约定

- `Id = string`（十进制64位ID），`Money = string`（十进制定点，无指数格式），`DateOnly = string`（YYYY-MM-DD），时间戳为带时区 ISO 字符串。version/count/qty/业务版次是整数 JSON number。
- 样衣域所有 GET/动作/DELETE 要求 query `companyId`，且必须等于 `X-Company-Id`；POST 新建取 body.companyId 并要求同头。PUT 主档的 query.companyId 是原主体，body.companyId 是修改后的主体；只有从未派单且无研发资料包时可换，其他记录始终取真实父头主体。
- 所有写入口（包括图片、打样附件、节点）必须带规范 UUID `Idempotency-Key`。每端点独立 operation；完成重放重新校验当前权限、DataScope、真实公司，业务主体/状态不会再次执行。成功收据使用对象 DTO，禁止裸整数收据。
- 已存在打样单的写 DTO：`version` = 子单 CAS；`sampleVersionLock` = 父样衣 CAS。`SampleOrder.sampleVersion` 始终是业务版次。主档 PUT/图片/删除/stop/reopen/convert 的 `version` = 父 CAS，当前子版本由已锁的服务器记录决定。
- 不接收 tenant/status/currentVersion/convertedStyleId/auditBy/服务端金额合计等实体字段。未知字段整请求 400。范围外或对象不存在 404，权限缺失 403，状态/版本冲突 1002，规则不允许 1000，下游引用阻止删除 1005。
- 所有读写权限前缀为 `dev:sample:`。SELF = 建档人或设计师或当前版版师；同时取实际公司交集。旧版只读。普通操作记录不插入价格明文。
- `estCost` 沿现有 `techpack:cost:query` 物理剥离；无权限提交改变成本返回403，缺失字段保留原值。公开 `estTagPrice` 不隐藏；未知金额保持 null。

## 4. 输入与动作规则

- 列表size默认20，最大100；关键字批量词≤100，样衣编码/任意打样单号精确匹配；单词查名称沿已有索引。categoryId在服务端展开真实子树，客户端不能传内部scope/categoryIds。
- 新建颜色1–100，尺码组实际尺寸1–100，组合≤10000；初版第一颜色+基码、qty=1，needDate由表单默认今天+10但必须提交真实日期。
- 主档颜色变化时，仅WAIT_ASSIGN当前版同步移除不存在颜色；若原选择全部被删，选新主档第一色（明确回显）。派单后的颜色快照不改。换尺码组仅首版未派单、无TP，选择重置新基码；有关子单变更同事务双CAS。
- 需要内部版师或外部工厂二选一；INTERNAL清空factoryId，EXTERNAL清空makerId，禁止把非选中的旧ID偷偷保留。新选人员启用、工厂需SAMPLE用途且成衣/加工分类。启用节点≤100、恰一SEND且最后。
- MAKING只允许改打样方式/人/工厂、needDate、requirement；其他提交字段必须与原版本一致，否则400，不静默忽略。改派更新未完成节点负责人但不重排计划，warning明确提示。
- SEND完成进入WAIT_REVIEW；前置漏报warning但不拒。节点计划PUT必须精确覆盖全部节点ID；NodeState为显示派生值，非可写状态。
- 评审意见按UTF-16长度校验（与Jakarta `@Size`、浏览器输入上限一致）：REVISE最多500，PASS/ELIMINATE最多1000。REVISE意见会完整作为新打样单原因，超过500先返回400，评审、版次、CAS、时间轴和幂等成功收据均不得部分写入。stop/reopen原因最多500，时间轴保留完整原因；评审时间轴仅记版次、结论与评审ID，完整意见在评审记录。
- reviewerIds原始1–100，去重后至少一人；日期不晚于今天；照片≤9。REVISE/ELIMINATE及stop/reopen原因必填。评审只能当前版WAIT_REVIEW；新版本+7天、REVISE类型，复制上一版要求/派单方和原尺码，但不复制节点和旧评审。选色在同一父锁下取旧版快照与当前主档颜色的交集；有移除时warning列出受影响色号/名称，全部失效则选当前主档第一色并明确warning。旧版快照不改；颜色未变化时完整复制。REVISE与reopen使用同一规则。
- 所有旧版附件/节点/评审只读。只允许首版WAIT_ASSIGN、无派单/节点/评审/TP/下游时删除；tombstone保留所有审计和历史身份。

## 5. 样衣资料包接口增量

`GET /api/tech-packs?sampleId=...&companyId=...&beforeVersion=&size=20`：样衣owner专用有界概况，`styleId`与`sampleId`必须二选一；原styleId调用契约保留。

返回现有 TechPackOverview 字段加 `sampleId:Id|null`、`companyId:Id|null`、`styleId:Id|null` 和样衣版本分页 `hasMore:boolean,nextBeforeVersion:number|null,total:number`。版本列表只取轻量头投影，不加载所有 owner_snapshot；概况成本只在授权后单独读当前有效版本，权限不足不返回价格字段。

`POST /api/tech-packs` 的新建DTO只允许styleId或sampleId一个owner；样衣必须stage=DEV并带companyId/header。资料包详情、保存、核价、PDF、图片、日志、附件、标签这些按 id 的现有入口只需显式 `X-Company-Id`，不新增 companyId query；先读轻量 OwnerIdentity、按真实样衣公司和 DataScope 鉴权、再核对 header（样衣 owner 缺头拒绝），随后才能读取快照。旧 style owner 共享语义不变。写入先样衣锁，再包锁，再核对owner未变化；owner已移交返回1002。旧款式owner路径保留。

SamplePackOwner由techpack定义、dev实现，不注入TechPackService。其公开返回包括真实companyId、父版本和PackOwner必要元数据；缺provider必须拒绝。所有版本移交先锁轻量Identity完整集合（≤50000），实际UPDATE数必须等于已锁数；组版本上限返回0映射1002整笔回滚。

## 6. 其他联动

- BizType加SAMPLE/YY、SAMPLE_ORDER/DY、SAMPLE_REVIEW；DocRef包含companyId。TECH_PACK仅未移交样衣owner时kind=SAMPLE,parentId=sampleId，公司取真实父头；转款后沿styleowner。
- Home在显式companyId存在且有dev:sample:list时追加真实MAKING数量；SAMPLE_REVIEW需review权限，普通DataScope，mine/owner按设计师；SAMPLE_LATE需当前节点负责人（与真实DataScope交集）。两组先SQL排序/LIMIT20，COUNT独立；不先全读后筛，不假零。
- SampleTagObjectProvider只在真实域存在后注册，读list、写edit+可编辑状态，真实公司/SELF，先锁样衣。未转样衣TP标签继承该owner可见性；移交后重新按style鉴权，并commit后失效旧/new对象epoch。
- 公共标签过滤、样衣八表公开DataLog guard、前端验收和云端门禁仍分别走负责人独立增量；不凭本接口草案签通过。

### 6.1 Home 精确增量（主控已冻结）

`GET /api/board/home/kpi?companyId=...` 的 companyId 可选；给定时必须匹配 `X-Company-Id`。不传主体则样衣数为 null，绝不扫描所有主体。

```ts
interface HomeDevKpi {
  styleCount: number | null
  packDraftCount: number | null
  sampleMakingCount: number | null
  companyId: Id | null
}
```

`HomeKpi.dev` 仍可整体 null。styleCount/packDraftCount 只在相应 style/techpack 列表权限下赋真实值，否则 null；有 dev:sample:list 且显式主体时 sampleMakingCount 为当前公司普通 DataScope 内 MAKING 单数。companyId 是样衣计数查询时快照，未查样衣时 null。没有权限的字段不显示入口，不能以 `?? 0` 显示假零。

`TodoGroup` 继续 `{key,total,items:TodoItem[]}`，新增 key `SAMPLE_REVIEW` / `SAMPLE_LATE`。对应 `TodoCount` 仍 `{key,count,companyId}`，这两个 key 的 companyId 必须为当前查询主体；每条 TodoItem.ref 为 SAMPLE 且携真实 companyId。SAMPLE_REVIEW 要 dev:sample:list+review，SAMPLE_LATE 要 dev:sample:list；普通 DataScope 与既有 mine/owner 收窄相交，OWNER分别设计师/当前未完成节点负责人。两组总数与数据库 LIMIT20 预览解耦。

### 主体迁移与一致读取补充

- `PUT /api/samples/{id}`：query `companyId` 和 `X-Company-Id` 必须均为原主体，body `companyId` 可以是经服务校验的新主体。只有该入口由服务端注解指定原主体参数位置，所有其他入口继续原body/header一致性规则。完整body（含新主体）始终参与幂等指纹。
- 主体迁移成功后，用原请求头/query和同key同body重放时，仍须重新检查当前编辑权限，以及样衣在收据新主体下的实际归属和SELF范围；再次迁移或失去可见性拒绝。不能因返回旧收据跳过当前授权，也不能把合法旧请求头改成新主体。
- SAMPLE及TECH_PACK的标签读取，在同一短REPEATABLE_READ事务内完成真实归属授权和Repository载荷读取；这两类对象不使用可能比授权快照更新的对象缓存。所有TECH_PACK（含已移交款式的包）保持同一路径，避免归属变更时分支混读；公共标签库options及其他对象缓存规则不变。
- 图片/附件元数据及新签发URL读取按当前owner授权；既有签名文件URL仍沿公共文件下载契约，不能将元数据拒绝等同于已签URL即时撤销。
