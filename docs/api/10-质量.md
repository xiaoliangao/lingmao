# 10 质量

质检：来料检验、产前样确认、中检、尾期验货，回货不合格返修，质量扣款，供应商质量（二期第一版，M09 的 09.01–09.06）。需求看 PRD §2.5 的 M09，设计看 RFC 019 §6（甲方 11-27 答 Q53），表看数据库设计 §17.3。

类型在 `web/src/types/quality.ts`，接口函数在 `web/src/api/quality.ts`（`qcApi`）。

## 1. 页面

### 1.1 菜单

在"生产"目录下（原型的位置），手机报工后面：

| 菜单 | 地址 | 页面文件 | 权限码 | 排 |
|---|---|---|---|---|
| 质检 | `/qc` | `views/quality/inspection/index.vue` | `quality:inspection:list` | 50 |

没有详情页，记录在列表里改。`docRoute` 不认 `QC_INSPECTION`（扣款登记上的"到质检改"直接去 `/qc?tab=records`）。

### 1.2 按钮权限码

| 权限码 | 管什么 |
|---|---|
| `quality:inspection:list` | 看待检、返修、质检记录、供应商质量 |
| `quality:inspection:edit` | 验货（记）、改、删、安排返修、返修完成 |

角色模板（V68）：跟单、仓管、生产经理、理单、总经理两个都给；财务、采购只看。**质量扣款**另要扣款登记的权限：填金额要 `settle:deduction:edit`，看金额（`deductAmount`）要 `settle:deduction:list`（`FieldPermissions.SETTLE_DEDUCTION`，和扣款登记一样）——仓管能记不合格，扣不扣钱由理单、跟单在记录上补。没有扣款登记权限的人改一条有扣款的记录，请求里的金额不看，原来的扣款只跟着改日期、原因。

数据范围：**不按检验人分**（仓管记的来料检验跟单、理单都要看）。品类线：来料检验不分线（物料出入库单不分），产前样、中检、尾期验货按生产单的品类线过滤，看不到的线当不存在（404）。

### 1.3 页面长什么样

页头「记产前样、中检」（对生产单记，对话框里选检验和生产单）。四个页签（`?tab=`）：

- **待检**（`pending`，默认）：最近 30 天审核过的采购入库、登记的回货还没验的，加上返修完成等再验的回货（标"第 n 次"，排最前）。来源单、类型、供应商、货品、生产单、批量、到货日期、主体，「验货」。分段「全部 / 回货 / 来料」。
- **不合格、返修**（`rework`）：尾期验货不合格还没返修完的回货。回货单、生产单 · 加工厂、货品、最近一次验货（第几次、抽检和不合格数、问题）、返修说明、状态（不合格 / 返修中）；「返修」写返修说明，「返修完成」回到待检。
- **质检记录**（`records`）：每次检验一条，新的在前。单号、类型、来源单（第几次）、供应商、货品、批量、抽检 / 不合格、结论、问题（照片、问题类型、问题、返修）、扣款、检验人和日期；分段按类型，筛结论、供应商、检验日期；显示列能挑。「改」「删除」（安排了返修的、扣款进了对账单的不出删除）。
- **供应商质量**（`stats`）：按家统计（默认最近 90 天），检验次数、合格率、不合格、让步接收、抽检 / 不合格、抽检不良率、常见问题、质量扣款；不合格多的在前。分段按类型，筛检验日期。

**验货对话框**：上面是供应商、货品、批量和 AQL 2.5 的建议（抽多少、允收几件），回货再验时列出前几次的结论和返修说明；下面填检验日期、结论（产前样是"通过 / 不通过"）、抽检数（默认 AQL 建议）、不合格数（超过允收数结论自动变不合格，自己选过结论就不跟）、问题类型（多选）、问题（不是合格的必填）、照片、质量扣款（有扣款登记权限、结论不是合格才出；进了对账单的灰掉）。

首页"其他提醒"、预警中心：`QC_PENDING` 待检的回货和来料（去 `/qc`）、`QC_REWORK` 回货验货不合格待安排返修（红，去 `/qc?tab=rework`），有 `quality:inspection:edit` 的人才有。

## 2. 规则

- **一次检验一条记录，不审核**，保存就算数。单号 `ZJ` + yyyyMMdd + 4 位流水。主体、供应商（加工厂）、品类线、货品、批量取来源单的（快照）。
- 来源按种类：来料检验 → **已审核的采购入库单**（一张只验一次，部分唯一索引）；尾期验货 → **已审核的回货单**；产前样、中检 → **已审核、生产中、已完成的生产单**（外发加工单、成品采购单），可以记多次。
- **回货的质检状态**由记录推出来，不往回货单上加列：没验 → 待检；最近一次合格、让步接收 → 验完了；不合格 → 「返修」→ 返修中 → 「返修完成」→ 待检，再验一次（`attemptNo` + 1，前面的记录留着）。现在不能验的（验完了、不合格没安排返修、在返修）记的时候报 1000，说先做什么。
- 必填：检验日期（不晚于今天）、结论；抽检数（产前样可以不填）；不合格数不大于抽检数；不是合格的要写问题。照片选填（原型要求不合格必须拍照，电脑上记的不一定有，先不卡）。
- 改：什么都能改，**安排了返修的结论不能改**（只能是不合格）。删：安排了返修的不能删；扣款进了没作废的对账单的不能删（1000）。
- **质量扣款**：结论不是合格、填了金额，同一个事务里登记一笔扣款（`stl_deduction.source_type = QC_INSPECTION`，日期 = 检验日期，原因"质检 ZJ…：尾期验货不合格，问题"，相关单号 = 质检单号），月底按日期进对账单。改记录的金额、日期同步改扣款，去掉金额就删扣款；**扣款进了没作废的对账单的，金额、日期不能改（1000），只改问题不动扣款的原因**（对账单上已经抄过去了）。扣款登记页上这笔不给改、删（接口回 1000），"到质检改"。扣款和手工登记一样按供应商的品类线管：供应商不在自己的线里，带扣款、改扣款的金额日期、删扣款报 1000（来料检验本身谁都能记、谁都能看）。
- 源单（入库单、回货单、生产单）反审核、作废不受质检记录拦：质检记录不算下游单据。已审核的入库单、回货单过了账删不掉，外键也不会碰到；生产单审过、记了产前样或中检又反审核回草稿的，删的时候拦住、让作废（docs/api/05 §3.2.6）。回货单作废了，它的不合格记录不再进"不合格、返修"列表和首页的数，也不能再安排返修。
- 两个人同时验同一批（同一张入库单、回货单同一次、生产单同一种检验同一次），后提交的报 1002。改记录必须带 `version`，不带也报 1002。
- AQL：2.5、一般检验水平 II，批量上限 → 抽检数 / 允收数：≤8 → 2/0，≤15 → 3/0，≤25 → 5/0，≤50 → 8/0，≤90 → 13/1，≤150 → 20/1，≤280 → 32/2，≤500 → 50/3，≤1200 → 80/5，≤3200 → 125/7，≤10000 → 200/10，更多 → 315/14；抽检数不超过批量。来料检验几种单位混在一起时批量是空的，不给建议。

## 3. 接口

前缀 `/api/qc-inspections`。写操作带记录（来源单）的主体 `X-Company-Id`：记的时候是来源单的 `companyId`，改、删、返修是记录的。

| 方法 | 地址 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/qc-inspections` | list | 质检记录分页。`kind`、`result`、`companyId`、`partnerId`、`prdOrderId`、`dateFrom`、`dateTo`、`keyword`（质检单号、来源单号、生产单号、供应商编码名称简称、货品） |
| GET | `/api/qc-inspections/pending` | list | 待检分页：`kind`（`INCOMING` / `FINAL`）、`companyId`、`keyword`。返回 `QcPendingRow`：`kind`、`sourceId`、`sourceNo`、`sourceDate`、供应商、生产单、`productLine`、`targetDesc`、`lotQty`（几种单位时 null）、`unit`（字典 `unit`；回货 `PIECE`）、`attemptNo` |
| GET | `/api/qc-inspections/reworks` | list | 不合格、返修：`QcRow[]`，早的在前，最多 500 条。`companyId` 选填 |
| GET | `/api/qc-inspections/supplier-stats` | list | 供应商质量：`dateFrom`、`dateTo`（默认到今天、往前 90 天）、`companyId`、`kind`。返回 `inspectCount`、`passCount`、`concessionCount`、`failCount`、`sampleQty`、`defectQty`（只算填了抽检数的）、`deductAmount`、`topDefects`（问题类型字典值，多的在前，最多 3 个） |
| GET | `/api/qc-inspections/source` | edit | 记之前看来源单：`kind`、`sourceId`。返回来源单号、状态、主体、供应商、生产单、货品、批量、单位、`attemptNo`（这次第几次）、`aqlSample`、`aqlAccept`、`history`（前几次，早的在前）。现在不能验的 1000，看不到的 404 |
| GET | `/api/qc-inspections/order-options` | edit | 记产前样、中检选生产单：`keyword`（单号、款号款名、加工厂），已审核、生产中、已完成的，新的在前，最多 20 张 |
| GET | `/api/qc-inspections/{id}` | list | 一条，带照片 |
| POST | `/api/qc-inspections` | edit | 记。`QcReq`：`kind`、`sourceId`、`inspectDate`、`sampleQty`、`defectQty`、`result`（`PASS` / `CONCESSION` / `FAIL`）、`defectTypes`（字典 `qc_defect_type`）、`note`、`photos`（先上传拿地址）、`deductAmount`。返回 `{ id, no }` |
| PUT | `/api/qc-inspections/{id}` | edit | 改，带 `version`（`kind`、`sourceId` 不看）。返回新的 `version` |
| DELETE | `/api/qc-inspections/{id}` | edit | 删，扣款一起删；有扣款的要 `settle:deduction:edit` |
| POST | `/api/qc-inspections/{id}/rework` | edit | 安排返修：`{ version, note }`，尾期验货不合格、还没安排的才行。返回新的 `version` |
| POST | `/api/qc-inspections/{id}/rework-done` | edit | 返修完成：`{ version }`，回货回到待检。返回新的 `version` |

`QcRow` 的字段：`id`、`no`、`companyId`、`companyName`、`kind`、`invDocId`、`prdReceiptId`、`prdOrderId`、`prdOrderKind`、`prdOrderNo`、`sourceNo`（采购入库单号、回货单号；产前样、中检是生产单号）、`attemptNo`、供应商、`productLine`、`targetDesc`、`lotQty`、`unit`、`inspectDate`、`sampleQty`、`defectQty`、`acceptQty`、`result`、`defectTypes`、`note`、`reworkNote`、`reworkBy(Name)`、`reworkTime`、`reworkDoneBy(Name)`、`reworkDoneTime`、`deductionId`、`deductAmount`（没扣款登记查看权限的不返回）、`deductStatementNo`（扣款进了哪张没作废的对账单）、`photos`、`version`、`createBy`、`inspectorName`、`createTime`。

扣款登记的行（`/api/deductions`）加了 `sourceType`（`QC_INSPECTION` 或 null）、`sourceId`；`sourceType` 不空的 `PUT`、`DELETE` 回 1000。

## 4. 以后

甲方给了质检流程再加：审核、返修单（现在返修记在验货记录上）、退货（现在不合格的来料要退，照常开采购退货）、待检仓 / 不良品仓（架构 §14.2）、回货没验不能入成品仓（原型这样画的，现在不拦）、供应商绩效报表算进质检的不合格（现在供应商绩效只算回货次品）。
