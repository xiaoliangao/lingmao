# 02 需求订单

覆盖：需求订单（颜色 × 尺码矩阵录单、Excel 导入、提交、多级审批、审核锁资料包版本、承诺交期）、审核时的评审信息、排单、订单变更单。

需求：PRD §6.5、§5.1（审批）、§6.10（排单取价）。机制：架构 §3.1（排单放在 production）、§4（单据框架）、§4.8（多级审批）、§5.3（已排产回写）。表：数据库设计 §10（`ord_`）。

类型在 `web/src/types/order.ts`，接口在 `web/src/api/order.ts`。下面两块界面在订单里、后端不在 order 域，类型和接口也放在这两个文件里：

- **排单**：后端在 production 域（`/api/production-orders/schedule…`），`scheduleApi`。生成的外发加工单、成品采购单在 05-生产。
- **审核对话框的评审信息**：计划由 board 域提供（`/api/board/orders/{id}/review`），`orderReviewApi`；该聚合后端尚未实现，不代表真实齐料/产能已验证。本轮不新造完整 board，订单提交/审核仍由业务 Service 权威校验。

列表里的"齐料"一列由 03-算料采购提供（`kittingApi.byOrders`），见 §3.13。

## 1. 页面

### 1.1 需求订单列表

- 地址：`/orders`。带 `?unscheduled=1` 时预先勾上"待排单"；带 `?status=PENDING` 时选中那个状态页签；`?status=PENDING&auditForMe=1` 是待我审核；带 `?orderDateFrom=&orderDateTo=` 时预先填下单日期。KeepAlive 下监听 query 变化。变更单列表 `/order-changes` 同样认 `?status=`，不把三类多级审批的 `auditForMe` 擅自扩给变更单。
- 原型：`docs/原型/src/5b-order.js` 的 `route('/orders')`（约 32 行）。
- 页面文件：`web/src/views/order/order/index.vue`。
- 顶上按钮：导入、导出、新建需求订单。
- 状态用分段控件（全部、草稿、待审核、已审核、生产中、已完成、已结案、已取消），数字取 `orderApi.counts`。
- 筛选弹层：订单类型、品牌、业务员、跟单员、下单日期、待排单。右边"我的 / 全部"切换（`mine`）。关键字搜单号、合同号、款号。
- 列（PRD §5.4 页面最多 12 列）：订单号、下单日期、类型（品牌小字跟在后面）、款式（缩略图 + 款号）、数量、金额、交期（有承诺交期显示承诺交期、小字"承诺"，没有显示要求交期、小字"要求"）、排产（进度条，审核前显示"—"）、回货（进度条，没排产显示"—"）、齐料、跟单、状态。
- 勾选列 + 底部批量条：提交、审核、导出选中。批量按钮的 `can` 看行上的 `actions`，`version` 用行上的（`OrderRow.version`）。批量审核的承诺交期用 `commitDate ?? requiredDate`，批量条上提示"承诺交期按要求交期定，要另定的进详情审"（原型同款）。
- 空表格文案照原型：没有符合条件的 → "没有符合条件的需求订单：换个状态页签，或者清空筛选"；"我的"下没有 → "还没有你是制单人、业务员或跟单员的订单"；待我审核为空 → "暂无轮到你审核的订单"；一张都没有 → "还没有需求订单"。不能向 SELF 用户承诺切到"全部"即可看到所有人。

### 1.2 新建、编辑

- 地址：`/orders/new`（带 `?styleId=` 时先把这个款加进来，款式详情的"下订单"用）、`/orders/:id/edit`。
- 原型：`5b-order.js` 的 `OrderForm`（约 93 行）。
- 页面文件：`web/src/views/order/order/form.vue`。加进 `web/src/router/index.ts` 的 `DETAIL_ROUTES`（照款式的 `form`）：`{ parent: '/orders', path: '/orders/new', file: 'order/order/form', title: '新建需求订单' }`、`{ parent: '/orders', path: '/orders/:id(\\d+)/edit', file: 'order/order/form', title: '编辑需求订单' }`。
- **做成整页，不照原型做成对话框。** 理由：一张单常有好几个款，每个款一张矩阵，加上单头十几个字段，对话框装不下；款式的新建、编辑也是整页，用户已经熟悉。
- 底部按钮：新建时"存草稿""提交审核"；编辑草稿时"保存""保存并提交"。

### 1.3 详情

- 地址：`/orders/:id`，`?tab=lines | down | changes | logs`。
- 原型：`5b-order.js` 的 `route('/orders/:no')`（约 167 行）、`OrderAudit`（约 283 行）、`OrderSchedule`（约 310 行）、`OrderChange`（约 370 行）。
- 页面文件：`web/src/views/order/order/detail.vue`。加进 `DETAIL_ROUTES`：`{ parent: '/orders', file: 'order/order/detail', title: '需求订单' }`。
- 审核、排单、提变更都是这一页上的对话框，建议拆成 `views/order/order/AuditDialog.vue`、`ScheduleDialog.vue`、`ChangeDialog.vue`（变更单详情页的"改了再提交"也用 `ChangeDialog`）。
- 页签：明细、下游单据（`references`）、变更（`orderChangeApi.page({ orderId })`）、操作记录。附件块照款式的 `DesignFiles`。

### 1.4 订单变更单

- 地址：`/order-changes`、`/order-changes/:id`。
- 原型：`5b-order.js` 的 `route('/changes')`（约 430 行）。原型里变更单没有详情页，点一行去订单的"变更"页签；**这里加一个简单的详情页**。理由：`docRoute` 的 `ORDER_CHANGE`、首页"待我审核"、操作记录都要能点到一张变更单；审核人要看全部改动、附件，订单的变更页签一行放不下。
- 页面文件：列表 `web/src/views/order/change/index.vue`，详情 `web/src/views/order/change/detail.vue`（加进 `DETAIL_ROUTES`：`{ parent: '/order-changes', file: 'order/change/detail', title: '订单变更' }`）。
- 列表：状态分段（全部、待审核、已审核、已驳回、草稿、已作废），筛选弹层里有变更类型、制单日期；"我的 / 全部"；关键字搜变更单号、订单号、SKU 码。列：变更单号、订单号、类型、改了什么（`summary`，可换行）、原因、责任方、制单（人 + 日期）、审核（人 + 日期）、状态。行尾：当前用户 `actions` 里有 `audit` 时出"驳回""审核"两个小按钮（原型同款）。
- 没有"新建"按钮：变更从订单详情的"提变更"进来。空表格："没有符合条件的变更单。已审核的订单在详情页「提变更」"。
- 详情：单头（订单号点了去订单、类型、原因、责任方、费用说明、驳回原因）、改动清单（`items`，一处一行"原 → 新"）、附件、操作记录。按钮按 `actions`：提交、撤回、驳回、审核、作废、改了再提交（`edit`，打开 `ChangeDialog`）、删除。

## 2. 状态

### 2.1 需求订单

`OrderStatus` 就是 `DocStatus`，中文按订单叫（`ORDER_STATUS`）：

| 状态 | 中文 | 标签 | 什么时候 | 能做什么 |
|---|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 新建、导入、驳回、撤回、反审核 | 编辑、删除、提交、作废 |
| `PENDING` | 待审核 | `pending` | 提交 | 审核、驳回、撤回、作废 |
| `APPROVED` | 已审核 | `active` | 最后一级审过 | 排单、提变更、算料、反审核、结案 |
| `RUNNING` | 生产中 | `progress` | 有一张生产单审核了（production 回调） | 排单、提变更、算料、结案 |
| `DONE` | 已完成 | `done` | 每个 SKU 都排满了，所有生产单都完成了（production 回调） | 看 |
| `CLOSED` | 已结案 | `closed` | 手动结案（剩下的不做了） | 取消结案 |
| `VOIDED` | 已取消 | `void` | 审核前作废；审核后经变更单取消 | 看 |

- 取消结案回到结案前的状态（有审核过的生产单是生产中，没有是已审核）。
- 反审核：只有已审核、没有下游单据（生产单、算料单）的能反审核，有就 1005，`data` 是 `DocRef[]`。反审核清掉锁定的资料包版本，承诺交期留着当下次审核的默认值。
- 已审核以后不能编辑、不能作废，要改走变更单，要取消也走变更单（"取消订单（走变更单）"）。

按钮看 `OrderDetail.actions`（`OrderAction`）：通用的 `submit / withdraw / reject / audit / unaudit / close / reopen / void`，加上：

| action | 按钮 | 什么时候有 |
|---|---|---|
| `edit` | 编辑 | 草稿，有 edit |
| `remove` | 删除 | 草稿，有 remove |
| `schedule` | 排单 | 已审核、生产中，还有 SKU 没排满，有 `production:order:add` |
| `change` | 提变更、取消订单（走变更单） | 已审核、生产中，没有没审完的变更单，有 `order:change:add` |
| `mrp` | 算料 | 已审核、生产中，有 `purchase:mrp:add`（03） |

多级审批：只有当前这一级的审批人 `actions` 里有 `audit`、`reject`，别人看到"现在等××审"（`approval.waitingFor`），README §4.4。

### 2.2 变更单

`ChangeStatus` 只用四个（`CHANGE_STATUS`）：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、提交、删除 |
| `DRAFT` 且 `rejectReason` 不空 | 已驳回 | `danger`（`CHANGE_REJECTED`） | 改了再提交、删除 |
| `PENDING` | 待审核 | `pending` | 审核、驳回、撤回 |
| `APPROVED` | 已审核 | `active` | 看 |
| `VOIDED` | 已作废 | `void` | 看 |

- 单级审核，有 `order:change:audit` 的人审，可以审自己提的（Q10）。
- 审核过了就写回订单，不能反审核：要改回去再提一张变更单。
- 一张订单同时最多一张没审完的变更单（草稿或待审核）。

### 3.2 列表 `GET /api/orders`

参数 `PageParams & OrderQuery`，返回 `PageResult<OrderRow>`。按下单日期倒序，同一天按单号倒序。

- `keyword` 一次查几个（README §3.2）：单号、款号精确查。变更单列表：变更单号、订单号精确查。
- `unscheduled=true`：已审核、一件都还没排的。
- `styleId`：含这个款的订单。
- `auditForMe=true`：只列 PENDING 且当前级轮到调用人审核的订单，忽略普通 `mine/ownerId` 归属筛选，其他条件仍取交集；默认 false。规则和模块访问前提见 README §3.2、§4.4。
- 行上有 `actions`，批量条按它判断。
- `counts` 的参数和列表一样（不看 `status`，保留 `auditForMe` 及其他规范化条件），返回 `{ DRAFT: 3, PENDING: 1, … }`，没有的状态不在里面。"全部"是各项相加，不把当前页签条件带进去使其他角标归零。

### 3.3 详情 `GET /api/orders/{id}`

返回 `OrderDetail`。

- `styles` 一个款一项（矩阵标题），`items` 是全部 SKU 明细，也是单价、行交期、备注的权威粒度。按 `styleId` 分块展示时不得拿首行/末行覆盖同款其他 SKU；不同值显示"多个值"并可查看各 SKU 原值。
- `styles[].techPackVersion`：审核后是锁定的版本；审核前是 null，显示 `currentPackVersion`（"资料包 V2"，没有显示"未生效"）。审核后锁定的和现在生效的不一样时，提示"现在生效的是 V3，要换走变更单"。
- `commitDate`：待审核时可能是上一级审批人填的，页面不显示成"承诺交期"，只在审核对话框里当默认值。
- `pendingChange`：有没审完的变更单时，顶上黄条"变更单 BG… 待审核：…"，按钮"去看"。
- `pendingNotices`：这张订单本身不收上游提醒（它是最上游），一直是 0。
- 不存在、不在数据范围：404。

### 3.4 画矩阵要的款式信息 `GET /api/orders/style-options?styleIds=`

返回 `OrderStyleOption[]`，按请求的顺序。录单、导入以后改单、提变更都用它。

- 选款式用 `DataPick kind="style"`（只列启用的款）；选完调它拿尺码、颜色、SKU。
- `problem` 不是 null 的款照样加进来，块的标题标红写原因（"没有生效的生产 BOM：先在款式的资料包里建好、点生效"），提交时后端照样会拦。
- `colors[].orderable = false` 的颜色：矩阵里那一行灰掉，悬停显示 `reason`（颜色在款上停用了、SKU 都停用了、已生效的生产 BOM 没给它配料）。
- 停用的 SKU（`skus[].status = 0`）那一格灰掉、不能填。
- 这些摘要用于录入提示，不代替指定 SKU 就绪检查。提交、各级审核及变更按实际 SKU 校验版本色码、配料与用量（01 §3.7）；未配齐可存草稿，但不能把颜色级正常误认为全部尺码正常。
- 登录就能调：订单页面、变更对话框都用它，返回的只是款式的公开信息。

### 3.5 新建、保存草稿

`POST /api/orders`（`OrderCreateForm`）返回 `DocSaved { id, version }`；`PUT /api/orders/{id}`（`OrderUpdateForm`）返回新的 `version`。

- 整单覆盖：没填的发 null，`items` 发全部（每个 SKU 一行，件数 0 的格子不发）。
- 每个 SKU 独立保留 `price`、`lineDueDate`、`remark`。款级、尺码级输入是**用户显式批改**，只有用户实施批改时才写到目标 SKU；加载和保存不自动展开分组代表值。同款同码不同颜色允许不同价/行交期/备注；混合显示"多个值"。未改行原样往返，null 与主动清空按行保存，件数 0 的格子仍不发。
- 保存草稿查必填单头（主体、订单类型、下单日期、要求交期、业务员、跟单员、币种）、正整数件数、非负单价及款式 SKU 存在；暂不查资料包和款式启用状态。单价允许 null（未定价），有值时最多四位小数且 ≤ `9999999999.9999`；行额、订单总额 ≤ `999999999999.99`；总件数 ≤ `2147483647`。后端以 BigDecimal 计算、金额 `HALF_UP` 两位，写库前检查行和合计；格式/容量错误返回 400 并指出字段或 SKU 行，不靠数据库 500。导入用 §3.9 的 1003 口径。
- `companyId` 必填，页面默认填我的默认主体（README §3.3）。
- `customerId`、`customerOrderNo` 一律发 null（TRADE 关）。
- 不是草稿了、`version` 对不上：1002；保留本地草稿并让用户明确重载/放弃，不替换 version 后直接覆盖。
- "提交审核" = `create`（或 `update`）成功后，拿返回的 `version` 接着 `act(id, 'submit', { version })`。提交没通过（见 §3.6）时，草稿已经存下了：留在编辑页，弹出原因。
- 新建成功后跳到 `/orders/{id}`，关掉新建页签。

### 3.6 提交、撤回、作废、删除

用 `docApi` 的 `act`、`remove`，README §4.2。

**提交的检查**（PRD §6.5.1）没通过回 1000，`data` 是 `string[]`（一条一句话），一次列全：

- 至少一行明细。
- 每个款：启用状态（"27CF002 已停用"），有生效的生产 BOM（"27CF003 没有生效的生产 BOM：先在款式的资料包里建好、点生效"）。
- 每个实际下单 SKU 启用，且生效生产 BOM 对该款色码就绪：版本上下文、随色/随码/随色码配料及分码用量完整（01 §3.7）。例如"27CF001 黑色 XXL：资料包 V2 第 3 行缺 XXL 配料，请修订生产版"；只检查有数量的 SKU，不检查全部色码组合。

前端调 `act(id, 'submit', body, { silent: true })`，出错照供应商"申请准入"的写法：`ErrorCode.BIZ` 且 `data` 是非空数组就 `showBizError`，不然 `ElMessage.error`。

- 提交时按订单总金额和实际审批规则取快照，并校验指定人启用、有 `order:order:list`，角色审批也有可用成员（README §4.4）。不能靠授予 ALL 修补不可达的审批人。
- 作废只在草稿、待审核时有，确认框用 `DOC_ACTION_CONFIRM.void`，状态变"已取消"。
- 删除只在草稿时有。确认："草稿删除后找不回来；想留个底就用「作废」。"按钮"删除"。删完回列表。

### 3.7 审核 `POST /api/orders/{id}/audit`

请求 `OrderAuditReq { version, commitDate }`。每一级都要填承诺交期（PRD §6.5.4、架构 §4.8）。

- 中间一级审过：单据还是待审核，承诺交期写进单头当下一级的默认值。提示"这一级审过了，等××审"。
- 最后一级审过：状态变已审核，**每个订单行锁定这个款当时生效的生产 BOM**（`techPackId`），承诺交期以这一级填的为准。提示"DD… 已审核，资料包已锁定"。
- 每一级都重跑提交时的指定 SKU 就绪检查；待审核订单若当前无可用生效生产版或缺色码配料/用量，回 1000（`data` 是 `string[]`）。审核已经锁定的历史包以后被新版替代为 VOIDED，不使旧订单自动换版或失效。
- 不是当前这一级的审批人：403"现在是第 2 级，等××审"。状态变了、别人刚审过：1002。
- 承诺交期早于下单日期：400。晚于要求交期不拦（这就是"评审后答应的日期"）。
- 批量审核（列表的批量条）调同一个接口，传 `{ silent: true }`，承诺交期用 `commitDate ?? requiredDate`。

驳回 `act(id, 'reject', { version, reason })`，原因必填；哪一级驳回都回到草稿。

### 3.8 评审信息 `GET /api/board/orders/{id}/review`

计划返回 `OrderReview`，审核对话框打开时调；后端 board 聚合尚未实现（只读、跨域汇总，架构 §3.1、§3.3）。未实现/加载失败展示"评审信息暂不可用"和重试，不把缺失数据当作零缺料、零产能占用，也不能用 mock 宣称审核已联调。下面是后续聚合契约，业务提交/审核的就绪检查不依赖它。

- `packs`：每个款审核后会锁哪一版；`problem` 不是 null 的标红"资料包没生效，不能审"。
- `shortages`：按生产 BOM 粗算这张订单要的料，和可用量（库存 + 赶得上的在途 − 别的算料单占着的，PRD §6.6.1）比，缺口最大的 5 种。都够时是 `[]`，表格空文案"现有库存够用"。
- `loads`：每个默认加工厂手上在制多少件、几张单（取自生产看板的口径）。款式没设默认加工厂的不出。
- 只是参考，不拦审核。

### 3.9 导入

- 模板：`GET /api/orders/import-template`。一行一个 SKU：分单号、合同号、款号、颜色（名称或编码）、尺码、数量、单价、行交期（PRD §6.5.2）。
- 导入：`ImportDialog` 的 `import-url` 用 `orderApi.importUrl(head)`，单头（`OrderImportHead`：主体、订单类型、品牌、要求交期、业务员、跟单员）拼在查询参数里，文件还是 multipart 的 `file`。主体必填（默认我的默认主体）；业务员、跟单员选填，不给 = 导入的人。
- **单头字段放进导入对话框的 `#head` 插槽**（显示成第一步，用法见 `ImportDialog.vue` 开头）。单头没填齐时传 `:ready="false"`，"开始导入"灰掉。
- 同一个分单号的行进同一张订单，分单号都不填整个文件一张。同一张订单的行合同号不一样：报错。
- 校验：款号、颜色、尺码存在且启用，数量是正整数；单价精度/容量、每行金额、分单总额与总件数遵循 §3.5。任一行或整张分单合计超界，整批不写，返回 1003 错误清单，可定位工作表/行/字段或分单；`ImportDialog` 自己显示。不同 SKU 的合法单价、行交期逐行保存，编辑后不得压成款级值。
- 不在导入时查资料包：导进来是草稿，提交时再查（原型的说明"导进来是草稿，核对后再提交审核"）。
- 成功返回 `{ total, notes }`：`total` 是导了几行明细，`notes` 每张单一句"DD202611150001：27CF001 等 2 个款，1,200 件"。

### 3.12 排单（后端在 production）

预填和生成接口要 `production:order:add`；`schedule-quote` 要 `production:order:add` 或 `production:order:edit`（生产草稿换厂也用）。订单要是已审核或生产中，不然 1002。生成生产单时先锁订单行（`SELECT … FOR UPDATE`）再查状态、写已排产：变更单取消订单也是先锁订单、再查有没有下游单据，两边排队，不会一边刚查完没有下游、另一边就排出一张生产单。

**打开对话框** `scheduleApi.prefill(orderId)` → `SchedulePrefill`：

- 只列还有没排完的款。每个款一块，默认带款式的默认加工厂；`skus[].remainQty` 是默认填的数，`maxQty` 是这个 SKU 最多还能排多少。
- 默认交期 = 承诺交期 − 10 天（东八区纯日期运算），默认生产跟单 = 订单的跟单员。

**选加工厂** `scheduleApi.quote(orderId, styleId, factoryId)` → `ScheduleQuote`：

- 打开时有默认加工厂的块，也调一次。
- `prices` 一次给齐每种加工方式的现价，切加工方式不用再调。单价默认取所选方式的 `price`；是 null 就要手填。
- `usable = false`（不是合作中、不是成衣厂或加工厂）：块上标红 `reason`，确定时后端也会拦。
- 加工厂下拉用 `SupplierSelect :category="['GARMENT', 'PROCESSOR']"`。

**确定** `scheduleApi.schedule(orderId, blocks)` → `DocRef[]`：

- 一块生成一张生产单草稿（一个加工厂 + 一个款式，PRD §6.5.5）。加工方式是 `FULL`（`PROCESS_MODE_FULL`，包工包料）生成成品采购单，别的生成外发加工单。
- 生产单带上订单锁定的资料包版本。
- 件数是 0 的 SKU 不发；整块都是 0 的不发。
- 超排（PRD §6.5.5：同一 SKU 的已排产合计 ≤ ⌊订单数 × 1.03⌋）：1004，`data` 是 `ScheduleOverRow[]`，`request.ts` 自动弹表格。
- 单价没填、加工厂不能用、单价和档案现价不一样又没写原因（`priceChangeReason`，Q25）：1000。
- 成功：提示"生成了 2 张生产单草稿：JG…、CP…，去生产单里核对后提交"，切到"下游单据"页签。点单号用 `docRoute`。
- **已排产在生成草稿时就占上**：草稿生产单的件数也算已排产，生产单作废、删除时退回（05 实现）。不然两个人同时排单、或者草稿还没审时再排一次，都会超排。

### 3.13 齐料一列（03 提供）

列表的"齐料"一列不在 `OrderRow` 里：列表加载完，拿本页已审核、生产中、已完成的订单 id 调 `kittingApi.byOrders(orderIds)`（`api/purchase.ts`，返回 `OrderKitting[]`，类型在 `types/purchase.ts`），按 `orderId` 填进去。标签用 `KITTING_STATUS[status]` 的颜色、`label` 的字（"部分到料 3/5"），点了去 `/mrp/{calcIds[0]}`（03 里的约定）。草稿、待审核、已结案、已取消的显示"—"。

### 3.14 变更单

**新建** `POST /api/order-changes`（`OrderChangeCreateForm`）返回 `DocSaved`；**改草稿** `PUT /api/order-changes/{id}`（`OrderChangeUpdateForm`）返回新的 `version`。"提交变更" = 新建成功后接着 `act(id, 'submit', { version })`。

表单（`OrderChangeForm`）发的是**改完以后的样子**，不是差异：矩阵里每一格的新件数都发（没改的也发），要换资料包的款发新版本，新的要求交期不改发 null。`prices` 仅发送用户明确要求统一改价的款（`{ styleId, price }`）；原订单混合单价显示"多个值"，未执行款级批改不得把分组值放进 `prices`，原 SKU 价格继续保留。后端拿它和订单现在的数比，算出 `items`、`changeTypes`，一样的不算。

**新建和提交跑同一套检查**（新建时先查一遍，免得留下提交不了的草稿）。没通过回 1000，一句话说清楚：

| 检查 | 提示 |
|---|---|
| 订单是已审核或生产中 | "订单现在是「已结案」，不能变更" |
| 这张订单没有别的没审完的变更单 | "已经有变更单 BG… 没审完，先处理它" |
| 有改动（或者勾了取消订单） | "没有改动" |
| 原因、责任方填了 | 400 |
| 新件数不小于已排产（PRD §6.5.6 规则 2） | 列出阻塞生产单及已排/已执行信息。未执行单按现有撤回、反审、作废条件释放后重排；已执行单明确不能直接减到已排量以下，不提示一个尚不存在的"调整生产单"流程 |
| 实际新增/变更 SKU 在锁定包或本次选的新包中就绪 | "27CF001 酒红 XXL：资料包 V2 第 3 行缺配料/用量，先修订并换资料包版本"；按 01 §3.7 检查 |
| 换的资料包是这个款现在生效的生产 BOM | "只能换到现在生效的版本" |
| 非负四位单价及行额、总额、总件数不超 §3.5 容量 | 保存、提交及审核写回前均校验，错误 400；版本冲突仍是 1002 |
| 责任方是"客户"（TRADE 关） | 400 |

取消订单（`cancel = true`）：订单有下游单据（生产单、算料单）时提交被拦，1005，`data` 是 `DocRef[]`，自动弹表格（PRD §6.5.6 规则 4）。

已经执行的生产数量不通过放开反审或结案来释放：结案不退已排量。此类减单按已有结案、原因留痕、后续新需求处置；首期不提供余量调整单，也不绕开变更审核直接改原单。变更通知只提醒下游，不自动改既有生产单的锁定 BOM。

**审核** `act(id, 'audit', { version })`：

- 写回前核对"原"还等于订单现在的值；对不上（这期间订单又变了）回 1002"订单在这期间变了，作废这张重新提"。
- 写回订单：数量、新 SKU、交期、单价（金额重算）、锁定的资料包版本；取消订单就把订单变成已取消。订单的 `version + 1`。
- 给每张受影响的下游单据（外发加工单、成品采购单、采购单、算料单）插一条变更提醒（README §4.5）："上游订单 DD… 于 11-20 变更：27CF001-KQ-M 数量 −20"。
- 提示"变更已写回订单，下游单据已提示"。

驳回要写原因，回到草稿，列表显示"已驳回"，制单人"改了再提交"。

列表 `GET /api/order-changes`：参数 `PageParams & OrderChangeQuery`，返回 `PageResult<OrderChangeRow>`，按制单时间倒序。订单详情的"变更"页签用同一个接口带 `orderId`。

"已驳回"不是一个状态（库里是草稿），分段控件按它分页签要后端筛："已驳回"发 `status=DRAFT&rejected=true`，"草稿"发 `status=DRAFT&rejected=false`。`counts` 去掉 status/rejected 页签条件、保留其他筛选，返回的 `DRAFT` 是全部草稿，另外多一个 `REJECTED` 键是其中被驳回的几张。理由：前端拿到一页再过滤，分页就不对了。

## 4. 前端要知道的规则

### 4.1 颜色 × 尺码矩阵

录单、只读明细、提变更、排单都是"行是颜色、列是尺码、格子里填件数、右边和底下合计"（PRD §6.5.1）。复用 `web/src/components/SkuMatrix.vue`；数量矩阵与每 SKU 单价/交期/备注模型分离，不能用分组输入替代原始行：

- `v-model`：`Record<styleSkuId, number>`（或 `colorId|sizeCode` 做键，前端定）。
- props：`sizes`、`colors`（带 `orderable`、`reason`）、`skus`（停用的灰掉）、`readonly`、`max`（排单时每格的上限）、`sub`（每格下面的小字：只读明细里"排 80 · 回 40"，变更里"原 120 · 已排 80"或"新加"）。
- 合计用 `formatQty`。件数只收正整数，输入非数字、小数时不收。
- 资料包的分码用量也能用它（只有一行），但不急。

### 4.2 新建、编辑

- 单头两列（`.form-grid`），标签放上面：主体（必填，默认我的默认主体）、订单类型（`DictSelect type="order_type"`，默认"自营备货"）、品牌、合同号、下单日期（东八区今天）、要求交期（东八区今天 + 60 天，原型同款）、业务员（默认我）、跟单员、币种（默认 CNY）、送货要求、备注。新建时多一块附件。
- 下面"加款式"按钮：`DataPick kind="style"`，已经在单上的灰掉（`have`）。选完调 `orderApi.styleOptions` 拿矩阵信息，一个款一块。
- 每块：缩略图、款号、款名、资料包版本（"资料包 V2"或标红的 `problem`）、款级/尺码级批改单价、行交期、行备注、矩阵、本款件数和金额、删掉这个款。分组存在不同值时显示"多个值"，可查看/编辑 SKU 原值；批改须有明确范围和用户动作，不在打开表单、切换开关、只改单头时批量重写。
- 单价输入最多四位小数，显示 `formatPrice`，占位写吊牌价参考（"吊牌价 299"）；金额才用两位格式。
- 底部显示合计件数、金额（前端即时算，保存后以后端为准）。
- 整页表单用 `useUnsavedChanges(form)`，纳入 SKU 字段及附件；加载完、保存完才 `markSaved()`。KeepAlive 激活保留 dirty，未完上传按 README §3.3 处理。
- 编辑草稿：以 `get.items` 的每 SKU 行为原值，`styleOptions` 仅补选项和可用性；选项请求失败/缺失不能丢掉原行。只改单头再保存应保持每行 price/lineDueDate/remark 完全不变，保存发原 `version`。

### 4.3 详情

- 顶上按钮按 `actions`：编辑、提交审核、驳回 + 审核（当前级审批人）或"现在等××审"、提变更、算料、排单（主按钮），"更多"里放撤回、反审核、结案、取消结案、取消订单（走变更单，红色）、作废、删除。
- 算料：调 03 的 `mrpApi.create([id])`，成功后跳到 `/mrp/{返回的 id}`，提示"SL… 算好了，勾选要买的行生成采购单"（原型 `doMrp`）。
- 标题下一行：件数、金额、交期（`commitDate ?? requiredDate`）、离交期还有几天（7 天内琥珀色，过了红色；只在已审核、生产中显示）。
- 明细页签：一个款一块，标题行有资料包标签（审核后"V2 已锁定"，蓝色）、单价摘要、小计；行交期、行备注小字；混合值显示"多个值"并可查看 SKU 详情，不误报统一值。只读矩阵每格小字"排 80 · 回 40"（已审核以后）。
- 下游单据页签：`references`，列类型、单号、状态、负责人；点单号 `docRoute`。空文案"还没有下游单据：审核后点「排单」「算料」"。
- 变更页签：变更单列表（同 §1.4 的列），空文案"没有变更。订单审核后要改数量、颜色、交期、单价，点「提变更」"。
- 审批块：README §4.4。

### 4.4 审核对话框

宽 640。三块评审信息（`orderReviewApi.get`）+ 承诺交期（默认 `commitDate ?? requiredDate`）。按钮"取消""通过"。有款 `problem` 不是 null 时"通过"灰掉，提示"有款资料包没生效，不能审"。

该聚合目前未实现，失败/未就绪须明确展示，不用默认空数组伪称资料包、供料或产能无问题。订单审核接口仍独立执行全部权威校验，是否可审以其结果为准。

### 4.5 排单对话框

宽 840，原型 `OrderSchedule`。

- 每个款一块：加工厂、加工方式（`DictSelect type="process_mode"`，切了换单价）、单价（标题按加工方式叫"加工费"或"成品单价"，外发加工时旁边小字"资料包加工费 38.00"，取锁定版本的 `laborPrice`）、改价原因（单价和带出的现价不一样时出现，必填）、交期、生产跟单（`UserSelect`）、结算方式（默认工厂档案的）、条款、备注、矩阵（每格默认 `remainQty`，上限 `maxQty`）。
- "再加一个工厂"：同一个款再加一块，件数默认 0。每块的件数加起来超过 `maxQty` 时那一格标红（后端还会拦 1004）。
- 底部显示"生成 n 张生产单：外发加工单 a 张、成品采购单 b 张"。

### 4.6 提变更对话框

宽 840，原型 `OrderChange`。

- 顶上"取消整张订单"勾选。勾了：隐藏下面的矩阵和交期，调 `orderApi.references(orderId)`，有下游单据就黄条列出来"先处理这些下游单据"。
- 没勾：每个款一块：矩阵（初始是订单现在的件数，小字"原 120 · 已排 80"，新加的颜色小字"新加"）、"加颜色"下拉（款上能下、订单里还没有的颜色）、显式款级改价（四位；原混合值标"多个值"，未动不发 `prices`）、资料包版本（只有现在锁的版本和现在生效的版本两个选项）。下面要求交期。
- 公共：责任方（默认我方，TRADE 关时没有"客户"）、原因（必填）、费用说明（占位"如：已裁片损失由我方承担"）、变更依据附件（`ImageUpload`，提示"审批截图、邮件、聊天记录"）。
- 前端即时查：新件数小于已排产的格子标红"已排 80"。
- 按钮："提交变更"（新建 + 提交）；改被驳回的：标题"改变更单 BG…"，按钮"重新提交"（`update` + `submit`）。
- 对话框表单用 `useUnsavedChanges(form, visible)`，加 `:before-close="guard.beforeClose"`。

### 4.7 贸易代工（TRADE）

前端一期按"关"做，不读开关（和后端 `TradeFeature` 的约定一样）：不出客户、客户订单号；订单类型的字典接口已经滤掉"客户订单"；责任方不列"客户"；交期一栏叫"要求交期"。

## 5. 按默认做的

| 问题 | 怎么做 |
|---|---|
| Q09 溢短装 | 排单上限 ⌊订单数 × 1.03⌋（溢装 3%），超过 1004 |
| Q10 谁审、能不能自己审 | 有 `order:order:audit` 的人审第 1 级，规则加的级照设置；允许自己审。变更单单级，有 `order:change:audit` 的人审 |

| Q25 改价要不要审批 | 不审批，排单改了价要写原因，生产单审核时记进价格档案 |
| Q12 包工包料哪些料我方出 | 排单选包工包料生成成品采购单；资料包里标"自购"的行照样算料 |

## 6. 用户定了的

1. **订单表单做成整页（`/orders/new`），不照原型的对话框**（11-15 定）：几个款几张矩阵，对话框太挤；和款式的新建、编辑一样。原型不改（是给甲方看的，样子差不多）。
2. **变更单有详情页（`/order-changes/:id`）**（11-15 定）：首页待办、操作记录、`docRoute` 都要能点到一张变更单，审核人要看全部改动和附件。订单的"变更"页签里是列表，点了去详情页。
