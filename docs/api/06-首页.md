# 06 首页

首页的概况、待办、近期交期，"上游已变更"页，以及一期设置里还没做的部分（结论：没有）。需求看 PRD §6.9.2（第 5 条待办）、§3.2（数据范围），机制看架构 §3.1（`board` 域）、§4.8（待我审核怎么查），原型是 `docs/原型/src/5a-home-style.js` 的 `/` 和 `/upstream`。

类型在 `web/src/types/home.ts`，接口函数在 `web/src/api/home.ts`。首页三个聚合接口 `/api/board/home/kpi`、`todos`、`deliveries`，上游 `/api/board/upstream`，以及 02 的 `/api/board/orders/{id}/review` 已由 `board` 域只读汇总各领域公共服务。不存在模块权限的块返回 null 或省略；失败显示错误和重试，不回退到硬编码业务数值。验收状态、真实 HTTP/DB 证据与剩余边界见 `docs/reviews/full-audit-ledger.md`，接口存在不等于生产验收全部完成。

既有列表 `auditForMe` 与首页审核组共用可信审批范围及 SQL CURRENT EXISTS，普通 SELF 归属不会因拥有审核码变成 ALL；当前级审批人的对象例外仍须模块 list。

### 2.1 总表

| 方法 | 路径 | 权限 | 做什么 |
|---|---|---|---|
| GET | `/api/board/home/kpi` | 登录及各块模块权限 | 四个概况格子 |
| GET | `/api/board/home/todos` | 登录及各块模块权限 | 待办分组和"其他提醒"的数 |

"负责人是我"的口径（mine/ownerId 进一步筛选时用）：生产单看生产跟单，采购单看采购员，算料单看制单人，需求订单看跟单员，供应商看负责采购员。普通 KPI、延期、异常、证照、上游提醒先按各域 DataScope；只有获准 ALL 的用户可看全范围，**审核码不等于 data:all**。原型 `homeMineOr` 以审核权限扩大普通可见范围的做法不作为授权依据。

### 2.3 待办 `GET /api/board/home/todos`

参数 `HomeTodoQuery`，返回 `HomeTodos`。`groups` 只放有条目的组，按下表的顺序；每组最多 20 条，`total` 是一共几条。`counts` 只放数不为 0 的。

**筛选**：`canSeeAll` 根据真实 ALL 数据范围与可访问模块计算，不根据审核码。获准 ALL 的用户默认看各模块获准范围，可用"全部 / 我的"和负责人下拉（`mine`、`ownerId`）进一步缩小；其他用户仍按各域 DataScope。跨域每组独立裁定，不能因一组可见全部而扩大其他组。筛选影响普通组及普通提醒数；"待我审核"和审核类计数只按当前级匹配，不叠加普通负责人筛选。选项可记 localStorage（try/catch），恢复时仍以后端权限为准；`/upstream` 同口径。

**分组**（PRD §6.9.2 的"给谁"，条目照原型的 `todo`）：

| 组 | 给谁 | 一条是什么（`title` / `sub`） | 点了去 |
|---|---|---|---|
| `AUDIT` 待我审核 | 需求订单、采购单、生产单：有模块 list、当前级匹配调用人，与对应列表 auditForMe 相同；变更/资料包/库存/供应商分别要求模块访问和既有审核/生效/准入动作权限及数据范围，不能套用 audit⇒ALL；供应商自己的申请不算 | "需求订单 DD…" / "客户或—· 2,400 件 · 交期 03-10 · 第 2 级"；"外发加工单 JG…" / "加工厂 · 400 件"；"资料包 27CF001 V2" / "款名 · 草稿待生效"；"供应商准入 某面料" / "面料 · 李四 11-14 申请" | 那张单据（资料包去款式的资料包页签，供应商去供应商详情） |

| `UNSCHEDULED` 待排单 | 已审核、一件都没排的需求订单，订单跟单员是我，并且我有 `production:order:add` | "需求订单 DD…" / "1,200 件 · 交期 03-20" | 需求订单 |

每条带一张缩略图（款式图、物料图；供应商没有）。同一组里按紧急程度排：延期的按逾期天数，审核的按提交时间，提醒按时间，都是旧的在前。

审核组每个来源先在数据库按实际提交时间（未提交的草稿按创建时间）、ID 排序，再 LIMIT 20，跨域合并后保留最早 20 条；total 是各来源完整 COUNT 之和。证照组按证照行计数，单一供应商的多份证照分别计入，按有效期、ID 排序。PRD §6.8.2与 §6.9.2 明确证照到期提醒负责采购员，因此 CERT 对 SELF 始终限定 supplier.buyer_id=当前用户；ALL 可看全部或按 mine/owner 进一步筛选，不因共享主档列表可读而扩大 SELF 提醒。到料 CUT 组按晚于开裁天数倒序先排序后分页。

上表普通组的"负责人是我"是 mine=true 的口径；ALL 的默认视图可包含其获准范围内的其他负责人，SELF 默认保留各域归属（包括我制单、别人负责），mine=true 再按当前负责人收窄；SELF 的 ownerId 参数忽略。不能通过把 mine=false 或 ownerId 清空扩大权限。

PRD 里的"供应商新增风险"是待排期的（Q22），这一期没有这一组。

### 2.4 近期交期 `GET /api/board/home/deliveries`

返回 `DeliveryRow[]`：今天起 7 天内要交的、和已经逾期还没交的，交期早的在前，最多 8 条，照数据范围。

- 需求订单：已审核、生产中的；交期 = 承诺交期 ?? 要求交期；进度 = 已回货 / 件数。
- 生产单：已下单、生产中的；交期 = 预计交期 ?? 交期；进度同上。

### 2.5 上游已变更 `GET /api/board/upstream`

参数 `UpstreamQuery { type?, mine?, ownerId?, cursor?, size? }`，`ownerId` 按 64 位整数验证；ID 在 JSON 中为字符串。`size` 默认 50，范围 1–100，越界返回 400。

返回 `UpstreamList { canSeeAll, rows, nextCursor, hasMore, total }`。`rows` 每行是 `{ doc, notices, noticesTotal }`；`notices` 仅含该单最新最多 100 条未处理通知，`noticesTotal` 是该单完整未处理数量。`total` 是当前授权/筛选范围的单据组总数，独立 COUNT，不随游标改变。

数据库先按模块列表权限、当前单据的 DataScope 和负责人筛选，再返回单据组计数、排序与 LIMIT。通知里的 `owner_id` 是历史快照，不用于扩权或当前负责人筛选。排序为最新通知时间、单据类型、单据 ID 全部倒序，游标按这三列 seek；游标以 HMAC 绑定部署租户、用户、当前授权、负责人、类型和 size，篡改或跨筛选重用返回 400。并发新增/处理提醒可改变实时总数，从第一页刷新后读取最新状态。

P33 同库摘要候选仅替换内部组计数/latest 的来源：与通知同事务维护，完成回填和逐键对账后才可显式启用，读取仍连接当前真实单据头。未就绪或显式回退时使用原分组 SQL；两种路径保持上述权限、完整计数和游标格式，数据库错误不自动切换路径。候选验收记录见 `production-hardening-rfc.md` §7.2.1。

首页 `UPSTREAM` 独立读取最早 20 个单据组和完整总数，每组只补齐 1 条最新通知作为预览。`/upstream` 不复用全量内存列表。前端每页替换 `rows`，用游标栈支持上一页/下一页；改变筛选或 size 后清空游标。无列表权限的模块不返回，审核权限不扩大普通数据范围。

处理用那张单据自己的接口 `POST /api/<单据>/{id}/notices/{noticeId}/handle`（README §4.3），前端用 `upstreamApi.handle(doc, noticeId, remark)`，它按 `doc.type` 找路径。board 只读，不另开写接口。

## 3. 前端要知道的规则

- **概况格子**：大数字点了去列表，三个小数各自点了去筛好的列表。数为 0 时灰色，不为 0 时按下面上色：

| 格子 | 大数字去 | 小数（颜色）→ 地址 |
|---|---|---|
| 开发款式 | `/styles` | 资料包草稿（琥珀），不能点：款式列表没有按资料包筛的条件 |
| 在手订单 | `/orders` | 待审核（琥珀）→ `/orders?status=PENDING`；待排单（琥珀）→ `/orders?unscheduled=1`；变更待审（琥珀）→ `/order-changes?status=PENDING` |
| 在制生产 | `/board` | 已逾期（红）→ `/board?card=LATE`；节点延期（红）→ `/board?card=NODE_LATE`；未关异常（红）→ `/board?card=ISSUE` |
| 在途物料 | `/stock-in?tab=pending` | 到料逾期（红）→ `/stock-in?tab=pending&risk=LATE`；采购待审（琥珀）→ `/purchases?status=PENDING`；算料待确认（琥珀）→ `/mrp?status=DRAFT` |

- **快捷入口**：新建需求订单（`/orders/new`）、新建款式（`/styles/new`）、算料（`/mrp`）、待到料（`/stock-in?tab=pending`）、生产看板（`/board`）、库存（`/stock`）、手机报工（`/mobile`）。只出当前用户有那个菜单（新建的两个再看 `order:order:add`、`style:style:add`）的。
- **待处理事项**：标题后面写一共几项。多于一组时上面一个分段控件："全部 n"和每组"标签 n"（`TODO_GROUP[key].label`、`total`）。"全部"里每组取前 4 条，每条后面一个 `StatusTag`（`TODO_GROUP[key].tone`，文字是组名）；选了一组就列这组的条目，`total > items.length` 时最后一行"还有 n 条"，点了去 `TODO_GROUP_MORE[key]`（null 的不出）。每条：缩略图 36px、`title`（加粗，一行放不下省略）、`sub`（小字）、右箭头，点了 `docRoute(item.ref)`。空的时候"暂无待处理的事"。
- **近期交期**：每行缩略图、种类小标签（`ref.typeLabel`）+ 单号（等宽字体）、`sub`、进度条（`doneQty / totalQty`）、右边"逾期 n 天"（红）或"还有 n 天"（≤ 7 琥珀）。点了 `docRoute(row.ref)`。空的时候"近 7 天没有要交的单"。
- **其他提醒**：一个数一个小块（`TODO_COUNT[key].label` + 数，数按 `tone` 上色），点了去 `TODO_COUNT[key].to`。四种多级待审链接必须带 `auditForMe=1`，KPI 的普通待审核总数则不混成待我审核。加载成功且为空才显示"没有别的要处理"，失败显示重试。
- **上游已变更页**：`FilterBar` 的 `#left` 放分段控件（全部 / 生产单 / 采购单 / 算料单），有"全部"范围的人多一个"我的 / 全部"，没有关键字。表格：勾选、单据（`doc.typeLabel`）、单号（点了 `docRoute(doc)`）、负责人、变更时间（最新一条提醒的时间）、变更内容（每条提醒一行："11-20 BG… ：内容"，变更单号点了 `docRoute(notice.source)`）、"已处理"按钮。点"已处理"弹一个小框写处理说明（选填），确定后只处理当前预览内的提醒（每单最多 100 条），然后重新查询当前页；不得直接移除仍有未处理通知的单据行。勾选后批量条"标成已处理"（逐条、`silent`，没成功的留着勾、报原因）。空表格："没有待处理的上游变更。需求订单的变更单审核后，受影响的生产单、采购单、算料单会列在这里"。
- **地址参数**：普通 KPI 待审用 `/orders?status=PENDING` 等；待我审核用 `/orders?status=PENDING&auditForMe=1`、`/purchases?status=PENDING&auditForMe=1`、`/production?status=PENDING&auditForMe=1`、`/fp-purchases?status=PENDING&auditForMe=1`。其余计划入口有 `/order-changes?status=PENDING`、`/mrp?status=DRAFT`、`/suppliers?toApprove=1`、`/suppliers?certExpiring=1`，须在实现聚合时连同目标筛选一起验收，不因文档列出便声称可达。KeepAlive 列表要监听 query，不能只在 onMounted 读。

## 5. 定了的

1. **获准 ALL 的管理层待办看全部，可以筛**（11-15 需求、RFC 010 明确授权边界）：延期、异常、上游变更、证照按模块权限及 DataScope，ALL 可看全范围并按我的/负责人缩小；审核码本身不扩大可见范围。当前级待我审核使用对象例外与 auditForMe，仍须模块 list（§2.3）。
2. **首页"我的功能"面板去掉，换成原型的快捷入口**（11-15，按推荐）：侧边栏已经列了全部菜单，再列一遍占地方；快捷入口只放最常用的几个动作。
