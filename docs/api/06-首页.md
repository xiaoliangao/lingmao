# 06 首页

首页的概况、待办、近期交期，"上游已变更"页，以及一期设置里还没做的部分（结论：没有）。需求看 PRD §6.9.2（第 5 条待办）、§3.2（数据范围），机制看架构 §3.1（`board` 域）、§4.8（待我审核怎么查），原型是 `docs/原型/src/5a-home-style.js` 的 `/` 和 `/upstream`。

类型在 `web/src/types/home.ts`，接口函数在 `web/src/api/home.ts`。后端都在 `board` 域：只读、跨域查，不写任何表。

## 1. 页面

### 1.1 首页 `/home`

已有的页面 `views/home/index.vue`（组件名 `HomePage`），不是菜单，所有人登录后都到这里。这一期按原型改：

- **页头**：标题"首页"，`#title` 插槽里放今天的日期（"2026 年 11 月 15 日 星期日"），`sub` 照旧是问候语。右边两个按钮：款式库（`/styles`，有 `style:style:list`）、新建需求订单（`/orders/new`，主按钮，有 `order:order:add`）。
- **概况**：四个格子（开发款式、在手订单、在制生产、在途物料），`homeApi.kpi`。
- **快捷入口**：一排图标按钮。
- **待处理事项**（左，占两行高）：`homeApi.todos` 的 `groups`。
- **近期交期**（右上）：`homeApi.deliveries`。
- **其他提醒**（右下）：`homeApi.todos` 的 `counts`。
- **备份情况**：现在页面上给超级管理员的那一行留着，不动。

要去掉的：现在的"我的功能"面板，换成快捷入口（侧边栏已经列了全部菜单，再列一遍没用）。原型里不做的：「待解决的意见」、左下角「批注」、"批注汇总"快捷入口（用户 11-14 定），"下单与回货"趋势图、"在制品类"环形图（报表看板 13.06，二期）。

窄屏（< 900px）一列排：概况、快捷入口、待处理事项、近期交期、其他提醒。

### 1.2 上游已变更 `/upstream`

入口照原型：首页待办里"上游已变更"那一组（点一条去那张单据，"还有 n 条"去这一页），和"其他提醒"里的"上游订单已变更，待处理 n"。不进侧边栏。

- 页面文件 `views/home/upstream.vue`，组件名 `UpstreamPage`。
- 路由：和 `/home` 一样写死在 `router/index.ts` 首页这一侧的 `children` 里（`meta: { title: '上游已变更', cacheName: 'UpstreamPage' }`），所有登录的人都有，内容由后端按负责人筛。不放 `DETAIL_ROUTES`：那里的 `parent` 必须是菜单，`/home` 不是。
- 开页签，页头左上返回首页。

## 2. 接口

### 2.1 总表

| 方法 | 路径 | 权限 | 做什么 |
|---|---|---|---|
| GET | `/api/board/home/kpi` | 登录 | 四个概况格子 |
| GET | `/api/board/home/todos` | 登录 | 待办分组和"其他提醒"的数 |
| GET | `/api/board/home/deliveries` | 登录 | 近期交期 |
| GET | `/api/board/upstream` | 登录 | 上游已变更、待处理 |
| POST | `/api/<单据>/{id}/notices/{noticeId}/handle` | 看得到那张单据 | 处理一条提醒（各单据自己的接口，README §4.3） |

三块分开取：一块慢了、出错了不挡别的。首页 `onActivated` 时三块都重取（现在的页面已经这样）。

"负责人是我"的口径（下面说"给谁"时用）：生产单看生产跟单，采购单看采购员，算料单看制单人，需求订单看跟单员，供应商看负责采购员。**有这类单据审核权限的人（管理层）看全部**，照原型的 `homeMineOr`。

### 2.2 概况 `GET /api/board/home/kpi`

返回 `HomeKpi`，照数据范围数（PRD §3.2：本人范围的看自己相关的单据）。没有那个菜单权限的格子是 null。

| 格子 | 要什么权限 | 大数字 | 三个小数 |
|---|---|---|---|
| 开发款式 | `style:style:list` | 没停用的款数 | 资料包草稿（研发、生产都算）；原型的"打样中""样衣"是二期，不出 |
| 在手订单 | `order:order:list` | 已审核、生产中的订单件数 · 张数 | 待审核、待排单（已审核一件没排）、变更待审（没有 `order:change:list` 是 null） |
| 在制生产 | `production:order:list` | 已下单、生产中的生产单（两种都算）件数（件数 − 已回货）· 张数 | 已逾期、节点延期、未关异常（口径同 05 §2.3） |
| 在途物料 | `purchase:order:list` | 没到齐的采购行数 | 到料逾期（03 待到料的 `LATE`）、采购待审、算料待确认（草稿算料单，没有 `purchase:mrp:list` 是 null） |

### 2.3 待办 `GET /api/board/home/todos`

参数 `HomeTodoQuery`，返回 `HomeTodos`。`groups` 只放有条目的组，按下表的顺序；每组最多 20 条，`total` 是一共几条。`counts` 只放数不为 0 的。

**筛选**（用户 11-15 定：管理层看全部，可以筛）：`canSeeAll` 是 true 的人（有那类单据审核权限的，一般是管理层）默认看全部人的；待办面板顶上出分段控件"全部 / 我的"和负责人下拉（`UserSelect`，清空 = 全部），对应参数 `mine`、`ownerId`。筛了以后待办分组和"其他提醒"的数一起变；"待我审核"一组和审核类的数不受影响（轮到谁审就是谁的）。选的值记在 `localStorage`（读写包 try/catch），下次打开还是这样。`canSeeAll` 是 false 的人不出筛选，只看自己的。`/upstream` 页同样有这两个筛选。

**分组**（PRD §6.9.2 的"给谁"，条目照原型的 `todo`）：

| 组 | 给谁 | 一条是什么（`title` / `sub`） | 点了去 |
|---|---|---|---|
| `AUDIT` 待我审核 | 需求订单、采购单、生产单：多级审批当前这一级是我（架构 §4.8：`status = 'CURRENT'` 且权限、角色、人对得上）；变更单：有 `order:change:audit`；资料包草稿：有 `techpack:pack:publish`；物料入库单、出库单草稿：有 `inventory:doc:audit`；盘点单待审核：有 `inventory:count:audit`；供应商准入、改动待批：有 `supplier:supplier:admit`，自己提的不算 | "需求订单 DD…" / "客户或—· 2,400 件 · 交期 03-10 · 第 2 级"；"外发加工单 JG…" / "加工厂 · 400 件"；"资料包 27CF001 V2" / "款名 · 草稿待生效"；"供应商准入 某面料" / "面料 · 李四 11-14 申请" | 那张单据（资料包去款式的资料包页签，供应商去供应商详情） |
| `PRODUCTION_LATE` 生产延期 | 已逾期或节点延期的生产单，负责人是我 | "JG… 款名" / "加工厂 · 交期 03-10 已过" 或 "加工厂 · 节点「车缝」延期" | 生产单 |
| `CUT_RISK` 赶不上开裁 | 采购员：自己采购单里预计到货晚于要料日期的行（03 待到料 `CUT` 的口径）；生产跟单：自己跟的已下单、生产中的生产单，它的订单有这种行 | 采购员看到采购行："卡其布 还差 120 米" / "CG… · 预计 11-25 到，开裁 11-22"；跟单看到生产单："JG… 款名" / "卡其布 预计 11-25 到，开裁 11-22" | 采购单 / 生产单 |
| `ARRIVAL_LATE` 到料逾期 | 采购行过了交期（有预计到货看预计到货）还没到齐，采购员是我 | "卡其布 还差 120 米" / "CG… · 供应商 · 应到 11-12" | 采购单 |
| `UPSTREAM` 上游已变更 | 没处理的提醒，`owner_id` 是我（有那种单据审核权限的看全部） | "外发加工单 JG…" / 提醒的 `content` | 那张单据（详情顶上有黄条） |
| `UNSCHEDULED` 待排单 | 已审核、一件都没排的需求订单，订单跟单员是我，并且我有 `production:order:add` | "需求订单 DD…" / "1,200 件 · 交期 03-20" | 需求订单 |
| `ISSUE` 异常待处理 | 没关闭的异常，生产单的负责人是我 | "缺料：面料还差 30 米" / "JG… · 张三 上报于 11-20" | 生产单（`ref.type = PRODUCTION_ISSUE`，`parentId` 是生产单） |
| `CERT` 证照将到期 | 30 天内到期的证照，供应商负责人是我 | "某面料 营业执照" / "12-01 到期，还剩 16 天 · 负责人 李四" | 供应商 |

每条带一张缩略图（款式图、物料图；供应商没有）。同一组里按紧急程度排：延期的按逾期天数，审核的按提交时间，提醒按时间，都是旧的在前。

PRD 里的"供应商新增风险"是待排期的（Q22），这一期没有这一组。

**其他提醒的数**（`TodoCountKey`，叫法、地址、颜色在 `TODO_COUNT`）：

| 数 | 数什么、给谁 |
|---|---|
| `ORDER_PENDING`、`PURCHASE_PENDING`、`OUTSOURCE_PENDING`、`BUY_PENDING` | 轮到我审的这种单，和 `AUDIT` 组里的条数一样（点进去是全部待审核的列表） |
| `CHANGE_PENDING`、`STOCK_IN_DRAFT`、`STOCK_OUT_DRAFT`、`COUNT_PENDING`、`SUPPLIER_APPROVE` | 同上，给有对应审核权限的人 |
| `UNSCHEDULED` | 同 `UNSCHEDULED` 组 |
| `PRODUCTION_LATE`、`PRODUCTION_NEAR`、`PRODUCTION_NODE_LATE`、`PRODUCTION_ISSUE` | 负责人是我的已下单、生产中的生产单里，已逾期、临期、节点延期、有异常的张数（05 §2.3） |
| `ARRIVAL_LATE`、`ARRIVAL_CUT` | 采购员是我的采购行（和点进去的待到料列表一个口径；生产跟单不给，跟单的看 `CUT_RISK` 组） |
| `UPSTREAM` | 同 `UPSTREAM` 组 |
| `CERT_EXPIRING` | 同 `CERT` 组 |
| `REORDER` | 补货清单的条数（03 §3.6.1 同一个算法，board 调 purchase 的方法数），给有 `purchase:order:add` 的人 |

### 2.4 近期交期 `GET /api/board/home/deliveries`

返回 `DeliveryRow[]`：今天起 7 天内要交的、和已经逾期还没交的，交期早的在前，最多 8 条，照数据范围。

- 需求订单：已审核、生产中的；交期 = 承诺交期 ?? 要求交期；进度 = 已回货 / 件数。
- 生产单：已下单、生产中的；交期 = 预计交期 ?? 交期；进度同上。

### 2.5 上游已变更 `GET /api/board/upstream`

参数 `UpstreamQuery`，返回 `UpstreamRow[]`：一张下游单据一行，带它所有没处理的提醒。给谁同 `UPSTREAM` 组；`mine = true` 时有审核权限的人也只看自己的。按最新一条提醒的时间倒序，不分页。

处理用那张单据自己的接口 `POST /api/<单据>/{id}/notices/{noticeId}/handle`（README §4.3），前端用 `upstreamApi.handle(doc, noticeId, remark)`，它按 `doc.type` 找路径。board 只读，不另开写接口。

## 3. 前端要知道的规则

- **概况格子**：大数字点了去列表，三个小数各自点了去筛好的列表。数为 0 时灰色，不为 0 时按下面上色：

| 格子 | 大数字去 | 小数（颜色）→ 地址 |
|---|---|---|
| 开发款式 | `/styles` | 资料包草稿（琥珀），不能点：款式列表没有按资料包筛的条件 |
| 在手订单 | `/orders` | 待审核（琥珀）→ `/orders?status=PENDING`；待排单（琥珀）→ `/orders?unscheduled=1`；变更待审（琥珀）→ `/order-changes?status=PENDING` |
| 在制生产 | `/board` | 已逾期（红）→ `/board?card=LATE`；节点延期（红）→ `/board?card=NODE_LATE`；未关异常（红）→ `/board?card=ISSUE` |
| 在途物料 | `/stock-in?tab=pending` | 到料逾期（红）→ `/stock-in?tab=pending&risk=LATE`；采购待审（琥珀）→ `/purchases?status=PENDING`；算料待确认（琥珀）→ `/mrp?status=DRAFT` |

- **快捷入口**：新建需求订单（`/orders/new`）、新建款式（`/styles/new`）、算料（`/mrp`）、待到料（`/stock-in?tab=pending`）、生产看板（`/board`）、库存（`/stock`）、手机报工（`/mobile`）。只出当前用户有那个菜单（新建的两个再看 `order:order:add`、`style:style:add`）的。
- **待处理事项**：标题后面写一共几项。多于一组时上面一个分段控件："全部 n"和每组"标签 n"（`TODO_GROUP[key].label`、`total`）。"全部"里每组取前 4 条，每条后面一个 `StatusTag`（`TODO_GROUP[key].tone`，文字是组名）；选了一组就列这组的条目，`total > items.length` 时最后一行"还有 n 条"，点了去 `TODO_GROUP_MORE[key]`（null 的不出）。每条：缩略图 36px、`title`（加粗，一行放不下省略）、`sub`（小字）、右箭头，点了 `docRoute(item.ref)`。空的时候"暂无待处理的事"。
- **近期交期**：每行缩略图、种类小标签（`ref.typeLabel`）+ 单号（等宽字体）、`sub`、进度条（`doneQty / totalQty`）、右边"逾期 n 天"（红）或"还有 n 天"（≤ 7 琥珀）。点了 `docRoute(row.ref)`。空的时候"近 7 天没有要交的单"。
- **其他提醒**：一个数一个小块（`TODO_COUNT[key].label` + 数，数按 `tone` 上色），点了去 `TODO_COUNT[key].to`。空的时候"没有别的要处理"。
- **上游已变更页**：`FilterBar` 的 `#left` 放分段控件（全部 / 生产单 / 采购单 / 算料单），有"全部"范围的人多一个"我的 / 全部"，没有关键字。表格：勾选、单据（`doc.typeLabel`）、单号（点了 `docRoute(doc)`）、负责人、变更时间（最新一条提醒的时间）、变更内容（每条提醒一行："11-20 BG… ：内容"，变更单号点了 `docRoute(notice.source)`）、"已处理"按钮。点"已处理"弹一个小框写处理说明（选填），确定后把这一行的提醒逐条处理掉，成功的行从表里拿掉。勾选后批量条"标成已处理"（逐条、`silent`，没成功的留着勾、报原因）。空表格："没有待处理的上游变更。需求订单的变更单审核后，受影响的生产单、采购单、算料单会列在这里"。
- **地址参数**：首页点进去的地址，03、04、05 的文档里已经写了；这几个还要各列表页认：`/orders?status=PENDING`、`/order-changes?status=PENDING`（02）、`/mrp?status=DRAFT`（03）、`/suppliers?toApprove=1`、`/suppliers?certExpiring=1`（供应商列表现在不读地址参数）。列表页是 keep-alive 的，要 `watch(() => route.query)`，不能只在 `onMounted` 里读。
