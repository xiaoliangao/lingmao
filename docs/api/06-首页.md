# 06 首页

首页的概况、待办、近期交期，"上游已变更"页，以及一期设置里还没做的部分（结论：没有）。需求看 PRD §6.9.2（第 5 条待办）、§3.2（数据范围），机制看架构 §3.1（`board` 域）、§4.8（待我审核怎么查），原型是 `docs/原型/src/5a-home-style.js` 的 `/` 和 `/upstream`。

类型在 `web/src/types/home.ts`，接口函数在 `web/src/api/home.ts`。后端在 `board` 域（11-19 做完，`BoardController`、`HomeServiceImpl`），只读：每一块问各域自己的列表、条数（Service），条件和点进去的列表一样，数据范围、品类线由各域加，board 只拼文字、排序、截前几条。失败时页面显示失败和重试，不显示默认 0。

## 1. 页面

### 1.1 首页 `/home`

已有页面 `views/home/index.vue`（组件名 `HomePage`），不是菜单；默认电脑入口是这里（有手机入口权限的小屏跳 `/mobile`，05）。布局：

- **页头**：标题"首页"，`#title` 插槽里放东八区今天的日期（"2026 年 11 月 15 日 星期日"），`sub` 照旧是问候语。右边两个按钮：款式库（`/styles`，有 `style:style:list`）、新建需求订单（`/orders/new`，有模块 list 且有 `order:order:add`）。
- **概况**：四个格子（开发款式、在手订单、在制生产、在途物料），`homeApi.kpi`。
- **快捷入口**：一排图标按钮。
- **待处理事项**（左，占两行高）：`homeApi.todos` 的 `groups`。
- **近期交期**（右上）：`homeApi.deliveries`。
- **其他提醒**（右下）：`homeApi.todos` 的 `counts`。
- **备份情况**：现在页面上给超级管理员的那一行留着，不动。

要去掉的：现在的"我的功能"面板，换成快捷入口（侧边栏已经列了全部菜单，再列一遍没用）。原型里不做的：「待解决的意见」、左下角「批注」、"批注汇总"快捷入口（用户 11-14 定），"下单与回货"趋势图、"在制品类"环形图（报表看板 13.06，二期）。

窄屏（< 900px）一列排：概况、快捷入口、待处理事项、近期交期、其他提醒。

### 1.2 上游已变更 `/upstream`

入口照原型：首页待办里"上游已变更"那一组（点一条去那张单据，"还有 n 条"去这一页），和"其他提醒"里的"上游订单已变更，待处理 n"。不进侧边栏。

- 页面文件 `views/home/upstream.vue`，组件名 `UpstreamPage`。

## 2. 接口

### 2.1 总表

| 方法 | 路径 | 权限 | 做什么 |
|---|---|---|---|
| GET | `/api/board/home/kpi` | 登录及各块模块权限 | 四个概况格子 |
| GET | `/api/board/home/todos` | 登录及各块模块权限 | 待办分组和"其他提醒"的数 |
| GET | `/api/board/home/deliveries` | 登录及各块模块权限 | 近期交期 |
| GET | `/api/board/upstream` | 登录及各块模块权限 | 上游已变更、待处理 |
| POST | `/api/<单据>/{id}/notices/{noticeId}/handle` | 看得到那张单据 | 处理一条提醒（各单据自己的接口，README §4.3） |
| GET | `/api/reports/…` | 各报表自己的权限 | 报表，见 §2.6 |

三块分开取：一块慢了、出错了不挡别的；各自有加载、空态、失败重试状态，失败不显示默认 0。首页 `onActivated` 可重取这些只读聚合。

"负责人是我"的口径（mine/ownerId 进一步筛选时用）：生产单看生产跟单，采购单看采购员，算料单看制单人，需求订单看跟单员，供应商看负责采购员。普通 KPI、延期、异常、证照、上游提醒先按各域 DataScope；只有数据范围是"全部"（`data:all`）的用户可看全范围、可筛负责人，**审核码不等于 data:all**。别的人传 `mine`、`ownerId` 都按"负责人是我"算。原型 `homeMineOr` 以审核权限扩大普通可见范围的做法不作为授权依据。

### 2.2 概况 `GET /api/board/home/kpi`

返回 `HomeKpi`，照数据范围数（PRD §3.2：本人范围的看自己相关的单据）。没有那个菜单权限的格子是 null。

| 格子 | 要什么权限 | 大数字 | 三个小数 |
|---|---|---|---|
| 开发款式 | `style:style:list` | 没停用的款数（草稿 + 启用） | 资料包草稿（11-18 起只有生产 BOM）；原型的"打样中""样衣"是二期，不出 |
| 在手订单 | `order:order:list` | 已审核、生产中的订单件数 · 张数 | 待审核、待排单（已审核一件没排）、变更待审（没有 `order:change:list` 是 null） |
| 在制生产 | `production:order:list` | 已下单、生产中的生产单（两种都算）件数（件数 − 已回良品）· 张数 | 已逾期、节点延期、未关异常（口径同 05 §2.3） |
| 在途物料 | `purchase:order:list` | 没到齐的采购行数 | 到料逾期（03 待到料的 `LATE`）、采购待审（全部待审核，不只轮到我的）、算料待确认（草稿算料单，没有 `purchase:mrp:list` 是 null） |

### 2.3 待办 `GET /api/board/home/todos`

参数 `HomeTodoQuery`，返回 `HomeTodos`。`groups` 只放有条目的组，按下表的顺序；每组最多 20 条，`total` 是一共几条。`counts` 只放数不为 0 的。

**筛选**：`canSeeAll` 根据真实 ALL 数据范围与可访问模块计算，不根据审核码。获准 ALL 的用户默认看各模块获准范围，可用"全部 / 我的"和负责人下拉（`mine`、`ownerId`）进一步缩小；其他用户仍按各域 DataScope。跨域每组独立裁定，不能因一组可见全部而扩大其他组。筛选影响普通组及普通提醒数；"待我审核"和审核类计数只按当前级匹配，不叠加普通负责人筛选。选项可记 localStorage（try/catch），恢复时仍以后端权限为准；`/upstream` 同口径。

**分组**（PRD §6.9.2 的"给谁"，条目照原型的 `todo`）：

| 组 | 给谁 | 一条是什么（`title` / `sub`） | 点了去 |
|---|---|---|---|
| `AUDIT` 待我审核 | 需求订单、采购单、生产单：有模块 list、当前级匹配调用人，与对应列表 auditForMe 相同；变更单（`order:change:audit`）、资料包草稿（`techpack:pack:publish`）、物料入库 / 出库单草稿（`inventory:doc:audit`）、待审核的盘点单（`inventory:count:audit`）、待我审批的供应商（`supplier:supplier:admit`，列表 `toApprove` 同一个条件，自己的申请不算）各要模块 list 加上这个动作权限，范围按各自列表 | "需求订单 DD…" / "27CF001 等 2 个款 · 2,400 件 · 交期 03-10"；"采购单 CG…" / "供应商 · 3 种料 · 交期 11-25"；"外发加工单 JG…" / "加工厂 · 款名 · 400 件"；"订单变更单 BG…" / "DD… · 改数量"；"资料包 27CF001 V2" / "款名 · 草稿待生效"；"物料入库单 RK…" / "仓库 · 3 种料"；"物料盘点单 PD…" / "仓库 · 范围"；"供应商准入 某面料"或"供应商资料变更 某面料" / "面料 · 负责人 李四" | 那张单据（资料包去款式的资料包页签，供应商去供应商详情） |
| `PRODUCTION_LATE` 生产延期 | 已逾期或节点延期的生产单，负责人是我 | "JG… 款名" / "加工厂 · 交期 03-10 已过" 或 "加工厂 · 节点「车缝」延期" | 生产单 |
| `CUT_RISK` 晚于开裁 | 采购员：自己采购单里预计到货晚于要料日期的行（03 待到料 `CUT` 的口径）；生产跟单：自己跟的已下单、生产中的外发加工单，它的订单有这种行（成品采购单包工包料，不列）。两种人的条目合在一组，组上的数是两者相加，所以全部权限的人这里的数会比"其他提醒"的"到料晚于开裁"（只数采购行）大 | 采购员看到采购行："卡其布 还差 120 米" / "CG… · 预计 11-25 到，开裁 11-22"；跟单看到生产单："JG… 款名" / "卡其布 预计 11-25 到，开裁 11-22" | 采购单 / 生产单 |
| `ARRIVAL_LATE` 到料逾期 | 采购行过了交期（有预计到货看预计到货）还没到齐，采购员是我 | "卡其布 还差 120 米" / "CG… · 供应商 · 应到 11-12" | 采购单 |
| `UPSTREAM` 上游已变更 | 可访问模块及 DataScope 内没处理的提醒，再按 mine/ownerId 筛负责人；审核权限不扩大范围 | "外发加工单 JG…" / 提醒的 `content` | 那张单据（详情顶上有黄条） |
| `UNSCHEDULED` 待排单 | 已审核、一件都没排的需求订单，订单跟单员是我，并且我有 `production:order:add` | "需求订单 DD…" / "1,200 件 · 交期 03-20" | 需求订单 |
| `ISSUE` 异常待处理 | 没关闭的异常，生产单的负责人是我 | "缺料：面料还差 30 米" / "JG… · 张三 上报于 11-20" | 生产单（`ref.type = PRODUCTION_ISSUE`，`parentId` 是生产单） |
| `CERT` 证照将到期 | 30 天内到期的证照，供应商负责人是我（供应商列表 `certExpiring` 同一个条件） | "某面料" / "最早一张 12-01 到期，还剩 16 天 · 负责人 李四" | 供应商 |

每条带一张缩略图（款式图、物料图；供应商、变更单、盘点单没有）。同一组里按紧急程度排：延期的按逾期天数，审核的按建单时间（列表行上没有提交时间，几种单据合起来排），提醒按时间，都是旧的在前。

上表普通组的"负责人是我"是 mine=true 的口径；ALL 的默认视图可包含其获准范围内的其他负责人，SELF 则始终受各域归属条件约束。不能通过把 mine=false 或 ownerId 清空扩大权限。

PRD 里的"供应商新增风险"是待排期的（Q22），这一期没有这一组。

**其他提醒的数**（`TodoCountKey`，叫法、地址、颜色在 `TODO_COUNT`）：

| `CHANGE_PENDING`、`STOCK_IN_DRAFT`、`STOCK_OUT_DRAFT`、`COUNT_PENDING`、`SUPPLIER_APPROVE` | 既有模块访问、审核动作和数据范围的交集，与目标列表可处理集合一致；前四个不含自己建的（Q10），跳目标列表时带 `auditForMe=1`，两边的数一样 |
| `UNSCHEDULED` | 同 `UNSCHEDULED` 组 |

### 2.4 近期交期 `GET /api/board/home/deliveries`

返回 `DeliveryRow[]`：今天起 7 天内要交的、和已经逾期还没交的，交期早的在前，最多 8 条，照数据范围。

- 需求订单：已审核、生产中的；交期 = 承诺交期 ?? 要求交期；进度 = 已回货 / 件数（已回货只算良品，生产单也一样）。
- 生产单：已下单、生产中的；交期 = 预计交期 ?? 交期；进度同上。

### 2.5 上游已变更 `GET /api/board/upstream`

参数 `UpstreamQuery`，返回 `UpstreamList { canSeeAll, rows }`。`canSeeAll` 按真实数据范围（§2.3），页面用它决定筛选入口；`rows` 是 `UpstreamRow[]`，一张下游单据一行，带其获准查看的未处理提醒。每组先校验模块权限/DataScope，再按 mine/ownerId 缩小，审核权限不另开全部视图。按最新一条提醒的时间倒序，不分页。

处理用那张单据自己的接口 `POST /api/<单据>/{id}/notices/{noticeId}/handle`（README §4.3），前端用 `upstreamApi.handle(doc, noticeId, remark)`，它按 `doc.type` 找路径。board 只读，不另开写接口。

### 2.6 报表 `/api/reports`（11-27，RFC 019 §3）

类型在 `web/src/types/report.ts`，接口函数在 `web/src/api/report.ts`，后端 `ReportController`、`ReportServiceImpl`（`board` 域，只读 SQL 现算）。数据范围按品类线。页面在侧边栏"报表"目录（V63）：预警中心 `/alerts`、供应商绩效 `/supplier-performance`、在做件数 `/line-wip`、订单毛利 `/order-margin`、呆滞料 `/stale-materials`。

| 方法 | 路径 | 权限 | 做什么 |
|---|---|---|---|
| GET | `/supplier-performance/materials?from&to&keyword` | `report:supplier:list` | 物料供应商的采购到货及时率，`PerfResult<PurchasePerfRow>`：`rows` 一个供应商一行，`total` 合计 |
| GET | `/supplier-performance/factories?from&to&keyword` | `report:supplier:list` | 加工厂的交期达成率（按单、按件）、次品率，`PerfResult<FactoryPerfRow>` |
| GET | `/line-wip?month=2026-12` | `report:wip:list` | 各品类线 × 一级品类在做件数，`LineWipRow[]`；`month` 不传是这个月 |
| GET | `/stale-materials?days&warehouseId&keyword&page&size` | `report:stale:list` | 呆滞料，分页；`days` 不传按默认 |
| GET | `/stale-materials/export` | `report:stale:export` | 导出，条件同上 |
| GET | `/stale-materials/days` | `report:stale:list` | 默认呆滞天数（`sys_config` 的 `report.stale_days`，没设是 90） |
| PUT | `/stale-materials/days` `{ days }` | `report:stale:edit` | 改默认天数（1-3650） |
| GET | `/order-margins?from&to&keyword&productLine&page&size` | `report:margin:list` + `order:price:query` + `techpack:cost:query` | 订单毛利，`OrderMarginPage`：这一页的单和全部单的合计（合计只算人民币的单，`foreignOrders` 是外币单张数） |

- `from`、`to` 必填，`from` 不能晚于 `to`，最长一年（400）。订单毛利一次超过 2000 张单报 1000"请缩小日期范围"。
- 百分数（及时率、次品率、毛利率）是一位小数的数，没得算是 null。
- 预警中心不另开接口，用 §2.3 的待办（去掉 `AUDIT` 组，只取预警类的数）。

### 2.7 消息推送 `/api/admin/notify` 和手机待办（11-27，RFC 019 §4）

钉钉推送"单据被驳回""货期预警"（甲方 11-27 答 Q65）。类型在 `web/src/types/notify.ts`，接口函数在 `web/src/api/notify.ts`，后端 `NotifyController`、`NotifyServiceImpl`（`system` 域）。都只给超级管理员（`@superAdmin`），页面在管理后台 › 系统管理 › 消息推送（V64，`system/notify/index`）。

| 方法 | 路径 | 做什么 |
|---|---|---|
| GET | `/api/admin/notify` | `NotifySettings`：钉钉配好没有（`configured`）、配了外网地址没有（`linkConfigured`）、两种消息各自开没开（`events`）、没发出去的条数（`failedCount`） |
| PUT | `/api/admin/notify/events` `{ events: ['DOC_REJECTED', 'DUE_WARNING'] }` | 改推哪几种，空数组 = 都不推；不认识的名字 400 |
| GET | `/api/admin/notify/messages?failed&page&size` | 最近的消息，新的在前；`failed=true` 只看没发出去的（死信）。`errorCode` 是最近一次失败的原因：`NOT_CONFIGURED`、`NO_RECIPIENT`、`REMOTE_REJECTED`、`TEMPORARY_FAILURE` |
| POST | `/api/admin/notify/messages/{id}/retry` | 没发出去的（`DEAD_LETTER`、`CANCELLED`）重发；还在发、发出去了的 1000 |
| POST | `/api/admin/notify/test` | 给自己发一条测试消息，当场发；返回"已发到 xx 的钉钉"，不通的 1000、带钉钉的原话 |

手机待办（`/mobile-todo`，菜单权限 `report:mobile:list`，单独成页）不另开接口：列表用 §2.3 的待办（"待我审核"组 + 预警类的组和数），单据页用各单据自己的详情和状态动作接口（需求订单审核是 `POST /api/orders/{id}/audit`，带承诺交期）。钉钉消息里的链接：驳回是 `/mobile-todo/{id}?type=ORDER`（电脑版要的 `kind`、`parentId` 也带上），货期预警是 `/mobile-todo?tab=alerts`。

## 3. 前端要知道的规则

- **概况格子**：大数字点了去列表，三个小数各自点了去筛好的列表。数为 0 时灰色，不为 0 时按下面上色：

| 格子 | 大数字去 | 小数（颜色）→ 地址 |
|---|---|---|
| 开发款式 | `/styles` | 资料包草稿（琥珀），不能点：款式列表没有按资料包筛的条件 |
| 在手订单 | `/orders` | 待审核（琥珀）→ `/orders?status=PENDING`；待排单（琥珀）→ `/orders?unscheduled=1`；变更待审（琥珀）→ `/order-changes?status=PENDING` |
| 在制生产 | `/board` | 已逾期（红）→ `/board?card=LATE`；节点延期（红）→ `/board?card=NODE_LATE`；未关异常（红）→ `/board?card=ISSUE` |
| 在途物料 | `/stock-in?tab=pending` | 到料逾期（红）→ `/stock-in?tab=pending&risk=LATE`；采购待审（琥珀）→ `/purchases?status=PENDING`；算料待确认（琥珀）→ `/mrp?status=DRAFT` |

- **快捷入口**：新建需求订单（`/orders/new`）、新建款式（`/styles/new`）、算料（`/mrp`）、待到料（`/stock-in?tab=pending`）、生产看板（`/board`）、库存（`/stock`）、手机报工（`/mobile`）。只出当前用户有那个菜单（新建的两个再看 `order:order:add`、`style:style:add`）的。
- **待处理事项**：标题后面写一共几项。多于一组时上面一个分段控件："全部 n"和每组"标签 n"（`TODO_GROUP[key].label`、`total`）。"全部"里每组取前 4 条，每条后面一个 `StatusTag`（`TODO_GROUP[key].tone`，文字是组名）；选了一组就列这组的条目，`total > items.length` 时最后一行"还有 n 条"，点了去 `TODO_GROUP_MORE[key]`（null 的不出）。每条：缩略图 36px、`title`（加粗，一行放不下省略）、`sub`（小字）、右箭头，点了 `docRoute(item.ref)`。空的时候"暂无待处理的事"。
- **近期交期**：每行缩略图、种类小标签（`ref.typeLabel`）+ 单号（等宽字体）、`sub`、进度条（`doneQty / totalQty`）、右边"逾期 n 天"（红）或"还有 n 天"（≤ 7 琥珀）。点了 `docRoute(row.ref)`。空的时候"近 7 天没有要交的单"。
- **其他提醒**：一个数一个小块（`TODO_COUNT[key].label` + 数，数按 `tone` 上色），点了去 `TODO_COUNT[key].to`。待审核的链接（四种多级审批，加上变更单、物料入库 / 出库单、盘点单）都带 `auditForMe=1`，KPI 的普通待审核总数则不混成待我审核。加载成功且为空才显示"没有别的要处理"，失败显示重试。
- **上游已变更页**：`FilterBar` 的 `#left` 放分段控件（全部 / 生产单 / 采购单 / 算料单），有"全部"范围的人多一个"我的 / 全部"，没有关键字。表格：勾选、单据（`doc.typeLabel`）、单号（点了 `docRoute(doc)`）、负责人、变更时间（最新一条提醒的时间）、变更内容（每条提醒一行："11-20 BG… ：内容"，变更单号点了 `docRoute(notice.source)`）、"已处理"按钮。点"已处理"弹一个小框写处理说明（选填），确定后把这一行的提醒逐条处理掉，成功的行从表里拿掉。勾选后批量条"标成已处理"（逐条、`silent`，没成功的留着勾、报原因）。空表格："没有待处理的上游变更。需求订单的变更单审核后，受影响的生产单、采购单、算料单会列在这里"。
- **地址参数**：普通 KPI 待审用 `/orders?status=PENDING` 等；待我审核用 `/orders?status=PENDING&auditForMe=1`、`/purchases?status=PENDING&auditForMe=1`、`/production?status=PENDING&auditForMe=1`、`/fp-purchases?status=PENDING&auditForMe=1`。`/order-changes?status=PENDING&auditForMe=1`、`/stock-in?tab=docs&status=DRAFT&auditForMe=1`、`/stock-out?status=DRAFT&auditForMe=1`、`/stock-takes?status=PENDING&auditForMe=1` 也一样。其余入口 `/mrp?status=DRAFT`、`/suppliers?toApprove=1`、`/suppliers?certExpiring=1`，目标列表都认这些参数。KeepAlive 列表要监听 query，不能只在 onMounted 读。

## 5. 定了的

1. **获准 ALL 的管理层待办看全部，可以筛**（11-15 需求、RFC 010 明确授权边界）：延期、异常、上游变更、证照按模块权限及 DataScope，ALL 可看全范围并按我的/负责人缩小；审核码本身不扩大可见范围。当前级待我审核使用对象例外与 auditForMe，仍须模块 list（§2.3）。
2. **首页"我的功能"面板去掉，换成原型的快捷入口**（11-15，按推荐）：侧边栏已经列了全部菜单，再列一遍占地方；快捷入口只放最常用的几个动作。
