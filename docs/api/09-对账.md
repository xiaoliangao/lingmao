# 09 对账

供应商对账单、扣款登记、和对方的 Excel 对账单比对（二期第一版，M11 的 11.01 供应商对账、11.05 扣款）。需求看 PRD §2.5 的 M11 和 §9.5，设计看 RFC 019 §5（甲方 11-27 答 Q68），表看数据库设计 §19.1、§19.5。

类型在 `web/src/types/settle.ts`，接口函数在 `web/src/api/settle.ts`（`statementApi`、`deductionApi`）。

## 1. 页面

### 1.1 菜单

顶层目录"对账结算"（`/settle`，图标 `Wallet`，排 55，成品后面、报表前面）：

| 菜单 | 地址 | 页面文件 | 权限码 | 排 |
|---|---|---|---|---|
| 供应商对账 | `/statements` | `views/settle/statement/index.vue` | `settle:statement:list` | 10 |
| 扣款登记 | `/deductions` | `views/settle/deduction/index.vue` | `settle:deduction:list` | 20 |

详情（`DETAIL_ROUTES`）：`/statements/:id`，`views/settle/statement/detail.vue`。`docRoute` 认 `STATEMENT`。

### 1.2 按钮权限码

| 权限码 | 管什么 |
|---|---|
| `settle:statement:list` | 看对账单、待对账 |
| `settle:statement:edit` | 生成、刷新、移出、加扣款、上传对方对账单比对、写差异说明、发送、撤回、作废 |
| `settle:statement:confirm` | 确认 |
| `settle:deduction:list` | 看扣款登记 |
| `settle:deduction:edit` | 登记、改、删扣款 |

角色模板：理单、财务、总经理给全部；生产经理只看两个 `:list`；跟单只有扣款登记（`settle:deduction:list`、`:edit`，延期扣款常是跟单登记）；采购不给（V66）。对账单、扣款上的金额（`price`、`amount`、`totalAmount`、`deductAmount`、`payableAmount`、`theirAmount`，比对结果的 `theirGoods`、`theirDeduct`、`theirTotal`、`ourTotal`、`diff`、`diffAmount`……）跟着 `settle:statement:list`、`settle:deduction:list` 走，不看成本、加工价的字段权限（`FieldPermissions.SETTLE`）——对账单上有物料采购价，给角色勾对账单时要想到这一点。数据范围：对账单、扣款按制单人（"本人"范围的只看自己生成的）；"待对账"和生成按供应商拉单据，**不按入库单、回货单的制单人限**（对账就是对整家的账）。品类线：对账单（待对账、生成、列表、详情、导出）要这家供应商做的线**我全都能看**，不然待对账、列表里没有，生成回 1000，详情 404；回货只拉生产单在我的线里的；扣款登记和供应商一样，有交集就行。

### 1.3 页面长什么样

- **供应商对账**：页头「生成对账单」（选主体、供应商、期间，期间默认上个月）。分段「对账单 / 待对账」：
  - 对账单：单号、供应商、主体、期间、货款、扣款、实付、比对（全部一致 / n 处不一致 / —）、状态；筛状态、供应商、期间，"我的 / 全部"。点行进详情。
  - 待对账：主体 × 供应商 × 月份，单据几张、实付（估）；「生成对账单」直接生成整月，「改期间再生成」打开生成对话框。
- **对账单详情**：上面货款、扣款、实付（比对过的再加对方合计）；明细表（类型、日期、单号点进源单、送货单号、订单号、摘要、单位、数量、单价，没单价标「缺单价」、金额、扣款），草稿能勾选移出；比对过的下面是比对结果（默认只列不一致的，每处写说明，「保存说明」）；右边对账单信息、对方的对账单原件、操作记录。页头按 `actions`：作废、撤回、刷新、加扣款、导出、上传对方对账单、发送、确认。
- **扣款登记**：日期、扣谁的、主体、金额、原因、相关单号、对账单（进了哪张、状态）、登记人；分段「全部 / 没对账 / 已进对账单」。进了对账单的不出改、删。

## 2. 对账单

基础路径 `/api/statements`。写操作要带对账单的主体（`X-Company-Id`）：生成从请求体的 `companyId` 取，详情页用 `bindCompanyApi`。

### 2.1 列表、待对账、详情

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/statements` | 列表，新的在前。`StatementQuery`：`status`（几个一起查，不传是全部含已作废）、`companyId`、`partnerId`、`periodFrom`、`periodTo`（期间有重叠的）、`keyword`（对账单号、供应商的编码、名称、简称）、`mine`。行上 `theirAmount` 是对方合计、`diffCount` 是不一致几处，没比对过两个都是 `null` |
| GET | `/api/statements/pending` | 待对账：`companyId`、`partnerId` 选填；按主体 × 供应商 × 月份，新的月份在前，最多 500 组 |
| GET | `/api/statements/{id}` | 详情 `StatementDetail`：明细、合计、比对结果、`actions` |
| GET | `/api/statements/{id}/logs` | 操作记录 |
| GET | `/api/statements/{id}/their-files` | 对方对账单的原件（最近一次比对传的） |
| GET | `/api/statements/{id}/export` | 导出 Excel（类型、日期、单号、送货单号、订单号、摘要、单位、数量、单价、金额、扣款，最后两行合计、实付）。原样传回来也能比对 |

`actions`：`refresh` 刷新、`removeItems` 移出、`addDeduction` 加扣款、`compare` 上传对方对账单、`notes` 写差异说明、`send` 发送、`withdraw` 撤回、`confirm` 确认、`void` 作废。草稿有前五个（`notes` 要比对过）和发送（有明细才有）、作废；已发送有比对、写说明、撤回、确认；已确认、已作废没有。没有 `settle:statement:edit` 只剩确认（有确认权限时）。

### 2.2 生成、改草稿

| 方法 | 路径 | 请求体 | 返回 | 说明 |
|---|---|---|---|---|
| POST | `/api/statements` | `{ companyId, partnerId, periodStart, periodEnd, remark? }` | `{ id, no, version, added }` | 拉进这段时间里这家还没进对账单的：已审核的采购入库、采购退货（一行一条明细，按采购单位，退货是负的）、已登记的回货（一张一行，单价取生产单的，次品按单价扣）、扣款登记。一张都没有回 1000；期间超过一年、起在今天以后回 400 |
| POST | `/api/statements/{id}/refresh` | `{ version }` | `{ id, no, version, added }` | 草稿：这段时间里后来审核的单据加进来 |
| POST | `/api/statements/{id}/remove-items` | `{ version, itemIds }` | 新的 `version` | 草稿：移出几行，单据回到待对账 |
| POST | `/api/statements/{id}/deductions` | `{ version, bizDate?, amount, reason, refNo? }` | 新的 `version` | 草稿：登记一条扣款（主体、供应商取对账单的；日期要在期间里、不晚于今天，不传是期间止和今天里早的那个）并加进来 |

明细变了（刷新、移出、加扣款），合计重算，比对结果清掉。

### 2.3 状态动作

`POST /api/statements/{id}/{action}`，请求体 `{ version, reason? }`，返回空：

| 动作 | 从 → 到 | 说明 |
|---|---|---|
| `send` | 草稿 → 已发送 | 空的回 1000 |
| `withdraw` | 已发送 → 草稿 | 对方有异议，改了再发；发送人、发送时间清掉（经过在操作记录里） |
| `confirm` | 已发送 → 已确认 | 要 `settle:statement:confirm`；`reason` 是确认时写的一句。比对过的，每处差异都写了说明才能确认，不然 1000，`data` 是没写说明的清单（`string[]`） |
| `void` | 草稿 → 已作废 | `reason` 是原因。明细全部放开，单据、扣款回到待对账 |

已确认的不能改、不能作废：差错另开单冲回（多入了开采购退货、少扣了登记扣款），进下个月的对账单。

### 2.4 和对方的对账单比对

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/statements/{id}/compare` | multipart：`file`（.xls、.xlsx，大小和行数照导入的上限）、`version`。草稿、已发送能传。返回 `CompareResult`，同时存在对账单上，原件存附件 |
| PUT | `/api/statements/{id}/compare/notes` | `{ version, notes: [{ key, note }] }`，只改传了的几处，`note` 空是清掉；返回新的 `version` |

读表：在每个没隐藏的工作表前 30 行里找表头——有金额类的列（金额、小计、货款、总额、应付……），再有单号、日期、品名、数量里的一个。认不出回 1000，说要哪几列。合计、小计、实付、应付、余额行跳过（写在单号列、或单号旁边写着"小计"的也算）；有"扣款"类的列（"扣款原因""扣款说明"不算，当备注）或摘要里有扣款、罚款、索赔这类词的算扣款；摘要里有退货、退回的金额记负数，金额写了负数的数量也记负；没写金额的用数量 × 单价；有单号、有数量、金额是 0 的行也读；金额按分四舍五入。单号、日期、品名纵向合并的格子取合并区第一行的值。单号认"单号""单据号""票号"和单独的"编号"（"No.""客户编号"不认），几列都有取左边先写了的。日期认 Excel 日期、`2026-10-05`、`2026/10/5`、`20261005`、`10-5`、`10月5日`（没写年份的取离对账期间最近的一年）。

比法：两边都按单据合起来（对方一张送货单好几行、我方一张入库单好几行都行；对方单号写的是我方采购单号、生产单号的，按单号 + 日期分开，一次送货一张）。先按单号（我方单号、送货单号；对不上再认只对得上一张的采购单号、生产单号），再按日期前后 3 天内数量一样，再按日期前后 3 天内金额一样；回货对方写的是扣了次品的也认。扣款合起来比一处。差 0.01 元以内算一致。

`CompareResult`：`fileName`、`comparedAt`、`comparedBy`、`comparedByName`、`sheetName`、`theirRowCount`、`theirGoods`、`theirDeduct`、`theirTotal`（对方实付）、`ourTotal`、`diff`（对方 − 我方）、`rows`。每一处 `{ key, outcome, their, ours, diffQty, diffAmount, note }`：`outcome` 是 `MATCH` 一致 / `DIFF` 不一致 / `THEIRS_ONLY` 对方有我方没有 / `OURS_ONLY` 我方有对方没有；`their` 是 `{ rowNos, no, date, description, qty, amount, deduct }`（`rowNos` 是 Excel 里的第几行），`ours` 是 `{ sourceType, sourceId, no, deliveryNo, date, description, qty, amount }`。各处的 `diffAmount` 加起来 = `diff`。

照片、PDF 识别没做（等第三方账号，RFC 019 §5.4）。

## 3. 扣款登记

基础路径 `/api/deductions`：

| 方法 | 路径 | 请求体 / 参数 | 说明 |
|---|---|---|---|
| GET | `/api/deductions` | `companyId`、`partnerId`、`dateFrom`、`dateTo`、`settled`（true 已进没作废的对账单，false 还没对）、`keyword`（原因、相关单号、供应商的编码、名称、简称） | 日期新的在前，带进了哪张对账单（`statementId`、`statementNo`、`statementStatus`） |
| POST | `/api/deductions` | `{ companyId, partnerId, bizDate, amount, reason, refNo? }` | 返回 id。日期不能晚于今天，金额大于 0、两位小数 |
| PUT | `/api/deductions/{id}` | 同上加 `version` | 返回新的 `version`。不能换主体（400）；进了没作废的对账单回 1000（说是哪张、怎么办） |
| DELETE | `/api/deductions/{id}` | — | 进了没作废的对账单回 1000 |

## 4. 别的模块受的影响

- 采购入库单、采购退货单进了没作废的对账单，**反审核**回 1005（`data` 是对账单）；回货单进了，**作废**回 1005。详情页的"反审核"按钮这时不出。要改先把对账单作废，或者在草稿上移出那几行。
- `BizType` 加 `STATEMENT`（对账单，单号前缀 DZ），"下游单据"页签里能看到。
