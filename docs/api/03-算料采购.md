# 03 算料和采购

算料单、采购单、待到料、齐料状态、补货提醒。需求看 PRD §6.6.1-§6.6.3、§6.6.7、§6.10，机制看架构 §5.4（软占用）、§4.8（多级审批），表看数据库设计 §12（`mrp_*`、`pur_*`）。

类型在 `web/src/types/purchase.ts`，接口函数在 `web/src/api/purchase.ts`。物料 SKU 的显示字段（编码、名称、颜色、图）是 `types/inventory.ts` 的 `MaterialSkuBrief`，各行 `extends` 它。

"待到料"是物料入库单页的第一个页签（04），但数据在采购这边，接口写在本文 §3.4。

### 1.4 页面长什么样

照原型 `docs/原型/src/5c-material.js`（算料、采购）和 `5e-price.js` 的 `/reorder`。用真组件重写，结构如下。

**算料列表 `/mrp`**：`PageHeader` 右边两个按钮"备料比"（`purchase:mrp:edit`，对话框改各物料类型的备料比）和"选订单算料"（`purchase:mrp:add`）。`FilterBar`：分段控件按状态（全部 / 草稿 / 已确认 / 已关闭），筛选里放制单人、算料日期，"我的 / 全部"。列：单号、订单、款式、要买（`buyCount` 种）、转采购（`convertedCount / buyCount` 进度）、要料日期、制单人、日期、状态（有 `nextCalcNo` 时状态后面写"→ SL…"，点了去新单）。

**选订单算料**：对话框，`MrpOrderOption` 分页表格，能搜、一次勾多条；每行后面列它算过的算料单（`calcs`），提醒别重复算。点"算料"建一张草稿，跳到详情。

**算料单详情 `/mrp/:id`**：

- 页头按钮按 `actions`：确认、生成采购单（对勾选的行）；更多里放重新算料、关闭、删除。
- 顶上：订单、款号、要料日期、预计金额、已转采购金额；`prevCalcNo` 有值时写"由 SL… 重新算料"，`nextCalcNo` 有值时出黄条"已经重新算料成 SL…（草稿），那张确认后这张自动关闭"。
- "和上一张比"块：`diff` 不是 null 才出，列物料、上一张需求、这一张需求、变化（+ 绿、− 红）。`diff` 是空数组写"需求没变"。
- "自购"表（`block = 'PURCHASE'`）：勾选列（`canConvert` 的才能勾）、物料、供应商、毛需求、备料比、需求、可用库存、本次用库存、可用在途、本次用在途、赶不上的在途、净需求、建议采购（采购单位）、参考单价、预计金额、已转采购、齐料（`shortQty` 0 写"齐"，否则"差 n"）。点"本次用在途"展开 `transitUses`（哪张采购单、预计到货、用了多少、到了多少），点"赶不上的在途"展开 `lateTransits`。
- "厂购"表（`block = 'FACTORY'`）：物料、毛需求、需求，只看。
- 侧栏：属性、附件、操作记录。

**采购列表 `/purchases`**：页头"新建采购单"。分段控件按状态（全部 / 草稿 / 待审核 / 已审核 / 部分到货 / 已到齐 / 已结案 / 已作废）。筛选：采购类型、供应商、采购员、下单日期，"我的 / 全部"。列：单号、供应商（`supplierStatus` 不是 `ACTIVE` 时后面标"供应商已停用"）、类型、物料（第一行 + "等 n 种"）、金额、下单日期、交期、到货（`receivedQty / totalQty` 进度，草稿、待审核、已作废写"—"）、采购员、状态。勾选后批量条：提交、审核、导出选中。

**采购单表单**：照原型 `PurchaseForm`。单头：供应商、采购类型、主体公司（必填，默认我的默认主体，README §3.3）、采购员、下单日期、交货日期、交货地点、结算方式、税率、含税、含运、计划用于款号（只有备货采购出）。明细：物料、采购单位、数量、单价（和 `archivePrice` 不一样时琥珀色，下面小字"档案 18.50"）、改价原因、金额、行交期、预计到货。"从物料库选"用 `DataPick kind="sku"`，已在单上的灰掉。附件建好以后传。

**采购单详情 `/purchases/:id`**：页头按 `actions`：编辑、提交、审核 / 驳回（不是这一级的审批人看到"现在等××审"）、到货入库；更多里放退货、撤回、反审核、结案、取消结案、打印、删除、作废。正文：明细表（数量、单价、金额、已入库、已退货、冲抵、未入库、行交期、预计到货、来源订单 / 款号；"冲抵"列只在有冲抵的单上出，见 §3.3.9）、"入库 / 退货"块（`stockDocs`，点单号用 `docRoute`）。侧栏：属性、审批块、附件、操作记录。

**补货提醒 `/reorder`**：照原型 `5e-price.js` 的 `/reorder`。表格带勾选：物料、供应商（下拉，默认 `defaultSupplierId`，没有写"物料没设默认供应商"）、库存、在途、已被占用、最小库存、差多少、补货量（能改，采购单位）、单价、已开的备货单（`openDrafts`，点单号去采购单）。有 `openDrafts` 的行默认不勾。页头"生成备货采购单（n）"。

## 2. 状态

### 2.1 算料单

不是 `DocStatus`，自己一套（`MrpStatus`）：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改行、删行、确认、重新算料（就地重算）、删除、生成采购单（先自动确认） |
| `CONFIRMED` | 已确认 | `active` | 换供应商、生成采购单、重新算料（另算一张新单）、关闭。它用的库存、在途和它生成的采购单都算占着（软占用） |
| `CLOSED` | 已关闭 | `closed` | 只读。占用释放。关闭原因见 `closeReason` |

关闭有三种原因：订单的生产单都领完料（`ISSUED`，05 领料时回写，自动）、手动关闭（`MANUAL`）、重新算料出来的新单确认了（`RECALC`，自动）。

### 2.2 采购单

用全套 `DocStatus`，中文按采购单叫（`PURCHASE_STATUS`）：

| 状态 | 中文 | 标签 | 怎么来的 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 新建、生成、反审核、驳回、撤回 |
| `PENDING` | 待审核 | `pending` | 提交。金额超过门槛的多审一级（默认 5 万，PRD §5.1） |
| `APPROVED` | 已审核 | `active` | 最后一级审过；或者入了库又全退了 |
| `RUNNING` | 部分到货 | `progress` | 有一行到货 > 0（净入库 + 冲入 − 冲出，RFC 014），但不是每行都到齐 |
| `DONE` | 已到齐 | `done` | 每一行到货（已入库 − 已退货 + 冲入 − 冲出，RFC 014）≥ 采购数 |
| `CLOSED` | 已结案 | `closed` | 剩下的不要了，手动结案；取消结案按到货重新算回上面三种之一 |
| `VOIDED` | 已作废 | `void` | 待审核时作废 |

已审核、部分到货、已到齐三者由入库单、出库单过账时自动换（审核、反审核都算一遍），不是按钮。

### 2.3 齐料状态

`KITTING_STATUS`：未算料（`off`）、未到料（`pending`）、部分到料 x/y（`progress`）、齐料（`done`）。怎么算见 `OrderKitting` 的注释。

### 2.4 待到料的风险

`ARRIVAL_RISK`：已逾期（红，`danger`）、临期（3 天内，琥珀）、正常（不标）。另外 `cutLateDays > 0` 的行标"晚于开裁 n 天"（红），和逾期不互斥。

### 3.2 算料单

#### 3.2.1 列表 `GET /api/mrp-calcs`

参数 `PageParams & MrpCalcQuery`，返回 `PageResult<MrpCalcRow>`，新的在前。关键字按算料单号、订单号、款号查；一次查几个（README §3.2）时这三个都精确查。行上、详情上有 `productLine`（README §3.7），详情里改供应商的下拉传它。

#### 3.2.2 详情 `GET /api/mrp-calcs/{id}`

返回 `MrpCalcDetail`。`companyId` 是它的订单的主体（算料单本身不存主体，一张算料单的订单主体都一样），页面的写操作按它带 `X-Company-Id`；`orders[].canOpen` 是我打不打得开那张订单（"本人"范围的采购算的是别人的订单，打不开，只显示单号）。算料结果是当时存下的快照，不随库存变（`lateTransits` 赶不上的在途也是）；`receivedQty`、`shortQty`、`convertedQty` 是现取的。内部 `input_snapshot` 只保存订单数量/锁定包/交期及迟到在途，不包含其他算料单全部占用，不能承诺凭它重放完整历史供应分配。`approval` 一直是 null；`auditBy`、`auditTime` 是确认人、确认时间。

共享在途按使用记录 `use.id` 的确定顺序分配（建行顺序，不称确认先后）；到货按已入减已退的净量，建议量夹到 0，退货会重新形成缺口。算料投影是 RFC 010 明确的跨域只读例外：可批量读锁定订单/BOM/库存，不能写上游表，SKU 可用性由资料包 Service 检查。

#### 3.2.3 能算料的订单 `GET /api/mrp-calcs/order-options`

参数 `PageParams & { keyword }`，返回 `PageResult<MrpOrderOption>`。只列已审核、生产中的需求订单（02 的状态）。关键字按订单号、款号查。行上有 `productLine`，能看几条线的人选订单时多一列；有 `companyId`（订单的主体），建算料单时拿它当主体：本人范围的采购不在订单上，打不开订单详情，不能靠详情取主体。

#### 3.2.4 选订单算料 `POST /api/mrp-calcs`

请求 `{ orderIds: number[] }`，返回 `MrpCreated`（新草稿的 id、单号）。

- 按 PRD §6.6.1 的公式对每个物料 SKU 算一行，存成草稿。每张订单用它审核时锁定的生产 BOM 版本，只算没取消的数量；先对实际订单 SKU 统一检查色码、配料和分码用量（01 §3.7），缺项回 1000 并定位款色码/物料行，不能静默漏料。旧锁版以后被新版替代为 VOIDED 仍按原锁版读取，不自动换新。
- 物料来源是"自购"的进 `PURCHASE` 块，"厂购"的进 `FACTORY` 块（Q12）。
- 供应商取 BOM 行上的，没有取物料的默认供应商。
- 草稿不占用任何东西。别人这时确认了一张，这张的可用量就过时了，确认时会拦（§3.2.7）。

报错：订单不是已审核、生产中，1000"订单 DD… 不能算料：它是××状态"；`orderIds` 空，400；订单不是同一条品类线，400"不同品类线的订单请分别算料"。

#### 3.2.5 改一行 `PUT /api/mrp-calcs/{id}/items/{itemId}`

请求 `MrpItemForm`，返回改完的整张 `MrpCalcDetail`（一格变了，净需求、建议采购、预计金额、合计都跟着变，整张换掉最省事）。

- 草稿：四格都能改，一次改一格（规则见 `MrpItemForm` 的注释）。本次用库存、本次用在途只能改小：库存最多 min（可用库存，需求），在途最多 min（可用在途，需求 − 本次用库存）。
- 已确认：只能换供应商，而且这一行还没转完（建议采购 > 已转采购）。用在"供应商后来停用了，剩下的换一家买"。另外三格发来和原值不一样，回 1000。
- 供应商要是合作中的，不然 1000"供应商××不是合作中"。

报错：已关闭、或有重新算料的草稿，1002；超上限，400"本次用库存最多 120"；建议采购小于已转采购，400。

#### 3.2.6 删一行 `DELETE /api/mrp-calcs/{id}/items/{itemId}?version=`

返回删完的 `MrpCalcDetail`。草稿、已转采购为 0 的行才能删。用在"这种料这次改由厂购"这类特殊情况（PRD §6.6.1 末段）。

#### 3.2.7 确认 `POST /api/mrp-calcs/{id}/confirm`

请求 `DocActionReq`。草稿才能确认。

后端在一个事务里加锁（按物料 SKU 的 advisory lock，架构 §5.4），用最新的数再算一遍每行的可用库存、可用在途：只要有一行和存着的不一样，回 1000"可用量已变化，请重新计算"，不确认。前端收到后提示用户点"重新算料"。两个人同时确认，后确认的那个会收到这个错。

涉及在途或重新算料改挂采购行时，先收集所有受影响采购头（包括旧算料上的头）按 ID 统一预锁，再移动明细、更新版本；与库存来源过账统一先来源后库存的顺序，失败整笔回滚。

确认后它的本次用库存、本次用在途（具体到哪条采购行，`mrp_calc_transit`）和它以后生成的采购单都算占着。

如果它是重新算料出来的新单，确认时把上一张关闭（`RECALC`），上一张已转采购的数和那些采购行一起转到这张对应的行（按物料 SKU 对）。新单上没有这个 SKU 的（订单改得不要这种料了），那几条采购行留在上一张上，上一张关了，它们就是谁都能用的在途。

#### 3.2.8 关闭 `POST /api/mrp-calcs/{id}/close`

请求 `DocActionReq`，`reason` 选填。已确认的才能关（草稿直接删）。占用释放；已经生成的采购单不受影响，还是在途，变成谁都能用的数。有重新算料的草稿时不能关，1000"有一张重新算料的草稿 SL…：先确认它（这张自动关闭）或者删掉它"。

#### 3.2.9 重新算料 `POST /api/mrp-calcs/{id}/recalc`

请求 `DocActionReq`，返回 `MrpCreated`。订单变更以后用（PRD §6.6.1）。

- 草稿：就地重算，返回的 id 就是这张。之前手改的数都没了。
- 已确认：按订单现在的数量另算一张草稿新单（`prevCalcId` 指向这张），返回新单；前端跳过去。这张先不关，还占着，等新单确认时才关（§3.2.7）；新单删了，这张原样留着。新单算可用量时不把这张的占用算成"别人占着的"。
- 一张已确认的单同时只能有一张重新算料的草稿：再点回 1000"已经有一张重新算料的草稿 SL…"。
- 已确认的单重新算料时，已经结案、取消的订单不再算，只算还是已审核、生产中的；一张都不剩，1000"这张算料单的订单都结案或取消了，不用重新算料，关闭它就行"。

为什么新单确认时才关旧单：旧单一关，它生成的采购单马上不算占着，新单还是草稿也不占，中间这段时间这批料会被别的算料单算走。

#### 3.2.10 删除 `DELETE /api/mrp-calcs/{id}`

草稿才能删（`docApi.remove`），附件、操作记录、变更提醒一起删。已经从它生成过采购单的草稿不会有（生成时自动确认了）。

#### 3.2.11 备料比 `GET / PUT /api/mrp-calcs/reserve-pcts`

GET 返回 `ReservePct[]`，每种物料类型一条。PUT 请求 `{ materialType, pct }[]`，`pct` 0 到 50。存在字典 `material_type` 的数值列（V11 已经这么约定），通过 system 的 `DictService` 写。只影响以后算的单；物料上自己设了备料比的，不看这里（Q18、Q31）。

### 3.3 采购单

#### 3.3.1 列表 `GET /api/purchase-orders`

参数 `PageParams & PurchaseQuery`（多一个 `productLine`），返回 `PageResult<PurchaseRow>`，新的在前。关键字按采购单号、供应商、物料、订单号、款号、算料单号查；一次查几个（README §3.2）时采购单号、订单号、款号、算料单号、物料编码精确查。

`auditForMe?: boolean` 默认 false；true 时只取 PENDING 且当前审批级匹配调用人的单据，忽略普通 `mine/ownerId` 归属条件，其他筛选仍取交集。当前并无独立采购状态 counts 接口，不凭空新增路由；列表、导出与后续首页待审计数必须复用同一谓词。

#### 3.3.2 详情 `GET /api/purchase-orders/{id}`

返回 `PurchaseDetail`。`approval` 是审批块（README §4.4）。`stockDocs` 是这张单生成的入库单、出库单（草稿也列）。

#### 3.3.3 表单默认值 `GET /api/purchase-orders/defaults`

参数 `PurchaseDefaultsQuery`，返回 `PurchaseDefaults`。前端什么时候调：

- 选了、换了供应商：带 `orderDate` 和表单上全部 `skuIds`。用返回的结算方式、税率、采购员填单头，用 `lines` 换掉**没手改过单价**的行的单价；手改过的行只更新 `archivePrice`（原型的做法）。
- 加了物料（从物料库选）：同样带全部 `skuIds`，新行用返回的单价。
- 改了下单日期：重取一次，现价按下单日期取（PRD §6.10 规则 3）。
- 交货日期：用户没手改过的，用返回的 `deliveryDate`。

默认单价的顺序是价格档案现价 → SKU 单价 → 物料参考单价，后端算好，前端不直接调价格档案的接口（采购不依赖 price 页面）。

#### 3.3.4 新建、改草稿

`POST /api/purchase-orders`，请求 `PurchaseForm`，返回 `PurchaseCreated`。`PUT /api/purchase-orders/{id}`，请求 `PurchaseUpdateForm`（多一个 `version`），整体覆盖。

校验（草稿也查的）：

- 供应商必须是合作中（Q19），不然 1000"供应商××不是合作中，不能下采购单"。
- 交货地点是启用的物料仓或工厂仓（Q11）。
- 明细至少一行，数量 > 0。单价 `null` 时用默认单价；默认也没有，400"第 3 行没有单价"。
- 单价和 `archivePrice` 不一样（档案里有价）时，改价原因必填，400"第 3 行改了单价，要写原因"（Q25）。
- 单价按四位小数输入/显示，金额按两位 `HALF_UP`；后端精确计算并在写库前校验列容量，格式/容量错误 400 且定位明细，前端预览不作为入账结果。
- `planStyleIds` 只有备货采购收，别的类型发了回 400；款要和采购单是同一条品类线，不然 400"计划用于的款 … 和这张采购单不是同一条品类线"。
- 品类线 `productLine`（README §3.7）：只有一条线的人不用传；几条线的必传，没传 400"请选品类线"。从算料单生成的跟算料单，改不了（传了也不看）。供应商要做这条线，不然 1000"××不做鞋类：……"；提交、审核时再查一遍（期间供应商档案可能改了）。
- 新建时 `calcItemId` 都发 null；改从算料单生成的草稿时原样带回。带 `calcItemId` 的行物料不能换。

结算方式、税率草稿里可以空着，提交时必填。改数量、删行时，来源算料行的已转采购跟着变。

#### 3.3.5 删除 `DELETE /api/purchase-orders/{id}`

草稿才能删，附件、操作记录、变更提醒一起删。来源算料行的已转采购退回去，那几行又能重新生成。

#### 3.3.6 状态动作 `POST /api/purchase-orders/{id}/<动作>`

请求 `DocActionReq`。前端用 `purchaseApi.act(id, action, body)`。

| 动作 | 从 → 到 | 权限 | 说明 |
|---|---|---|---|
| `submit` | 草稿 → 待审核 | `purchase:order:submit` | 再查 §3.3.4，结算方式、税率必填。按金额和实际规则取审批快照，校验指定人启用且有 purchase:order:list，角色型也须有可用成员（README §4.4） |
| `withdraw` | 待审核 → 草稿 | 制单人 | |
| `reject` | 待审核 → 草稿 | 登录（当前这一级的审批人） | 原因必填 |
| `audit` | 待审核 → 已审核（或下一级） | 登录（当前这一级的审批人） | 每一级都再查供应商是不是合作中。最后一级审过时，单价和档案现价不一样的行自动在价格档案里记一条（PRD §6.10 规则 4，来源单据 = 这张单） |
| `unaudit` | 已审核 → 草稿 | `purchase:order:audit` | 有入库单、出库单（草稿也算），或被已确认的算料单用作本次使用在途，回 1005，`data` 是那些单据。审核时记进价格档案的几条一起作废 |
| `close` | 已审核、部分到货 → 已结案 | `purchase:order:close` | 还有入库单草稿没审，1000"还有入库单 RK… 没审核"。结案后没到的不再算在途，从待到料里消失 |
| `reopen` | 已结案 → 按到货算 | `purchase:order:close` | 回到已审核、部分到货或已到齐 |
| `void` | 待审核 → 已作废 | `purchase:order:void` | 来源算料行的已转采购退回去 |

已到齐的不能结案（已经是终态了，PRD §5.1）。到货入库、退货不是状态动作，见 §3.3.9。

#### 3.3.7 由算料单生成 `POST /api/purchase-orders/from-mrp`

请求 `{ calcId, itemIds, version }`（`version` 是算料单的），返回 `PurchaseCreated[]`。

- 算料单是草稿的，先自动确认（同一个事务，确认没过就整个不做，回 1000"可用量已变化，请重新计算"）。
- 只收 `canConvert` 的行。每行数量 = 建议采购 − 已转采购（采购单位），单价按这家供应商今天的默认单价（价格档案现价 → SKU 单价 → 物料参考单价），不用算料单上的参考单价（那是算料那天的）。
- 按供应商拆，一家一张草稿：采购类型 = 订单采购，交货地点 = 第一个启用的物料仓（按排序），采购员 = 当前用户，主体 = 当前用户的默认主体，下单日 = 今天，交货日期按默认算，结算方式、税率带供应商的。
- 回写算料行的已转采购。

报错：有行没选供应商，1000"第 3、5 行还没选供应商"；供应商不是合作中、默认单价都没有、物料的采购单位在算料以后改过（要重新算料），一次列全回 1000，`data` 是清单，一张都不建；算料单已关闭、有重新算料的草稿，1002。

前端：成功后提示"按供应商拆成 n 张采购单草稿"，带"打开 CG…"链接，刷新算料单。

#### 3.3.8 由补货清单生成 `POST /api/purchase-orders/from-reorder`

请求 `{ items: ReorderPickItem[], productLine }`，返回 `PurchaseCreated[]`。按供应商拆成几张备货采购单草稿，其他默认值同上。供应商要合作中、要做 `productLine` 这条线，数量 > 0。`productLine` 规则同 §3.3.4：只有一条线的人不用传。

#### 3.3.9 到货入库、退货

不在采购这边建单，调库存的接口（04 §3.3）：

- 详情页"到货入库"：`invDocApi.prefillFromPurchase(id, { docType: 'PURCHASE_IN' })` 取默认值和明细，画对话框，点"存草稿"或"入库并过账"调 `invDocApi.fromPurchase(id, { …, post, clientActionId })`。clientActionId 为本次动作 UUID，结果未知时保留原 ID 和原请求体重试（README §3.6、04 §3.3）。
- "退货"：同样两步，`docType: 'PURCHASE_RETURN'`。

`actions` 里有 `receive` / `return` 才出这两个按钮：`receive` 要已审核或部分到货（已到齐的单有一行靠冲入到齐、自己净入库还不到采购数的也出），有 `inventory:doc:add`；`return` 要部分到货或已到齐、有 `inventory:doc:add`。列表行上的 `actions` 不查冲抵，已到齐的不出 `receive`。

**超收冲抵在途（RFC 014）**：同一主体、供应商、品类线、物料 SKU、采购单位的采购行是一组（物料仓之间不管哪个仓；直发工厂仓的只和同一个工厂仓的冲）。入库过账后某行到货超过采购数，多的冲给同组没到齐的行（已审核、部分到货，下单早的先冲）；反审核入库、退货让它不够了，冲出去的从最近一笔往前退回来；靠冲入到齐的行自己又入了，先把冲来的还回去。已到齐的单只能入靠冲入到齐的行；只靠冲入、自己没入过库的单不出退货。明细上 `offsetInQty`、`offsetOutQty` 是冲入、冲出合计，`offsets: PurchaseOffset[]` 是和哪张单的第几行（`otherSeq`，可能就是本单）冲了多少；`pendingQty` = max(0, 采购数 − 到货)。单头和列表的 `receivedQty` 还是净入库。两张单各记一条操作记录（`action = offset`）。过账时按 id 从小到大锁住这张单和同组会动到的单；万一被数据库判了死锁，返回 1002"有人同时在改，请重试"。

入库单、出库单正向/反向过账均先在来源行锁内合并 delta、校验并回写累计，再写库存余额/流水，和单头状态同事务。任一方向须满足 `0 ≤ 已入库 − 已退货 ≤ 采购数 × 1.05`。采购单已结案先取消结案；净入库会变负时先撤销相关退货；退货后已补收、撤销原退货会超上限时，先处理补收单，不能靠反审绕过超收限制（1004）。失败不改任何累计、状态或流水。

#### 3.3.10 改预计到货、跟进备注 `PUT /api/purchase-orders/{id}/items/{itemId}/follow`

请求 `FollowForm`，两格都发。已审核、部分到货的单才能改。不带 `version`、不改单据版本（随手改的跟进信息，不该和别人改单据冲突），写一条操作记录。改了预计到货，算料的"赶得上"和待到料的风险跟着变。

#### 3.3.11 导出 `GET /api/purchase-orders/export`

参数同列表（含 `auditForMe`），加 `ids` 导勾选且仍符合筛选/权限的。一行一条明细，单头字段重复；明细有"冲抵"列（冲入 − 冲出，RFC 014），未入库按到货算。使用最近成功展示列表的规范化条件快照，包含状态映射、去掉分页；不把编辑中的筛选或失败查询条件用于导出（README §3.2）。

#### 3.3.12 打印

不加接口。前端用详情数据排一张打印页（`window.print()`），抬头用 `config.ts` 的系统名，内容是供应商（全称、联系人、电话）、交货地点和地址、明细、合计、结算方式、税率。后端出 PDF 的话一张单要多写一套模板，采购单的打印不值这个钱。

### 3.4 待到料

#### 3.4.1 列表 `GET /api/purchase-orders/pending-items`

参数 `PageParams & PendingArrivalQuery`，返回 `PageResult<PendingArrivalRow>`，按"预计到货 ?? 交期"从早到晚。一行是已审核、部分到货的采购单里未入库 > 0 的一条明细（未入库按到货算，带 `offsetInQty`、`offsetOutQty`；"已到"列照旧写净入库，有冲入的后面写"冲来 50"）。

要料日期从生产那边取（05 提供"订单 → 裁剪计划开始"的接口，架构里的 `NeedDateSource`）；没排单的按承诺交期倒推。

#### 3.4.2 页签上的数 `GET /api/purchase-orders/pending-items/counts`

参数同列表去掉 `tab`，返回 `PendingArrivalCounts`。筛选条件变了就重取。

#### 3.4.3 行上的操作

- 改预计到货、跟进备注：行上直接改，失焦或回车时调 `purchaseApi.follow`（要 `actions` 里有 `follow`）。
- 入库（要 `actions` 里有 `receive`）：单行点"入库"，开和采购单详情一样的入库对话框，`prefillFromPurchase(purchaseOrderId, { docType: 'PURCHASE_IN', itemIds: [purchaseItemId] })`，只带这一行。
- 勾几行点"入库"：按采购单分组，每个来源动作生成一个 UUID，调 `invDocApi.fromPurchase(poId, { docType: 'PURCHASE_IN', items: null, itemIds: [...], post: false, clientActionId, 其余 null }, { silent: true })`。同一组结果未知的重试复用原 ID/请求体；下一次明确的新批次才换 ID。每行按未入库数建草稿，批量条逐条报结果，成功提示"建了 n 张入库单草稿，去入库单页签里改实收数、填缸号后审核"。

### 3.5 齐料状态 `GET /api/order-kitting?orderIds=`

参数 `orderIds`（最多 500 个），返回 `OrderKitting[]`，每个 id 一条，没算料的也有（`NONE`）。只要登录，因为只回状态、不回明细。

前端用 `kittingApi.byOrders(orderIds)`：订单列表、生产单列表拿当前页的订单 id 调一次，按 `orderId` 对上，显示 `KITTING_STATUS[status]` 的标签和 `label`。点标签可以去 `/mrp/{calcIds[0]}`。

### 3.6 补货提醒、物料的在途

#### 3.6.1 补货清单 `GET /api/reorder-items`

返回 `ReorderRow[]`，不分页（只列低于最小库存的，量不大），差得多的在前。规则见 PRD §6.6.7：在途不看赶不赶得上，库存只算物料仓。

首页待办"物料低于最小库存 n"（06）的数就是这个清单的条数，06 决定是直接调它还是另加一个计数接口。

#### 3.6.2 物料的在途 `GET /api/material-supply?skuIds=`

返回 `SkuSupply[]`，每个 SKU 一条。库存页（04）拿当前页的 SKU id 调一次，显示"在途"列，`belowSafety` 的行标黄。库存那边不能读采购（依赖方向是 purchase → inventory），所以分两次取。

## 4. 前端要知道的规则

- **按钮全看 `actions`**。算料单的确认、关闭、重新算料不走 `docApi.act`（不是 `DocAction`），用 `mrpApi.confirm / close / recalc`。
- **算料单草稿里改格子**：失焦时调 `updateItem`，用返回的详情整张换掉（`version` 也换）。输入时可以即时显示净需求，但以后端返回的为准。输入框的 `max`：本次用库存 `min(availStockQty, needQty)`，本次用在途 `min(availTransitQty, needQty − useStockQty)`。已确认的单只有供应商一格能改。
- **确认收到 1000"可用量已变化"**：提示里给"重新算料"按钮。
- **生成采购单**：只有勾了 `canConvert` 的行才亮。勾的行里有没选供应商、供应商不是合作中的，先在前端拦住并标红这几行，不用等后端。
- **重新算料**：已确认的单点了以后跳到新单。新单上 `diff` 列出变化。
- **采购单的单价**：输入最多四位，单价/档案现价用 `formatPrice`，金额才用 `formatMoney`。显示 `archivePrice` 时，单价不一样就琥珀色，改价原因变必填（`archivePrice` 是 null 的不用填）。金额 = 数量 × 单价，前端即时算，保存后以后端为准。
- **换供应商**：重取默认值（§3.3.3），确认框提示"单价按新供应商的现价重新带出，手改过的不动"。供应商下拉用 `SupplierSelect`，只列合作中的。
- **交货地点**：仓库下拉列启用的物料仓和工厂仓，工厂仓后面标"直发工厂"。
- **计划用于款号**：只有备货采购出这一格，用 `DataPick kind="style"` 选；切到别的类型时清空。
- **提交前**：前端先查结算方式、税率、改价原因，空的标红。
- **审核**：待审核时，单价和档案不一样的行在明细里标出来，审核确认框写"有 n 行单价和价格档案不一样，审核后记进价格档案"。
- **到货进度**：草稿、待审核、已作废写"—"；别的状态 `receivedQty / totalQty`，超过 100% 照写（超收）。
- **待到料**：剩几天 `daysLeft` 负数写"逾期 n 天"（红），0-3 写"还有 n 天"（琥珀）。要料日期是 null 写"—"，鼠标悬停说"没被算料用上的备货采购没有要料日期"。
- **地址带的参数**（首页待办、别的页面跳过来用）：`/purchases?status=PENDING`；待我审核用 `/purchases?status=PENDING&auditForMe=1`；`/mrp?status=DRAFT`；`/stock-in?tab=pending&risk=LATE`（04）。KeepAlive 监听 query，dirty 采购表单激活不重载。
- **上游订单变更**：订单变更单审核后，受影响的算料单、采购单 `pendingNotices > 0`，详情顶上出黄条（README §4.5）。算料单的黄条里放"重新算料"按钮，处理完点"已处理"。
- **操作记录**：`DocLogList` 的 `actions` 传 `MRP_LOG_ACTION` / `PURCHASE_LOG_ACTION`，`statuses` 传 `MRP_STATUS` / `PURCHASE_STATUS` 的 label。

## 5. 按默认做的

| 问题 | 按什么做 |
|---|---|
| Q09 溢收 | 正反向均校验净入库非负且最多超收 5%；撤销退货也不能突破上限，超了 1004（04 §3.4） |
| Q10 审核 | 基础一级，金额门槛和附加审批人依实际配置；5 万是规则示例，不代表环境已配置。自己做的单能自己审，指定人必须可访问模块 |
| Q11 直发工厂 | 交货地点能选工厂仓；直发工厂仓的在途不进算料的公共数，也不进补货的在途 |
| Q12 包工包料 | 算料只算物料来源 = 自购的行；厂购的只列 |
| Q18、Q31 备料比 | 物料上设的优先，没设按物料类型（字典数值列），默认 0；算料页能改物料类型的 |
| Q19 准入 | 采购单（三种类型都算）只能选合作中的供应商；"能打样"说的是二期的打样单 |
| Q25 偏离 | 不审批，只留痕：改价要写原因，审核时记进价格档案 |
| Q32 最小库存 | 甲方 11-17 确认：领猫的"最小库存"就是补货线，导成 SKU 的最小库存（11-17 以前页面上叫安全库存，字段名 `safetyStock` 不变） |
| Q39 退货补发 | 未入库 = 采购数 − 到货（已入库 − 已退货 + 冲入 − 冲出，RFC 014），补发的照样入原单；退货让已到齐的单回到部分到货 |

## 6. 用户定了的

1. **结案谁能做**（11-15 定）：加 `purchase:order:close`（结案、取消结案），给采购和管理层。PRD §6.6.2 规则 3 说"不补了就结案"，这是采购员跟供应商谈完的事。PRD v0.11、架构 §8 已跟着改。
2. **已审核的采购单不能改预计到货、跟进备注以外的东西**（11-15 定）：要改就反审核（没入库时）或另开一张单；改单据走订单变更那种流程，一期不做。
