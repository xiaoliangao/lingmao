物料入库单、物料出库单、物料盘点单、库存、库存日志。需求看 PRD §6.6.5、§6.6.6、§6.6.8，机制看架构 §5（过账、条件更新、`StockSourceHandler`）、§4.10（一张表两种单据），表看数据库设计 §13（`inv_*`）。

### 1.3 入库单、出库单怎么分

一张表 `inv_doc`、一组接口 `/api/inventory-docs`，按 `kind` 分（架构 §4.10）。前端：

- **列表**：两个菜单页各自固定 `kind`，`/stock-in` 发 `kind=IN`，`/stock-out` 发 `kind=OUT`。列表本身写成一个组件（建议 `views/inventory/doc/DocList.vue`，`kind` 当 prop），两个页面各放一个。
- **新建**：页头"新建"的下拉项从 `INV_DOC_TYPE` 里取 `kind` 对得上、`sourceRequired = false` 的类型。入库单：退料入库、其他入库；出库单：调拨、其他出库，另加一项"领料出库（选生产单）"。
- **详情**：一个页面文件挂两个地址。标题、字段按接口返回的 `kind`、`docType` 换（"物料入库单 RK…" / "物料出库单 CK…"）。地址和 `kind` 对不上时（有人手敲了 `/stock-in/` 去看出库单），用 `router.replace(docRoute({ type: 'INV_DOC', kind, id, parentId: null }))` 换到对的地址。
- **权限**：两种单共用 `inventory:doc:*`，要分开给以后再加（架构 §4.10）。

### 1.5 页面长什么样

照原型 `docs/原型/src/5c-material.js`：`/stock-in`、`/stock-out`（列表组件 `StockDocList`、表单 `StockDocForm`、详情 `SD_DETAIL`）、`/stock-takes`、`/stock`，入库对话框是 `PurchaseReceive`。

**物料入库单 `/stock-in`**：页头"新建"下拉（退料入库、其他入库），要 `inventory:doc:add`。下面两个页签：

- "待到料"（`?tab=pending`，默认）：只给有 `purchase:order:list` 的人，没有的人默认进"入库单"。分段控件：全部 / 已逾期 / 3 天内 / 晚于开裁（数用 `pendingArrivalApi.counts`）。筛选：供应商、采购员、交期。列：采购单（下面小字采购员）、供应商、物料、订单 / 款、已到 / 采购、未到（带采购单位）、交期（下面"逾期 n 天 / 还有 n 天"）、预计到货（能改）、要料日期（下面"晚于开裁 n 天"）、跟进（能改）、"入库"按钮。勾选列 + 批量条"入库"。行上的操作见 03 §3.4.3。
- "入库单"（`?tab=docs`）：入库单列表。

**物料出库单 `/stock-out`**：页头"新建"下拉（调拨、其他出库、领料出库（选生产单））。下面直接是出库单列表。

**入库单、出库单列表**：分段控件按类型（全部 + 这种单的几种类型）。筛选：状态（草稿 / 已审核 / 已作废）、日期、仓库（出仓或入仓是它）、往来单位（`SupplierSelect`），"待我审核"勾选（勾上时"我的 / 全部"灰掉），"我的 / 全部"。列：单号、类型、出仓 → 入仓、往来、源单、物料（第一行 + "等 n 种"）、日期、状态。勾选后批量条：审核、导出选中。空表格："还没有入库单：采购到货在「待到料」点「入库」，其他的点页头按钮新建"（出库单："领料在生产单上点「领料」，其他的点页头按钮新建"）。

**手工新建、改草稿**：对话框（照原型 `StockDocForm`），宽一点放明细。单头：主体公司、日期、出仓、入仓（按 `INV_DOC_TYPE` 的 `from`、`to` 出不出、能选哪种仓）、原因（`reasonDict` 有值用 `DictSelect`，必填；没有就是一行字，选填）、物流单号、备注。退料入库多一格"源生产单"（选填，选了以后走 §3.3.2 的生成接口）。明细：物料（`DataPick kind="sku"` 挑）、出仓库存（有出仓时）、数量（库存单位）、单价、金额、缸号、卷数、备注。

**由源单生成的对话框**（到货入库、退货、领料、退料共用一个，建议放 `components/`，采购单详情、待到料、出库单页、05 的生产单详情都用）：照原型 `PurchaseReceive`。单头：入哪个仓 / 从哪个仓出、日期、物流单号、送货单号（采购入库）、原因（退货、退料）、备注。明细按 `InvDocDraft.items`：物料、可入 / 可退 / 还差（按类型）、出仓库存（有出仓时）、本次（默认 `suggestQty`）、缸号、卷数、超领原因（领料超了才出）、备注。按钮"存草稿"和"入库并过账"（退货叫"退货并过账"，领料叫"领料并过账"），后一个要 `inventory:doc:audit`。

**入库单、出库单详情**：页头按 `actions`：编辑、审核过账、反审核、删除或作废。正文：属性（类型、源单（点了用 `docRoute(source)`）、出仓、入仓、往来、日期、原因、送货单号、物流单号）、明细表（物料、数量 + 单位、采购单位数量（采购的两种）、单价、金额、缸号、卷数、超领原因、备注；草稿且有出仓时多一列"出仓库存"，不够的标红）。侧栏：附件、操作记录。

**物料盘点单列表 `/stock-takes`**：页头"录期初库存"（开新建对话框、用途选好期初录入）和"新建盘点单"，都要 `inventory:count:add`。分段控件按状态（全部 / 草稿 / 待审核 / 已审核 / 已作废）。筛选：仓库、用途、盘点日期。列：单号、仓库、用途、范围（`scopeText`）、盘点日期、盘点人、已填实盘（`filledCount / itemCount`）、差异（"盘盈 n · 盘亏 n"）、状态。

**新建盘点单**：对话框（照原型 `StockTakeNew`）。仓库下拉里，`countApi.openWarehouses()` 返回的仓灰掉，后面写"PD… 还没审"。用途、盘点日期（默认今天）、盘点人（默认自己，`UserSelect`）、范围：全部 / 按物料分类（分类小块多选）/ 手选物料（`DataPick kind="sku"`）。用途选期初录入时范围固定是手选，可以一个都不选（建空单再导入）。

**物料盘点单详情**：页头按 `actions`：导出盘点表、导回实盘数（草稿）、保存（草稿）、提交、审核过账 / 驳回；更多里放从物料库加物料、没填的按账面数填、重新取账面数、撤回、反审核、删除。分段控件：全部 / 没填实盘 / 有差异（前端筛）。列：物料、单位、账面数、实盘数（草稿里能填）、差异（盘盈绿、盘亏红）、已调整（审核后）、备注。侧栏：属性（仓库、用途、范围、盘点日期、盘点人、取账面数的时间）、附件、操作记录。

曾过账草稿以"作废"代替"删除"，均按 actions。页面上不放常驻说明：提交被拦时提示里说清哪几行取账面以后有过进出，点"重新取账面数"只重拍、清空这几行。

**库存 `/stock`**：页头按钮：补货提醒（n）（有 `purchase:order:list` 才出，去 `/reorder`）、盘点（去 `/stock-takes?new=DAILY`）、导入期初库存（去 `/stock-takes?new=OPENING`）、导出。仓库类型页签：物料仓 / 工厂仓 / 全部；仓库下拉；视图分段：明细 / 按物料 / 进销存 / 日志。

- 明细：仓库、物料（图、名称、颜色、规格、SKU 码）、数量（带单位；物料仓的行 `belowSafety` 时琥珀色）、在途、最小库存、最近变动。点一行弹它的库存日志（带上仓库和 SKU）。
- 按物料：物料、物料仓合计、工厂仓合计、合计、在途（送各个仓的合计）、最小库存。
- 进销存（二期，RFC 016 §4）：仓库类型页签、仓库、关键字（SKU 码、物料编码、名称），期间（`DateRange`，默认本月，清空回到本月）放右边。列：物料、单位、期初、入库、出库、期末（固定在右边）；"显示列"里能勾出入库、出库拆开的列（采购入库、退料入库、领料入厂、其他入库、调入、盘盈、期初录入；领料出库、退料出厂、采购退货、其他出库、调出、盘亏），默认藏着，是 0 的格子空着。导出带全部列。明细、进销存的仓库下拉只列当前页签那一类仓，切页签时选了别类的仓清掉。
- 工厂仓数量统一标为"净托管账面量"，即已领入减退回/调出加经审核调整；回货不自动扣 BOM 耗料，不能称实时未耗实物，也不纳入公共可用库存。
- 日志：日期、变动类型（多选）、关键字（单号、物料、缸号）。列：日期、类型、单号（点了打开单据）、仓库、物料、变动数量（入绿出红）、结存、缸号、操作人；价值字段见 §3.6.4，未知显示"—/未知"，不能显示 0 冒充已估值。

## 2. 状态

### 2.1 入库单、出库单

`INV_DOC_STATUS`：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、审核过账；没过过账的删，过过账的作废 |
| `APPROVED` | 已审核 | `active` | 反审核（库存改回去，回到草稿） |
| `VOIDED` | 已作废 | `void` | 只读 |

没有待审核，审核即过账（PRD §6.6.5）。没过过账的草稿直接删；过过账（审核过）又反审核回草稿的不能删、只能作废（用户 11-17 定，§6）：库存日志指着它和它的明细。详情的 `posted` 说这张单过没过过账，`actions` 里 `remove` 和 `void` 只出一个。

### 2.2 物料盘点单

`COUNT_STATUS`：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 填实盘数、加删行、导回实盘数、重新取账面数、提交；没过过账的删，过过账的作废 |
| `PENDING` | 待审核 | `pending` | 审核过账、驳回、撤回（制单人） |
| `APPROVED` | 已审核 | `active` | 反审核（调整退回去，回到草稿） |
| `VOIDED` | 已作废 | `void` | 只读；不算"没审核的"，这个仓能再开盘点单 |

单级审核，不走多级审批。删除、作废同入库单（§2.1，用户 11-17 定）；差异全为 0、没有库存日志的单算没过过账，但也须反审核回草稿才可删除。

### 3.2 入库单、出库单

#### 3.2.1 列表 `GET /api/inventory-docs`

参数 `PageParams & InvDocQuery`，`kind` 必填（不传 400），返回 `PageResult<InvDocRow>`，新的在前。`auditForMe=true`：只列草稿、不列自己建的（Q10），不看 `mine`，没有 `inventory:doc:audit` 的一条都没有，范围是调用人的数据范围，角色勾了"审核不受数据范围限制"的不按本人筛；首页待我审核和页面上的"待我审核"勾选用它（README §4.2）。关键字按单号、源单号、送货单号、物流单号、物料、缸号查；一次查几个（README §3.2）时单号、源单号精确查。

#### 3.2.2 详情 `GET /api/inventory-docs/{id}`

返回 `InvDocDetail`。草稿且有出仓时，每行带 `fromStockQty`（出仓现在的库存）。`posted`：过过账（有库存日志）；每行的 `posted`：这一行过过账，编辑时删除按钮灰掉、物料不能换。`filesEditable`：附件能不能改（在本人数据范围里、有 `inventory:doc:edit`；只靠"审核不受数据范围限制"看到的单是 false），不看状态，附件区照它禁用。

#### 3.2.3 手工新建 `POST /api/inventory-docs`

请求 `InvDocCreateForm`，返回 `InvDocCreated`（草稿）。只收 `INV_DOC_TYPE` 里 `sourceRequired = false` 的类型：退料入库（不挂源单）、其他入库、调拨、其他出库。别的类型回 400"采购入库要从采购单生成"。

校验：

- 出仓、入仓按 `INV_DOC_TYPE` 的 `from`、`to`：该有的必填，仓库类型对得上，启用的。
- 调拨：出仓、入仓不能是同一个仓，而且是同一种（物料仓之间、工厂仓之间，PRD §6.6.5）。
- 其他入库、其他出库：原因必填，是字典里的值。
- 退料入库：往来单位由工厂仓带出（仓库上的加工厂），发什么都按仓库的。
- 日期不能晚于东八区业务日。明细至少一行，数量 > 0。同一个 SKU 可以有几行（缸号不同），过账时合起来算；单价四位、金额两位，写库前校验容量，错误 400 定位行。

#### 3.2.4 改草稿 `PUT /api/inventory-docs/{id}`

请求 `InvDocForm`，整体覆盖。草稿才能改。

明细整体覆盖，靠每行的 `id` 认：带 `id` 的是原来的行（原样带回），没 `id` 的是新加的，请求里没有的行删掉。过过账的行（`posted`）不能删、不能换物料，回 1000"第 n 行过过账，不能删"；数量、缸号这些照常改。

源单生成的草稿（采购入库、采购退货、领料、退料）只能改单头的日期、仓库、送货单号、物流单号、原因、备注，明细只能改数量、缸号、卷数、超领原因、备注，能删行，不能加源单以外的行（`sourceItemId` 和 `materialSkuId` 要对得上源单）。采购的两种发 `purchaseQty`、`qty` 发 null，后端换算。改了数量就按最新的源单数据再查一遍 1004（§3.4.2）。

#### 3.2.5 删除 `DELETE /api/inventory-docs/{id}`

没过过账的草稿才能删，库存、源单都不用动。过过账的回 1000"这张单过过账，不能删，只能作废"。

#### 3.2.6 审核过账 `POST /api/inventory-docs/{id}/audit`

请求 `DocActionReq`，草稿 → 已审核。前端用 `invDocApi.act(id, 'audit', body)`。

一个事务里做完（架构 §5.2、RFC 010）：单头状态 CAS、先锁来源并校验/回写累计，再按统一库存键顺序更新余额、写流水及操作记录。来源处理器不能在库存锁之后再获取上游采购/MRP 锁；后续任何失败都回滚前面的来源回写。

| 类型 | 库存 | 回写源单 |
|---|---|---|
| 采购入库 | 入仓 + | 采购明细已入库 +（采购单位），采购单状态重算（03 §2.2） |
| 退料入库 | 出仓（工厂仓）−，入仓 + | 挂了生产单的，生产单的已领 −（05） |
| 其他入库 | 入仓 + | — |
| 领料出库 | 出仓 −，入仓（工厂仓）+ | 生产单的已领 +（05）；订单的生产单都领完料时，它的算料单自动关闭（`ISSUED`） |
| 采购退货 | 出仓 − | 采购明细已退货 +，采购单状态重算（已到齐的会回到部分到货，Q39） |
| 调拨 | 出仓 −，入仓 + | — |
| 其他出库 | 出仓 − | — |

库存用条件更新（`qty + 变动 >= 0`），整张单所有行都试一遍，不够的全收集起来，一起回 1001（§3.4.1）。按完整库存键（仓库、SKU、物权、物权方、货位）合并、排序并加锁，当前一期 OWN/0/0 的口径不变。

每个仓每个 SKU 记一条库存日志（调拨、领料、退料一张单两条：出仓一条、入仓一条），`changeType` 就是单据类型，缸号带上（一行一条日志时带那行的缸号；几行合并的，日志按行分开记，不合并）。

一次原子过账/反过账产生变动流水时，该库存键的 `movement_revision` 递增一次（同键多行合并，版本不是流水条数）；同次合并净量为 0 但实际有流水也递增；零差异盘点未产生流水则不递增。流水同时冻结当次可知的价格、金额、单位和币种（§3.6.4）。

源单状态不对回 1000：采购单已结案、已作废，"采购单 CG… 已结案，不能入库"；生产单那边的条件由 05 定。

#### 3.2.7 反审核 `POST /api/inventory-docs/{id}/unaudit`

请求 `DocActionReq`，已审核 → 草稿。和正向一样先做来源校验/累计回写再改库存，全部同事务。库存日志追加反向事件、不删原记录：`reversalOfLogId` 指向被冲销原流水，复用原价、单位、币种并反转金额符号，不能读取后来已改价的源明细冒充历史。库存变负回 1001；源单状态不允许回 1000；采购净收上下限也要校验，撤销退货导致补收后超上限回 1004，先处理补收单。

前端确认框不用通用的文字，写"库存改回去，这张单回到草稿。"

#### 3.2.8 导出 `GET /api/inventory-docs/export`

参数同列表（`kind` 必填），加 `ids`。一行一条明细，单头字段重复；导出最近成功展示列表的规范化筛选快照，ID 与筛选/权限取交集（README §3.2）。

#### 3.2.9 作废 `POST /api/inventory-docs/{id}/void`

请求 `DocActionReq`（`reason` 选填，进操作记录），草稿 → 已作废。只给过过账又反审核回来的草稿，没过过账的回 1000"直接删除就行"。作废不动库存（反审核时已经改回去了），日志都留着。前端用 `invDocApi.act(id, 'void', body)`，确认框用通用的 `DOC_ACTION_CONFIRM.void`。

### 3.3 由源单生成

两步：GET 带出默认值和明细（不存库）画对话框，POST 建单。也可以不弹对话框直接 POST（待到料批量入库）。请求体都是 `InvDocFromSourceReq`，规则写在类型的注释里。

两个 POST 都新增必填 UUID 字符串 `clientActionId`（缺失/格式错误 400），返回仍是 `InvDocCreated`，GET 不带此字段。来源 ID 在路径中，docType、单头、items/itemIds、post 等全部有效字段参与请求摘要。同一次登记超时/结果未知时保留原 ID 和完整原请求重试；同键同体回原单据结果，同键异体 1002。不同真实批次使用新 ID，不因每次点击或未确认结果的表单修改自动换 ID（README §3.6）。

数量单位：采购入库、采购退货按**采购单位**（和采购单、待到料对得上，后端换成库存单位：`qty = 采购单位数量 × 换算系数`，三位小数）；领料、退料按**库存单位**。

`post = true` 时建完马上审核过账，一个事务：过账没过（1001、1004），单据也不建。要 `inventory:doc:add` 和 `:audit`，少一个回 403。甲方 11-21 答 Q10 以后自己建的单不能自己审，`post = true` 总是回 1000、单据不建（README §4.2）；字段留着，前端只发 `false`，建完由别人审核过账。

#### 3.3.1 采购单

`GET /api/inventory-docs/from-purchase/{purchaseOrderId}?docType=PURCHASE_IN|PURCHASE_RETURN&itemIds=`，返回 `InvDocDraft`。

- 采购入库：采购单要已审核、部分到货；已到齐的单有靠冲入到齐的行（RFC 014）也行，只能入这种行。带出 `maxQty > 0` 的行，`suggestQty` = 未入库（按到货算，靠冲入到齐的行是 0），`maxQty` = 采购数 × 1.05 −（已入库 − 已退货）。入仓默认是采购单的交货地点。
- 采购退货：采购单要部分到货、已到齐，且有净入库 > 0 的行（只靠冲入到货的不能退）。带出净入库 > 0 的行，`suggestQty` = 0，`maxQty` = 已入库 − 已退货。出仓默认是交货地点。
- `itemIds` 不传 = 这张单的全部行。

`POST /api/inventory-docs/from-purchase/{purchaseOrderId}`，请求 `InvDocFromSourceReq`，返回 `InvDocCreated`。

- 单价按采购单价换成库存单位（`采购单价 ÷ 换算系数`，四位小数），金额 = 采购单位数量 × 采购单价。前端不传单价。
- 往来单位 = 采购单的供应商。
- 建草稿时就查 1004（超收、超退），不等审核。
- 待到料批量入库：`items: null`、`itemIds` 发勾的行、`post: false`，每行按未入库建草稿；未入库是 0 的行跳过，全跳过回 400"没有要入库的数"。

#### 3.3.2 生产单

`GET /api/inventory-docs/from-production/{productionOrderId}?docType=ISSUE_OUT|RETURN_IN&fromWarehouseId=`，返回 `InvDocDraft`。源是外发加工单或成品采购单（`prd_order`，两种 `kind` 都行）。

- 领料出库：明细由生产那边算（`StockSourceHandler.prefill`，05 实现）：只算物料来源 = 自购的行，`needQty` = 加工数 × BOM 用量 ×（1 + 损耗），`issuedQty` = 已领 − 已退，`suggestQty` = 还差的数，`maxQty` 是 null（不限，超了要写原因）。出仓默认第一个启用的物料仓（`fromWarehouseId` 能指定，换了出仓要重取，`fromStockQty` 跟着变）；入仓 = 加工厂的工厂仓。
- 退料入库：带出已领 > 0 的行，`suggestQty` = 0，`maxQty` = 已领 − 已退。出仓 = 加工厂的工厂仓，入仓默认第一个启用的物料仓。
- 加工厂还没有工厂仓，回 1000"加工厂××还没有工厂仓，先在仓库里建一个"。

`POST /api/inventory-docs/from-production/{productionOrderId}`，请求 `InvDocFromSourceReq`，返回 `InvDocCreated`。

- 领料超过还差的数（`qty > suggestQty`），那一行 `overReason` 必填，400"第 2 行领多了，要写原因"。
- 退料超过已领，1004。
- 单价：领料、退料尚无可靠估值时为 null，流水 `valuationStatus=UNKNOWN`；二期移动平均是另一个范围，当前不能把未知显示为零或从未来现价回填。

出库单页"领料出库（选生产单）"：先弹一个选生产单的小对话框（接口 05 提供，见 §3.7），选了再走上面两步。退料入库表单里选了"源生产单"的，同样走这两步。

### 3.4 1001、1004 的清单

全局的 `BizErrorDialog` 拿到 `data` 直接按字段画表：字段按下面的顺序出，每个字段一列。名称、单位都是后端翻好的中文，表头由 `BizErrorTable` 的 `LABELS` 翻（Claude 加，见汇报）。`msg` 是一句话的总结，批量条（`silent`）只显示 `msg`，所以 `msg` 要能单独看懂。

#### 3.4.1 1001 库存不足

什么时候：出库单、调拨、领料、退料、采购退货审核；任何入库单反审核；盘点单审核、反审核（调完是负的）。`data` 是 `StockShortRow[]`：

| 字段 | 表头 | 例子 |
|---|---|---|
| `seqs` | 行 | `3、5`（单上第几行，同仓同 SKU 的几行合成一行） |
| `warehouseName` | 仓库 | 面料仓 |
| `skuCode` | SKU | `ML0001-KQ` |
| `materialName` | 物料 | 220g 斜纹棉-卡其 |
| `stockQty` | 库存 | 0.14 |
| `needQty` | 要扣 | 1（盘点是盘亏的数） |
| `shortQty` | 差 | 0.86 |
| `unit` | 单位 | 米（库存单位） |

`msg`：`库存不够：220g 斜纹棉-卡其 库存 0.14，差 0.86 米`，多种的加"等 3 种"（PRD §6.6.6 验收 5 的说法）。

#### 3.4.2 1004 超出上限

什么时候：采购入库超收（净入库超过采购数 × 1.05，Q09）、采购退货超过可退（已入库 − 已退货）、退料超过已领，以及反审核使净收突破上下限。建草稿、改草稿、审核/反审核时都按最新来源累计检查；多个相同源行先合并 delta。`data` 是 `InvOverRow[]`：

| 字段 | 表头 | 例子 |
|---|---|---|
| `seq` | 行 | 2 |
| `skuCode` | SKU | `ML0001-KQ` |
| `materialName` | 物料 | 220g 斜纹棉-卡其 |
| `sourceNo` | 源单 | `CG202611150001` |
| `thisQty` | 本次 | 420 |
| `maxQty` | 最多 | 414.55 |
| `unit` | 单位 | 米（采购的两种是采购单位，退料是库存单位） |
| `reason` | 说明 | 采购 871 米，溢收 5%，已入库 500、已退 0 |

`msg`：`220g 斜纹棉-卡其 这次 420 米，最多还能入 414.55 米`，多种的加"等 n 种"。

### 3.5 物料盘点单

#### 3.5.1 列表 `GET /api/inventory-counts`

参数 `PageParams & CountQuery`，返回 `PageResult<CountRow>`，新的在前。`auditForMe=true` 同出入库单（只列待审核的）；页面右边有"待我审核"勾选。

#### 3.5.2 详情 `GET /api/inventory-counts/{id}`

返回 `CountDetail`，每个 `CountItem` 新增只读 `bookRevision: number | null`，为拍账时该完整库存键的变动水位；null 表示升级前的旧记录，不能当 0 放行（重新取账面数时当作有过进出处理）。`movesSinceBook` 是待审核时的流水提示，不替代提交时 revision 校验，也不能凭余额没变判断没有收发。`filesEditable` 同出入库单（看 `inventory:count:edit`）。

#### 3.5.3 有没审核盘点单的仓库 `GET /api/inventory-counts/open-warehouses`

返回 `CountOpenWarehouse[]`。新建对话框打开时调一次。

#### 3.5.4 新建 `POST /api/inventory-counts`

请求 `CountCreateForm`，返回 `CountCreated`。主体必填，对话框里默认填我的默认主体（README §3.3），没有就空着让人选。

- 同一个仓库已经有草稿或待审核的盘点单，回 1000"这个仓库有一张没审核的盘点单 PD…"（数据库有部分唯一索引兜底，PRD §6.6.8 规则 4）。
- 日常盘点：全部 = 这个仓有库存记录的 SKU（数量是 0 的也带）；按分类 = 其中这几个二级分类的；手选 = `skuIds`，至少一个。账面数 = 现在的库存。
- 期初录入：范围只能是手选（发别的回 400），`skuIds` 可以是空的。账面数都是 0。已经有库存（不是 0）的 SKU 不能进期初录入单，回 1000 列出是哪几种，提示"用日常盘点"——不然审核时期初数会叠加到已有库存上。
- 在同一个完整库存键锁内读取账面量和 `movement_revision`，存为 `bookQty/bookRevision`，记 `bookTime`；无余额记录先确保记录存在再锁。期初量虽为 0 也记录真实水位，不硬编码 revision=0。

#### 3.5.5 存草稿 `PUT /api/inventory-counts/{id}`

请求前端 `CountForm`（后端 `CountSaveReq`），带单头 `version` 整体覆盖：`items` 按 SKU 对上已有行，改实盘数和备注；没有的行删掉（过账行不能删，1000）；新 SKU 不在这里加（400），用 §3.5.6。实盘数 ≥ 0，可为 null。账面量和 `bookRevision` 只读，客户端不传回或修改水位，提交用服务端保存的水位校验。

#### 3.5.6 加物料 `POST /api/inventory-counts/{id}/items`

请求 `{ version, skuIds }`，返回加完的 `CountDetail`。已有 SKU 跳过；新增行按 §3.5.4 同锁拍账面数和水位，实盘为 null（期初录入账面是 0，有库存的 SKU 同样拦）。

#### 3.5.7 重新取账面数 `POST /api/inventory-counts/{id}/refresh-book`

请求 `DocActionReq`，返回新的 `CountDetail`。在同键锁内逐行比对：`bookRevision` 为 null 或和现在的变动次数不一样的行，重拍账面数和 `bookRevision`（期初量仍为 0）、`countedQty` 清为 null，要重数；没动过的行不变（11-17 改，原来全部清空）。更新 `bookTime`；全部/分类范围补入新出现的 SKU，已有行不删。前端确认框："取账面以后有过进出的行，按现在的库存重拍账面数、清空实盘数，要重数；没动过的行不变。" 成功后提示清空了几行。

#### 3.5.8 状态动作

请求 `DocActionReq`，前端用 `countApi.act(id, action, body)`。

| 动作 | 从 → 到 | 权限 | 说明 |
|---|---|---|---|
| `submit` | 草稿 → 待审核 | `inventory:count:submit` | 明细至少一行且实盘全填；完整库存键锁内核对当前 revision 等于每行 bookRevision，任一 null/变化回 1002，消息里写出是哪几行（第 n 行 + SKU 码，最多列 5 行），data 是全部行；整单不提交 |
| `withdraw` | 待审核 → 草稿 | 制单人 | |
| `reject` | 待审核 → 草稿 | `inventory:count:audit` | 原因必填 |
| `audit` | 待审核 → 已审核 | `inventory:count:audit` | 提交已确认差额，之后收发允许；把固定的实盘−账面差额加到当前库存，记盘盈/盘亏/期初，负库存回 1001。不再用提交后的 movement 判过期；旧 PENDING 且 bookRevision=null 须先退回重取重数 |
| `unaudit` | 已审核 → 草稿 | `inventory:count:audit` | 调整退回、追加反向流水；负库存 1001，仓库已有另一张未审核盘点 1000。实盘数留着，`bookRevision` 对齐到反过账后的变动次数：改了能直接再提交，回草稿以后又有进出的行提交时照样拦（11-17 改） |
| `void` | 草稿 → 已作废 | `inventory:count:remove` | 只给过过账又反审核回来的草稿（§2.2），原因选填 |

审核确认框说明"提交时已确认差额，审核将此差额应用到当前库存；提交后的正常收发保留"。`movesSinceBook` 仅作信息提示。提交前即使先出 10 再入 10、余额恢复原值，revision 变化仍须重取重数；不能套用"只提示不拦"放行计数期间收发。反审核确认写"调整退回，回到草稿；再次提交前须重取账面并重新数货"。

#### 3.5.9 删除 `DELETE /api/inventory-counts/{id}`

没过过账的草稿才能删（过过账的 1000，只能作废）。删了、作废了，这个仓都能重新开盘点单。

#### 3.5.10 导出盘点表 `GET /api/inventory-counts/{id}/sheet`

用 `countApi.sheet(id, no)` 下载。Excel 一张表，列：SKU 码、物料编码、名称、颜色、规格、单位、账面数、实盘数、备注。实盘数、备注填现在单上的（没填的空着），这样盘了一半导出、再导回不会丢。

#### 3.5.11 导回实盘数 `POST /api/inventory-counts/{id}/import`

用 `ImportDialog`：`template-url` 传 `countApi.sheetUrl(id)`（盘点表就是模板），`import-url` 传 `countApi.importUrl(id)`。草稿才能导。

- 按 SKU 码对上行，填实盘数和备注。实盘数空着的行跳过（不清掉单上已填的）。
- DAILY表里有、单上没有的SKU首次仅加行，按§3.5.4同锁拍账面与水位，countedQty仍为null，ImportResult.notes要求重数后填写/重导；不能把拍账前的文件实盘直接当有效。OPENING仍零余额且校验水位；已有行不借导入刷新水位。导入不绕过提交前 revision 校验，也不能用导入旧实盘规避重新数货要求。
- 有一行对不上（SKU 码不存在、实盘数不是数字或是负数、期初录入里有库存的 SKU），整批不导，回 1003，`data` 是错误清单（`{ row, column, message }`）。
- 成功返回 `{ total, notes }`，`notes` 写"新加了 2 种物料""5 行实盘数是空的，跳过了"这类说明。导完前端重新取详情。

#### 3.5.12 导出列表 `GET /api/inventory-counts/export`

参数同列表，加 `ids`。一行一张单；使用最近成功展示的规范化条件快照，选中 ID 仍受该条件和权限限制。

### 3.6 库存、库存日志

#### 3.6.1 库存明细 `GET /api/stocks`

参数 `PageParams & StockQuery`，返回 `PageResult<StockRow>`，按仓库、SKU 码排。成品仓不在这里（成品二期，Q01、Q44）。默认不列数量是 0、也没有在途的格子；有在途（已审核、没入齐的采购行送到这个仓）的格子，库存是 0、还没有库存记录也列一行：数量 0，`id`、`updateTime` 是 null（11-22）。哪些格子有在途由采购那边给（`StockTransitSource`，库存不依赖采购）。

在途、是否低于最小库存不在这里：拿当前页的 SKU id 调 `supplyApi.bySkus`（03 §3.6.2）。在途只给交货地点就是这一行仓库的显示（`transits` 按仓库分）；`belowSafety` 只标物料仓的行（补货看的是物料仓合计）。

#### 3.6.2 按物料汇总 `GET /api/stocks/summary`

参数同上（`warehouseType`、`warehouseId` 用来限定合计哪些仓），返回 `PageResult<StockSummaryRow>`。有在途的 SKU 库存是 0 也默认列（同 §3.6.1）；在途数同样另调 `supplyApi.bySkus`，页面显示送各个仓的合计。

#### 3.6.3 现库存 `GET /api/stocks/qty?warehouseId=&skuIds=`

返回 `StockQty[]`，没库存记录的 SKU 返回 0。表单的"出仓库存"列用：选了出仓、加了行时调。有 `inventory:doc:add` 的人也能调（仓管建单时要看，但不一定看得到库存页）。

#### 3.6.4 库存日志 `GET /api/stock-logs`

参数 `PageParams & StockLogQuery`，返回 `PageResult<StockLogRow>`，新的在前。流水只增不减，页码翻页只给前 1000 页、前 1 万行，再往后回 400"流水较多，请使用游标翻页或缩小日期范围"。

页面用游标翻页 `GET /api/stock-logs/seek`（`stockLogApi.seek`）：参数 `StockLogQuery` 加 `size`（1–100）和 `cursor`（第一页不带），返回 `SeekResult<StockLogRow> { list, nextCursor, hasMore }`（类型在 `composables/useSeekTable.ts`），排序同上，不算总数。`nextCursor` 原样带回去取下一页；它绑定了筛选条件，条件变了还带旧游标回 400"游标无效或查询条件已变化"，前端换条件时从第一页查。`ids` 一次最多 100 个。

点单号：`docRoute({ type: row.docType, kind: row.docKind, id: row.docId, parentId: null })`。

`StockLogRow`（后端 `StockLogRowVO`）新增/明确这些不可变事件字段：

| 字段 | 类型与含义 |
|---|---|
| `unitPrice` | `number \| null`，当次库存单位的四位单价，不是采购单位价；未知为 null |
| `amount` | `number \| null`，当次有符号金额，保留实际过账事实；未知为 null |
| `stockUnit` | `string \| null`，当次库存单位快照，覆盖公共 SKU 简况的现单位；旧未知不冒充历史 |
| `currency` | `string \| null`，当次币种（已知人民币为 CNY） |
| `valuationStatus` | `'RECORDED' \| 'UNKNOWN'`；RECORDED 只表示原始价/额已留存，不代表已做移动加权核算 |
| `reversalOfLogId` | `number \| null`，反向事件引用的原流水 ID；复用原价/单位/币种，金额反号 |

旧流水、无法估值的期初/盘点保留 UNKNOWN，不能写 0 伪造成本，不按当前源价回填历史；原单后续改价不改已有日志。上述字段列表和导出使用同一口径。导出时估值状态写中文（已记价 / 估值未知）；没有 `techpack:cost:query` 的，单价、金额、币种、估值状态四列都不出（11-22 走查改）。

#### 3.6.5 导出

`stockApi.export`、`stockApi.exportSummary`、`stockApi.exportMovement`、`stockLogApi.export`，参数同各自的列表，加 `ids`（明细）。每种视图分别持有最近成功查询的规范化快照，避免从日志切明细后串用筛选；库存单位/价值字段依 §3.6.4。

库存日志可能很多，页面上的"导出"走后台任务（`StockLogExportDialog`、`api/exportJob.ts`，类型 `types/exportJob.ts`）：

- 建任务 `POST /api/export-jobs/stock-logs`：请求体是日志的筛选条件（不带 `page`、`size`、`cursor`），必带 `Idempotency-Key`（README §3.6）。返回 HTTP 202，`R<ExportJobView>`。每人同时最多 2 个没结束的任务，多了回 429。
- 查状态 `GET /api/export-jobs/{id}`：`status` 是 `PENDING`（等待）、`PROCESSING`（生成中）、`RETRY_WAIT`（等待重试）、`SUCCEEDED`、`DEAD_LETTER`（失败）、`CANCELLED`、`EXPIRED`；`rows` 已写行数，`errorCode` 失败原因（文案在 `types/exportJob.ts`），`downloadUrl` 成功后才有。只能看自己建的任务，别人的回 404。
- 取消 `POST …/cancel`、重推 `POST …/retry`（失败、取消、过期的才能重推），都带 `Idempotency-Key`。
- 下载 `GET …/file`：下载时再查一次权限；文件 24 小时后过期。没有看价权限的人导出的文件里没有单价、金额列；建任务时有、后来没了看价权限的，含价格的文件不能再看、不能再下（403），要按现在的权限重新导。
- 上限：100 万行、250MB、15 分钟，超了任务失败、`errorCode` 说明原因，半个文件会删掉。同步导出 `/api/stock-logs/export` 只用于 1 万行以内，超了回 400 提示改用后台任务。


#### 3.6.6 进销存汇总 `GET /api/stocks/movement`（二期，RFC 016 §4）

参数 `PageParams & StockMovementQuery`：`bizDateFrom`、`bizDateTo` 必填（没传 400），最多一年（结束往前推一年要早于开始，超了 400"期间最多选一年"），开始晚于结束 400，年份不在 1900–9999 400；`warehouseType`（`MATERIAL` / `FACTORY`，不传两种都算，别的值 400）、`warehouseId`、`keyword`（SKU 码、物料编码、名称）。返回 `PageResult<StockMovementRow>`，按 SKU 码排，一个物料 SKU 一行（选中的仓合在一起）。

从库存日志现算，不建表：

- 期初 = 业务日期早于 `bizDateFrom` 的变动之和；期末 = 到 `bizDateTo` 为止的变动之和 = 期初 + 入库 − 出库。期末是今天时和库存表的合计对得上。
- 入库、出库按"原来的方向"分：变动数为正是入、为负是出；反审核写的反向日志取反，算进原来那一列，所以采购入库反审核是"采购入库"那列减（拆开的列可以是负数），不算出库。反向日志的业务日期是原单的，反审核会改过去期间的数。
- 拆开的列：`purchaseIn`、`returnIn`、`issueIn`（领料入厂：领料出库在工厂仓那边是入）、`otherIn`、`transferIn`（调入）、`countGain`、`openingIn`（期初录入的盘点单，不是"期初"那一列）；`issueOut`、`returnOut`（退料出厂：退料入库在工厂仓那边是出）、`purchaseReturn`、`otherOut`、`transferOut`（调出）、`countLoss`。入库的几列加起来等于 `inQty`，出库的等于 `outQty`，物料仓、工厂仓、全部都是。选中的几个仓之间的调拨、领料、退料同时算进两边，合计不变。
- 期初、入库、出库、期末全是 0 的不列（期间里进了又全冲掉的也不列）。
- 不出金额：期初、盘点的日志很多没价格（`UNKNOWN`），加起来会误导；等成本模块定了计价方法再加。

导出 `GET /api/stocks/movement/export`（`inventory:stock:export`），参数同上，带全部拆开的列。
### 3.7 和采购、生产的约定

- **03 采购**：待到料的数据和接口在采购（`pendingArrivalApi`）；在途、低于最小库存在采购（`supplyApi.bySkus`）。采购单的入库、退货用本文的 `prefillFromPurchase` / `fromPurchase`。采购那边实现 `StockSourceHandler`（回写已入库、已退货，重算采购单状态，查 1004）。
- **05 生产**：

  - 生产单详情的"领料""退料"直接用 `invDocApi.prefillFromProduction` / `fromProduction` 和本文的对话框组件。
  - 05 已有 `GET /api/production-orders/issue-options?keyword=&factoryId=&returnable=` 给出库单页、退料表单用：领料列还有没领齐的自购料的生产单，`returnable=true` 列已领 > 0 的；返回单号、`kind`、加工厂、款号、数量。
  - 源单 `DocRef` 的 `kind` 是生产单的 `kind`（`OUTSOURCE` / `BUY`），`docRoute` 按它去外发加工单或成品采购单。

## 4. 前端要知道的规则

- **按钮全看 `actions`**。入库单、出库单没有提交，草稿上直接是"审核过账"。
- **表单按类型显示**：出仓、入仓、往来、源单、原因出不出、怎么填，都从 `INV_DOC_TYPE[docType]` 取，页面里不写 `if (docType === …)`。
- **出仓库存**：有出仓的单，选了出仓、加了行、换了仓都调 `stockApi.qty(fromWarehouseId, skuIds)`，填进"出仓库存"列。数量大于库存的标红，提示"库存不够，审核会失败"，但不拦保存（库存可能审核前就到了）。
- **调拨**：选了出仓后，入仓下拉只列同一种仓、去掉出仓本身。
- **日期**：默认东八区业务日，不能选其以后；快捷日期和纯日期加减同 README §3.3。
- **由源单生成的对话框**：
  - "本次"默认 `suggestQty`，旁边显示可入 / 可退 / 还差。
  - 采购入库超过未入库但没超 `maxQty`：琥珀色，提示"超收 n"；超过 `maxQty` 标红、按钮灰掉（后端也会回 1004）。
  - 领料超过 `suggestQty`：琥珀色，超领原因变必填。
  - 本次是 0 的行不建；全是 0 时按钮灰掉。
  - 只有"存草稿"（11-21 起，自己建的单不能自己审，去掉了"入库并过账""出库并过账"）。
  - 一次动作固定 `clientActionId` 和请求快照；结果未知时保留原值重试，并明确提示状态未知。成功/确认前次结束后的新批次才生成新 ID，换来源不能把未确认请求静默当失败。
  - 成功后提示"建了入库单草稿 RK…"带链接；刷新来源页面（采购单详情、待到料）。
- **批量审核**：逐条调 `act(id, 'audit', { version }, { silent: true })`。失败的显示后端的 `msg`（1001、1004 的 `msg` 是一句话总结），留着勾；确认框写"审核后马上改库存"。
- **盘点单草稿**：详情页就是表单，用 `useUnsavedChanges(form)`；首次加载成功或明确保存成功后 hydrate/markSaved，KeepAlive 激活遇 dirty 不覆盖。点提交有修改先存，再用新 version 提交；保存遇 1002 保留输入，问一声，用户点"放弃并载入最新"才重取；不偷偷清空或只换 version 重试。
- **没填的按账面数填**：前端把实盘数是 null 的行填成账面数，标成没保存，用户点保存才生效。
- **盘点单导入**：导完重新取详情，`version` 也换。
- **新建盘点单**：期初录入时范围固定手选、可以不选物料；日常盘点手选至少一个。建好跳到详情。
- **库存页**：在途、标黄要等 `supplyApi.bySkus` 回来，先显示"—"。进这页的人都有 `inventory:stock:list`，这个接口认它，调得通。
- **地址带的参数**（首页待办、库存页按钮跳过来用）：`/stock-in?tab=pending&risk=LATE|NEAR|CUT`、`/stock-in?tab=docs&status=DRAFT`、`/stock-out?status=DRAFT`、`/stock-takes?status=PENDING`（首页待我审核再带 `&auditForMe=1`）、`/stock-takes?new=DAILY|OPENING`（直接打开新建对话框，用途选好）、`/stock?view=log`。
- **操作记录**：`DocLogList` 的 `actions` 传 `INV_DOC_LOG_ACTION` / `COUNT_LOG_ACTION`，`statuses` 传 `INV_DOC_STATUS` / `COUNT_STATUS` 的 label。

1. ~~入库单、出库单没有"作废"~~（11-15 定，11-17 改成第 3 条）。
