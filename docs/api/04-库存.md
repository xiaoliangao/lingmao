# 04 库存

物料入库单、物料出库单、物料盘点单、库存、库存日志。需求看 PRD §6.6.5、§6.6.6、§6.6.8，机制看架构 §5（过账、条件更新、`StockSourceHandler`）、§4.10（一张表两种单据），表看数据库设计 §13（`inv_*`）。

类型在 `web/src/types/inventory.ts`，接口函数在 `web/src/api/inventory.ts`。

物料入库单页的第一个页签"待到料"，数据和接口在采购那边，见 [03-算料采购](03-算料采购.md) §3.4。

### 1.3 入库单、出库单怎么分

一张表 `inv_doc`、一组接口 `/api/inventory-docs`，按 `kind` 分（架构 §4.10）。前端：

- **列表**：两个菜单页各自固定 `kind`，`/stock-in` 发 `kind=IN`，`/stock-out` 发 `kind=OUT`。列表本身写成一个组件（建议 `views/inventory/doc/DocList.vue`，`kind` 当 prop），两个页面各放一个。
- **新建**：页头"新建"的下拉项从 `INV_DOC_TYPE` 里取 `kind` 对得上、`sourceRequired = false` 的类型。入库单：退料入库、其他入库；出库单：调拨、其他出库，另加一项"领料出库（选生产单）"。
- **详情**：一个页面文件挂两个地址。标题、字段按接口返回的 `kind`、`docType` 换（"物料入库单 RK…" / "物料出库单 CK…"）。地址和 `kind` 对不上时（有人手敲了 `/stock-in/` 去看出库单），用 `router.replace(docRoute({ type: 'INV_DOC', kind, id, parentId: null }))` 换到对的地址。
- **权限**：两种单共用 `inventory:doc:*`，要分开给以后再加（架构 §4.10）。

### 1.5 页面长什么样

照原型 `docs/原型/src/5c-material.js`：`/stock-in`、`/stock-out`（列表组件 `StockDocList`、表单 `StockDocForm`、详情 `SD_DETAIL`）、`/stock-takes`、`/stock`，入库对话框是 `PurchaseReceive`。

**物料入库单 `/stock-in`**：页头"新建"下拉（退料入库、其他入库），要 `inventory:doc:add`。下面两个页签：

- "待到料"（`?tab=pending`，默认）：只给有 `purchase:order:list` 的人，没有的人默认进"入库单"。分段控件：全部 / 已逾期 / 3 天内 / 赶不上开裁（数用 `pendingArrivalApi.counts`）。筛选：供应商、采购员、交期。列：采购单（下面小字采购员）、供应商、物料、订单 / 款、已到 / 采购、未到（带采购单位）、交期（下面"逾期 n 天 / 还有 n 天"）、预计到货（能改）、要料日期（下面"赶不上开裁，晚 n 天"）、跟进（能改）、"入库"按钮。勾选列 + 批量条"入库"。行上的操作见 03 §3.4.3。
- "入库单"（`?tab=docs`）：入库单列表。

**物料出库单 `/stock-out`**：页头"新建"下拉（调拨、其他出库、领料出库（选生产单））。下面直接是出库单列表。

**入库单、出库单列表**：分段控件按类型（全部 + 这种单的几种类型）。筛选：状态（草稿 / 已审核）、日期、仓库（出仓或入仓是它）、往来单位（`SupplierSelect`），"我的 / 全部"。列：单号、类型、出仓 → 入仓、往来、源单、物料（第一行 + "等 n 种"）、日期、状态。勾选后批量条：审核、导出选中。空表格："还没有入库单：采购到货在「待到料」点「入库」，其他的点页头按钮新建"（出库单："领料在生产单上点「领料」，其他的点页头按钮新建"）。

**手工新建、改草稿**：对话框（照原型 `StockDocForm`），宽一点放明细。单头：主体公司、日期、出仓、入仓（按 `INV_DOC_TYPE` 的 `from`、`to` 出不出、能选哪种仓）、原因（`reasonDict` 有值用 `DictSelect`，必填；没有就是一行字，选填）、物流单号、备注。退料入库多一格"源生产单"（选填，选了以后走 §3.3.2 的生成接口）。明细：物料（`DataPick kind="sku"` 挑）、出仓库存（有出仓时）、数量（库存单位）、单价、金额、缸号、卷数、备注。

**由源单生成的对话框**（到货入库、退货、领料、退料共用一个，建议放 `components/`，采购单详情、待到料、出库单页、05 的生产单详情都用）：照原型 `PurchaseReceive`。单头：入哪个仓 / 从哪个仓出、日期、物流单号、送货单号（采购入库）、原因（退货、退料）、备注。明细按 `InvDocDraft.items`：物料、可入 / 可退 / 还差（按类型）、出仓库存（有出仓时）、本次（默认 `suggestQty`）、缸号、卷数、超领原因（领料超了才出）、备注。按钮"存草稿"和"入库并过账"（退货叫"退货并过账"，领料叫"领料并过账"），后一个要 `inventory:doc:audit`。

**入库单、出库单详情**：页头按 `actions`：编辑、审核过账、反审核、删除。正文：属性（类型、源单（点了用 `docRoute(source)`）、出仓、入仓、往来、日期、原因、送货单号、物流单号）、明细表（物料、数量 + 单位、采购单位数量（采购的两种）、单价、金额、缸号、卷数、超领原因、备注；草稿且有出仓时多一列"出仓库存"，不够的标红）。侧栏：附件、操作记录。

**物料盘点单列表 `/stock-takes`**：页头"录期初库存"（开新建对话框、用途选好期初录入）和"新建盘点单"，都要 `inventory:count:add`。分段控件按状态（全部 / 草稿 / 待审核 / 已审核）。筛选：仓库、用途、盘点日期。列：单号、仓库、用途、范围（`scopeText`）、盘点日期、盘点人、已填实盘（`filledCount / itemCount`）、差异（"盘盈 n · 盘亏 n"）、状态。

**新建盘点单**：对话框（照原型 `StockTakeNew`）。仓库下拉里，`countApi.openWarehouses()` 返回的仓灰掉，后面写"PD… 还没审"。用途、盘点日期（默认今天）、盘点人（默认自己，`UserSelect`）、范围：全部 / 按物料分类（分类小块多选）/ 手选物料（`DataPick kind="sku"`）。用途选期初录入时范围固定是手选，可以一个都不选（建空单再导入）。

**物料盘点单详情**：页头按 `actions`：导出盘点表、导回实盘数（草稿）、保存（草稿）、提交、审核过账 / 驳回；更多里放从物料库加物料、没填的按账面数填、重新取账面数、撤回、反审核、删除。分段控件：全部 / 没填实盘 / 有差异（前端筛）。列：物料、单位、账面数、实盘数（草稿里能填）、差异（盘盈绿、盘亏红）、已调整（审核后）、备注。侧栏：属性（仓库、用途、范围、盘点日期、盘点人、取账面数的时间）、附件、操作记录。

**库存 `/stock`**：页头按钮：补货提醒（n）（有 `purchase:order:list` 才出，去 `/reorder`）、盘点（去 `/stock-takes?new=DAILY`）、导入期初库存（去 `/stock-takes?new=OPENING`）、导出。仓库类型页签：物料仓 / 工厂仓 / 全部；仓库下拉；视图分段：明细 / 按物料 / 日志。

- 明细：仓库、物料（图、名称、颜色、规格、SKU 码）、数量（带单位；物料仓的行 `belowSafety` 时琥珀色）、在途、安全库存、最近变动。点一行弹它的库存日志（带上仓库和 SKU）。
- 按物料：物料、物料仓合计、工厂仓合计、合计、安全库存。
- 日志：日期、变动类型（多选）、关键字（单号、物料、缸号）。列：日期、类型、单号（点了打开单据）、仓库、物料、变动数量（入绿出红）、结存、缸号、操作人。

## 2. 状态

### 2.1 入库单、出库单

`INV_DOC_STATUS`：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、删、审核过账 |
| `APPROVED` | 已审核 | `active` | 反审核（库存改回去，回到草稿） |

没有待审核，审核即过账（PRD §6.6.5）。也没有作废（用户 11-15 定，§6）：草稿直接删，审核过的先反审核再删。

### 2.2 物料盘点单

`COUNT_STATUS`：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 填实盘数、加删行、导回实盘数、重新取账面数、提交、删除 |
| `PENDING` | 待审核 | `pending` | 审核过账、驳回、撤回（制单人） |
| `APPROVED` | 已审核 | `active` | 反审核（调整退回去，回到草稿） |

单级审核，不走多级审批。草稿直接删、不作废（用户 11-15 定，§6）。

### 3.2 入库单、出库单

#### 3.2.1 列表 `GET /api/inventory-docs`

参数 `PageParams & InvDocQuery`，`kind` 必填（不传 400），返回 `PageResult<InvDocRow>`，新的在前。关键字按单号、源单号、送货单号、物流单号、物料、缸号查。

#### 3.2.2 详情 `GET /api/inventory-docs/{id}`

返回 `InvDocDetail`。草稿且有出仓时，每行带 `fromStockQty`（出仓现在的库存）。

#### 3.2.3 手工新建 `POST /api/inventory-docs`

请求 `InvDocCreateForm`，返回 `InvDocCreated`（草稿）。只收 `INV_DOC_TYPE` 里 `sourceRequired = false` 的类型：退料入库（不挂源单）、其他入库、调拨、其他出库。别的类型回 400"采购入库要从采购单生成"。

校验：

- 出仓、入仓按 `INV_DOC_TYPE` 的 `from`、`to`：该有的必填，仓库类型对得上，启用的。
- 调拨：出仓、入仓不能是同一个仓，而且是同一种（物料仓之间、工厂仓之间，PRD §6.6.5）。
- 其他入库、其他出库：原因必填，是字典里的值。
- 退料入库：往来单位由工厂仓带出（仓库上的加工厂），发什么都按仓库的。
- 日期不能晚于今天。明细至少一行，数量 > 0。同一个 SKU 可以有几行（缸号不同），过账时合起来算。

#### 3.2.4 改草稿 `PUT /api/inventory-docs/{id}`

请求 `InvDocForm`，整体覆盖。草稿才能改。

源单生成的草稿（采购入库、采购退货、领料、退料）只能改单头的日期、仓库、送货单号、物流单号、原因、备注，明细只能改数量、缸号、卷数、超领原因、备注，能删行，不能加源单以外的行（`sourceItemId` 和 `materialSkuId` 要对得上源单）。采购的两种发 `purchaseQty`、`qty` 发 null，后端换算。改了数量就按最新的源单数据再查一遍 1004（§3.4.2）。

#### 3.2.5 删除 `DELETE /api/inventory-docs/{id}`

草稿才能删。没有过账，库存、源单都不用动。

#### 3.2.6 审核过账 `POST /api/inventory-docs/{id}/audit`

请求 `DocActionReq`，草稿 → 已审核。前端用 `invDocApi.act(id, 'audit', body)`。

一个事务里做完（架构 §5.2）：改库存、写库存日志、回写源单。

| 类型 | 库存 | 回写源单 |
|---|---|---|
| 采购入库 | 入仓 + | 采购明细已入库 +（采购单位），采购单状态重算（03 §2.2） |
| 退料入库 | 出仓（工厂仓）−，入仓 + | 挂了生产单的，生产单的已领 −（05） |
| 其他入库 | 入仓 + | — |
| 领料出库 | 出仓 −，入仓（工厂仓）+ | 生产单的已领 +（05）；订单的生产单都领完料时，它的算料单自动关闭（`ISSUED`） |
| 采购退货 | 出仓 − | 采购明细已退货 +，采购单状态重算（已到齐的会回到部分到货，Q39） |
| 调拨 | 出仓 −，入仓 + | — |
| 其他出库 | 出仓 − | — |

库存用条件更新（`qty + 变动 >= 0`），整张单所有行都试一遍，不够的全收集起来，一起回 1001（§3.4.1）。按仓库、SKU 合并后排序再更新，防死锁。

每个仓每个 SKU 记一条库存日志（调拨、领料、退料一张单两条：出仓一条、入仓一条），`changeType` 就是单据类型，缸号带上（一行一条日志时带那行的缸号；几行合并的，日志按行分开记，不合并）。

源单状态不对回 1000：采购单已结案、已作废，"采购单 CG… 已结案，不能入库"；生产单那边的条件由 05 定。

#### 3.2.7 反审核 `POST /api/inventory-docs/{id}/unaudit`

请求 `DocActionReq`，已审核 → 草稿。上表反过来做一遍，库存日志再记反方向的一条（不删原来的）。改回去库存会变负的（比如入的料已经领走了），回 1001，清单格式一样。源单那边不让退的（05 定），回 1000。

前端确认框不用通用的文字，写"库存改回去，这张单回到草稿。"

#### 3.2.8 导出 `GET /api/inventory-docs/export`

参数同列表（`kind` 必填），加 `ids`。一行一条明细，单头字段重复。

### 3.3 由源单生成

两步：GET 带出默认值和明细（不存库）画对话框，POST 建单。也可以不弹对话框直接 POST（待到料批量入库）。请求体都是 `InvDocFromSourceReq`，规则写在类型的注释里。

数量单位：采购入库、采购退货按**采购单位**（和采购单、待到料对得上，后端换成库存单位：`qty = 采购单位数量 × 换算系数`，三位小数）；领料、退料按**库存单位**。

`post = true` 时建完马上审核过账，一个事务：过账没过（1001、1004），单据也不建。要 `inventory:doc:add` 和 `:audit`，少一个回 403。

#### 3.3.1 采购单

`GET /api/inventory-docs/from-purchase/{purchaseOrderId}?docType=PURCHASE_IN|PURCHASE_RETURN&itemIds=`，返回 `InvDocDraft`。

- 采购入库：采购单要已审核、部分到货。带出 `maxQty > 0` 的行，`suggestQty` = 未入库，`maxQty` = 采购数 × 1.05 −（已入库 − 已退货）。入仓默认是采购单的交货地点。
- 采购退货：采购单要部分到货、已到齐。带出净入库 > 0 的行，`suggestQty` = 0，`maxQty` = 已入库 − 已退货。出仓默认是交货地点。
- `itemIds` 不传 = 这张单的全部行。

`POST /api/inventory-docs/from-purchase/{purchaseOrderId}`，请求 `InvDocFromSourceReq`，返回 `InvDocCreated`。

- 单价按采购单价换成库存单位（`采购单价 ÷ 换算系数`，四位小数），金额 = 采购单位数量 × 采购单价。前端不传单价。
- 往来单位 = 采购单的供应商。
- 建草稿时就查 1004（超收、超退），不等审核。
- 待到料批量入库：`items: null`、`itemIds` 发勾的行、`post: false`，每行按未入库建草稿；未入库是 0 的行跳过，全跳过回 400"没有要入库的数"。

#### 3.3.2 生产单

`GET /api/inventory-docs/from-production/{productionOrderId}?docType=ISSUE_OUT|RETURN_IN&fromWarehouseId=`，返回 `InvDocDraft`。源是外发加工单或成品采购单（`prd_order`，两种 `kind` 都行）。

- 领料出库：明细由生产那边算（`StockSourceHandler.prefill`，05 实现）：只算物料来源 = 我方采购的行，`needQty` = 加工数 × BOM 用量 ×（1 + 损耗），`issuedQty` = 已领 − 已退，`suggestQty` = 还差的数，`maxQty` 是 null（不限，超了要写原因）。出仓默认第一个启用的物料仓（`fromWarehouseId` 能指定，换了出仓要重取，`fromStockQty` 跟着变）；入仓 = 加工厂的工厂仓。
- 退料入库：带出已领 > 0 的行，`suggestQty` = 0，`maxQty` = 已领 − 已退。出仓 = 加工厂的工厂仓，入仓默认第一个启用的物料仓。
- 加工厂还没有工厂仓，回 1000"加工厂××还没有工厂仓，先在仓库里建一个"。

`POST /api/inventory-docs/from-production/{productionOrderId}`，请求 `InvDocFromSourceReq`，返回 `InvDocCreated`。

- 领料超过还差的数（`qty > suggestQty`），那一行 `overReason` 必填，400"第 2 行领多了，要写原因"。
- 退料超过已领，1004。
- 单价：领料、退料不记单价（null）。成本二期按移动平均算时再补。

出库单页"领料出库（选生产单）"：先弹一个选生产单的小对话框（接口 05 提供，见 §3.7），选了再走上面两步。退料入库表单里选了"源生产单"的，同样走这两步。

### 3.4 1001、1004 的清单

全局的 `BizErrorDialog` 拿到 `data` 直接按字段画表：字段按下面的顺序出，每个字段一列。名称、单位都是后端翻好的中文，表头由 `BizErrorTable` 的 `LABELS` 翻（Claude 加，见汇报）。`msg` 是一句话的总结，批量条（`silent`）只显示 `msg`，所以 `msg` 要能单独看懂。

#### 3.4.1 1001 库存不足

什么时候：出库单、调拨、领料、退料、采购退货审核；任何入库单反审核；盘点单审核、反审核（调完是负的）。`data` 是 `StockShortRow[]`：

| 字段 | 表头 | 例子 |
|---|---|---|
| `seqs` | 行 | `3、5`（单上第几行，同仓同 SKU 的几行合成一行） |
| `warehouseName` | 仓库 | 面料仓 |
| `skuCode` | SKU | `ML0001-KQ` |
| `materialName` | 物料 | 220g 斜纹棉-卡其 |
| `stockQty` | 库存 | 0.14 |
| `needQty` | 要扣 | 1（盘点是盘亏的数） |
| `shortQty` | 差 | 0.86 |
| `unit` | 单位 | 米（库存单位） |

`msg`：`库存不够：220g 斜纹棉-卡其 库存 0.14，差 0.86 米`，多种的加"等 3 种"（PRD §6.6.6 验收 5 的说法）。

#### 3.4.2 1004 超出上限

什么时候：采购入库超收（净入库超过采购数 × 1.05，Q09）、采购退货超过可退（已入库 − 已退货）、退料超过已领。建草稿、改草稿、审核时都查，审核时按最新的数再算（草稿建好以后源单又入了一批，也在这里拦住）。`data` 是 `InvOverRow[]`：

| 字段 | 表头 | 例子 |
|---|---|---|
| `seq` | 行 | 2 |
| `skuCode` | SKU | `ML0001-KQ` |
| `materialName` | 物料 | 220g 斜纹棉-卡其 |
| `sourceNo` | 源单 | `CG202611150001` |
| `thisQty` | 本次 | 420 |
| `maxQty` | 最多 | 414.55 |
| `unit` | 单位 | 米（采购的两种是采购单位，退料是库存单位） |
| `reason` | 说明 | 采购 871 米，溢收 5%，已入库 500、已退 0 |

`msg`：`220g 斜纹棉-卡其 这次 420 米，最多还能入 414.55 米`，多种的加"等 n 种"。

### 3.5 物料盘点单

#### 3.5.1 列表 `GET /api/inventory-counts`

参数 `PageParams & CountQuery`，返回 `PageResult<CountRow>`，新的在前。

#### 3.5.2 详情 `GET /api/inventory-counts/{id}`

返回 `CountDetail`。`movesSinceBook` 只在待审核时算（其他状态是 0），审核确认框用。

#### 3.5.3 有没审核盘点单的仓库 `GET /api/inventory-counts/open-warehouses`

返回 `CountOpenWarehouse[]`。新建对话框打开时调一次。

#### 3.5.4 新建 `POST /api/inventory-counts`

请求 `CountCreateForm`，返回 `CountCreated`。

- 同一个仓库已经有草稿或待审核的盘点单，回 1000"这个仓库有一张没审核的盘点单 PD…"（数据库有部分唯一索引兜底，PRD §6.6.8 规则 4）。
- 日常盘点：全部 = 这个仓有库存记录的 SKU（数量是 0 的也带）；按分类 = 其中这几个二级分类的；手选 = `skuIds`，至少一个。账面数 = 现在的库存。
- 期初录入：范围只能是手选（发别的回 400），`skuIds` 可以是空的。账面数都是 0。已经有库存（不是 0）的 SKU 不能进期初录入单，回 1000 列出是哪几种，提示"用日常盘点"——不然审核时期初数会叠加到已有库存上。
- 记下取账面数的时间 `bookTime`。

#### 3.5.5 存草稿 `PUT /api/inventory-counts/{id}`

请求 `CountForm`，整体覆盖：`items` 按 SKU 对上已有的行，改实盘数和备注；`items` 里没有的行删掉；单上没有的 SKU 不在这里加（400），用 §3.5.6。实盘数 ≥ 0，可以是 null（还没盘）。账面数不改。

#### 3.5.6 加物料 `POST /api/inventory-counts/{id}/items`

请求 `{ version, skuIds }`，返回加完的 `CountDetail`。已经在单上的跳过。账面数取现在的库存（期初录入是 0，有库存的 SKU 同 §3.5.4 拦住）。

#### 3.5.7 重新取账面数 `POST /api/inventory-counts/{id}/refresh-book`

请求 `DocActionReq`，返回新的 `CountDetail`。按范围重新带出明细、重拍账面数、更新 `bookTime`；已经填了的实盘数按 SKU 留着；手选的范围不重新带出，只重拍账面数。前端确认框："账面数换成现在的库存，已填的实盘数留着。"

#### 3.5.8 状态动作

请求 `DocActionReq`，前端用 `countApi.act(id, action, body)`。

| 动作 | 从 → 到 | 权限 | 说明 |
|---|---|---|---|
| `submit` | 草稿 → 待审核 | `inventory:count:submit` | 明细至少一行，实盘数都填了，不然 1000"还有 3 行没填实盘数" |
| `withdraw` | 待审核 → 草稿 | 制单人 | |
| `reject` | 待审核 → 草稿 | `inventory:count:audit` | 原因必填 |
| `audit` | 待审核 → 已审核 | `inventory:count:audit` | 差异不为 0 的行按差异调库存：调整量 = 实盘 − 账面（快照），加到现在的库存上；日志记盘盈、盘亏，期初录入记期初。调完是负的回 1001 |
| `unaudit` | 已审核 → 草稿 | `inventory:count:audit` | 调整退回去，日志再记反方向的；退回去是负的回 1001；这个仓已经有另一张没审核的盘点单，回 1000 |

审核的确认框：`movesSinceBook > 0` 时写"建单以后有 n 笔进出，盘点只调差异，不影响这些进出"（PRD §6.6.8 规则 2，只提示不拦）；反审核的写"调整的库存退回去，这张单回到草稿。"

#### 3.5.9 删除 `DELETE /api/inventory-counts/{id}`

草稿才能删。这个仓随后能重新开盘点单。

#### 3.5.10 导出盘点表 `GET /api/inventory-counts/{id}/sheet`

用 `countApi.sheet(id, no)` 下载。Excel 一张表，列：SKU 码、物料编码、名称、颜色、规格、单位、账面数、实盘数、备注。实盘数、备注填现在单上的（没填的空着），这样盘了一半导出、再导回不会丢。

#### 3.5.11 导回实盘数 `POST /api/inventory-counts/{id}/import`

用 `ImportDialog`：`template-url` 传 `countApi.sheetUrl(id)`（盘点表就是模板），`import-url` 传 `countApi.importUrl(id)`。草稿才能导。

- 按 SKU 码对上行，填实盘数和备注。实盘数空着的行跳过（不清掉单上已填的）。
- 表里有、单上没有的 SKU 加一行，账面数取现在的库存（期初录入是 0）。
- 有一行对不上（SKU 码不存在、实盘数不是数字或是负数、期初录入里有库存的 SKU），整批不导，回 1003，`data` 是错误清单（`{ row, column, message }`）。
- 成功返回 `{ total, notes }`，`notes` 写"新加了 2 种物料""5 行实盘数是空的，跳过了"这类说明。导完前端重新取详情。

#### 3.5.12 导出列表 `GET /api/inventory-counts/export`

参数同列表，加 `ids`。一行一张单。

### 3.7 和采购、生产的约定

- **03 采购**：待到料的数据和接口在采购（`pendingArrivalApi`）；在途、低于安全库存在采购（`supplyApi.bySkus`）。采购单的入库、退货用本文的 `prefillFromPurchase` / `fromPurchase`。采购那边实现 `StockSourceHandler`（回写已入库、已退货，重算采购单状态，查 1004）。
- **05 生产**：
  - 生产那边实现 `StockSourceHandler`：`prefill`（应领、已领、还差，只算我方采购的行；成品采购单可能一行都没有）、`onPosted` / `onUnposted`（回写已领，不让退的回 1000；订单的生产单都领完料时让采购关闭算料单）。
  - 生产单详情的"领料""退料"直接用 `invDocApi.prefillFromProduction` / `fromProduction` 和本文的对话框组件。
  - 05 要提供一个选生产单的接口给出库单页、退料表单用，建议 `GET /api/production-orders/issue-options?keyword=&factoryId=&returnable=`：领料列还有没领齐的我方采购料的生产单，`returnable=true` 列已领 > 0 的；返回单号、`kind`、加工厂、款号、数量。
  - 源单 `DocRef` 的 `kind` 是生产单的 `kind`（`OUTSOURCE` / `BUY`），`docRoute` 按它去外发加工单或成品采购单。

## 4. 前端要知道的规则

- **按钮全看 `actions`**。入库单、出库单没有提交，草稿上直接是"审核过账"。
- **表单按类型显示**：出仓、入仓、往来、源单、原因出不出、怎么填，都从 `INV_DOC_TYPE[docType]` 取，页面里不写 `if (docType === …)`。
- **出仓库存**：有出仓的单，选了出仓、加了行、换了仓都调 `stockApi.qty(fromWarehouseId, skuIds)`，填进"出仓库存"列。数量大于库存的标红，提示"库存不够，审核会失败"，但不拦保存（库存可能审核前就到了）。
- **调拨**：选了出仓后，入仓下拉只列同一种仓、去掉出仓本身。
- **日期**：默认今天，不能选今天以后。
- **由源单生成的对话框**：
  - "本次"默认 `suggestQty`，旁边显示可入 / 可退 / 还差。
  - 采购入库超过未入库但没超 `maxQty`：琥珀色，提示"超收 n"；超过 `maxQty` 标红、按钮灰掉（后端也会回 1004）。
  - 领料超过 `suggestQty`：琥珀色，超领原因变必填。
  - 本次是 0 的行不建；全是 0 时按钮灰掉。
  - 没有 `inventory:doc:audit` 的人只看到"存草稿"。
  - 成功后：`post = true` 提示"入库了，库存已更新"，否则"建了入库单草稿 RK…"带链接；刷新来源页面（采购单详情、待到料）。
- **批量审核**：逐条调 `act(id, 'audit', { version }, { silent: true })`。失败的显示后端的 `msg`（1001、1004 的 `msg` 是一句话总结），留着勾；确认框写"审核后马上改库存"。
- **盘点单草稿**：详情页就是表单，用 `useUnsavedChanges(form)`，加载完、保存完 `markSaved()`。点"提交"时有没保存的改动，先存再提交。
- **没填的按账面数填**：前端把实盘数是 null 的行填成账面数，标成没保存，用户点保存才生效。
- **盘点单导入**：导完重新取详情，`version` 也换。
- **新建盘点单**：期初录入时范围固定手选、可以不选物料；日常盘点手选至少一个。建好跳到详情。
- **库存页**：在途、标黄要等 `supplyApi.bySkus` 回来，先显示"—"。进这页的人都有 `inventory:stock:list`，这个接口认它，调得通。
- **地址带的参数**（首页待办、库存页按钮跳过来用）：`/stock-in?tab=pending&risk=LATE|NEAR|CUT`、`/stock-in?tab=docs&status=DRAFT`、`/stock-out?status=DRAFT`、`/stock-takes?status=PENDING`、`/stock-takes?new=DAILY|OPENING`（直接打开新建对话框，用途选好）、`/stock?view=log`。
- **操作记录**：`DocLogList` 的 `actions` 传 `INV_DOC_LOG_ACTION` / `COUNT_LOG_ACTION`，`statuses` 传 `INV_DOC_STATUS` / `COUNT_STATUS` 的 label。

## 6. 用户定了的

1. **入库单、出库单没有"作废"**（11-15 定）：草稿直接删，审核过的反审核再删，少一个状态。原型里有"作废"，是因为原型建单即过账、没有草稿这一步。
2. **盘点单草稿直接删除、不作废**（11-15 定）：草稿没被任何东西引用，照架构 §6"没被引用的直接删"。权限码 `inventory:count:remove`；PRD v0.11 §6.6.8、数据库设计 v0.7 §13.5、架构 §8 已跟着改。
