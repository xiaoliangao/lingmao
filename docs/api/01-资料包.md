# 01 资料包

覆盖：资料包（研发 / 生产两个阶段、版本、尺寸指示、物料清单、工艺指示、核价四个页签、导出 PDF）、按款看成本、工艺标准（资料包里拉出的抽屉）。

需求：PRD §6.4、§6.9.2（工艺标准）、§6.10（默认取价）。机制：架构 §4.9（核价）、§11.1（PDF）。表：数据库设计 §9（`tp_`）、§3.2（`size_point.text_value`）、§3.9（`sys_config`）。

类型在 `web/src/types/techpack.ts`，接口在 `web/src/api/techpack.ts`。

## 1. 页面

### 1.1 资料包页签（在款式详情里）

资料包没有自己的列表页，是款式详情的一个页签。

- 地址：`/styles/:id?tab=techpack&techPackId=&sub=`。`techPackId` 选哪一版，不给就用 `overview.defaultPackId`；`sub` 是 `spec | bom | craft | cost`，不给是 `bom`。`docRoute` 的 `TECH_PACK` 已经这样拼了。
- 原型：`docs/原型/src/5a-home-style.js` 的 `TechPack`（约 745 行起）、`BomRowForm`、`TpExport`、`TpPrintBody`；款式详情本身在同一个文件约 610 行。
- 页面文件：资料包写成组件，放 `web/src/views/style/style/techpack/`，由 `detail.vue` 引进来。建议拆成 `TechPackTab.vue`（版本条、单头、四个子页签的壳、保存）、`SpecTable.vue`、`BomTable.vue`、`BomRowDialog.vue`、`CraftPanel.vue`、`CostPanel.vue`、`PdfDialog.vue`。

`web/src/views/style/style/detail.vue` 要加的东西：

1. 页签加 `techpack`（资料包）、`orders`（需求订单）。顺序：基本信息、资料包、颜色尺码、需求订单、价格、操作记录。默认还是基本信息。资料包页签要有 `techpack:pack:list`，需求订单页签要有 `order:order:list`。
2. 读地址上的 `tab`、`techPackId`、`sub`。详情页是 keep-alive 的，同一个款再从别处点进来（比如 1005 清单里点了另一版）不会重新挂载，所以要 `watch(() => route.query)`，不能只在 `onMounted` 里读。
3. 打开时调一次 `techPackApi.overview(styleId)`，下面三处都用它：
   - 顶上的黄条：`unmatchedColors` 不空时显示"新颜色 酒红 还没配料，订单不能下这个颜色"，按钮"去资料包"切到资料包页签。
   - 基本信息里加一行"资料包核价"：`unitCost` 不是 null 时显示（研发版前面写"研发估"），点了跳到那一版的核价子页签；有权限但两个阶段都没生效，写"资料包还没生效"；没有 `techpack:cost:query` 不出这一行。
   - 顶上加"下订单"按钮：款式是启用状态，`packs` 里有已生效的生产 BOM，有 `order:order:add`。点了去 `/orders/new?styleId=`（见 02）。
4. 需求订单页签：`orderApi.byStyle(styleId, …)`（在 `api/order.ts`），点一行去订单详情。
5. 资料包生效、修订、建新版以后重新取 overview（黄条和核价跟着变）。

## 2. 状态

资料包不用单据的 `DocStatus`，有自己的三个状态 `PackStatus`（`PACK_STATUS`）：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、删、生效、导出 PDF（表头印"草稿"） |
| `EFFECTIVE` | 已生效 | `done` | 修订；研发版还能转生产 BOM；导出 PDF |
| `VOIDED` | 已作废 | `void` | 只能看、导出 PDF |

- 阶段 `PackStage` 不是状态：研发 BOM（`DEV`）只估价，生产 BOM（`PROD`）发工厂、算料、订单锁它。页面上用普通 `el-tag` 标"研发""生产"，不用 `StatusTag`。
- 版本号每个阶段各自从 V1 起。叫法用 `packName()`："研发 V1"、"V2"。
- 同款同阶段最多一个草稿、一个已生效。新版本生效时，同阶段旧的已生效版自动变已作废。
- 没有"待审核"：有 `techpack:pack:publish` 的人点"生效"就生效（PRD §3.1 的"审"就是它）。

按钮看 `TechPackDetail.actions`（`TechPackAction`），后端按"状态 ∩ 权限 ∩ 业务条件"算好：

| action | 按钮 | 什么时候有 |
|---|---|---|
| `edit` | 页面进入编辑态、出"保存" | 草稿，有 edit |
| `remove` | 删除草稿 | 草稿，有 remove |
| `publish` | 生效 | 草稿，有 publish |
| `revise` | 修订 | 已生效，同阶段没有草稿，有 add，款式没停用 |
| `toProd` | 转生产 BOM | 研发已生效，生产阶段没有草稿，有 add，款式没停用 |

导出 PDF 不在 `actions` 里：能看资料包就能导。

### 3.2 概况 `GET /api/tech-packs?styleId=`

返回 `TechPackOverview`。

- `packs` 研发在前、生产在后，各自新版本在前。版本条照这个顺序排。
- `defaultPackId`：生产草稿 > 生产已生效 > 研发草稿 > 研发已生效（原型 `pickKey`）。
- `creatableStages`：哪个阶段能点"建研发 BOM""建生产 BOM"。生产 BOM 不要求先有研发 BOM（PRD §6.4.1：导入的老款、直接下大货的款直接建生产 BOM）。
- `unmatchedColors`：已生效的生产 BOM 里"随款色""随款色和尺码"的行，没给这些款色配料（款式后来加的颜色，PRD §6.2 规则 4）。
- `unitCost`：生产已生效版的单件成本，没有取研发已生效版；没有看成本权限是 null。
- 款式不存在、看不到：404。

### 3.3 一个版本 `GET /api/tech-packs/{id}`

返回 `TechPackDetail`。核价另取（`cost`），这里只有一个 `unitCost`（没权限是 null）。

- `sizes`、`baseSize` 是款式尺码组的；`colors` 是款式现在启用的颜色。随款色的配料、"按颜色"视图按 `colors` 出行。
- `colors` 跟着款式走，不跟着版本走：已生效的老版本里，后来加的颜色没有配料，页面照样列出来、标"没配料"。
- `pointOptions`：尺寸指示选部位的下拉，带默认测量方法。
- `craftSections` 九段都有，没写的 `content` 是 `''`。
- `processes[].images` 是 `FileVO`（`name` 是文件名，`size` 是 0），直接给 `ImageUpload`。
- `versionLock` 是乐观锁，保存、生效都带回去。叫这个名字是因为 `tp_tech_pack.version` 是版本号。

### 3.4 新建 `POST /api/tech-packs`

请求 `{ styleId, stage }`，返回新草稿的 id。

- 这个阶段已经有草稿：1000"生产 BOM 已经有草稿 V3，改那一版就行"。
- 款式停用：1000。草稿款可以建（草稿款本来就要先建资料包）。
- 新草稿：版本号 = 这个阶段最大版本 + 1；工艺指示九段带工艺标准的默认文字，包装方式带默认包装方式（PRD §6.4.4 规则 1）；其他都是空的。

### 3.5 保存草稿 `PUT /api/tech-packs/{id}`

请求 `TechPackSaveForm`，整版覆盖：单头能改的几项 + 尺寸指示、物料清单、工艺指示、工序工价的全部行，数组顺序就是序号。

- `cost`：核价的手填部分（按什么算、成品单价、其他费用）。**没有看成本权限的人一律发 null**，后端不动核价；有权限的人发整份。这样没权限的人保存不会把核价清掉。
- 不是草稿了、`versionLock` 对不上：1002，页面提示后重新取。
- 保存不做生效前的检查（没配齐料也能存），只查格式：部位、物料必填，用量、损耗率、单价不能是负数，物料要存在。
- 单位不用发：后端取物料的库存单位存一份。
- 返回新的 `versionLock`。"有修改时点生效"就用它接着调 `publish`。平时保存完重新 `get` 一次（拿后端算好的单件成本）。

### 3.6 删除草稿 `DELETE /api/tech-packs/{id}`

只能删草稿，已生效、已作废的回 1002。确认框："这一版改的内容都不要了，删除后找不回来；已生效的版本不受影响。"按钮"删除"。删完版本条选 `defaultPackId`。

### 3.7 生效 `POST /api/tech-packs/{id}/publish`

请求 `{ versionLock }`。

**检查没通过**回 1000，`data` 是 `PublishProblem[]`，一次列全（PRD §6.4.3）：

| 检查 | 例子 |
|---|---|
| V2 起要写本版说明 | `{ row: 0, message: "V2 起要写本版说明" }` |
| 至少一行 BOM | `{ row: 0, message: "物料清单是空的" }` |
| 随款色、随款色和尺码的行，每个启用颜色都配了 | `{ row: 1, message: "黑色还没配料" }` |
| 随尺码、随款色和尺码的行，每个尺码都配了 | `{ row: 3, message: "XXL 还没配料" }` |
| 分码的行每个尺码都有用量 | `{ row: 2, message: "S 码没填用量" }` |
| 用到的物料、SKU 都没停用 | `{ row: 4, message: "物料 220g 斜纹棉 已停用" }` |

前端调的时候传 `{ silent: true }`，出错照供应商详情"申请准入"的写法：`code === ErrorCode.BIZ` 且 `data` 是非空数组，就 `showBizError` 弹清单（`row` 是 0 时 `BizErrorTable` 显示"—"）；不是就 `ElMessage.error`。

- 尺寸指示不是必填（PRD §6.4.2 规则 3）。
- 款式停用了：1000。款式是草稿也能生效。
- 成功：同阶段旧的已生效版变已作废；写操作记录；生效人、生效时间是当前用户和现在。提示"V2 已生效"，研发版加一句"要下大货就点「转生产 BOM」"。

### 3.8 修订、转生产 BOM

`POST /api/tech-packs/{id}/revise`、`POST /api/tech-packs/{id}/to-prod`，返回新草稿的 id。版本条切到新草稿。

- 修订：同阶段复制，版本号 + 1。四个页签和核价的手填部分全部带过去；工艺指示带的是上一版的文字，不再取默认（PRD §6.4.4 规则 1）；本版说明清空。
- 转生产 BOM：只有研发已生效版能转。复制成生产阶段的下一版（第一次就是 V1），记下来源（`sourcePackId`）。**物料清单的单价按生产 BOM 的规则重新取**（价格档案现价 > SKU 单价 > 物料参考单价）；用量、损耗、配料照抄。
- 同阶段已经有草稿：1000。不是已生效：1002。
- 提示照原型：修订"修订出 V3，尺寸、物料、工艺、其他费用都带过来了，改完点「生效」"；转生产"复制成生产 V1 草稿：单价按价格档案重新取了，改完点「生效」"。

### 3.9 BOM 默认值 `POST /api/tech-packs/{id}/bom-defaults`

请求 `{ items: BomDefaultReq[] }`，返回 `BomDefault[]`，按请求的顺序一一对应。

什么时候调：加一行（选完物料）、换物料、换供应商、配料换了 SKU。一次能问几行（从物料库一次勾几种料加进来时）。

返回的东西填进行里：供应商（没选的话）、损耗率、物料来源、参考单价、价格来源、含税含运、各 SKU 单独的单价。**只在加行、换物料时整套覆盖；换供应商、换 SKU 时只覆盖单价那几项**，用户手改过的用量、备注不动。

单价规则（PRD §6.4.3）：

- 生产 BOM：价格档案里这家供应商这个 SKU 的现价 > 这家供应商这个物料的现价 > 物料 SKU 单价 > 物料参考单价。
- 研发 BOM：不看价格档案，物料 SKU 单价 > 物料参考单价。
- 都换算成元 / 库存单位（价格档案、物料单价是按采购单位的）。
- 后端算默认值，前端不直接调价格档案的接口：取价规则只写在后端一处。

物料停用了：1000。

### 3.10 核价 `GET /api/tech-packs/{id}/cost?colorId=`

返回 `TechPackCost`。都是打开时现算的，不存（架构 §4.9）。

- 没有 `techpack:cost:query`：403。前端没权限就不出核价子页签，不会调到。
- `colorId` 不给 = 款式第一个颜色。随款色的行各颜色单价可能不一样，页签顶上放颜色切换，切了重新调。
- 面料块 = 物料类型是面料、里料的行；辅料块 = 其余的行。只有"我方采购"的行 `counted = true` 计入；工厂自备的显示"含在加工价里"，客供的显示"客户出"，`cost` 是 0。
- 加工费：按外发算 = `laborTotal`（工序工价合计）；按成品采购算 = 成品单价，没填用 `buyPriceDefault`，都没有是 0。
- 按外发算时，`buyPriceDefault` 不是 null 就多显示一行"成品采购参考价"，不计入（原型 `cpRef`）。
- `dev` 不是 null 时多一列"研发估"，显示每一块研发版算出多少、差多少（PRD §6.4.5）。行上的 `devCost`、`devAmount` 是 null 时显示"研发没有"。
- `mixedBasis = true` 时在合计旁边标"单价口径不一（有的含税有的不含），照录入的数加总"。
- 倍率 `ratio` 后端算好，两位小数。

草稿版本的核价算的是**上次保存的**数。页面上改了没保存时，核价子页签上方提示"有没保存的修改，保存后核价才更新"。

### 3.11 操作记录 `GET /api/tech-packs/{id}/logs`

返回 `DocLog[]`，新的在前。用 `DocLogList`，`actions` 传 `TECH_PACK_LOG_ACTIONS`，`statuses` 传 `PACK_STATUS` 的 label。放在资料包页签最下面，或者版本信息那一行点"操作记录"展开，前端定。

动作：`create` 新建、`update` 保存、`revise` 修订、`to-prod` 转生产 BOM、`publish` 生效、`void` 被新版本替代、`export-pdf` 导出 PDF（备注里写选了什么颜色、含不含价格、附不附工艺标准）。

### 3.12 导出 PDF `GET /api/tech-packs/{id}/pdf`

参数 `PdfOptions`：`colorId`（不给 = 全部颜色）、`price`（含价格，默认 false）、`appendix`（附工艺标准，默认 true）。返回 `application/pdf`，文件名在 `Content-Disposition` 里（`27CF001-女式风衣-工艺单-V2.pdf`），`download()` 会读它。

- `price=true` 没有 `techpack:cost:query`：403，不悄悄去掉价格（架构 §11.1）。
- 草稿也能导，表头印"草稿"。
- 每次导出记一条操作记录。
- 版式、哪些块不出（空的段、没填的尺寸指示）都是后端定的，前端只给选项。

### 3.13 按款看成本 `GET /api/style-costs`

参数 `PageParams & StyleCostQuery`，返回 `PageResult<StyleCostRow>`。

- 一个款一行：取生产已生效版，没有取研发已生效版；两个都没有的款不列。
- 数字和资料包核价子页签按款式第一个颜色算的合计一样（PRD §6.4 验收 10）。
- 排序：款号倒序（新款在前）。
- 筛选：关键字（款号、名称、花名）、品类（含下级）、品牌、年份、季节、取到的是研发还是生产版。品类用 `categoryApi` 的树，品牌、季节用 `DictSelect`。

### 3.14 工艺标准

`GET /api/craft-standards` 返回 `CraftStandard`：文件、九段默认文字、默认包装方式、部位和测量方法、`editable`（有没有改的权限）。

- 文件：先 `upload` 到 `/api/files` 拿 `FileVO`，再 `replaceFiles` 整组替换。数组顺序就是导出时附页的顺序，改 `name` 就是改附页标题。只收 PDF 和图片（jpg、png），别的类型 400。
- 默认文字：`saveTexts` 整份覆盖，九段都发。改了只影响以后新建的资料包，已有的不变。
- 测量方法：`saveMethods` 只改传了的部位。存在字典 `size_point` 的 `text_value` 上。
- 加部位：`addPoint(label, method)`，部位进字典 `size_point`（value 就用名称）。同名的已经有了：1000。删部位、停用部位到管理后台的字典管理里做，这里不做。
- 资料包本身不靠这个接口：新建草稿时后端带默认文字，尺寸指示的下拉在 `TechPackDetail.pointOptions` 里。只有拉出工艺标准抽屉时才调。

## 4. 前端要知道的规则

### 4.1 版本条

- 一个版本都没有：空状态"还没有资料包：生产 BOM 生效后才能下订单"，下面两个按钮"建生产 BOM""建研发 BOM"，按 `creatableStages` 出。
- 有版本：顶上一排分段控件选版本，文字是 `packName()` + 状态（"V2 生效中""V3 草稿""研发 V1 已作废"）。右边按钮按 `actions` 出：生效、转生产 BOM、修订、导出 PDF、删除草稿；`creatableStages` 里有、但这个阶段一个版本都没有的，再出"建研发 BOM"或"建生产 BOM"。
- 下面一行版本信息：阶段标签、状态、来源（"来源：研发 V1"，点了切到那一版）、生效人和时间、排版利用率、参考加工价、单件成本（没权限不出）。草稿多一个"本版说明"输入框，V2 起占位文字写"本版说明（V2 起必填）：这版改了什么"。
- 子页签：尺寸指示、物料清单、工艺指示、核价。核价要 `techpack:cost:query`。尺寸指示、物料清单的页签上带行数。

### 4.2 编辑和保存

- 只有 `actions` 里有 `edit` 才可编辑；已生效、已作废的整页只读。
- 四个子页签共用一份表单，一个"保存"按钮（放在版本条右边）。切子页签不丢修改。整页表单用 `useUnsavedChanges(form)`，加载完、保存完 `markSaved()`。
- 换版本、离开页签前有没保存的修改：问一句"V3 有没保存的修改，不要了吗？"。
- 生效前先保存：有没保存的修改时点"生效"，先 `save` 再 `publish`。
- 拖动排序：物料清单、尺寸指示、工序工价的行都能拖（只有草稿）。

### 4.3 尺寸指示

- 列：序号、部位、测量方法、公差 ±、档差、各尺码（按 `sizes`，基码那一列标出来）、备注。数字一位小数，单位 cm。
- 部位：`el-select filterable allow-create`，选项是 `pointOptions`。换部位时，测量方法空着、或者还是原部位的默认写法，就换成新部位的默认测量方法（原型 `setPt`）。
- **按档差生成**（PRD §6.4.2 规则 2）在前端算：填了基码尺寸和档差的行，其他码 = 基码 ± 离基码第几档 × 档差。这一行已经填了数的格子会被覆盖，生成前问一句。没填档差的行不动。提示"按档差算了 3 行；1 行没填档差，没动，算完每格还能改"。
- 新加一行默认公差 0.5。

### 4.4 物料清单

- 列：序号、缩略图、部位、物料（编码 + 名称）、配料（摘要，见下）、用量（统一写一个数，分码写"2.10–2.50"）、单位、损耗 %、来源、供应商、参考单价、单件成本、备注。单件成本没权限也显示（PRD 只把核价页签算作成本，架构 §4.9：BOM 的单价不受看成本权限管）。
- 加一行：从物料库选（`DataPick kind="sku"`，一次勾多条），一种物料一行。同一种物料只勾了一个 SKU 的，配料方式默认"固定"、配上它；勾了几个不同颜色的，默认"随款色"、按颜色配（物料 SKU 的 `colorId` 和款色相同就配上，两边用的是同一张颜色表），配不上的留空。加完调一次 `bomDefaults` 填默认值。部位要用户自己选。
- 改一行（原型 `BomRowForm` 那个对话框）：配料方式、配料、用量方式、用量、损耗、来源、供应商、单价、含税含运、备注。配料的 SKU 下拉用 `materialApi.get(materialId)` 的 SKU 列表。
- 配料方式和配料：
  - 固定：选一个 SKU。
  - 随款色：每个款色一行，各选一个 SKU。
  - 随尺码：每个尺码一个 SKU。
  - 随款色和尺码：款色 × 尺码一张小表。
  - SKU 下拉只列启用的；已经配了的停用 SKU 照样显示、标红。
  - 配出来的 SKU 可以各有参考单价（`BomSkuForm.refPrice`），null = 用行上的。
- 用量方式：统一一个数；分码每个尺码一个数（小表）。
- 表格行可以展开看配料小表、分码用量小表（PRD §6.4.3 的"页面"一段）。
- **"按颜色"视图**：选一个款色，列出这个颜色实际要用的每个物料 SKU 和各码用量。导出 PDF 的物料清单就是它。数据都在 `TechPackDetail` 里，前端拼。
- **BOM 图**：原型的 `BomFigure` 是示意画。真页面左边放款式图（按选中的颜色），右边放当前行的料卡（图、SKU、用量、来源、供应商、单价）；表格里指到哪行料卡就换成哪行。不做图上标号（库里没存位置）。
- 停用的物料、SKU 标红，提示"生效时会被拦"。随款色的行少配了颜色，配料摘要标"黑色没配料"。这些前端看得出来的问题先标出来，生效时后端再查一遍。
- 单件成本在前端即时算（输入时显示），保存后以后端为准：基码用量 ×（1 + 损耗率 / 100）× 单价；随款色的行取第一个款色的 SKU 单价，随尺码的行取基码那个 SKU 的；工厂自备、客供的行不算。
- 参考单价按库存单位（元 / 米）。旁边小字提示换算回采购单位（"合 18.50 元/公斤"），用 `BomDefault` 里的 `purchaseUnit`、`conversionFactor`。
- 物料来源"客供"只在 TRADE 开时出现（`MATERIAL_SOURCE_LABEL` 里有，下拉里过滤掉）。

### 4.5 工艺指示

- 分三块，照 `CRAFT_GROUPS`：车间缝制（裁剪要求、缝制要求、部位工艺细则、做工品质）、后道（锁钉要求、整烫说明、洗唛 / 烫标、包装要求）、注意事项。
- 每段一个多行文本框 + 插图（`ImageUpload`）。只读时空的段不出。
- 包装要求那一段上面有包装方式单选（字典 `packing_mode`：平铺、挂装、折叠）。
- 最下面是工序工价，标"内部"：列是序号、工序类别（字典 `process_category`）、工序名称、工艺要求、图示、标准工时（秒）、工价（元）、备注；底下合计总工时、参考加工价。工价、合计没有看成本权限也显示（架构 §4.9）。

### 4.6 核价

- 顶上：按什么算（外发 / 成品采购，分段控件）、颜色切换；按成品采购算时多一个成品单价输入框，占位写 `buyPriceDefault`（"默认 85.00，取自价格档案"）。这三样只读版本也显示，只是不能改。
- 四块：面料、辅料（列：部位、物料 SKU、用量、损耗、单价、单件成本、研发估）、加工费（一行，说明"n 道工序"或"成品单价"）、其他费用（草稿能加行：名称、金额、备注）。
- 合计 = 单件成本，旁边显示吊牌价、倍率；有研发估时写"比研发估高 3.20"。
- 按什么算、成品单价、其他费用跟着保存一起发（`TechPackSaveForm.cost`）。没有看成本权限的人看不到这个子页签，保存时 `cost` 发 null。

### 4.7 导出 PDF

- 对话框（原型 `TpExport`）：颜色（全部 / 某一个，`el-select`）、含价格（复选框，**没有 `techpack:cost:query` 不出这个选项**）、附工艺标准（默认勾）。确定后 `techPackApi.pdf(id, options, fallbackName)`，`fallbackName` 用 `款号-款名-工艺单-V版本.pdf`。
- 手机上：用 `utils/request.ts` 的 `fetchFile` 取回文件，`navigator.canShare({ files })` 可以就弹系统分享面板，不行就 `saveFile` 下载（架构 §11.1，用法见 `fetchFile` 的注释）。
- 在微信里打开的（UA 带 `MicroMessenger`）：先提示"点右上角，在浏览器里打开"，不直接下载。

### 4.8 工艺标准抽屉

- 没有 `editable` 的人整个只读，没有底栏。每次拉出来都重取。关抽屉时默认文字、测量方法哪块没保存都先问。
- 文件：一行一个，显示名称（能改）、类型、大小，能上下移、删除。删除确认："以后导出的工艺单不再附这个文件；已经发出去的不受影响。"
- 默认文字：九段一段一个文本框，按 `CRAFT_GROUPS` 分三块；包装要求那段上面是默认包装方式。一个"保存"按钮。
- 部位：一张表，部位名 + 测量方法输入框，停用的灰掉；底下"加部位"输入框。测量方法改完一起保存。

## 5. 按默认做的

| 问题 | 怎么做 |
|---|---|
| Q24 分不分研发 / 生产 BOM | 分。研发只估价，转生产时复制，订单只锁生产 BOM；没有研发阶段的款直接建生产 BOM |

## 6. 定了的取舍

11-15 定（技术取舍，Claude 拍板，告诉过用户）：

1. **核价子页签按"上次保存的"算，不按页面上没保存的数算。** 理由：核价有价格档案、研发版对比，放在后端一处算，前端不再写一遍；草稿改了没保存时提示一句。另一种做法是前端照着同一套规则实时算，要在前后端各写一遍规则，容易对不上。
2. **"研发 vs 生产"对比视图（原型物料清单的第三个视图）放到最后做。** 理由：PRD 只要求核价里有"研发估"一列，已经有了；对比视图不用新接口（取两个版本的 `get` 在前端比），时间够再加。
