# 01 资料包

覆盖：资料包（版本；物料清单、工艺单、核价三个页签；从甲方的 BOM 表导入物料清单；工艺单 Excel 预览）、按款看成本。

需求：PRD §6.4（v0.23）、§6.10（默认取价）。设计：RFC 011（工艺单改成上传文件、BOM 导入、加工费）。机制：架构 §4.9（核价）、§8（文件）。表：数据库设计 §9（`tp_`）、`biz_attachment`（工艺单文件）。

类型在 `web/src/types/techpack.ts`，接口在 `web/src/api/techpack.ts`。

## 1. 页面

### 1.1 资料包页签（在款式详情里）

资料包没有自己的列表页，是款式详情的一个页签。

- 地址：`/styles/:id?tab=techpack&techPackId=&sub=`。`techPackId` 选哪一版，不给就用 `overview.defaultPackId`；`sub` 是 `bom | files | cost`，不给是 `bom`。`docRoute` 的 `TECH_PACK` 已经这样拼了。
- 原型：`docs/原型/src/5a-home-style.js` 的 `TechPack`、`BomRowForm`、`TpFiles`（工艺单页签）、`TpImport`（从 BOM 表导入）、`XlsPreview`（Excel 预览）；款式详情本身在同一个文件。
- 页面文件：`web/src/views/style/style/TechPackTab.vue`（版本条、单头、三个子页签、保存），由同目录 `detail.vue` 引入。同目录：配料对话框 `BomRowDialog.vue`、工艺单页签 `TechPackFiles.vue`、导入对话框 `BomImportDialog.vue`；Excel 预览是公共件 `components/ExcelPreviewDialog.vue`（生产单详情也用）。

`web/src/views/style/style/detail.vue` 要加的东西：

1. 页签加 `techpack`（资料包）、`orders`（需求订单）。顺序：基本信息、资料包、颜色尺码、需求订单、价格、操作记录。默认还是基本信息。资料包页签要有 `techpack:pack:list`，需求订单页签要有 `order:order:list`。
2. 读地址上的 `tab`、`techPackId`、`sub`。详情页是 keep-alive 的，同一个款再从别处点进来（比如 1005 清单里点了另一版）不会重新挂载，所以要 `watch(() => route.query)`，不能只在 `onMounted` 里读。
3. 打开时调一次 `techPackApi.overview(styleId)`，下面三处都用它：
   - 顶上的黄条：`unmatchedColors` 不空时显示"新颜色 酒红 还没配料，订单不能下这个颜色"，按钮"去资料包"切到资料包页签。
   - 基本信息里加一行"资料包核价"：`unitCost` 不是 null 时显示，点了跳到那一版的核价子页签；有权限但还没有生效的版本，写"资料包还没生效"；没有 `techpack:cost:query` 不出这一行。
   - 顶上加"下订单"按钮：款式是启用状态，`packs` 里有已生效的生产 BOM，有 `order:order:add`。点了去 `/orders/new?styleId=`（见 02）。
4. 需求订单页签：`orderApi.byStyle(styleId, …)`（在 `api/order.ts`），点一行去订单详情。
5. 资料包生效、修订、建新版以后重新取 overview（黄条和核价跟着变）。

## 2. 状态

资料包不用单据的 `DocStatus`，有自己的三个状态 `PackStatus`（`PACK_STATUS`）：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改（含传工艺单、从 BOM 表导入）、删、生效 |
| `EFFECTIVE` | 已生效 | `done` | 修订 |
| `VOIDED` | 已作废 | `void` | 只能看 |

- 资料包只有生产 BOM 一种（PRD §6.4.1，甲方 11-18 答 Q24：研发不填物料清单）：发工厂、算料、订单锁它。返回里的 `stage` 都是 `PROD`，二期生产单自己的资料包才有别的值（架构 §4.7），页面上不显示阶段。
- 版本号每个款从 V1 起。叫法用 `packName()`："V2"。
- 同款最多一个草稿、一个已生效。新版本生效时，旧的已生效版自动变已作废。
- 没有"待审核"：有 `techpack:pack:publish` 的人点"生效"就生效（PRD §3.1 的"审"就是它）。

按钮看 `TechPackDetail.actions`（`TechPackAction`），后端按"状态 ∩ 权限 ∩ 业务条件"算好：

| action | 按钮 | 什么时候有 |
|---|---|---|
| `edit` | 页面进入编辑态、出"保存" | 草稿，有 edit |
| `remove` | 删除草稿 | 草稿，有 remove |
| `publish` | 生效 | 草稿，有 publish |
| `revise` | 修订 | 已生效，没有草稿，有 add，款式没停用 |

工艺单的下载、预览不在 `actions` 里：能看资料包就能看。

### 3.2 概况 `GET /api/tech-packs?styleId=`

返回 `TechPackOverview`。

- `packs` 新版本在前。版本条照这个顺序排。
- `defaultPackId`：草稿 > 已生效 > 最新的一版。
- `creatable`：能不能点"建生产 BOM"（有 add、款式没停用、还没有草稿）。
- `unmatchedColors`：已生效的生产 BOM 里"随款色""随款色和尺码"的行，没给这些款色配料（款式后来加的颜色，PRD §6.2 规则 4）。这是颜色级提示，不代表每个待下单 SKU 已就绪；提交、审核、变更和算料还须按 §3.7 的指定 SKU 检查。
- `unitCost`：已生效版的单件成本，`unitCostPackId` 是那一版；没有已生效版、没有看成本权限是 null。
- 款式不存在、看不到：404。

### 3.3 一个版本 `GET /api/tech-packs/{id}`

返回 `TechPackDetail`。核价另取（`cost`），这里只有一个 `unitCost`（没权限是 null）。

- `contextSource: 'LIVE' | 'SNAPSHOT' | 'LEGACY'` 说明展示上下文来源。草稿用 `LIVE`，`sizes`、`baseSize`、`colors` 及款式展示信息取当前主档；新生效版及其以后转为 `VOIDED` 的历史版用 `SNAPSHOT`，读取生效时冻结的色码顺序、基码与展示信息。
- 已生效/已作废旧包没有历史快照时用 `LEGACY`：取款式现在的颜色尺码，再加上 BOM 里用到的（含已停用的色码），保证老版本照样能看。页面上不另加提示（11-17 定：老版本的颜色尺码就是这么来的，提示只会让人看不懂）。
- 对外仍沿用 `sizes`、`baseSize`、`colors` 和既有款式展示字段，随款色配料、按颜色视图均用这份上下文；不暴露内部 `owner_snapshot` 整段 JSON。当前主档新增色码不自动进入已冻结版本。
- `files`：工艺单页签的文件（`PackFile`），按组排（`CRAFT_SHEET` 工艺单、`PATTERN` 纸样和其他、`BOM_SOURCE` 导入的 BOM 表），组里按上传时排的顺序。`url` 带签名，直接下载；`id` 是预览用的。
- `versionLock` 是乐观锁，保存、生效都带回去。叫这个名字是因为 `tp_tech_pack.version` 是版本号。

### 3.4 新建 `POST /api/tech-packs`

请求 `{ styleId }`，返回新草稿的 id。

- 已经有草稿：1000"生产 BOM 已经有草稿 V3，改那一版就行"。
- 款式停用：1000。草稿款可以建（草稿款本来就要先建资料包）。
- 新草稿：版本号 = 这个款最大版本 + 1，内容都是空的。

### 3.5 保存草稿 `PUT /api/tech-packs/{id}`

请求 `TechPackSaveForm`，整版覆盖：单头能改的几项 + 物料清单的全部行（数组顺序就是序号）+ 工艺单文件。

- `files`：工艺单页签的全部文件，按组整组替换，组里的顺序就是数组里的顺序。先 `upload` 到 `/api/files` 拿 `FileVO`，再带上 `category` 放进来。`null` = 不动文件（老页面）；`[]` = 都删了。每组收的类型：工艺单 xls、xlsx、pdf、jpg、jpeg、png、webp；纸样和其他再加 prj；导入的 BOM 表只收 xls、xlsx。放错组、一组超过 20 个：1000，原来的都不动。

- `cost`：核价的手填部分（按什么算、成品单价、加工费、其他费用）。无 `techpack:cost:query` 时前端发 null；服务端在转换内容、删除或写入任何成本字段之前独立裁定权限，无权限即使发了非 null 也忽略并保留原成本。单头成本模式/成品价和费用行使用同一授权决定。
- 有成本权限时，`cost=null` 也表示保留原值；只有当前 pack 的核价请求成功后才能发送非 null 的完整成本对象。成功加载后明确发送空费用/空成品价才表示清空。核价未加载、加载中或失败时仍可保存物料清单、工艺单，但必须发 `cost:null`，不得把默认 `OUTSOURCE`、null 价格、空费用当成已知内容覆盖。
- 不是草稿了、`versionLock` 对不上：1002。保留本地修改并提供重载/放弃入口，不自动覆盖草稿，也不只换 versionLock 强行保存。
- 保存不做生效前的检查（没配齐料也能存），只查格式：部位、物料必填，用量、损耗率、单价不能是负数，物料要存在。
- 单位不用发：后端取物料的库存单位存一份。
- 返回新的 `versionLock`。"有修改时点生效"就用它接着调 `publish`。平时保存完重新 `get` 一次（拿后端算好的单件成本）。

### 3.6 删除草稿 `DELETE /api/tech-packs/{id}`

只能删草稿，已生效、已作废的回 1002。确认框："这一版改的内容都不要了，删除后找不回来；已生效的版本不受影响。"按钮"删除"。删完版本条选 `defaultPackId`。

### 3.7 生效 `POST /api/tech-packs/{id}/publish`

请求 `{ versionLock }`。

**检查没通过**回 1000，`data` 是 `PublishProblem[]`，一次列全（PRD §6.4.3）：

| 检查 | 例子 |
|---|---|
| V2 起要写本版说明 | `{ row: 0, message: "V2 起要写本版说明" }` |
| 至少一行 BOM | `{ row: 0, message: "物料清单是空的" }` |
| 随款色、随款色和尺码的行，每个启用颜色都配了 | `{ row: 1, message: "黑色还没配料" }` |
| 随尺码、随款色和尺码的行，每个尺码都配了 | `{ row: 3, message: "XXL 还没配料" }` |
| 分码的行每个尺码都有用量 | `{ row: 2, message: "S 码没填用量" }` |
| 用到的物料、SKU 都没停用 | `{ row: 4, message: "物料 220g 斜纹棉 已停用" }` |

前端调的时候传 `{ silent: true }`，出错照供应商详情"申请准入"的写法：`code === ErrorCode.BIZ` 且 `data` 是非空数组，就 `showBizError` 弹清单（`row` 是 0 时 `BizErrorTable` 显示"—"）；不是就 `ElMessage.error`。

- 工艺单不是必填：没有工艺单时前端先问一句"还没有工艺单，发工厂时没有文件可发。还是生效吗？"（RFC 011 §2.1）。
- 款式停用了：1000。款式是草稿也能生效。
- 成功：同一事务内冻结版本的 `owner_snapshot`（schemaVersion、所有者展示信息、尺码组/基码、有序尺码与颜色 id/code/name/hex），旧的已生效版变已作废且保留其快照；写操作记录和生效人、时间。提示"V2 已生效"。

**指定 SKU 就绪检查**是资料包 Service 的内部能力，不新增 HTTP 路径。订单提交、每级审核、变更和 MRP 传入实际使用的 `packId + styleSkuIds`，逐 SKU 核对启用状态、版本可用色码、随尺码/随色码的配料及分码用量；错误须定位款色码和物料行。两种口径（11-17 用户定）：新订单提交、审核用 `checkRequirements`，款式颜色 SKU、物料、物料 SKU 停用了也拦；已审核订单的算料和变更单用 `checkLockedRequirements`，只查配料、用量配齐，下单以后才停用的不拦。新快照版本新增色码须先修订生效；旧无快照版本的统一用量/固定配料不能仅因追加尺码而被拒绝。不得扩成全色×全码笛卡尔积检查，也不自动替换已锁定的旧版本；历史包被新版本替代为 `VOIDED` 后，既有订单仍按其锁版执行，不能一律判成失效。

### 3.8 修订

`POST /api/tech-packs/{id}/revise`，返回新草稿的 id。版本条切到新草稿。

- 复制成下一版，版本号 + 1。物料清单、工艺单文件（只抄引用，文件还是那一个）、核价的手填部分（含加工费）全部带过去；本版说明清空。新草稿不复制冻结上下文，重新用 `LIVE` 的当前款色码，补齐后再生效。
- 已经有草稿：1000。不是已生效：1002。
- 提示照原型："修订出 V3，物料清单、工艺单、核价都带过来了，改完点「生效」"。

### 3.9 BOM 默认值 `POST /api/tech-packs/{id}/bom-defaults`

请求 `{ items: BomDefaultReq[] }`，返回 `BomDefault[]`，按请求的顺序一一对应。

什么时候调：加一行（选完物料）、换物料、换供应商、配料换了 SKU。一次能问几行（从物料库一次勾几种料加进来时）。

返回的东西填进行里：供应商（没选的话）、损耗率、物料来源、参考单价、价格来源、含税含运、各 SKU 单独的单价。**只在加行、换物料时整套覆盖；换供应商、换 SKU 时只覆盖单价那几项**，用户手改过的用量、备注不动。

单价规则（PRD §6.4.3）：

- 价格档案里这家供应商这个 SKU 的现价 > 这家供应商这个物料的现价 > 物料 SKU 单价 > 物料参考单价。
- 都换算成元 / 库存单位（价格档案、物料单价是按采购单位的）。
- 后端算默认值，前端不直接调价格档案的接口：取价规则只写在后端一处。

物料停用了：1000。

### 3.10 核价 `GET /api/tech-packs/{id}/cost?colorId=`

返回 `TechPackCost`。合计等派生结果打开时现算、不另存一份（架构 §4.9）；成本模式、成品单价、其他费用等手填数据由 §3.5 保存。

- 没有 `techpack:cost:query`：403。前端没权限就不出核价子页签，不会调到。
- `colorId` 不给 = 该版本上下文的第一个颜色。随款色的行各颜色单价可能不一样，页签顶上放颜色切换，切了重新调。
- 面料块 = 物料类型是面料、里料的行；辅料块 = 其余的行。只有"自购"的行 `counted = true` 计入；厂购的显示"含在加工价里"，客供的显示"客户出"，`cost` 是 0。
- 加工费：按外发算 = `laborPrice`（资料包上填的），没填用 `laborPriceDefault`：价格档案里这个款默认加工厂的清加工现价，没有取半包（`laborPriceDefaultMode` 是 `CMT` 或 `HALF`），都没有是 0。按成品采购算 = 成品单价，没填用 `buyPriceDefault`，都没有是 0。
- 按外发算时，`buyPriceDefault` 不是 null 就多显示一行"成品采购参考价"，不计入（原型 `cpRef`）。
- `mixedBasis = true` 时在合计旁边标"单价口径不一（有的含税有的不含），照录入的数加总"。
- 倍率 `ratio` 后端算好，两位小数。

草稿版本的核价算的是**上次保存的**数。页面上改了没保存时，核价子页签上方提示"有没保存的修改，保存后核价才更新"。

核价请求独立维护未授权、加载中、成功、失败状态，并绑定 packId/请求代次。失败显示重试和未知值，不显示默认 0 或可编辑的空成本；迟到响应不能污染另一版本。重试只刷新对应成本区，不重新 hydrate 其他已编辑块。保存遵循 §3.5 的 null 保留语义。

### 3.11 操作记录 `GET /api/tech-packs/{id}/logs`

返回 `DocLog[]`，新的在前。用 `DocLogList`，`actions` 传 `TECH_PACK_LOG_ACTIONS`，`statuses` 传 `PACK_STATUS` 的 label。放在资料包页签最下面，或者版本信息那一行点"操作记录"展开，前端定。

动作：`create` 新建、`update` 保存、`revise` 修订、`publish` 生效、`void` 被新版本替代。11-18 以前的老记录里还有 `export-pdf` 导出 PDF，照样显示。

### 3.12 从 BOM 表导入 `POST /api/tech-packs/{id}/bom-import`

multipart：`file`（甲方的 BOM 明细表，xls 或 xlsx，10MB 以内），可选 `sheet`（用第几张，从 0 起）、`picks`（人工挑的物料，`行号:物料id`，几个用逗号分开，如 `7:12,9:15`）。返回 `BomImport`，**只解析、不写库**：页面上看过、改过，点"加进物料清单"以后和手填的一样走 §3.5 保存（RFC 011 §4.4）。

- 只有草稿能调，报错和保存一样（不是草稿 1002，款式停用 1000）。文件打不开、不是 Excel、设了密码：1000，提示原因。
- 选哪张 sheet：给了 `sheet` 用它（不是 BOM 表 1000）；没给按第 1 行的款号对上这个款，再按款名、sheet 名，都对不上用第一张能认的。一张都认不出：1000"认不出这张表…物料清单照常手工填"。`sheets` 列出全部，`bom = false` 的在下拉里灰掉。
- 认表：按表头的字认列（有"物料名称"和"单件用量"的那一行是表头），不按第几列；面料块、辅料块各有表头。小计、合计不导；汇总块的加工费进 `laborPrice`，"…运费"进 `fees`。
- 每行一个 `status`：`OK` 认出来了；`CHECK` 能导，`notes` 里写了要看的（单位换算过、价格和档案不一样、供应商用了默认的、部位没认出……）；`UNMATCHED` 没认出物料，`item` 是 null，要先挑（带上 `picks` 再调一次）、新建物料（建完再调一次）或者不导。
- `item` 和 `TechPackDetail.bomItems` 的行一个样子，只是没有 `id`；前端加进表单时给临时 id。规则见 RFC 011 §4.2：同名物料用规格分；颜色写一个 → 固定，几个或"顺色" → 随款色；厘米、米互换；损耗整列是系数时 1.03 → 3；"含税运"等换成含税、含运两个标记。
- 没有 `techpack:cost:query`：`item.refPrice`、`source.price`、`laborPrice` 是 null，`fees` 是空的；保存时新行照常带档案价（§3.5）。
- 走上传的限流（每人每分钟 60 次）和重活的并发闸，和别的导入一样。

### 3.13 工艺单文件和预览

- `GET /api/tech-packs/{id}/files`：返回 `PackFile[]`，和详情里的 `files` 一样。生产单详情的"工艺单"用它，不用拉整个资料包。
- `GET /api/tech-packs/{id}/files/{fileId}/preview`：一个 Excel 的表格数据 `ExcelBook`（RFC 011 §2.3）。不是这一版的文件 404；不是 xls、xlsx：1000"请下载看"；服务器上找不到文件 404。
  - 每个 sheet：列宽、行高（像素，隐藏的是 0）、有字或有底色边框的格子（`r`、`c` 从 0 起，`v` 是 Excel 里显示的字，`s` 是 `styles` 的下标）、合并单元格、图片（位置、大小、data URI）。
  - 上限 20 个 sheet、每个 500 行 × 60 列、图片合计 10MB；超出的数在 `moreSheets`、`moreRows`、`moreCols`、`skippedImages` 里，页面写"后面还有 N 行，下载看全部"。
  - 格子的字一律当文本画（`{{ }}`，不用 `v-html`）。

### 3.14 按款看成本 `GET /api/style-costs`

参数 `PageParams & StyleCostQuery`，返回 `PageResult<StyleCostRow>`。

- 一个款一行：取已生效版；没有的款不列。
- 数字和资料包核价子页签按该版本上下文第一个颜色算的合计一样（PRD §6.4 验收 10）。
- 排序：款号倒序（新款在前）。
- 筛选：关键字（款号、名称、花名）、品类（含下级）、品牌、年份、季节。品类用 `categoryApi` 的树，品牌、季节用 `DictSelect`。

## 4. 前端要知道的规则

### 4.1 版本条

- 一个版本都没有：空状态"还没有资料包：生产 BOM 生效后才能下订单"，下面一个按钮"建生产 BOM"，`creatable` 才出。
- 有版本：顶上一排分段控件选版本，文字是 `packName()` + 状态（"V2 生效中""V3 草稿""V1 已作废"）。右边按钮按 `actions` 出：生效、修订、删除草稿。
- 下面一行版本信息：状态、生效人和时间、排版利用率、参考加工价、单件成本（没权限不出）。草稿多一个"本版说明"输入框，V2 起占位文字写"本版说明（V2 起必填）：这版改了什么"。
- 子页签：物料清单、工艺单、核价。核价要 `techpack:cost:query`。物料清单、工艺单的页签上带个数。

### 4.2 编辑和保存

- 只有 `actions` 里有 `edit` 才可编辑；已生效、已作废的整页只读。
- 三个子页签共用一份表单，一个"保存"按钮（放在版本条右边）。切子页签不丢修改。整页表单用 `useUnsavedChanges(form)`，加载完、保存完 `markSaved()`。
- 换版本、关闭页签或放弃编辑前有没保存的修改：问一句"V3 有没保存的修改，不要了吗？"。KeepAlive 切走再激活、切换子页签不丢修改；dirty 时不自动重取并覆盖表单。
- 生效前先保存：有没保存的修改时点"生效"，先 `save` 再 `publish`。
- 排序：物料清单的行能拖，工艺单每组里的文件点上移、下移（只有草稿）。

### 4.3 工艺单

- 三组，一组一块：工艺单、纸样和其他、导入的 BOM 表（这一组只读，导入时自动加，没有就不出这一块）。每块一张小表：文件名、大小、上传时间不出（附件没存），操作"预览""下载""删除"。
- 草稿点"上传"选文件（一次多个；工艺单一个都没有时也能拖进来），先 `upload` 到 `/api/files`，拿到的 `FileVO` 带上 `category` 放进表单的 `files`，点"保存"才挂到资料包上。组里上移、下移排顺序。
- 上传前前端先按组查扩展名（和 §3.5 一样的规矩），不对的当场提示，不传。
- 预览：xls、xlsx 打开 `ExcelPreviewDialog`（sheet 页签 + 表格）；图片用图片预览；PDF、prj 只能下载（Nginx 把不是图片的文件都按下载发）。
- 删除确认："从这一版资料包上拿掉 xx。保存后生效；已经发出去的不受影响。"按钮"删除"。
- 一个都没有：草稿写"还没有工艺单：把甲方的工艺单 Excel 拖进来"，只读写"这一版没有工艺单"。

### 4.4 物料清单

- 列：序号、缩略图、部位、物料（编码 + 名称）、配料（摘要，见下）、用量（统一写一个数，分码写"2.10–2.50"）、单位、损耗 %、来源、供应商、参考单价、单件成本、备注。单件成本没权限也显示（PRD 只把核价页签算作成本，架构 §4.9：BOM 的单价不受看成本权限管）。
- 加一行：从物料库选（`DataPick kind="sku"`，一次勾多条），一种物料一行。同一种物料只勾了一个 SKU 的，配料方式默认"固定"、配上它；勾了几个不同颜色的，默认"随款色"、按颜色配（物料 SKU 的 `colorId` 和款色相同就配上，两边用的是同一张颜色表），配不上的留空。加完调一次 `bomDefaults` 填默认值。部位要用户自己选。
- 改一行（原型 `BomRowForm` 那个对话框）：配料方式、配料、用量方式、用量、损耗、来源、供应商、单价、含税含运、备注。配料的 SKU 下拉用 `materialApi.get(materialId)` 的 SKU 列表。
- 配料方式和配料：
  - 固定：选一个 SKU。
  - 随款色：每个款色一行，各选一个 SKU。
  - 随尺码：每个尺码一个 SKU。
  - 随款色和尺码：款色 × 尺码一张小表。
  - SKU 下拉只列启用的；已经配了的停用 SKU 照样显示、标红。
  - 配出来的 SKU 可以各有参考单价（`BomSkuForm.refPrice`），null = 用行上的。
- 用量方式：统一一个数；分码每个尺码一个数（小表）。
- 表格行可以展开看配料小表、分码用量小表（PRD §6.4.3 的"页面"一段）。
- **"按颜色"视图**：选一个款色，列出这个颜色实际要用的每个物料 SKU 和各码用量。数据都在 `TechPackDetail` 里，前端拼。
- **从 Excel 导入**：草稿的工具栏上一个按钮，见 §4.5。
- **BOM 图**：原型的 `BomFigure` 是示意画。真页面左边放只读款色主图，右边放当前行料卡（图、SKU、用量、来源、供应商、单价）；表格行 hover 或键盘焦点切换当前行。无主图、未配料、加载中/失败各有明确状态；仅展示已有信息，不改编辑表格或加图上坐标/标号。
- 停用的物料、SKU 标红，提示"生效时会被拦"。随款色的行少配了颜色，配料摘要标"黑色没配料"。这些前端看得出来的问题先标出来，生效时后端再查一遍。
- 单件成本在前端即时算（输入时显示），保存后以后端为准：基码用量 ×（1 + 损耗率 / 100）× 单价；随款色的行取第一个款色的 SKU 单价，随尺码的行取基码那个 SKU 的；厂购、客供的行不算。
- 参考单价按库存单位（元 / 米）。旁边小字提示换算回采购单位（"合 18.50 元/公斤"），用 `BomDefault` 里的 `purchaseUnit`、`conversionFactor`。
- 物料来源"客供"只在 TRADE 开时出现（`MATERIAL_SOURCE_LABEL` 里有，下拉里过滤掉）。

### 4.5 从 BOM 表导入

照原型 `TpImport`（RFC 011 §4.3）：

1. 点"从 Excel 导入"选文件，调 `bomImport`。有几张 sheet 时顶上一个下拉（显示 `title`），换了重新调。
2. 一张预览表：行号、表里写的（物料名称、规格、颜色、用量、单位）、认成的（物料、配料摘要、部位、用量、损耗、单价）、状态（`StatusTag`：认出来了 `done`、要看一下 `pending`、没认出来 `danger`）、提示。部位、用量、损耗、单价能直接改。
3. 没认出来的行三个按钮：挑物料（`DataPick kind="material"`，挑完带 `picks` 重新调一次）、新建物料（`MaterialForm`，名称、规格、单位、颜色、供应商、价格照这一行预先填好，存完带 `picks` 重新调）、不导（这行勾掉）。
4. 底下"加进物料清单（n 行）"：没认出来的行没处理完时按钮灰掉、写"还有 n 行没认出来"。物料清单是空的直接放；已经有行时问"替换现有 n 行"还是"加在后面"。加工费、运费一起填进核价表单（加工费已经填了的问一句要不要换）。导入的文件加进工艺单页签的"导入的 BOM 表"一组。
5. 这时只改了页面上的表单，和手填一样，点"保存"才存。

### 4.6 核价

- 顶上：按什么算（外发 / 成品采购，分段控件）、颜色切换；按成品采购算时多一个四位小数的成品单价输入框，占位写 `buyPriceDefault`（"默认 85.00，取自价格档案"）；按外发算时是加工费输入框，占位写 `laborPriceDefault` 和来源（"默认 25.50，取自价格档案的清加工"）。显示用 `formatPrice`。只读版本也显示，只是不能改。
- 四块：面料、辅料（列：部位、物料 SKU、用量、损耗、单价、单件成本）、加工费（一行，说明"加工费"或"成品单价"）、其他费用（草稿能加行：名称、金额、备注）。
- 合计 = 单件成本，旁边显示吊牌价、倍率。
- 按什么算、成品单价、加工费、其他费用只有当前版本成本成功加载后才随保存发非 null（`TechPackSaveForm.cost`）。没有看成本权限不出此页签；未加载/加载中/失败发 null 保留，失败区可单独重试，见 §3.5、§3.10。

### 4.7 发工厂

导出 PDF 11-18 去掉了：发工厂就发上传的工艺单（§1.3）。手机上点下载以后用系统的分享面板发微信。

## 6. 定了的取舍

11-15 定（技术取舍，Claude 拍板，告诉过用户）：

1. **核价子页签按"上次保存的"算，不按页面上没保存的数算。** 理由：核价要取价格档案，放在后端一处算，前端不再写一遍；草稿改了没保存时提示一句。另一种做法是前端照着同一套规则实时算，要在前后端各写一遍规则，容易对不上。
