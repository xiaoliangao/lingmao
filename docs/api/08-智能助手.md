# 08 智能助手

用户在系统里问一句话，助手替他查系统、用几句话回答，回答里带能点开的单据链接。只能查、不能改。设计看 RFC 017 §3、§13 和 RFC 009 §6（入口；那里写的右侧抽屉 11-22 按用户的意思改成了右下角的浮动卡片），部署看部署手册第 10 节。

接口不在 app 里，在单独的助手服务（`assistant/`，Nginx 把 `/assistant/` 转给它；本机 `pnpm dev` 时 Vite 转给 `VITE_ASSISTANT_TARGET`，默认 `http://localhost:8091`）。类型在 `web/src/types/assistant.ts`，接口函数在 `web/src/api/assistant.ts`。不走 `utils/request.ts`：要带的是助手令牌、问话是流式的；`pnpm dev:mock` 也没有假数据，助手服务没起时图标变灰、提示"暂时用不了"。

## 1. 页面

不是一个页面，是业务菜单这一侧（`/`，`layout/AppLayout.vue`）浮在页面上的两样东西：右下角的图标 `components/assistant/AssistantLauncher.vue` 和点开的对话卡片 `components/assistant/AssistantPanel.vue`，都不占页面的地方（11-22 用户定，原来是右侧抽屉）。状态在 `composables/useAssistant.ts`（模块级单例：切页签、去管理后台再回来，对话都还在）。管理后台和手机页面没有。侧边栏里没有入口。

- **图标**：卡片收着时浮在右下角，默认比分页条高一截（不挡列表页的翻页）；按住能拖到别处，位置记在本机。收着还在答，外圈转；答完了没看，亮个琥珀色的点，打开就灭。快捷键 ⌘J / Ctrl+J 打开、收起。⌘K 快捷跳转里输入两个字以上时，最后一项是"问助手：<输入的话>"，回车打开卡片并发出这句话。
- **出不出图标**：`/api/auth/me` 的 `features.ai` 是 true、有 `assistant:chat:use`。只决定显示，真正的拦截在 app 和助手服务里。
- **服务调不通**（没起容器、没配模型）：图标照样在，变灰，指上去说"暂时用不了"；打开卡片说明原因，有"再试一次"，不弹报错。图标出来时查一次 `health`。
- **卡片**：默认 400×640，贴右下角；按住标题栏能拖（拖出窗口的拉回来，位置记在本机）；"放大"变成 800 宽、差不多整屏高（双击标题栏也行），"还原"回到放大前的地方；"收起"回到图标，在答的接着答。顶上还有最近的对话（下拉，最多 20 个，每个能删）、新对话。下面是对话，最底下输入框：回车发出，Shift+回车换行，最多 2000 字；在答的时候发送键变"停止"。
- **回答**：答的过程中显示"查了 物料（3 行）"这样的工具进度和模型的原话；答完换成处理过的全文，按 Markdown 显示（段落、列表、加粗、行内代码、表格），链接只认站内页面，点了在主区域打开那一页，卡片留着（窄屏上卡片差不多盖满页面，自己收起）。
- **新对话**清空上下文；不跨对话记东西。
- **对话留几天**：默认 7 天，超过没再问的自动删（`ASSISTANT_RETENTION_DAYS`，每小时清一次）；最近的对话下面写一句。接着问一句就从这时重新算（列表里还看得到、没轮到清理的也能接着问）。用户也能自己删，删前确认、找不回来。

## 2. 接口

| 方法 | 路径 | 令牌 | 说明 |
|---|---|---|---|
| GET | `/assistant/health` | 不用 | 服务和它的库好不好、配没配模型 |
| GET | `/assistant/info` | 不用 | 模型是外部的还是内网自部署的（打开 AI 开关前的提醒用）、对话留几天 |
| POST | `/assistant/chat` | 助手令牌 | 问一句，回 SSE |
| GET | `/assistant/conversations` | 助手令牌 | 自己最近的对话，最多 20 个，新的在前 |
| GET | `/assistant/conversations/{id}` | 助手令牌 | 一个对话的全部问答 |
| DELETE | `/assistant/conversations/{id}` | 助手令牌 | 删掉自己的一个对话 |

返回体和 app 一样是 `R { code, msg, data }`，HTTP 状态和 code 一致。

**令牌**：`POST /api/auth/assistant-token`（README §3.1）换来的 30 分钟只读令牌，放 `Authorization: Bearer`。只放内存，不进 localStorage；快到期（剩不到 5 分钟）先换新的。助手服务不收登录令牌（403）。

### 2.1 GET /assistant/health

`AssistantHealth { status: 'UP' | 'DOWN', db: 'up' | 'down', model: 'configured' | 'none' }`。

- 200 + `model: 'none'`：服务好的，但没配模型，问话会回 503"还没有配置模型"。
- 503：库连不上（data 照样是 `AssistantHealth`），或者容器没起（Nginx 回的，`data` 是 null，msg"智能助手没有启动，请联系管理员"）。
- 本机没起助手服务时，Vite 代理回 502 / 504（不是 JSON），当"没启动"。

### 2.2 GET /assistant/info

`AssistantInfo { model: { mode: 'external' | 'self-hosted' | 'none' }, retentionDays: number }`。不给模型地址、Key、主机名。`none` 是没配模型。`retentionDays`：对话超过这么多天没再问就自动删掉（默认 7）。

### 2.3 POST /assistant/chat

请求体 `AssistantChatRequest { message: string, conversationId?: string | null }`：`message` 去掉首尾空白后不能空、最多 2000 字；`conversationId` 是 `meta` 给过的，接着问就带上，不带是新对话。

成功是 HTTP 200、`Content-Type: text/event-stream`，依次推：

| 事件 | data | 说明 |
|---|---|---|
| `meta` | `{ conversationId, created }` | 第一个到。`created` 是不是新开的对话 |
| `tool` | `{ name, label, status: 'running' }` / `{ name, status: 'ok' \| 'failed', rows }` | 开始查、查完；工具一个接一个查，完成的那条对应最近一条同名的 running。`rows` 是查到几行（不是列表的是 null） |
| `delta` | `{ text }` | 模型的原话，一段一段到。**只能当纯文本显示**：没处理过，可能有外链、HTML |
| `done` | `{ messageId, text, usage: { promptTokens, completionTokens } }` | 答完。`text` 是处理过的全文（只留站内链接，其余 `[ ] <` 换成全角），**只有它能当 Markdown 渲染**，替换掉前面的 delta |
| `error` | `{ message, messageId }` | 没答完（模型出错、服务在重启）。用户自己点停止的不推 |

`done` 和 `error` 只会到一个，到了流就结束。流断了却两个都没到：当"连接断了，这句没答完"。

不是 SSE 时是 JSON 错误：

| HTTP / code | 什么时候 | 前端怎么办 |
|---|---|---|
| 400 | 问题是空的、太长、请求体不对 | 显示 msg |
| 401 | 令牌过期或失效（换它的那次登录退出了） | 重新换令牌再发一次；还 401 就显示 msg |
| 403 | 不是助手令牌、AI 功能关了、没有使用权限 | 显示 msg |
| 404 | `conversationId` 不是自己的、不存在 | 显示 msg，回到新对话 |
| 429 | 上一句还在答；全系统同时在答的满了；今天的次数或全系统 token 到上限 | 显示 msg（刚点了停止马上再问，可能碰到"上一句还在答"，等一两秒再发） |
| 502 | 助手连不上 app | 显示 msg |
| 503 | 没配模型、服务在重启、容器没起 | 显示 msg，图标变灰、提示"暂时用不了" |

浏览器断开（点停止、关页面）时，助手服务马上取消模型调用和正在查的工具，这句记成"用户中途停止"。

### 2.4 GET /assistant/conversations

`AssistantConversation[]`：`{ id, title, updatedAt }`，`title` 是第一句话（最多 100 字，列表里显示不下的省略）。

### 2.5 GET /assistant/conversations/{id}

`AssistantMessage[]`：`{ id, role: 'user' | 'assistant', content, error, createdAt }`，按时间排。`role: 'assistant'` 的 `content` 和 `done.text` 一样处理过，能当 Markdown；`role: 'user'` 的是用户原话，只能当纯文本。没答出来的回答 `content` 是空串、`error` 写原因。别人的、不存在的、id 不合规的一律 404。

### 2.6 DELETE /assistant/conversations/{id}

删掉自己的一个对话，问答和工具记录一起删，找不回来。成功 `data: null`。别人的、不存在的、删过的、id 不合规的 404；这个人正在答（不管哪个对话）409"正在答的时候不能删，停了再删"。

## 3. 前端要知道的规则

- 显示回答不用 `v-html`、不用 Markdown 库：`utils/assistantText.ts` 只认上面那几种写法，渲染成组件（`AssistantAnswer`）。链接再过一遍：地址只能是 `/小写页面` 或 `/小写页面/数字`，`router.resolve` 能落到业务菜单这一侧的真页面（不是 404 那条；登录页、管理后台、手机报工不算），才渲染成 `RouterLink`；不是的只显示文字。不渲染图片。
- 退出登录、换了人（别的页签登录了别人）时：停掉正在答的、清掉令牌和对话；那之前发出去的换令牌请求回来了也不要。
- 一次只答一句：在答的时候不能再发。⌘K 里"问助手"赶上在答，打开卡片、这句放进输入框（输入框里有字的不覆盖），答完自己发。
- 点"停止"连换令牌一起停；停了、断了，还在转圈的"查 …"改成"没查完 / 没查成"。打开历史对话、加载对话列表只认最后一次（先点的慢回来不覆盖）。

## 4. 按默认做的

- RFC 009 §6.1 说⌘K 里"页面和单号都搜不到时"才出"问助手"。这里改成输入两个字以上就一直排在最后：像"ML0001 还有多少库存"这种问题，物料能搜到，按原来的写法就没有问助手了。
- RFC 009 §6.2 的数字卡片、10 行小表格、上传图片做草稿，这一期不做（回答里模型自己写的 Markdown 表格照样显示）。
