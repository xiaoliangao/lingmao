# 05 生产

外发加工单、成品采购单（统称"生产单"）、进度节点和报进度、异常、回货、领料页签、生产看板、手机报工。需求看 PRD §6.7，机制看架构 §4.10（一张表两种单据）、§4.8（多级审批）、§5.2（`StockSourceHandler`）、§5.5（`NeedDateSource`）、§10.1（手机页），表看数据库设计 §14（`prd_*`）。

类型在 `web/src/types/production.ts`，接口函数在 `web/src/api/production.ts`。排单（生成生产单草稿）是 02 的：界面在需求订单详情，接口 `scheduleApi`、类型在 `types/order.ts`，本文不重复。领料、退料的单据是 04 的物料出库单、入库单，本文只定生产这边的条件和回写。

两种单的字段、状态、节点、报工、异常、回货都一样，一组接口 `/api/production-orders`，列表按 `kind` 分：`OUTSOURCE` 外发加工单（清加工、半包，单号 JG）、`BUY` 成品采购单（包工包料，单号 CP）。种类排单时按加工方式定，之后不能改。

### 1.4 页面长什么样

照原型 `docs/原型/src/5d-production.js`。

**列表 `/production`、`/fp-purchases`**：`PageHeader` 只有标题（外发加工单 / 成品采购单），没有"新建"：生产单只能由需求订单排单生成。`FilterBar`：分段控件按状态（全部 / 草稿 / 待审核 / 已下单 / 生产中 / 部分回货 / 已完成 / 已结案 / 已作废，数用 `productionApi.counts`）；筛选里放风险（单选，`PRODUCTION_RISK_LABEL`）、交期（`DateRange`）、加工厂（`SupplierSelect`，`category` 传成衣厂和加工厂）、生产跟单（`UserSelect`）、品牌（`DictSelect type="brand"`），"我的 / 全部"。关键字占位"单号、订单号、款号、加工厂"。

列：勾选、单号、款式（缩略图 + 款号）、加工厂 · 加工方式、数量、金额、交期（`expectDate ?? dueDate`，后面"还有 n 天 / 逾期 n 天"；有 `expectDate` 时下面一行小字划掉原交期）、节点（`nodes` 画成一格一格的进度条）、齐料、领料（`MATERIAL_ISSUE_STATUS`，`null` 写"—"）、回货（`returnedQty / totalQty` 进度，草稿、待审核、已作废写"—"）、跟单、状态（`StatusTag`；`risk.issue` 时后面一个琥珀色感叹号，`risk.upstream` 时一个"变更"小图标）。默认按风险排，后端排好。

勾选后批量条：提交、审核、导出选中。空表格："没有符合条件的外发加工单。需求订单审核后，在订单详情里点「排单」生成"（成品采购单把"外发加工单"换掉，再加"，排单时加工方式选包工包料"）。

地址带的参数（首页、看板跳过来用）：`?status=PENDING`、`?risk=LATE|NEAR|NODE_LATE|ISSUE|UPSTREAM`。

**详情 `/production/:id`、`/fp-purchases/:id`**：页头按 `actions`：编辑、提交、审核 / 驳回（不是这一级的审批人看到"现在等××审"）、领料、登记回货、报进度（主按钮）；"更多"里放上报异常、改节点计划、退料、撤回、反审核、结案、取消结案、打印、导出工艺单、删除、作废。打印、导出工艺单不在 `actions` 里，一直有（导出工艺单另看 `techpack:pack:list`）。

正文顶上：`pendingNotices > 0` 时黄条"上游订单已变更"（README §4.5）；每条没关闭的异常一条红条（`openIssues`："缺料：面料还差 30 米（预计交期 03-15）"，按钮"去处理"切到异常页签）。标题是加工厂简称 + 状态，下面一行：款号（点了去款式）、款名、种类 · 加工方式、件数、交期和剩余天数。

页签：进度（节点时间线）、明细（颜色 × 尺码矩阵，审核以后每格下面小字"回 120 · 次 2 · 未 0"）、领料（`issueStatus` 是 `null` 时页签照样在，里面一句"资料包里没有标「我方采购」的料，不用领料"）、异常（n）、回货（n）。

页签的地址参数 `?tab=progress | lines | materials | issues | receipts`（`docRoute` 指向回货单、异常时带上），不给是进度。详情页是 keep-alive 的，要 `watch(() => route.query.tab)`；纠正地址时（§1.2）把 `?tab=` 带过去。

进度时间线一个节点一行：节点名、计划起止、实际起止（没完成写"进行中"）、完成数量、最近谁哪天报的、备注、照片（前 4 张）、`reportCount > 1` 时"汇报记录 n 次"（点开调 `nodeReports`）；右边按 `state` 标"延期 / 晚了 n 天""临期"或绿勾。点一行打开"报进度"对话框、选中这个节点。没节点时（审核前）一句"审核下单后按交期往前倒排节点"。

侧栏：款式图、属性（需求订单、资料包版本、加工厂、加工方式、单价——名字按 `PRODUCTION_KIND[kind].priceLabel`，`archivePrice` 和 `unitPrice` 不一样时下面琥珀色小字"改价：原因"——、金额、税率、下单日期、交期 → 预计交期、生产跟单、结算方式；审核以后再加当前节点、齐料、领料、回货 / 次品；条款）、审批块、附件、操作记录（`PRODUCTION_LOG_ACTION`）。

**对话框**（都照原型同名组件）：

- 编辑（`ProdEdit`）：主体公司、加工厂、加工方式、单价、交期、改价原因（和档案现价不一样时才出来，必填）、生产跟单、结算方式、税率、含税、条款（下面"填常用条款"：字典 `prod_terms` 的项，点一项把它的文字接在后面）、备注。换了加工厂调 `scheduleApi.quote(orderId, styleId, factoryId)`，带出各加工方式的现价、结算方式、税率；单价旁边小字"档案现价 38.00"，没有就写"档案里没有这家的价，审核时记进去"。加工方式：外发加工单列 `process_mode` 字典里 `FULL` 以外的项，成品采购单固定包工包料、灰掉。
- 报进度（`ProdReport`）：上面一排节点（报过完成的带绿勾），下面计划起止和"上次 张三 11-20 报的"；实际开始（默认节点的实际开始，没有用今天）、实际完成（不预填）、数量、备注、照片（`ImageUpload`，能拍照，最多 9 张，"这个节点已经有 n 张，再传是追加"）。两个按钮："只报开始"（节点报过完成时灰掉）、"报完成"（主按钮）。成功 toast "裁剪已报完成"，有 `warning` 接在后面。
- 改节点计划（`ProdPlan`）：一个节点一行，计划开始、计划完成两个日期框，实际完成只读。
- 上报异常（`ProdException`）：类型（`DictSelect type="issue_type"`）、责任方（我方 / 工厂 / 供应商，TRADE 开时多一个客户，另有"待定"；默认我方）、描述、照片（必传，标题旁红字"问题部位、到货短缺或现场，对责任时要用"）、"影响交期"勾选、预计新交期（勾了才出，默认预计交期 + 5 天）。
- 关闭异常：处理措施（必填）、责任方（带上报时的）。
- 登记回货（`ProdReturn`）：回货日期（默认今天，不能选以后）、收货仓（`warehouseApi.options('PRODUCT')`，默认第一个）、物流单号；回货数矩阵（含次品，每格默认 `remainQty`，小字"加工 120 · 已回 0"）、次品矩阵、分色分码备注（折叠）、照片。按钮"登记"。成功 toast "HH… 已登记：400 件"，`status` 是 `DONE` 时接"，外发加工单完成"。
- 回货单（点回货页签的一行）：单头一行、明细（颜色、尺码、回货、次品、良品、备注，带合计）、照片；作废的显示红条（原因、谁、什么时候）。`actions` 有 `void` 时左下"作废这张回货单"，先弹框写原因。
- 领料、退料：用 04 的"由源单生成"对话框（`invDocApi.prefillFromProduction` / `fromProduction`，04 §3.3.2），成功后切到领料页签、重新取 `materials`。

**打印**：不加接口，照 03 §3.3.12 的做法用详情数据排一张打印页（`window.print()`），内容照原型 `PrintSheet`：抬头（`config.ts` 的系统名 + 种类）、加工厂（全称、联系人、电话）、加工方式、款号款名、需求订单、资料包版本、下单日期、交期、生产跟单、单价、数量、金额（结算方式）、颜色 × 尺码数量表（带合计）、条款、备注、签字栏（制单、审核、加工厂确认）。

**导出工艺单**：小对话框只有一个"附工艺标准"勾选（默认勾），确定后 `techPackApi.pdf(techPackId, { price: false, appendix }, '款号-款名-工艺单-V版本.pdf')`。颜色不选（全部），不含价格（发给工厂的）。打印页不再拼工艺单：PDF 是后端出的（架构 §11.1），拼不进浏览器的打印页，工厂要的也是两份能发微信的文件。

**看板 `/board`**：`PageHeader` 只有标题"看板"。`FilterBar` 的 `#left` 放种类分段控件（全部 / 外发加工 / 成品采购），筛选里放交期、加工厂、生产跟单、品牌，"我的 / 全部"，没有关键字。下面一排数字卡（`boardApi.cards`）：在制 n（m 件）、待开工、7 天内交货（天数取 `nearDays`）、已逾期（数不为 0 时红）、节点延期（琥珀）、有异常（红）、本月回货 m 件（不能点）。点卡片筛下面的列表，再点一次取消；地址 `?card=LATE` 进来时预先选上。

再下面分段控件"按单 / 按工厂"。按单：列表（`boardApi.page`）和外发加工单列表同一个表格组件，去掉勾选、金额、领料，加种类、异常（第一条的类型，多条写"等 n 个"）两列。按工厂（`boardApi.factories`）：加工厂、类型、在制单数、在制件数（后面一根横条，按最多的那家算比例）、逾期单（不为 0 时红）；点一行把加工厂筛进去、切回按单。

**手机报工 `/mobile`**：照原型的手机框里的内容，去掉"跟单员 / 工厂"切换（工厂账号等 Q02）。顶上"我的跟单"和自己的名字；下面一张单一张卡片（`productionApi.myFollow`）：款图 52px、款号、交期和剩余天数、加工厂 · 件数、节点进度条和当前节点、有异常时红色感叹号。空的时候"没有在做的单"。点卡片去 `/mobile/:id`。

## 2. 状态

### 2.1 生产单

| 状态 | 中文 | 颜色 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、删、提交、作废 |
| `PENDING` | 待审核 | `pending` | 审核、驳回、撤回、作废 |
| `APPROVED` | 已下单 | `active` | 报进度、改节点计划、上报异常、领料、退料、登记回货、反审核、结案 |
| `RUNNING` | 生产中 | `progress` | 同上，不能反审核 |
| `RUNNING` + 回过货 | 部分回货 | `progress` | 同上（不是单独的状态，`PRODUCTION_PARTIAL`） |
| `DONE` | 已完成 | `done` | 登记回货（尾数）、退料、处理异常、结案 |
| `CLOSED` | 已结案 | `closed` | 取消结案；处理异常 |
| `VOIDED` | 已作废 | `void` | 只读 |

转换：

- 草稿 →（提交）待审核 →（最后一级审核）已下单。待审核 →（驳回、撤回）草稿；已下单 →（反审核）草稿。
- 已下单 → 生产中：第一次报进度带了实际开始，或者第一次登记回货。
- 生产中 → 已完成：累计回货 ≥ 总件数 × 97%（短装比例 3%，Q09）。作废回货单后不够了，退回生产中（一件都没回、也没报过开始的退回已下单）。
- 已下单、生产中、已完成 →（结案）已结案；已结案 →（取消结案）回到结案前的状态（存在操作记录里，后端记一份）。
- 草稿、待审核 →（作废）已作废。

### 2.2 节点

`NODE_STATE`：已完成（绿）、延期（红）、临期（琥珀）、进行中（铜褐）、未开始（灰）。条件见 PRD §6.7.2，后端现算。

### 2.3 货期预警

`ProductionRisk`，只看已下单、生产中的单：已逾期（今天 > 预计交期 ?? 交期）、临期（还剩 ≤ 7 天）、节点延期（有节点今天 > 计划完成还没完成）、有异常（有没关闭的）、上游已变更（有没处理的提醒）。

排序的分数照原型：逾期 8、节点延期 4、有异常 2、临期 1，相加后从高到低，同分按交期从早到晚。列表、看板、手机报工都这样排。

### 2.4 异常

`ISSUE_STATUS`：待处理（琥珀）→（开始处理）处理中（铜褐）→（关闭）已关闭（灰）。待处理也能直接关闭。异常不是单据，没有审核、没有作废。

### 2.5 回货单

`RECEIPT_STATUS`：已登记（绿）、已作废（删除线）。"登记"一步 = 建 + 审核（数据库设计 §14.6）。作废已登记的回货单在一个事务里回退再作废，不让用户先反审核再作废。草稿状态这一期用不到。

- 不是草稿、`version` 对不上：1002。

- 单价没填或 ≤ 0、交期、生产跟单、结算方式没填：400。

### 3.3 进度节点和报进度

#### 3.3.1 节点怎么生成

最后一级审核时按字典 `prod_node` 的启用项、按排序生成，每项的数值列是默认天数（没填按 1 天）。从交货日期往前倒排：最后一个节点的计划完成 = 交期，计划开始 = 计划完成 −（天数 − 1）；前一个节点的计划完成 = 后一个的计划开始 − 1 天，依次往前。反审核删掉节点，再审核重新生成。

"裁剪"（`CUT`）的计划开始就是这张单的要料日期，03 通过 `NeedDateSource` 来取（§3.9）。

#### 3.3.2 改节点计划 `PUT /api/production-orders/{id}/nodes`

请求 `{ nodes: NodePlanItem[] }`，全部节点一起发。

- 生产单不是已下单、生产中：1000"审核下单以后、完成之前才能改节点计划"。
- 节点对不上（少发、多发、不是这张单的）：400。
- 计划开始、完成没填，或计划完成早于计划开始：400"车缝：计划完成不能早于计划开始"。
- 不带 `version`。理由：节点计划只有跟单员一个人改，报进度又随时在变，带版本号会让报工和改计划互相顶掉。操作记录写改了哪几个节点（"车缝 11-20–11-29 → 11-22–11-30"）。

#### 3.3.3 报进度 `POST /api/production-orders/{id}/nodes/{nodeId}/reports`

请求 `NodeReportForm`，返回 `NodeReportResult`。电脑上的"报进度"和手机报工都用它（PRD §6.7.3）。

- 生产单不是已下单、生产中：1000"外发加工单审核后才能报进度"。
- `START`：`actualStart` 必填（400）；`actualFinish` 不是 null（400"只报开始就不填实际完成；做完了点「报完成」"）；节点已经报过完成（1000"裁剪已经报过完成（11-20），不能改回进行中；完成日期报错了，重新点「报完成」填对的日期"）。
- `FINISH`：`actualFinish` 是 null 按今天；`actualStart` 是 null 用节点原来的，原来也没有就等于完成日期。
- 实际完成早于实际开始，或者实际日期晚于今天：400。
- 照片超过 9 张：400。
- 写节点的最新值（实际开始、实际完成、数量、备注、最近汇报人和时间），插一条 `prd_node_report`，照片挂在这条报工上。
- 生产单是已下单、这次有实际开始：变生产中。
- 报完成时前面还有节点没报完成：照样报上，`warning` 写"前面还有节点没报完成"（PRD §6.7.2：跳着报提示，不拦）。

#### 3.3.4 汇报记录 `GET /api/production-orders/{id}/nodes/{nodeId}/reports`

返回 `NodeReport[]`，新的在前。

### 3.4 领料、退料

#### 3.4.1 领料页签 `GET /api/production-orders/{id}/materials`

返回 `ProductionMaterials`。应领只算锁定的生产 BOM 里物料来源 = 我方采购的行（两种单都一样；成品采购单通常只有主唛、吊牌、包装袋，常常一行都没有，Q12）：每个明细 SKU × 对应颜色的物料 SKU，件数 × 这个尺码的用量 ×（1 + 损耗率），按物料 SKU 加起来。已领只算已审核的单。

#### 3.4.2 选生产单 `GET /api/production-orders/issue-options`

给 04 的出库单页"领料出库（选生产单）"、退料表单的"源生产单"用（04 §3.7）。参数 `PageParams & IssueOptionQuery`，返回 `PageResult<IssueOption>`。

- 领料（`returnable` 不传或 false）：已下单、生产中，还有没领齐的我方采购料的。
- 退料（`returnable = true`）：已下单、生产中、已完成，已领 > 0 的。
- 照数据范围。

#### 3.4.3 和 04 的约定（生产实现 `StockSourceHandler`）

- `prefill`：数和 §3.4.1 一样。领料出库 `suggestQty` = 还差，`maxQty` = null；退料入库带出已领 > 0 的行，`maxQty` = 已领。
- `onPosted`：领料出库要求生产单是已下单、生产中；退料入库要求已下单、生产中、已完成。不是就 1000"外发加工单 JG… 已结案，不能领料"。过账后重算领料状态 `issue_status`，把已领回写到算料单的行上（调 purchase 的回写方法，架构 §5.4）；这张订单排满了、它的生产单都领齐了，让 purchase 关闭订单的算料单（关闭原因 `ISSUED`，03）。
- `onUnposted`：生产单已结案、已作废的不让反审核（1000）；反审核后重算领料状态、回写算料单。
- 源单的 `DocRef`：`type = PRODUCTION_ORDER`，`kind` 是 `OUTSOURCE` / `BUY`，`typeLabel` 按种类叫，负责人是生产跟单。

### 3.5 异常

#### 3.5.1 异常列表 `GET /api/production-orders/{id}/issues`

返回 `ProductionIssue[]`，没关闭的在前，同样的按上报时间倒序。

#### 3.5.2 上报异常 `POST /api/production-orders/{id}/issues`

请求 `IssueForm`，返回 `IssueCreated`。单号 YC + 日期 + 4 位流水。

- 生产单不是已下单、生产中：1000"外发加工单审核后才能上报异常"。
- 类型、描述没填，没传照片：400（PRD §6.7.4 描述、照片都必填）。
- `impactDelivery = true` 时 `newExpectDate` 必填（400）。填了就改生产单的预计交期（`expect_date`），原交期不动；几条异常都填了，以最后上报的为准。
- 操作记录写在生产单上："上报异常：缺料，预计交期改为 03-15"。

#### 3.5.3 开始处理、关闭

- `POST …/issues/{issueId}/start`：待处理 → 处理中，处理人记当前用户；已经不是待处理 1002。
- `POST …/issues/{issueId}/close`：请求 `IssueCloseForm`。处理措施没填 400"关闭前要写处理措施"；已经关了 1002。记关闭人、关闭时间，责任方按这次发的改。
- 这两个不管生产单是什么状态都能做（单子完成了、结案了，异常照样要收尾）。关闭不改回预计交期。

### 3.6 回货

#### 3.6.1 回货单列表 `GET /api/production-orders/{id}/receipts`

返回 `ProductionReceipt[]`，含作废的，新的在前。

#### 3.6.2 登记回货 `POST /api/production-orders/{id}/receipts`

请求 `ReceiptForm`，返回 `ReceiptCreated`。单号 HH + 日期 + 4 位流水。一个事务里建单、审核、回写。

- 生产单是已下单、生产中、已完成才行，不是就 1000"外发加工单 JG… 已结案，不能登记回货"。已完成的还能登记：回够 97% 就算完成，尾数还会陆续回来（原型只让已下单、生产中登记，这里放宽）。
- 回货日期晚于今天、一个数都没填、某行次品大于回货：400。
- 每个 SKU 累计回货不能超过 ⌊件数 × 1.03⌋（Q09，PRD §6.7.5 规则 1）。超了 1004，`data` 是 `ReceiptOverRow[]`，表格列：SKU、加工、已回、这次、上限、说明。建单、审核时都按最新的数查。
- 回写生产单明细的已回货、次品（条件更新，防两个人同时登记超了）；状态按 §2.1 重算；回写订单行的已回货，订单的完成检查见 §3.9。
- 收货仓只记录，一期不记成品库存（Q01、Q44；二期由回货单生成成品入库单）。

#### 3.6.3 作废回货单 `POST /api/production-orders/{id}/receipts/{receiptId}/void`

请求 `{ reason }`，原因必填（400）。

- 已经作废了：1002。生产单已结案、已作废：1000"外发加工单已结案，回货不能作废"。
- 一个事务里：明细的已回货、次品减回去，生产单状态重算（§2.1），订单行的已回货减回去；订单要是已完成、这张单不再算完成，退回生产中。两边的操作记录都写一条（"回货 HH… 作废（数量登记错了），已完成 → 生产中"）。
- 以后有了验货、成品入库、对账，已经验过、入过成品仓、进了对账单的不能作废，到时候再加。

### 3.9 和别的模块的约定（后端）

- **02 需求订单**：排单生成草稿时就占上订单行的已排产；删草稿、作废退回（§3.2.5、§3.2.6）。审核、回货、作废回货、结案、取消结案后调订单的回写：第一张生产单审核 → 订单生产中；反审核后没有别的已下单、生产中的单 → 订单已审核；订单所有行已排产 ≥ 订单数、没作废的生产单都是已完成或已结案 → 订单已完成，反过来不满足了退回生产中（PRD §6.7.5 规则 3）。
- **03 算料采购**：production 实现 `NeedDateSource`：一张订单的要料日期 = 它已下单、生产中的生产单里"裁剪"节点最早的计划开始；还没审核（没节点）的返回 null，03 按承诺交期倒推。领料过账时回写算料行的已领、触发关闭算料单（§3.4.3）。
- **04 库存**：§3.4.2、§3.4.3。
- **价格档案**：审核时记、反审核时作废（§3.2.5）。种类和价格档案的加工方式一一对应：外发加工单记清加工、半包的加工价，成品采购单记包工包料的价。
- **单据公共**：变更单审核后给受影响的生产单插提醒，`owner_id` = 生产跟单（02 写入，README §4.5）。多级审批的 `biz_type = PRODUCTION_ORDER`，金额用总金额。回货单、异常的 `DocRef`：`type` 是 `PRODUCTION_RECEIPT`、`PRODUCTION_ISSUE`，`parentId` 是生产单 id。

## 4. 前端要知道的规则

- **种类**：列表按地址定 `kind`，标题、单价叫法、空表格的话都从 `PRODUCTION_KIND` 取。详情按数据里的 `kind`，地址对不上就 `router.replace`（§1.2）。
- **状态标签**：`status === 'RUNNING' && returnedQty > 0` 用 `PRODUCTION_PARTIAL`，别的用 `PRODUCTION_STATUS`。
- **交期**：显示 `expectDate ?? dueDate`；有 `expectDate` 时原交期划掉放在下面。剩余天数用后端的 `daysLeft`，颜色看 `risk`：`late` 红、`near` 琥珀，前端不自己比天数。
- **齐料**：列表、看板拿当前页的 `orderId` 调 `kittingApi.byOrders` 一次，按 `orderId` 对上，只给已下单、生产中、已完成的行显示（03 §3.5）；别的写"—"。详情侧栏也一样（一个 id）。
- **按钮**：全看 `actions`；领料、退料、报进度这些也是后端按"状态 + 权限 + 业务条件"算好的（比如成品采购单没有我方采购的料就没有 `issue`）。打印一直有；导出工艺单看 `techpack:pack:list`。
- **改草稿的单价**：前端拿 `scheduleApi.quote` 的 `prices` 找当前加工方式的现价，和输入的不一样（按 4 位小数比）就出改价原因框；用的是现价时把 `priceSourceId` 带上，手填的发 null。最后以后端校验为准。
- **报进度**：实际开始默认节点的实际开始，没有用今天；实际完成不预填（PRD §6.7.3：不会一提交就把节点报成完成）。"只报开始"时不发实际完成；节点 `actualFinish` 不空时"只报开始"灰掉，标题提示"这个节点已经报过完成"。
- **登记回货**：每格默认 `remainQty`；输入超过 `maxReceiveQty` 的格子标红、提示"最多还能回 n 件"，但不拦，提交以后端的 1004 为准。次品格大于回货格时标红，不让提交。
- **照片**：先 `fileApi.upload` 拿 `FileVO`（`ImageUpload` 组件已经包好），提交时整组发。异常至少一张；报进度、回货选填；都最多 9 张。
- **责任方**：选项用 `RESPONSIBLE_PARTY`（02 的），`CUSTOMER` 只在 TRADE 开时出现，判断方法和 02 的变更单一样；"待定"发 null。
- **上游变更**：黄条和"已处理"用 `productionApi.notices` / `handleNotice`（README §4.5）；处理完重新取详情，`risk.upstream` 跟着变。
- **看板**：地址 `?card=` 进来预先选卡片；`keep-alive` 下再从首页点进来，要 `watch(() => route.query)`。卡片和列表的筛选条件一起变，卡片数不受 `card` 影响。
- **手机**：页面宽度 360px 起不出横向滚动；按钮 44px 高；照片上传时显示进度，失败的那张能重传。微信里打开导出工艺单的处理见架构 §11.1（先提示"在浏览器里打开"）。

## 6. 定了的

1. **结案时没回的件数不退回订单的"待排单"**（11-15，按推荐）。理由：结案最常见的是工厂短交、我方接受了，订单也就按实际收尾，结案后订单照样能变"已完成"；真要补做，提变更单加数量再排单。退回的话，取消结案时还得把件数再占回来，订单那边可能已经又排出去了。和原型一样。
2. **结案、取消结案单独给 `production:order:close`**（11-15，跟着 03 §6 第 1 条定）：给生产跟单和管理层。工厂短交、尾数不要了是跟单员谈的。
