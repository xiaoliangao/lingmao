# 一期接口文档

## 1. 这份文档怎么用

本文是前后端契约，覆盖页面、接口和状态，不以文档存在代表功能已上线。11-15 的初稿曾供前端先行开发；本轮整改按 [RFC 010](../rfc/010-审查整改契约.md) 先统一契约，再实现后端、前端并验证。新增字段和规则须与对应 DTO、TypeScript 类型及验收结果一并交付；运行状态见 `docs/进度.md` 和验收记录。06 的首页聚合、上游提醒聚合仍属待实现范围，不能用 mock 代替后端验收。

- 每个模块一份文档（§2 的表），讲页面、接口、状态和前端要知道的规则。
- 类型和接口函数统一放在 `web/src/types/<模块>.ts`、`web/src/api/<模块>.ts`。新增契约字段同步到这些文件和后端 DTO；前端直接 import，不在页面里再定义一遍。
- 需求看 PRD（每个接口后面写了节号），样子看原型 `docs/原型/`（§2 的表写了在哪个文件），写法照 `CLAUDE.md` 的"前端"一节。已经做好的款式、供应商、物料页面是样板。
- 写前端时觉得接口不够用、不好用：在那个模块文档末尾的"改动记录"里写一行，连同 `types`、`api` 文件一起改，Claude review 时一起看。不要只改页面、让接口和文档对不上。

## 3. 通用约定

生产加固的新增公共契约见 [production-contract](../architecture/production-contract.md)；以下条款按本轮契约同步，运行证据另见阶段审查记录。

### 3.1 请求和返回

- 地址都以 `/api` 开头。`utils/request.ts` 自动带上登录的 token；接入 A2 刷新会话后，401 先尝试一次 Cookie 刷新及允许的原请求重放，刷新失败才跳登录页。登录成功仍全页重载；回跳只接受单字符串、单斜线开头且解析后同源的内部 path/query/hash，拒绝外站、`//`、反斜线及控制字符，不合法时用默认首页/手机页。
- 返回体 `R { code, msg, data }`，`code = 0` 才算成功。`http.get / post / put / delete` 直接拿到 `data`。
- 出错时请求函数抛 `ApiError`，消息已经弹过了，调用方只管自己的流程（关不关对话框、要不要刷新）。批量条逐条调时传 `{ silent: true }`，出错不弹，由批量条汇总。
- 请求体是严格 JSON：带了接口没有的字段回 400"请求包含不支持的字段"，类型不对回 400 并写出字段名。前端类型和后端 DTO 要一起改。

登录 `POST /api/auth/login` 仍返回 `R<string>` access token，同时设置 HttpOnly / SameSite=Strict 刷新和浏览器绑定 Cookie。`POST /api/auth/refresh` 与 `POST /api/auth/logout` 均发送空 JSON `{}` 及 `X-Requested-With: XMLHttpRequest`；登出在 access 过期时也撤销有效刷新会话。前端通过同会话跨标签锁与同页 SingleFlight 合并刷新，重放保留原主体、请求体、幂等键；重放后的 403/500 仍是业务失败，不能据此再次刷新或登出。改密、重置、停用或删除使既有会话失效。升级时旧无版本会话要求重新登录，精确 Cookie 和轮换窗口见 [生产加固公共契约](../architecture/production-contract.md#登录刷新与日志导出接线a2--a3)。

| code | 意思 | 前端怎么处理 |
|---|---|---|
| 400 | 参数不对（必填没填、格式不对） | 自动弹消息 |
| 403 | 没有权限；多级审批里不是这一级的审批人 | 自动弹消息 |
| 404 | 不存在，或者不在你的数据范围里（不区分） | 详情页显示"找不到" |
| 1000 | 一般业务错误，`msg` 就是给用户看的 | 自动弹消息 |
| 1001 | 库存不足，`data` 是缺料清单 | 自动弹表格 |
| 409 | 同一个幂等键的上一次请求还在处理，HTTP 头带 `Retry-After` | `request.ts` 等一下自动重发，见 §3.6 |
| 413 | 请求体或上传文件太大 | 自动弹消息 |
| 429 | 太频繁（登录、改密这类敏感操作限流），或已有文件正在导入、导出 | 自动弹消息，稍后再试 |
| 503 | 服务暂时不可用（升级、限流存储连不上） | 写操作按 §3.6 处理，读操作弹消息 |
| 1002 | 状态或版本冲突；也用于盘点水位失效、同一个幂等键换了内容 | 保留未保存内容，提示冲突并提供明确重载/放弃入口；盘点须重取重数，见各模块 |
| 1003 | 导入校验没通过，`data` 是错误清单 | `ImportDialog` 自己显示 |
| 1004 | 超出上限（超排、超收、超回货），`data` 是超了的行 | 自动弹表格 |
| 1005 | 有下游单据，不能反审核、取消、删除，`data` 是 `DocRef[]`；删除被引用的主数据时没有 `data` | 自动弹表格 |
| 500 | 系统出错，消息里带错误编号 | 自动弹消息 |

按错误码判断时用 `utils/errorCodes.ts` 里的名字，不写数字。1001、1004 的清单每种单据长得不一样，各模块文档里写了每列是什么。

### 3.2 列表

- **分页**：`page` 从 1 起，`size` 最多 500，返回 `{ list, total }`。列表页用 `composables/useTable.ts`。
- **关键字**：`keyword`，按各接口写的字段包含查（不分大小写）。
- **一次查几个**（PRD §5.4）：关键字里有分隔符（空白、半角全角逗号、顿号、分号；从 Excel 粘一列进来是换行）就再拆开，按列表上的单号、款号、编码这些列精确查（不分大小写），和整句包含查 OR 起来（名称里本来就有空格、逗号）。只有一个词时，单号、编码也按包含查。一次最多 200 个，多了回 400。哪些列算，看各接口文档的关键字说明。后端用 `common/page/Keywords.codes`；前端就一个搜索框（`FilterBar`、`DataPick`），从 Excel 粘一列进来换行换成空格，口径在 `utils/keywords.ts`
- **多选条件**：数组参数发成 `status=A&status=B`，`request.ts` 已经这样配了。
- **日期范围**：`xxxFrom`、`xxxTo`，`yyyy-MM-dd`，两头都含。组件用 `DateRange`。
- **选出来的 id**：查询类型里写成 `string | null`（`UserSelect`、`SupplierSelect` 清空后是 `null`）。值是 `null` 的参数 axios 不发，等于没筛。
- **我的 / 全部**：普通列表按 DataScope，`mine=true` 进一步只看自己负责的。"全部"只表示当前获准范围，不会把 SELF 变成 ALL；审核权限也不等于 `data:all`（PRD §3.2）。
- **待我审核**：订单、采购、生产的 Query 增加 `auditForMe?: boolean`（默认 false）。true 只取待审核且当前审批级匹配调用人的单据；当前审批人的对象级例外不受普通 SELF 归属限制，但仍须有对应模块 `:list`。这是独立的待审视角，不再叠加 `mine/ownerId` 的普通负责人筛选；其他筛选条件仍取交集，不能扩大成全部待审核。列表、计数和导出使用同一谓词；计数去掉状态条件及相应状态子条件。页面地址可用 `auditForMe=1`，API 参数按 boolean 发送。
- **导出**：`GET /api/<资源>/export`，筛选参数和列表一样，再加 `ids` 只导勾选的。列表加载与导出共用规范化查询；导出使用最近一次成功展示列表的条件快照，含状态页签映射，不能读取尚未查询成功的筛选框值。勾选 ID 与该快照、数据权限取交集，不绕过筛选；去掉分页参数，用 `download()`。查询中或失败时不得把新条件冒充已展示结果。

### 3.3 字段

- **主键、关联键**：BIGINT ID 以十进制字符串传输（包括数组、创建结果与审计人 ID）；前端原样用于路由、选择器和请求，不得先转 JS Number。`version`、页码、计数和数量不是 ID，继续用数字。

- **时间**：纯业务日期为 `2026-11-15`，不转时间戳；事件时间为 ISO-8601 `2026-11-15T10:30:00+08:00`，显式携带偏移。显示用 `formatDate`、`formatDateTime`。默认今天、日期快捷区间及纯日期加减统一以 `Asia/Shanghai` 业务日计算，不使用 UTC 的 `toISOString().slice(0, 10)` 或浏览器本地时区替代业务日。
- **数量、单价、金额**：JSON 里是普通数字，后端用 `BigDecimal`、数据库用精确数值列。单价最多四位小数、金额两位，按 `HALF_UP` 归一；显示分别用 `formatQty`、`formatPrice`、`formatMoney`，不能用金额格式把单价截成两位。前端计算只作即时预览，后端重算并在写库前校验字段及合计容量，超界返回可定位行的 400；订单具体上限与 Excel 错误口径见 02 §3.5。不能用 JS 浮点预览作为入账结果，也不能等数据库溢出返回 500。
- **字典**：存的是 value。显示用 `useDict(type).labelOf(value)`，下拉用 `DictSelect`。字典类型写在字段注释里。
- **文件**：上传 `POST /api/files` 得到 `FileVO`，地址带签名，原样用，不要自己拼 `/files/...`。挂在记录上的图片、附件是整组替换：`PUT …/images` 或 `…/attachments`，传 `FileVO` 数组（`attachmentBody`）。尚有上传中/失败待重试文件时保存须等待或禁用并提示，不能默默丢弃；关闭、换记录后迟到的上传响应不能写入新表单。
- **保存是整体覆盖**：单据草稿保存单头、全部明细与 `version`，已加载且可编辑的空字段按契约发 `null`。未加载、请求失败、未授权不等于用户清空，不能用默认空数组/零值覆盖原数据；资料包成本的 `cost=null` 特指保留原成本（01 §3.5）。KeepAlive 激活不重新 hydrate dirty 表单，只有干净页面可自动刷新；载入和保存成功后才重置 dirty 基线。
- **受控字段**：本轮 A2 收紧为后端物理剥离。`techpack:cost:query` 控制物料、BOM、采购和库存成本；`order:price:query` 单独控制订单销售报价；`production:price:query` 单独控制生产成交/参考价及 PROCESS 加工价档案。权限不互相隐含授予。供应商联系方式由 `supplier:supplier:contact` 控制，银行信息由 `supplier:supplier:bank` 控制。无权限字段不返回掩码/null，详情、列表、嵌套快照、系统摘要、导出保持一致。编辑请求不得把省略字段清零或越权改价，详见 `docs/architecture/production-contract.md`。
- **新建、保存的返回**：新建单据返回 `DocSaved { id, no, version }`（有的多几个字段），保存草稿返回新的 `version`。"存草稿并提交"拿它接着调 `submit`，不用再取一次详情。
- **主体**：单据上的 `companyId` 必填。新建时默认填我的默认主体：登录信息（`GET /api/auth/me`）里的 `defaultCompany`，页面用 `user.defaultCompanyId`。它是 `null`（没设默认主体、启用的主体又不止一个）时空着，让人选。

### 3.5 按钮和批量

- **按钮看 `actions`**：详情接口返回 `actions`，是后端按"状态允许 ∩ 有权限 ∩ 业务条件"算好的（架构 §4.2）。前端照着显示，不在页面里再写一遍状态规则。列表行上的操作也一样，看行上的 `actions`。
- **批量**：勾选后底部出 `BatchBar`，逐条调单条接口，不另写批量接口。批量按钮的 `can` 用行上的 `actions` 判断。
- 带批量条的单据列表，行上有 `version`，批量动作直接带它，不先取一次详情；列表取到以后别人改过，后端回 1002，批量条留着勾、报原因。批量条逐条调的接口函数，最后一个参数都收 `RequestOptions`（传 `{ silent: true }`）。
- **权限**：按钮用 `v-perm` 或 `user.hasPerm(…)` 控制显不显示；有没有权限最后由后端判断。权限码在各模块文档里。

### 3.6 新建和记数的幂等

断网、超时、网关 502/503/504 时，前端不知道服务器做没做。为了重发不建出第二张单，这些写操作要带幂等键：

- **哪些接口**：新建订单、变更单、物料、物料 SKU、款式、生成款式 SKU、供应商、供应商资质、盘点单、入出库单、排产、报工、生产问题、算料单、采购单（含从算料、补货生成）、资料包（新建、改版、转生产）、导出任务（建、取消、重推）。登记回货（05 §3.6.2）和由来源单生成入出库单（04 §3.3）另在请求体里带 `clientActionId`。清单在前端 `utils/writePolicy.ts`（`CREATED_RESOURCES`、`IDEMPOTENT_CHILDREN`），后端是 `@IdempotentCreate`，两边一起改。
- **怎么带**：HTTP 头 `Idempotency-Key: <UUID>`；没带键或不是 UUID 回 400；有 `clientActionId` 的接口两处填同一个值，不一致也回 400。一次用户动作一个键，重发时键和请求体都不变；成功后的下一次、换了内容的新动作才换新键。这些都由 `utils/request.ts` 做，页面不用管。
- **后端怎么判**：按用户、动作、键去重，摘要包括主体和全部有效字段。同键同内容：返回第一次成功的结果（结构不变）；同键换了内容：1002；第一次还在处理：HTTP 409 + `Retry-After`（秒）。幂等记录和业务写入同一个事务，失败不留记录；重放仍查当前身份、权限和数据范围。真正不同的两次动作即使内容一样也各有新键，不按内容全局去重。
- **核对** `GET /api/http-actions/{key}` → `{ done: boolean }`：只查当前用户自己的键，`done=true` 表示那次写入已经成功保存。键不是 UUID 回 400，没登录 401。`done=false` 只说明现在还没有，重发的请求可能还在路上，前端过一分半仍是 `false` 才算没保存（第三次重发最晚第 34 秒发出，服务器一次提交最长 30 秒）。

前端（`utils/request.ts`）的做法：

1. 结果不确定就用原键原内容自动重发，最多两次（等 1 秒、3 秒；有 `Retry-After` 照它）。多数时候用户只看到"成功"。
2. 还不确定时，提示"不确定有没有成功，系统会自动核对"，把键和内容摘要记在本机（不存请求内容，24 小时过期），右下角显示"正在核对 N 笔提交"，一分半以后自动调核对接口（打开系统时也会查一遍）。成功了通知"提交已经保存了"，到时间还没有就通知"有一笔提交没有保存"，让用户重新提交；核对接口不通就隔半分钟再试。
3. 结果出来之前，同一个地方再提交：内容一样就用原键重发；内容变了先核对上一次，已保存就弹"上一次已经保存"、不发新的，没保存就当新动作发。
4. 不能自动重发的写操作（审核、删除这类）结果不确定时，只提示"请刷新页面看一下结果再操作"。

### 3.7 品类线

甲方要按品类线（服装、鞋类、百货，字典 `product_line`）隔开数据，不同线的人互相看不见（RFC 013 §2，甲方 Q13、Q30）。

- **我能看哪几条**：`/api/auth/me` 的 `perms` 里，每条线一个 `line:APPAREL`……；超级管理员是 `line:all`（看全部）。页面用 `useProductLines()`：`multi` 能看不止一条，`only` 只有一条时是它，`labelOf` 显示名字。
- **带品类线的**：款式、订单、算料单、采购单、生产单是 `productLine`（一个）；供应商是 `productLines`（几个）。物料、仓库、库存、出入库单、盘点、主体不分线，大家共用。
- **看不见的**：列表、下拉、导出里没有；详情和动作回 404，和数据范围一样不区分"不存在"。品类线和数据范围（全部 / 本人）叠在一起。
- **页面**：只有一条线的人看不到"品类线"这几个字，新建时后端按他那条线带上。有几条的：款式、订单、算料、采购、生产单列表多一个"品类线"筛选（`productLine`）和一列；手工建采购单、补货生成采购单要选一条。
- **配对**：一张订单只放一条线的款，一次只算一条线的订单；采购单、生产单的供应商、加工厂要做这条线（`SupplierSelect :product-line`），不做的回 1000"××不做鞋类：换一家，或者先在供应商档案里给它加上「鞋类」"。

## 4. 单据公共

需求订单、变更单、算料单、采购单、物料入库单、出库单、盘点单、外发加工单、成品采购单、成品入库单、出库单都套这一套（架构 §4）。类型在 `types/biz.ts`，接口在 `api/biz.ts` 的 `docApi(base)`。

### 4.1 状态

通用状态是 `DocStatus`：草稿、待审核、已审核、执行中、已完成、已结案、已作废。各单据只用其中一部分，中文按单据叫，比如采购单的 RUNNING 叫"部分到货"、需求订单的 VOIDED 叫"已取消"。每个模块的 `types` 里有自己的 `XXX_STATUS`（中文 + 标签颜色）。

资料包、算料单、异常的状态和这套不一样，各用自己的类型。

### 4.2 状态动作

`POST /api/<单据>/{id}/<动作>`，请求体 `DocActionReq { version, reason? }`。前端用 `docApi(base).act(id, action, body)`。

| 动作 | 中文 | 点之前 |
|---|---|---|
| `submit` | 提交 | — |
| `withdraw` | 撤回（只有制单人） | — |
| `reject` | 驳回 | 弹框写原因，必填 |
| `audit` | 审核 | 有的单据要填东西（需求订单填承诺交期），见模块文档 |
| `unaudit` | 反审核 | 确认："回到草稿，改完要重新提交审核。" |
| `close` | 结案 | 确认后果 |
| `reopen` | 取消结案 | 确认 |
| `void` | 作废 | 确认，红色按钮 |

确认框的文字在 `DOC_ACTION_CONFIRM`。动作成功后重新取详情，刷新操作记录。

**自己建的单不能自己审**（甲方 11-21 答 Q10，PRD §3.1）：所有要审核的单据都一样，"自己"看制单人。制单人的 `actions` 里没有 `audit`、`reject`（要退回用 `withdraw`）；多级审批的单据每一级都这样（`approval.canPass` 是 false）；首页和列表的"待我审核"不列自己建的。点了也没用：后端审核时再拦，回 1000"自己建的单不能自己审，请其他有审核权限的人审"；单级单据驳回回 1000"自己建的单不能自己驳回，要退回请用撤回"，多级审批的驳回回 403，`approval.waitingFor` 末尾带"（制单人以外）"。反审核不拦。变更单、出入库单、盘点单列表的 `auditForMe=true` 只列待审的（出入库单是草稿，另两种是待审核）、不看 `mine`（传了也按"全部"），范围是调用人的数据范围；角色勾了"审核不受数据范围限制"（PRD §3.2）又有这种单审核权限的人不按本人筛。这种只靠这个勾看到的单，`actions` 只有 `audit`、`reject`、`unaudit`，别的动作和改附件回 404；`auditForMe=true` 时列表行的 `actions` 也只给这几个。所以建单时顺手过账（`post: true`）也过不去，前端只发 `post: false`。

`version` 是打开详情时拿到的。别人在这期间改过、审过，后端回 1002：保留本地草稿并给出明确重载/放弃入口，不能自动覆写表单或只换成新 version 强行保存；无本地改动的只读详情可以刷新。节点计划用独立 `planRevision`（05 §3.3.2），盘点测量还须核对服务端 `bookRevision`（04 §3.5）。删除草稿是 `DELETE /api/<单据>/{id}`（`docApi(base).remove`），已提交或过账单按各模块反审、作废规则处理。

### 4.3 详情的公共部分

每种单据的详情 `XxxDetail` 都 extends `DocHeader`：单号、状态、`version`、主体公司、备注、制单人、审核人、`actions`、`approval`、`pendingNotices`。

详情页的公共页签和块：

| 什么 | 接口 | 组件 |
|---|---|---|
| 操作记录页签 | `GET …/{id}/logs` | `DocLogList` |
| 附件 | `GET …/{id}/attachments`，整组替换 `PUT …/{id}/attachments` | 照款式的 `DesignFiles` |
| 下游单据页签 | `GET …/{id}/references` → `DocRef[]`，点单号用 `docRoute` | — |
| 上游变更提醒（顶上的黄条） | `pendingNotices > 0` 时显示；`GET …/{id}/notices`，处理一条 `POST …/{id}/notices/{noticeId}/handle` | — |
| 审批块 | 详情里的 `approval` | — |

### 4.4 多级审批

需求订单、采购单、外发加工单、成品采购单金额超过门槛会多审一级（PRD §5.1，架构 §4.8）。这几种单据的详情多一个 `approval: ApprovalView`。

- 待审核时显示审批块：每一级谁审、门槛、谁什么时候审的、现在等谁。审完了只有多于一级的留着。
- 只有当前这一级的审批人 `actions` 里才有 `audit`、`reject`。别人看到的是"现在等××审"（`approval.waitingFor`），不出按钮。
- 中间一级审过，单据还是待审核，提示"这一级审过了，等××审"。
- 哪一级驳回都回到草稿；重新提交从第 1 级审起。
- 当前审批人可以查看并处理轮到自己的对象，即使 SELF 且不是负责人；仍须有订单、采购或生产对应的模块 `:list`，不因此取得 ALL。配置规则和提交生成快照时校验审批人启用且有此访问权限，角色型规则也须有可用的有权限成员。旧审批快照不自动改写；若审批人后来失去访问权限，由管理员恢复权限，或按现有撤回重提流程处理。
- 各模块列表提供 `auditForMe` 入口，按 §3.2 返回真正轮到调用人审核的单据；首页聚合未实现不影响该入口。金额门槛依实际已配置规则，文档示例阈值不等于环境中已有规则。

### 4.5 下游单据和变更提醒

- `DocRef` 是"指向一张单据"：类型、单号、状态（中文和颜色都翻好了）、负责人。1005 的清单、"下游单据"页签、首页待办、变更提醒里都是它。
- 需求订单的变更单审核以后，给每张受影响的下游单据（外发加工单、采购单、算料单）各插一条提醒。下游详情顶上出黄条"上游订单已变更"，点开看说了什么，处理完点"已处理"（可以写一句怎么处理的）。首页"上游已变更"列的是还没处理的。

### 4.6 设置 › 审批

管理后台的一页，只给超级管理员（`biz:approval-rule:list`、`:edit`）。菜单在"系统管理"下，地址 `/system/approval-rule`，页面文件 `views/system/approval-rule/index.vue`，和用户、角色这些页面放在一起。

- 接口：`approvalRuleApi`，列表/新增是 `GET/POST /api/approval-rules`，修改/删除是 `PUT/DELETE /api/approval-rules/{id}`。
- 一条规则 = 单据类型 + 金额超过多少 + 审批人（角色和指定的人二选一）。
- 同一种单据有几条就加几级，门槛低的先审。改规则只影响以后提交的单，已经提交的不变。
- 保存规则及提交取快照时，按 §4.4 校验指定人或角色中的实际审批人可访问相应模块；不能配置一个没有入口的审批人，也不通过自动加 `data:all` 修补。
- 样子照原型 `/settings` 里的"审批"。

## 5. 菜单和权限

页面出不出现在侧边栏，由后端的菜单表 `sys_menu` 决定：菜单的 `component` 对应 `web/src/views/` 下的一个页面文件，没有这个文件的菜单显示"还没上线"。

各模块文档里列了它的菜单（放在哪个目录下、地址、页面文件、权限码）。前端开工前，Claude 先把这些菜单和按钮权限加进迁移，提交后在开发库里就能看到菜单。之后要改菜单，跟 Claude 说。

详情页、新建页这种不在侧边栏的页面，加在 `web/src/router/index.ts` 的 `DETAIL_ROUTES` 里，样板是物料、供应商、款式的详情页。它们依赖父菜单注册，直接粘贴详情地址不能绕过模块 list 权限；指定审批人的可达性按 §4.4、§4.6 校验。

## 6. 后端没好之前：mock

开发时尚未实现的接口可用假数据联调。当前业务模块不能被统一称为 mock；首页/订单审核辅助聚合等未完成部分须单独标识（06）。mock 只用于开发演示，不算真实接口、权限、库存或幂等验收：

```bash
cd web && pnpm dev:mock
```

- 只有写了 mock 的请求由假数据回答；别的照常发给后端。所以登录、菜单、基础资料、供应商、款式还是用真的，后端（IDEA 里的 8080，或者 `VITE_API_TARGET` 指的地址）要开着。
- 假数据里的单据指向款式 1（FS2611150101）、物料 1-4、供应商 1-4、仓库 1-3、主体 1，这些走真后端。开发库是空的时候点款号会是"这个款式不存在"：先往开发库灌示例主数据 `docker exec -i scm-dev-postgres psql -U scm -d scm -v ON_ERROR_STOP=1 < dev/seed-demo.sql`（跑几遍都一样，只给本机开发库用）。假数据改了 id，`dev/seed-demo.sql` 跟着改。
- 每个模块一个文件 `web/src/mock/<模块>.ts`，用法写在 `web/src/mock/index.ts` 开头。数据放在内存里，刷新就回到初始。
- 假数据照 `types` 里的类型造；状态动作要能点通（提交 → 待审核 → 审核 → 已审核……），好看每个状态下的页面。业务规则不用全写，挑页面上看得出来的写（比如超收报 1004、库存不够报 1001），清单的样子照文档。
- 导出、PDF、盘点表这些下载接口，mock 返回一个 `Blob` 就行，`download()` 照样存成文件。
- 正式打包不带 mock（`import.meta.env.DEV` 在打包时是 false）。后端写好一个模块，就删掉它的 mock 文件。

## 8. 模块文档怎么写

每份照这个顺序，不相关的节可以省：

1. **页面**：地址、原型在哪、页面文件、菜单（放在哪个目录下、排第几、权限码）、按钮权限码。
2. **状态**：每个状态的中文、标签颜色、能做什么。
3. **接口**：先一张总表（方法、路径、权限、一句话），再逐个写参数、返回（类型名）、会报什么错、规则（PRD 节号）。
4. **前端要知道的规则**：什么时候灰掉、输入时怎么校验、算什么、提示什么。
5. **按默认做的**：PRD §12 里还没答的问题，这里按哪个默认做法（Q 编号）。
6. **要用户定的**：推荐的做法写在前面。
7. **改动记录**。
