# 07 成品

成品入库单、成品出库单、成品库存和库存日志。本轮功能与硬化以 [功能补齐冻结契约](../architecture/functional-completion-contract.md) 为准，旧 RFC 中一回货一入库或立即自审的残留约定已废止。需求看 PRD §6.12，设计看 RFC 008（本文是它 §4、§5 的落地），机制照物料（[04-库存](04-库存.md)、架构 §5），表看数据库设计 §18。

类型在 `web/src/types/fg.ts`，接口函数在 `web/src/api/fg.ts`（`fgDocApi`、`fgStockApi`、`fgStockLogApi`）。

### 1.3 页面长什么样

照原型 `6-pages-later.js` 的 `fgPage`、`FgShip`、`FgOtherOut`。

**成品入库单 `/fg-in`**：页头"其他入库"（要 `fg:doc:add`）。两个页签：

- "待入库"（`?tab=pending`，有 `fg:doc:add` 时默认）：筛选加工厂、回货日期，关键字查回货单号、生产单号、款号。列：勾选、回货单（`fixed="left"`）、生产单（下面小字外发加工单 / 成品采购单）、款式（缩略图 + 款号）、加工厂、回货、次品、良品、已入、还没入、收货仓、回货日期、操作"入库"（`fixed="right"`）。
  - 点"入库"开对话框：入仓、日期、备注，一个颜色 × 尺码矩阵（`SkuMatrix`），格子默认还没入的良品数、能改少（上限就是它），每格下面小字"良品 n · 已入 n"。按钮"存草稿"，提交后由其他审核人审核。
  - 勾选后批量条"存入库草稿"：逐条调生成接口（`items: null`、`post: false`），没成的留着勾、列原因；不自动自审。
  - 空表格："回货都入库了"。
- "入库单"（`?tab=docs`）：分段（全部 / 回货入库 / 其他入库）；筛选状态、日期、仓库、加工厂，款号、回货单号用关键字查；"我的 / 全部"。列：勾选、单号、类型、入仓、来源（回货单号，或原因）、款式（第一款 + "等 n 款"）、件数、日期、状态；默认不显示：加工厂、生产单、制单人、审核人、备注。批量条：审核过账、导出选中。空表格："还没有成品入库单：回货在「待入库」点「入库」，期初、退回的货点「其他入库」"。

**成品出库单 `/fg-out`**：页头"其他出库"、"发货出库"（主按钮）。分段（全部 / 发货出库 / 其他出库）；筛选状态、日期、仓库，订单号、物流单号、款号用关键字查。列：勾选、单号、类型、出仓、需求订单或原因、发到、款式、件数、物流单号、日期、状态；默认不显示：金额（有看价权限才有）、制单人、审核人、备注。批量同上。空表格："还没有出库单：成品仓有货以后点「发货出库」，拿样品、报废点「其他出库」"。

- **发货出库**对话框：需求订单（能搜的下拉，`ship-orders`）、出仓、发到（默认订单的送货要求）、物流单号、日期、备注；每款一个矩阵，格子默认空，每格下面"订单 120 · 已发 0 · 库存 80"，上限 = 最多还能发和库存里小的那个（标红不拦）。
- **其他入库、其他出库**对话框：主体、仓、原因（`DictSelect`，`fg_in_reason` / `fg_out_reason`）、日期、备注，"选款式"（`DataPick kind="style"`）挑款，每款一个矩阵填件数；出库的格子下面"库存 n"。其他入库的草稿详情多一个"从 Excel 导入"（`ImportDialog`）。

**成品库存 `/fg-stock`**：页头"导出"。仓库下拉（成品仓）；视图分段：明细 / 按款 / 日志。

- 明细：仓库、款式（缩略图 + 款号 + 款名）、颜色、尺码、SKU 码、数量、最近变动；默认不列 0 的。点一行弹它的日志。
- 按款：款号、款名、合计；点开是只读的颜色 × 尺码矩阵。
- 日志：日期、类型、单号（点了开单据）、仓库、SKU、变动（入绿出红）、结存、操作人。筛选日期、类型、关键字（单号、款号、SKU 码）。

**详情**：页头按 `actions`（编辑、审核过账、反审核、删除或作废）。正文：属性（类型、仓、回货单 / 需求订单（链接）、生产单、加工厂、原因、发到、物流单号、日期、备注）+ 每款一个只读矩阵、下面合计；草稿出库单格子下面"库存 n"，不够的标红；发货出库有看价权限的多显示金额。侧栏：附件、操作记录。草稿点"编辑"开新建时的同一个对话框（回货入库开入库对话框）。

## 2. 状态

`FG_DOC_STATUS` 照物料入库单（04 §2.1）：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、审核过账；没过过账的删，过过账的作废 |
| `APPROVED` | 已审核 | `active` | 反审核（库存改回去，回到草稿） |
| `VOIDED` | 已作废 | `void` | 只读；回货入库的作废以后，数量退回回货单的"还没入" |

审核即过账，没有待审核。过过账又反审核回来的草稿删 → 1000"这张单过过账，只能作废"；`actions` 里 `remove` 和 `void` 只出一个。

| PUT | `/api/fg-docs/{id}` | `fg:doc:edit` | 改草稿（整体覆盖，带 `version`），返回新 `version` |

公共接口 `/logs`、`/attachments`（GET、PUT）、`/references` 照 README §4.3；`references` 是空数组（成品单据没有下游）。

数据范围：本人范围只看制单人是自己的成品单据。库存与日志按显式主体分账，不能用请求头代替业务权限；这里没有引入主干另一项产品线过滤。待入库/回货来源按生产单的制单人或跟单范围，发货来源按订单制单人、业务或跟单范围。FG 来源只读白名单允许对应 FG 操作权限，不授予上游完整列表、详情、成本或导出权限；当前审批人例外不扩大为全量范围。

除静态导入模板外，所有 FG 请求明确 `companyId` 并携带相同 `X-Company-Id`：新建、更新、from-receipt POST 在 body；其余接口在 query。请求和目标主体不符拒绝，批量混入不可见/不存在目标整批 404。ID 为十进制字符串，数量为 JSON 数字，日历日 `YYYY-MM-DD` 不转 UTC。列表默认 20、最多 500，勾选 `ids` 最多当前页 500；SKU/款式/回货批量来源最多 100。

幂等：创建、由回货生成、更新、删除、audit/unaudit/void 都携带 UUID `Idempotency-Key`；由回货生成的 body `clientActionId` 与 header 相同。创建 operation 分别 `FG_CREATE` / `FG_FROM_RECEIPT`，动作分别 `FG_AUDIT` / `FG_UNAUDIT` / `FG_VOID`。同键同内容重放原成功结果并重验当前对象权限；同键改内容或 version 为 1002，在途同键为 409。前端不能对新键写请求盲目自动重试。

### 3.2 成品单据

#### 3.2.1 列表 `GET /api/fg-docs`

参数 `PageParams & FgDocQuery`，返回 `PageResult<FgDocRow>`，新的在前。关键字查单号、回货单号、生产单号、订单号、物流单号、款号；一次查几个（README §3.2）时单号精确查。

#### 3.2.2 详情 `GET /api/fg-docs/{id}`

返回 `FgDocDetail`。`styles` 只包含本单已用的 SKU 及必要颜色/尺码（按单上款式顺序），不展开整款未使用色码，`items` 一个 SKU 一行。混合已知/未知单价时 `totalAmount=null`，不能把未知按 0 合计。草稿时：出库单每行带 `stockQty`（出仓现库存）；回货入库每行带 `maxQty`（这一行最多能入：剩余良品 + 本单已填的）；发货出库每行带 `maxQty`（最多还能发 + 本单已填的）。

#### 3.2.3 手工新建 `POST /api/fg-docs`

请求 `FgDocCreateForm`，返回 `FgDocCreated`。`docType` 只能是 `OTHER_IN`、`SHIP_OUT`、`OTHER_OUT`（回货入库走 §3.3）。检查：

- 日期不能晚于今天（400）；仓要是启用的成品仓（400 / 1000）。 所有查询日期区间（包括待入库回货日期）开始晚于结束均返回400，不能返回成功空列表。
- 其他入库、其他出库：原因必填、要在字典里（400）。
- 发货出库：订单要是已审核、生产中、已完成、已结案的（1000）；只能发订单上的 SKU（400）；每个 SKU 不能超过最多还能发（1004，见 §3.5.2）。单价、金额按订单行算，前端不传。`companyId` 要等于订单的主体（发货带出里的 `companyId`），不一样 400。
- 其他入库、其他出库：主体要启用；SKU 要存在（停用的也收）。
- 一张单一个 SKU 一行，重复的 400；数量是正整数（0 的行前端不发）；至少一行。

#### 3.2.4 改草稿 `PUT /api/fg-docs/{id}`

请求 `FgDocForm`（带 `version`），整单覆盖；返回新的 `version`。后端按 `(doc_id,style_sku_id)` 保留已有明细 ID，批量 UPDATE、新增和删除分开，金额独立重算；不允许客户端设置状态、审核人或金额。规则同新建；类型、主体、回货单、订单不能改。回货入库的草稿只能改日期、入仓、备注、各行数量（只能是这张回货单上的 SKU，超了 1004），在回货单锁内重算。

#### 3.2.5 删除、作废

- `DELETE /api/fg-docs/{id}?companyId=&version=`：没过过账的草稿；过过账的 1000"这张单过过账（库存日志里有它），不能删，只能作废"。
- `POST /api/fg-docs/{id}/void`：`DocActionReq`，原因必填；没过过账的 1000"这张单没过过账，直接删除就行"。作废的回货入库单不算"已入"，回货单回到待入库、也能作废。

#### 3.2.6 审核过账、反审核

`POST …/audit`、`…/unaudit`，query `companyId`、body `{version,reason?}`，并带幂等键。

- 审核：制单人自审 403；先按来源→成品单头的固定锁序锁定，DRAFT 状态下按最新来源重算明细/价格，再比较并交换 草稿 → 已审核；回货入库先锁回货单重算剩余（超了 1004）；发货出库按订单排队重算已发（超了 1004）；然后改库存、记日志。出库不够 1001（整张单一起列）。
- 反审核：已审核 → 草稿，按原始过账事件生成精确逆向事件（不改原流水，`reversalOfLogId` 指向原记录）；扣不回来（入的货已经发走了）1001。

#### 3.2.7 导出 `GET /api/fg-docs/export`

参数同列表（加 `ids`），父行与实际明细分别最多 50000，SQL 在每批使用剩余预算 +1，多出即拒绝。按实际引用 SKU 取元数据，一行一条明细：单号、类型、状态、日期、仓库、来源（回货单 / 订单 / 原因）、款号、款名、颜色、尺码、SKU 码、件数、单价、金额（有看价权限才有这两列）、物流单号、制单人、备注。

### 3.3 回货入库

#### 3.3.1 待入库 `GET /api/fg-docs/pending-receipts`

参数 `PageParams & FgPendingReceiptQuery`，返回 `PageResult<FgPendingReceiptRow>`，回货日期早的在前。列的是：已登记（没作废）、`sys_config` 的 `fg.receipt_from` 那天以后登记的、还有良品没入的回货单。"已入"算没作废的成品入库单（草稿也算）。

#### 3.3.2 带出 `GET /api/fg-docs/from-receipt/{receiptId}`

返回 `FgReceiptDraft`：主体/入仓等单头默认值、实际来源 SKU 元数据和全部来源行（含剩余 0）。每行 `reservedQty`=有效草稿占用、`postedQty`=已审核数量、`remainingQty=max(0,goodQty-reservedQty-postedQty)`；兼容字段 `stockedQty=reservedQty+postedQty`。新建 `maxQty=remainingQty`，默认数量取该值。

编辑传可选 `docId`，要求 `fg:doc:edit`、本单可见、同主体/同回货来源、RECEIPT_IN/DRAFT。`maxQty=max(0,goodQty-reservedQty-postedQty+本草稿本行数量)`，三项全局数量仍保持真实口径。前端初始化已录入行取当前草稿数量，原来源未录入行取 0，允许之后补入；不能直接用新建默认值覆盖编辑内容。其他单据/主体/状态的 `docId` 拒绝 404。

入仓默认回货单的启用成品仓，否则首个启用成品仓；无成品仓 1000。全部无可入数时返回安全业务错误，不泄漏隐藏成品单号。VOIDED 来源写预填/写入拒绝；历史关联只读另见 §3.7。

#### 3.3.3 生成 `POST /api/fg-docs/from-receipt/{receiptId}`

请求 `FgFromReceiptReq`，返回 `FgDocCreated`。`items: null` = 每行按还没入的全入（批量入库用）；给了就按给的（`qty` 0 的行不建，能少入，不能多入：1004）。全是 0 → 400"没有要入库的数"。`post:false` 保存草稿；`post:true` 先检查审核权限，仍因制单人自审规则返回 403，不产生单据。建单在回货单锁内重算剩余：两个人同时入同一张回货单，加起来不会超过良品数。

### 3.4 发货出库

#### 3.4.1 能发货的订单 `GET /api/fg-docs/ship-orders?keyword=&warehouseId=`

返回 `FgShipOrderOption[]`，最多 50 条，按单号倒序。已审核、生产中、已完成、已结案的需求订单；关键字查订单号、款号。给了 `warehouseId` 时带上这个仓里订单上 SKU 的库存件数（下拉里"仓里有 80 件"）。

#### 3.4.2 发货带出 `GET /api/fg-docs/ship-prefill?orderId=&warehouseId=&docId=`

返回 `FgShipPrefill`：订单信息（单号、送货要求）+ 实际来源 SKU 的矩阵数据 + 每个 SKU 一行（订单数、已发、最多还能发、出仓库存、单价）。`docId` 必须是同主体/同订单、可见的 SHIP_OUT 草稿；已发里不算它。

已发 = 本单以外已审核的发货出库；最多还能发 = ⌊订单数 × 1.03⌋ − 已发（不小于 0）。

### 3.6 库存、日志

- `GET /api/fg-stocks`：`PageParams & FgStockQuery` → `PageResult<FgStockRow>`，按仓库、SKU 码排；默认不列 0 的（`includeZero=true` 列）。
- `GET /api/fg-stocks/by-style`：同样的筛选参数（不接受明细 `ids`）→ `PageResult<FgStockByStyleRow>`，一款一行，带画矩阵的数据和各 SKU 的数（几个仓的加在一起）。按款查询和按款导出携带非空 `ids` 均返回400，不能静默忽略该筛选。
- `GET /api/fg-stocks/qty?warehouseId=&skuIds=` → `FgStockQty[]`，没有库存行的返回 0。表单的"库存 n"用。
- `GET /api/fg-stock-logs`：`cursor?&size=1..100` → `SeekPage<FgStockLogRow> {list,nextCursor,hasMore}`，按 `(create_time,id)` 降序，不作 COUNT。只允许 `page=1`，下一页传签名游标，游标绑定主体、当前用户权限和所有筛选。切主体/筛选须清游标；超过 100 行仍可继续翻页。流水返回 `companyId/locationId/reversalOfLogId/requestId`，FG 单号链接携带响应的 `companyId`。
- 库存按款先取得固定预算内的完整元数据，再按这些确切 SKU 和主体聚合，不能在第二条 SQL 重新按款式展开并发新建 SKU。跨仓合计为 long；当前库位仅允许 `locationId=0`，不宣称有实际库位管理。
- 导出参数同各自列表；明细加 `ids`。同步库存日志最多 10000 行；普通明细最多 50000 行。按款导出先验证颜色行数 ≤50000、列数（所有尺码并集 +4）≤16384、总格数（含表头）≤5000000，超限返回 1000 明确错误，不生成截断文件。
- 目前下载为有界 List + SXSSF/byte[] 的同步响应，不能据此宣称已完成全域响应流、客户端断连取消或无限大表导出。

### 3.7 给上游页面的

| 哪里 | 接口 | 什么时候调 |
|---|---|---|
| 生产单详情 › 回货页签：每张回货单后面"已入库 CR…"或"待入库" | `GET /api/fg-docs/by-receipts?receiptIds=` → `FgReceiptStocked[]`（每来源最多 20 张可见预览、独立真实计数与占用） | 有 `fg:doc:list` 时 |
| 需求订单详情：矩阵每格下面加"发 n" | `GET /api/fg-docs/shipped?orderId=` → `FgShippedRow[]`（已审核的发货出库） | 还需 `order:order:list`；看不见这张订单 404 |
| 需求订单"下游单据"页签 | 订单的 `/references` 自动列出发货出库单（fg 实现 `ReferrerProvider`） | — |
| 作废回货单、取消订单 | 有效引用拦截 1005；存在隐藏引用只给通用提示，不回传隐藏数量/ID/单号；全部可见最多100个预览，更多引导来源过滤分页 | — |
| 首页"其他提醒" | 06 的 `TODO_COUNT` 加 `FG_PENDING`（回货待入成品仓 n，去 `/fg-in?tab=pending`） | 有 `fg:doc:add` 且 todos 明确 companyId 才出，返回 count.companyId 快照用于跳转 |
| ⌘K | `CommandPalette` 按单号找 CR / CC（列表接口，`keyword`） | 有 `fg:doc:list` 时 |

`by-receipts` 最多 100 个来源，响应每行 `{receiptId,documents:[{id,no,status,qty}],documentsTotal,hasMoreDocuments,reservedQty,postedQty,remainingQty}`。所有来源先整体校验真实公司与生产单 DataScope；纯 `fg:doc:list` 可走此只读历史投影，不因此获得写来源权限。APPROVED/VOIDED 历史同批可读，VOIDED 可入基数为 0。数量 SUM 计算全部有效占用，documents/count 只计算当前 FG DataScope 可见单据，禁止把隐藏草稿变成假剩余。

预览每来源固定 20 张、按 `(create_time,id)` 降序，SQL 批量 LATERAL 限界；数量 SUM 和可见 COUNT 独立查询。`hasMoreDocuments=true` 时打开 `/fg-in?tab=docs&receiptId=&companyId=`，用 `GET /api/fg-docs` 的 receiptId 精确分页读全量可见关联。

### 3.8 Excel 明细导入

`POST /api/fg-docs/{id}/items/import?companyId=&version=`，multipart file，限 OTHER_IN 草稿/fg:doc:edit。沿用 XLSX 魔数、10MiB、全表行列预校验和公式注入拒绝，单次最多2000明细、合并后单据最多2000行。文件 SHA-256 与用户/操作/单据/公司/version 组成完成收据；同文件同选项重复提交重放，不能再次改版本或日志。

解析与校验文件在数据库事务外，写入再锁单/重验 version、状态、公司及实时权限；任何行错误全部回滚并返回精确行列，不能半截导入。已有 SKU 行保留 ID 并批量 UPDATE，新 SKU 批量插入。Hash 防重不是忽略不同 version 的所有后续文件。

审计接口保留既有 `system:audit:query` + `data:all` 门槛，并对成品追加对象守卫：单头/明细需 `fg:doc:list`，余额需 `fg:stock:list`，均必须传真实 `X-Company-Id`。已删对象仅凭当前命名空间最后一条可信 DELETE 审计证明定位；没有证据拒绝，不扫描任意历史去猜可见性。

## 4. 前端要知道的规则

- 两种单共用一组接口，按 `kind` 分；新建菜单项从 `FG_DOC_TYPE` 里取 `kind` 对得上、`manual = true` 的。
- 矩阵的格子 id 用款式 SKU id。保存时只发 > 0 的格子。
- 单价、金额只在发货出库上有，而且要看价权限（订单的销售价，`order:price:query`）；没权限的人接口不返回这两个字段。
- 创建/更新明细最多2000行，数量为1至99,999,999整数，回货生成允许0但不落库，至少一行正数。
- 详情只带实际 SKU；手工编辑要扩矩阵时另调 style-options（允许 add 或 edit），回货/发货编辑走绑定 docId 的有界来源预填。
- 无权限的 price/amount/totalAmount 在 JSON/Excel/DataLog 中物理剥离；有权限但未知价保留 null，混合未知价总额仍为 null。
- 改草稿要带 `version`；1002 时保留本地改动，给"重新加载 / 放弃"（README §4.2）。

## 5. 按默认做的

- Q44 成品入库单、出库单在本系统记，成品库存以本系统为准，不推聚水潭；Q01 不对接（RFC 008 §10）。
- 发货上限借 Q09 回货的 3%；成品不允许负库存（Q08）。
- 接口多了 `style-options`（RFC 008 §4 没列）：其他入库、其他出库挑完款要画矩阵，款式那边的选款接口不带 SKU，订单的 `style-options` 要订单权限，仓管没有。
- 单头接口只给一个 `warehouseId`（入库单是入仓、出库单是出仓）；表里照 RFC 留 `from_warehouse_id`、`to_warehouse_id` 两列，以后调拨用。
