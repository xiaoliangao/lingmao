# 07 成品

成品入库单、成品出库单、成品库存和库存日志（二期，M10 的一部分）。需求看 PRD §6.12，设计看 RFC 008（本文是它 §4、§5 的落地），机制照物料（[04-库存](04-库存.md)、架构 §5），表看数据库设计 §18。

类型在 `web/src/types/fg.ts`，接口函数在 `web/src/api/fg.ts`（`fgDocApi`、`fgStockApi`、`fgStockLogApi`）。

### 1.3 页面长什么样

照原型 `6-pages-later.js` 的 `fgPage`、`FgShip`、`FgOtherOut`。

**成品入库单 `/fg-in`**：页头"其他入库"（要 `fg:doc:add`）。两个页签：

- "待入库"（`?tab=pending`，有 `fg:doc:add` 时默认）：筛选加工厂、回货日期，关键字查回货单号、生产单号、款号。列：勾选、回货单（`fixed="left"`）、生产单（下面小字外发加工单 / 成品采购单）、款式（缩略图 + 款号）、加工厂、回货、次品、良品、已入、还没入、收货仓、回货日期、操作"入库"（`fixed="right"`）。
  - 点"入库"开对话框：入仓、日期、备注，一个颜色 × 尺码矩阵（`SkuMatrix`），格子默认还没入的良品数、能改少（上限就是它），每格下面小字"良品 n · 已入 n"。按钮只有"存草稿"（11-21 起自己建的单不能自己审，去掉了"入库并过账"）。
  - 勾选后批量条"入库"：逐条调生成接口（`items: null`、`post: false`）建草稿，没成的留着勾、列原因；草稿由别人在"入库单"页签审核过账。
  - 空表格："回货都入库了"。
- "入库单"（`?tab=docs`）：分段（全部 / 回货入库 / 其他入库）；筛选状态、日期、仓库、加工厂，款号、回货单号用关键字查；"我的 / 全部"。列：勾选、单号、类型、入仓、来源（回货单号，或原因）、款式（第一款 + "等 n 款"）、件数、日期、状态；默认不显示：加工厂、生产单、制单人、审核人、备注。批量条：审核过账、导出选中。空表格："还没有成品入库单：回货在「待入库」点「入库」，期初、退回的货点「其他入库」"。

**成品出库单 `/fg-out`**：页头"其他出库"、"发货出库"（主按钮）。分段（全部 / 发货出库 / 其他出库）；筛选状态、日期、仓库，订单号、物流单号、款号用关键字查。列：勾选、单号、类型、出仓、需求订单或原因、发到、款式、件数、物流单号、日期、状态；默认不显示：金额（有看价权限才有）、制单人、审核人、备注。批量同上。空表格："还没有出库单：成品仓有货以后点「发货出库」，拿样品、报废点「其他出库」"。

- **发货出库**对话框：需求订单（能搜的下拉，`ship-orders`）、出仓、发到（默认订单的送货要求）、物流单号、日期、备注；每款一个矩阵，格子默认空，每格下面"订单 120 · 已发 0 · 库存 80"，上限 = 最多还能发和库存里小的那个（标红不拦）。
- **其他入库、其他出库**对话框：主体、仓、原因（`DictSelect`，`fg_in_reason` / `fg_out_reason`）、日期、备注，"选款式"（`DataPick kind="style"`）挑款，每款一个矩阵填件数；出库的格子下面"库存 n"。其他入库的草稿详情多一个"从 Excel 导入"（`ImportDialog`）。

**成品库存 `/fg-stock`**：页头"导出"。仓库下拉（成品仓）；视图分段：明细 / 按款 / 日志。

- 明细：仓库、款式（缩略图 + 款号 + 款名）、颜色、尺码、SKU 码、数量、最近变动；默认不列 0 的。点一行弹它的日志。
- 按款：款号、款名、合计；点开是只读的颜色 × 尺码矩阵。
- 日志：日期、类型、单号（点了开单据）、仓库、SKU、变动（入绿出红）、结存、操作人。筛选日期、类型、关键字（单号、款号、SKU 码）。

**详情**：页头按 `actions`（编辑、审核过账、反审核、删除或作废）。正文：属性（类型、仓、回货单 / 需求订单（链接）、生产单、加工厂、原因、发到、物流单号、日期、备注）+ 每款一个只读矩阵、下面合计；草稿出库单格子下面"库存 n"，不够的标红；发货出库有看价权限的多显示金额。侧栏：附件、操作记录。草稿点"编辑"开新建时的同一个对话框（回货入库开入库对话框）。

## 2. 状态

`FG_DOC_STATUS` 照物料入库单（04 §2.1）：

| 状态 | 中文 | 标签 | 能做什么 |
|---|---|---|---|
| `DRAFT` | 草稿 | `off` | 改、审核过账；没过过账的删，过过账的作废 |
| `APPROVED` | 已审核 | `active` | 反审核（库存改回去，回到草稿） |
| `VOIDED` | 已作废 | `void` | 只读；回货入库的作废以后，数量退回回货单的"还没入" |

审核即过账，没有待审核。过过账又反审核回来的草稿删 → 1000"这张单过过账，只能作废"；`actions` 里 `remove` 和 `void` 只出一个。

### 3.2 成品单据

#### 3.2.1 列表 `GET /api/fg-docs`

参数 `PageParams & FgDocQuery`，返回 `PageResult<FgDocRow>`，新的在前。关键字查单号、回货单号、生产单号、订单号、物流单号、款号；一次查几个（README §3.2）时单号精确查。

#### 3.2.2 详情 `GET /api/fg-docs/{id}`

返回 `FgDocDetail`。`styles` 是单上各款画矩阵要的数据（按单上的顺序），`items` 一个 SKU 一行。草稿时：出库单每行带 `stockQty`（出仓现库存）；回货入库每行带 `maxQty`（这一行最多能入：剩余良品 + 本单已填的）；发货出库每行带 `maxQty`（最多还能发 + 本单已填的）。

#### 3.2.3 手工新建 `POST /api/fg-docs`

请求 `FgDocCreateForm`，返回 `FgDocCreated`。`docType` 只能是 `OTHER_IN`、`SHIP_OUT`、`OTHER_OUT`（回货入库走 §3.3）。检查：

- 日期不能晚于今天（400）；仓要是启用的成品仓（400 / 1000）。
- 其他入库、其他出库：原因必填、要在字典里（400）。
- 发货出库：订单要是已审核、生产中、已完成、已结案的（1000）；只能发订单上的 SKU（400）；每个 SKU 不能超过最多还能发（1004，见 §3.5.2）。单价、金额按订单行算，前端不传。`companyId` 要等于订单的主体（发货带出里的 `companyId`），不一样 400。
- 其他入库、其他出库：主体要启用；SKU 要存在（停用的也收）。
- 一张单一个 SKU 一行，重复的 400；数量是正整数（0 的行前端不发）；至少一行。

#### 3.2.4 改草稿 `PUT /api/fg-docs/{id}`

请求 `FgDocForm`（带 `version`），整单覆盖；返回新的 `version`。规则同新建；类型、主体、回货单、订单不能改。回货入库的草稿只能改日期、入仓、备注、各行数量（只能是这张回货单上的 SKU，超了 1004），在回货单锁内重算。

#### 3.2.5 删除、作废

- `DELETE /api/fg-docs/{id}`：没过过账的草稿；过过账的 1000"这张单过过账（库存日志里有它），不能删，只能作废"。
- `POST /api/fg-docs/{id}/void`：`DocActionReq`，原因必填；没过过账的 1000"这张单没过过账，直接删除就行"。作废的回货入库单不算"已入"，回货单回到待入库、也能作废。

#### 3.2.6 审核过账、反审核

`POST …/audit`、`…/unaudit`，`DocActionReq`。

- 审核：比较并交换 草稿 → 已审核；回货入库先锁回货单重算剩余（超了 1004）；发货出库按订单排队重算已发（超了 1004）；然后改库存、记日志。出库不够 1001（整张单一起列）。
- 反审核：已审核 → 草稿，库存反过来做一遍、日志再记一条反方向的；扣不回来（入的货已经发走了）1001。

#### 3.2.7 导出 `GET /api/fg-docs/export`

参数同列表（加 `ids`），一行一条明细：单号、类型、状态、日期、仓库、来源（回货单 / 订单 / 原因）、款号、款名、颜色、尺码、SKU 码、件数、单价、金额（有看价权限才有这两列）、物流单号、制单人、备注。

### 3.3 回货入库

#### 3.3.1 待入库 `GET /api/fg-docs/pending-receipts`

参数 `PageParams & FgPendingReceiptQuery`，返回 `PageResult<FgPendingReceiptRow>`，回货日期早的在前。列的是：已登记（没作废）、`sys_config` 的 `fg.receipt_from` 那天以后登记的、还有良品没入的回货单。"已入"算没作废的成品入库单（草稿也算）。

#### 3.3.2 带出 `GET /api/fg-docs/from-receipt/{receiptId}`

返回 `FgReceiptDraft`：单头默认值（主体、入仓、今天）+ 款式矩阵数据 + 每行（回货、次品、良品、已入、`maxQty` = 还没入）。还没入是 0 的行不带。入仓默认回货单的收货仓（是启用的成品仓时），否则第一个启用的成品仓；一个都没有 → 1000"还没有成品仓，先在 基础 › 仓库 建一个"。全部入完 → 1000"回货单 HH… 的良品都入过库了：CR…、CR…"。回货单作废了 → 1000。

#### 3.3.3 生成 `POST /api/fg-docs/from-receipt/{receiptId}`

请求 `FgFromReceiptReq`，返回 `FgDocCreated`。`items: null` = 每行按还没入的全入（批量入库用）；给了就按给的（`qty` 0 的行不建，能少入，不能多入：1004）。全是 0 → 400"没有要入库的数"。`post: true` 建完马上审核过账，要 `fg:doc:audit`（没有 403）；11-21 起自己建的单不能自己审，`post: true` 总是回 1000、单据不建，前端只发 `false`。建单在回货单锁内重算剩余：两个人同时入同一张回货单，加起来不会超过良品数。

### 3.4 发货出库

#### 3.4.1 能发货的订单 `GET /api/fg-docs/ship-orders?keyword=&warehouseId=`

返回 `FgShipOrderOption[]`，最多 50 条，按单号倒序。已审核、生产中、已完成、已结案的需求订单；关键字查订单号、款号。给了 `warehouseId` 时带上这个仓里订单上 SKU 的库存件数（下拉里"仓里有 80 件"）。

#### 3.4.2 发货带出 `GET /api/fg-docs/ship-prefill?orderId=&warehouseId=&docId=`

返回 `FgShipPrefill`：订单信息（单号、送货要求）+ 款式矩阵数据 + 每个 SKU 一行（订单数、已发、最多还能发、出仓库存、单价）。`docId` 是改草稿时这张单自己：已发里不算它。

已发 = 本单以外已审核的发货出库；最多还能发 = ⌊订单数 × 1.03⌋ − 已发（不小于 0）。

### 3.5 1001、1004 的清单

`BizErrorDialog` 按 `data` 画表，表头在 `BizErrorTable` 的 `LABELS`。

#### 3.5.1 1001 库存不够

出库单审核、入库单反审核时。`data` 是 `FgShortRow[]`：

| 字段 | 表头 | 例子 |
|---|---|---|
| `seqs` | 行 | `3` |
| `warehouseName` | 仓库 | 成品仓 |
| `skuCode` | SKU | `27CF001-KQ-M` |
| `styleName` | 款式 | 休闲长裤 |
| `colorName` | 颜色 | 卡其 |
| `sizeCode` | 尺码 | M |
| `stockQty` | 库存 | 100 |
| `needQty` | 要扣 | 110 |
| `shortQty` | 差 | 10 |

`msg`：`库存不够：27CF001-KQ-M 库存 100，差 10 件`，多个的加"等 n 个"。

#### 3.5.2 1004 超出上限

回货入库超过还没入的良品、发货超过最多还能发。`data` 是 `FgOverRow[]`：

| 字段 | 表头 | 例子 |
|---|---|---|
| `seq` | 行 | 2 |
| `skuCode` | SKU | `27CF001-KQ-M` |
| `sourceNo` | 源单 | `HH202603080001` / `DD202603010001` |
| `thisQty` | 本次 | 124 |
| `maxQty` | 最多 | 123 |
| `reason` | 说明 | 订单 120 件，溢装 3%，已发 0 / 良品 396，已入 300 |

`msg`：`27CF001-KQ-M 这次 124 件，最多还能发 123 件`（入库是"最多还能入"），多个的加"等 n 个"。

### 3.6 库存、日志

- `GET /api/fg-stocks`：`PageParams & FgStockQuery` → `PageResult<FgStockRow>`，按仓库、SKU 码排；默认不列 0 的（`includeZero=true` 列）。
- `GET /api/fg-stocks/by-style`：同样的参数 → `PageResult<FgStockByStyleRow>`，一款一行，带画矩阵的数据和各 SKU 的数（几个仓的加在一起）。
- `GET /api/fg-stocks/qty?warehouseId=&skuIds=` → `FgStockQty[]`，没有库存行的返回 0。表单的"库存 n"用。
- `GET /api/fg-stock-logs`：`PageParams & FgStockLogQuery` → `PageResult<FgStockLogRow>`，新的在前；页码翻页只给前 1 万行，再往后 400"流水较多，请缩小日期范围"。点单号：`docRoute({ type: 'FG_DOC', kind: row.docKind, id: row.docId, parentId: null })`。
- 导出参数同各自的列表；明细加 `ids`。

### 3.7 给上游页面的

| 哪里 | 接口 | 什么时候调 |
|---|---|---|
| 生产单详情 › 回货页签：每张回货单后面"已入库 CR…"或"待入库" | `GET /api/fg-docs/by-receipts?receiptIds=` → `FgReceiptStocked[]`（没作废的成品入库单，一张回货单可能几张） | 有 `fg:doc:list` 时 |
| 需求订单详情：矩阵每格下面加"发 n" | `GET /api/fg-docs/shipped?orderId=` → `FgShippedRow[]`（已审核的发货出库） | 有 `fg:doc:list` 时；看不见这张订单 404 |
| 需求订单"下游单据"页签 | 订单的 `/references` 自动列出发货出库单（fg 实现 `ReferrerProvider`） | — |
| 作废回货单、取消订单 | 被成品单据引用 → 1005，清单里是 CR / CC 单 | — |
| 首页"其他提醒" | 06 的 `TODO_COUNT` 加 `FG_PENDING`（回货待入成品仓 n，去 `/fg-in?tab=pending`） | 有 `fg:doc:add` 才出 |
| ⌘K | `CommandPalette` 按单号找 CR / CC（列表接口，`keyword`） | 有 `fg:doc:list` 时 |

## 4. 前端要知道的规则

- 两种单共用一组接口，按 `kind` 分；新建菜单项从 `FG_DOC_TYPE` 里取 `kind` 对得上、`manual = true` 的。
- 矩阵的格子 id 用款式 SKU id。保存时只发 > 0 的格子。
- 单价、金额只在发货出库上有，而且要看价权限（订单的销售价，`order:price:query`）；没权限的人接口不返回这两个字段。
- 改草稿要带 `version`；1002 时保留本地改动，给"重新加载 / 放弃"（README §4.2）。

## 5. 按默认做的

- Q44 成品入库单、出库单在本系统记，成品库存以本系统为准，不推聚水潭；Q01 不对接（RFC 008 §10）。
- 发货上限借 Q09 回货的 3%；成品不允许负库存（Q08）。
- 接口多了 `style-options`（RFC 008 §4 没列）：其他入库、其他出库挑完款要画矩阵，款式那边的选款接口不带 SKU，订单的 `style-options` 要订单权限，仓管没有。
- 单头接口只给一个 `warehouseId`（入库单是入仓、出库单是出仓）；表里照 RFC 留 `from_warehouse_id`、`to_warehouse_id` 两列，以后调拨用。
