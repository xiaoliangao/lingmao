# SCM 部署手册

这份手册给负责部署的 IT 同事。照着做，第一次安装半小时左右；之后每周升级一次，一条命令、几分钟。

## 开始之前

我们每次发版给你两个文件：

- `scm-<版本>.tar.gz`：安装包。第一次安装用文件名带 `-full` 的**完整包**（多带了数据库和 Redis 的镜像，几百 MB）；之后每周的**升级包**只带应用，小一些。
- `scm-<版本>.tar.gz.sha256`：校验值，用来确认包传完整了。

版本号就是发版日期，比如 `2026.11.14`；同一天发第二次是 `2026.11.14-2`。

几个约定：

- 命令里 `<尖括号>` 的部分换成你自己的值，比如 `<服务器 IP>`。
- 默认装在 `/opt/scm`。装在别的目录的话，下面所有命令里的 `/opt/scm` 都换成你的目录。
- 命令都要 root 权限，下面统一写了 `sudo`。
- 我们默认不登录你们的服务器。遇到问题开屏幕共享，你来操作，我们看着。**共享屏幕时不要打开 `.env`，也不要让密码出现在屏幕上**：对方能看到，录屏里也会留下。

## 1. 准备服务器

### 1.1 配置和系统

- 2 核 4G 内存、40G 硬盘起步。系统和镜像占 5G 左右，其余留给数据库、上传的图片和备份。
- 系统：Ubuntu 22.04 / 24.04 或 Debian 12。其他能装 Docker 24 以上的 Linux 也可以，下面以 Ubuntu 为例。
- CPU：查一下 `uname -m`。`x86_64` 是大多数云服务器；`aarch64` 是 ARM 服务器（比如鲲鹏、倚天），要先告诉我们，安装包要按 ARM 打。
- 服务器不需要访问 Docker Hub：安装包自带全部镜像。

### 1.2 装 Docker

Docker 官方的软件源在国内大多很慢或者连不上，用清华或者云厂商的镜像源。Ubuntu 上依次执行：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

- Debian：把上面两处 `linux/ubuntu` 换成 `linux/debian`。
- 服务器在阿里云、腾讯云、华为云上的，可以把 `https://mirrors.tuna.tsinghua.edu.cn` 换成各自的镜像站（`https://mirrors.aliyun.com`、`https://mirrors.cloud.tencent.com`、`https://repo.huaweicloud.com`），走内网更快。
- Rocky、AlmaLinux 这类系统：

  ```bash
  sudo dnf -y install dnf-plugins-core
  sudo dnf config-manager --add-repo https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/centos/docker-ce.repo
  sudo sed -i 's#https://download.docker.com#https://mirrors.tuna.tsinghua.edu.cn/docker-ce#' /etc/yum.repos.d/docker-ce.repo
  sudo dnf -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
  sudo systemctl enable --now docker
  ```

装好以后检查版本：

```bash
sudo docker version --format '{{.Server.Version}}'    # 要 24 以上
sudo docker compose version                          # 要 v2.20 以上
```

### 1.3 安全组和防火墙

云服务器的**安全组**（入方向）只放行：

- Web 端口：默认 80；用 HTTPS（第 4 节）时再加 443。试用期最好只放行公司的出口 IP。
- SSH 的 22 端口：最好也只放行公司的 IP。

数据库、Redis 不对外开端口，不用放行。

**注意：Docker 发布的端口会绕过服务器上的 ufw、firewalld。** Docker 自己改 iptables，它的规则排在 ufw、firewalld 前面，在服务器上用 ufw 拦 80 端口是拦不住的。控制谁能访问，要用云安全组。没有安全组的机房，规则要加在 iptables 的 `DOCKER-USER` 链里（Docker 官方文档 "Packet filtering and firewalls" 一节）。

### 1.4 服务器时间

```bash
timedatectl
```

要看到 `System clock synchronized: yes`。不是的话执行 `sudo timedatectl set-ntp true`。页面上的时间统一按北京时间显示，和服务器设的时区无关，但服务器的时钟要准。

## 2. 安装

### 2.1 传包、校验

把完整包和校验文件传到服务器上（下面以放在当前用户的主目录为例），然后：

```bash
cd ~
sha256sum -c scm-2026.11.14-full.tar.gz.sha256
```

显示 `OK` 才往下。不是 `OK`，说明包没传完整，重新传一次。

### 2.2 执行安装

```bash
tar -xzf scm-2026.11.14-full.tar.gz
cd scm-2026.11.14
sudo ./scripts/install.sh
```

想装到数据盘上，在后面写目录，比如 `sudo ./scripts/install.sh /data/scm`。

安装脚本会：

1. 检查 Docker 版本、CPU 架构；内存不到 4G、硬盘空闲不到 20G 时提醒；检查端口有没有被占。
2. 把包里的文件复制到 `/opt/scm`，生成配置文件 `/opt/scm/.env`：数据库、Redis 的密码，登录用的密钥，管理员的初始密码，都是随机生成的。
3. 载入镜像、启动，等系统起来（第一次启动要建表，一两分钟）。
4. 打印访问地址、管理员账号，以及初始密码在哪里看。**脚本不在屏幕上打印密码。**

安装脚本可以重复执行：已经有的配置、数据都不会被覆盖。

### 2.3 看一下状态

```bash
cd /opt/scm
sudo docker compose ps
```

应该有 5 个服务：web、app、postgres、redis 后面是 `(healthy)`，backup 是 `Up`。

装好以后，解压出来的 `~/scm-2026.11.14` 目录可以删掉，安装目录里已经有一份了。

## 3. 第一次登录，改掉管理员密码

1. 浏览器打开 `http://<服务器 IP>/`（端口不是 80 的话要带上端口，比如 `http://<服务器 IP>:8080/`）。
2. 看初始密码。**远程协助的话先停止屏幕共享**，再执行：

   ```bash
   sudo grep INIT_ADMIN_PASSWORD /opt/scm/.env
   ```

3. 用 `admin` 和这个密码登录，马上在右上角的用户菜单里改密码（至少 8 位）。改掉以后，`.env` 里的初始密码就不起作用了。

版本号在登录页底部，登录以后在右上角的用户菜单里，报问题时告诉我们是哪个版本。超级管理员的首页右上角显示最近一次备份的时间；超过 36 小时没有新备份，或者一份备份都还没有，首页顶部会出现红色提示，见第 9 节"备份失败"。

## 4. 域名和 HTTPS

不用 HTTPS 的话，登录密码和业务数据在网络上是明文传的。试用期可以先用 IP 加端口，**正式上线前必须换成域名 + HTTPS**。

### 4.1 选哪种接法

| 情况 | 怎么做 | 见 |
|---|---|---|
| 前面已经有入口（云负载均衡、公司网关）负责 HTTPS | `.env` 里保持 `SCM_WEB_MODE=http`，入口转发到这台服务器 | 4.2 |
| 没有入口，证书直接放在这台服务器上 | `.env` 里改成 `SCM_WEB_MODE=https`，证书放进 `certs/` | 4.3 |
| 只在内网用，或者试用期 | `http` 模式，安全组只放行公司的 IP | 4.4 |

### 4.2 前面有入口（负载均衡、网关）

1. 在入口上配好域名和证书，后端转发到这台服务器的 HTTP 端口（`.env` 里的 `SCM_HTTP_PORT`，默认 80）。
2. 入口要把用户的 IP 放在 `X-Forwarded-For` 头里（云负载均衡的 HTTP、HTTPS 监听一般默认就这样）。
3. 把入口的 IP 或网段写进 `/opt/scm/nginx/trusted-proxies.conf`（文件里有例子），然后让 Nginx 重新读：

   ```bash
   cd /opt/scm
   sudo docker compose exec web nginx -t
   sudo docker compose exec web nginx -s reload
   ```

   不写的话，操作日志里记的都是入口的 IP，而不是用户的。
4. 入口的请求大小上限要不小于 11MB，否则上传 10MB 的文件会被入口拦住。
5. 安全组里，这台服务器的 Web 端口只放行入口的地址，别人就绕不过入口。

### 4.3 证书放在这台服务器上

1. 域名解析（A 记录）指向这台服务器的公网 IP。
2. 准备证书。云厂商有免费证书（下载 Nginx 格式），但有效期只有几个月，到期前要换，很容易忘；建议用下面的 acme.sh 自动续期。拿到证书文件以后：

   ```bash
   sudo cp <证书文件>.pem /opt/scm/certs/fullchain.pem    # 证书链：服务器证书在前，中间证书在后
   sudo cp <私钥文件>.key /opt/scm/certs/privkey.pem
   sudo chmod 600 /opt/scm/certs/privkey.pem
   ```

3. 改成 HTTPS 模式，重建 web：

   ```bash
   cd /opt/scm
   sudo sed -i 's/^SCM_WEB_MODE=.*/SCM_WEB_MODE=https/' .env
   sudo docker compose up -d
   ```

4. 安全组放行 443（80 也留着：访问 HTTP 会自动跳到 HTTPS）。
5. 浏览器打开 `https://<域名>/` 试一下。

HTTPS 端口不用 443 的话，改 `.env` 里的 `SCM_HTTPS_PORT`，再 `sudo docker compose up -d`。

**用 acme.sh 自动申请、续期证书**（DNS 验证，不占 80 端口）。下面以阿里云解析为例，域名在腾讯云 DNSPod 的，把 `dns_ali` 换成 `dns_dp`，两个变量换成 `DP_Id`、`DP_Key`。以 root 执行：

```bash
sudo -i
git clone https://gitee.com/neilpang/acme.sh.git /root/acme.sh-src     # GitHub 连不上时用 Gitee 的镜像
cd /root/acme.sh-src && ./acme.sh --install -m <你的邮箱>
export Ali_Key="<只有解析权限的子账号 AccessKey ID>"
export Ali_Secret="<对应的 AccessKey Secret>"
~/.acme.sh/acme.sh --issue --server letsencrypt --dns dns_ali -d scm.example.com
~/.acme.sh/acme.sh --install-cert -d scm.example.com \
  --fullchain-file /opt/scm/certs/fullchain.pem \
  --key-file /opt/scm/certs/privkey.pem \
  --reloadcmd "cd /opt/scm && docker compose exec -T web nginx -s reload"
exit
```

`scm.example.com` 换成你们的域名。证书装好以后，接着做上面的第 3 到第 5 步。之后 acme.sh 每天检查一次，快到期时自动续期、换证书、让 Nginx 重新读，不用再管。AccessKey 用只有解析权限的子账号，不要用主账号的。

### 4.4 只在内网用，或者试用期

保持 `http` 模式，在安全组里把 Web 端口只放行公司的出口 IP（在公司的电脑上用浏览器搜索"IP"，显示的就是出口 IP）。

想换端口（比如 80 被别的程序占了），改 `.env` 里的 `SCM_HTTP_PORT`，再执行 `cd /opt/scm && sudo docker compose up -d`。

### 4.5 ICP 备案

服务器在中国大陆的，用域名访问之前，域名必须先做 ICP 备案，否则云厂商会拦截访问。备案在服务器所在的云厂商办，通常要一到三周。

- 最快的办法：公司已经有备案过的域名，用它的子域名（比如 `scm.<公司域名>`），加一条解析就行，不用再备案。原来的备案不在这家云厂商的，要在这家办一次"接入备案"，比新备案快。
- 备案期间先用 IP 加端口（4.4）。

## 5. 异地备份（必做）

系统每天自动备份数据库，存在 `/opt/scm/backups/`。但备份和数据库在**同一块硬盘**上：硬盘坏了、服务器被误删、被勒索病毒加密，备份和数据一起没。所以每天要把下面两个目录同步到另一个地方：

- `/opt/scm/backups/`：数据库备份
- `/opt/scm/data/uploads/`：上传的图片和附件（只增不删，数据库里记着它们的地址）

两种做法选一种。

### 5.1 另一台机器每天用 rsync 拉

在**备份机**（另一台 Linux 机器，最好在另一个机房或者另一家云）上：

```bash
sudo ssh-keygen -t ed25519 -N '' -f /root/.ssh/scm_offsite
sudo cat /root/.ssh/scm_offsite.pub        # 复制输出的这一行
```

在 **SCM 服务器**上，把它加进 root 的授权密钥，并限制只能从备份机连：

```bash
sudo mkdir -p /root/.ssh && sudo chmod 700 /root/.ssh
echo 'from="<备份机的 IP>",restrict <上一步复制的那一行>' | sudo tee -a /root/.ssh/authorized_keys
sudo chmod 600 /root/.ssh/authorized_keys
```

`restrict` 让这把密钥只能用来传文件，不能开终端、不能转发端口。SCM 服务器不允许 root 用密钥登录的话（`/etc/ssh/sshd_config` 里是 `PermitRootLogin no`），改成 `PermitRootLogin prohibit-password`（只允许密钥、不允许密码），再 `sudo systemctl reload ssh`。

回到**备份机**，先手动拉一次（第一次连会问是否信任，输入 `yes`）：

```bash
sudo mkdir -p /data/scm-offsite
sudo rsync -a -e 'ssh -i /root/.ssh/scm_offsite' root@<SCM 服务器 IP>:/opt/scm/backups/ /data/scm-offsite/backups/
sudo rsync -a -e 'ssh -i /root/.ssh/scm_offsite' root@<SCM 服务器 IP>:/opt/scm/data/uploads/ /data/scm-offsite/uploads/
```

没问题就加成每天的定时任务（`sudo crontab -e`，加一行）。数据库每天 2:30 备份，这里 4:00 拉；备份机上的备份留 30 天：

```
0 4 * * * rsync -a -e 'ssh -i /root/.ssh/scm_offsite' root@<SCM 服务器 IP>:/opt/scm/backups/ /data/scm-offsite/backups/ && rsync -a -e 'ssh -i /root/.ssh/scm_offsite' root@<SCM 服务器 IP>:/opt/scm/data/uploads/ /data/scm-offsite/uploads/ && find /data/scm-offsite/backups -name 'scm-*.dump' -mtime +30 -delete
```

不加 `--delete`：SCM 服务器上删掉的旧备份，备份机上还留着，由最后那条 `find` 按 30 天清理。

### 5.2 同步到云厂商的对象存储

没有第二台机器的话，用对象存储（阿里云 OSS、腾讯云 COS）：

1. 建一个**私有**的存储桶，打开"版本控制"（误删、被覆盖的文件还能找回来），再设一条生命周期规则，让旧版本 30 天后删除。
2. 建一个子账号，只给这个存储桶的写权限，用它的 AccessKey。
3. 在 SCM 服务器上装命令行工具（阿里云 `ossutil`、腾讯云 `coscli`，安装和配置 AccessKey 的步骤看各自的文档），然后先手动同步一次，比如阿里云：

   ```bash
   sudo ossutil sync /opt/scm/backups/ oss://<存储桶>/scm/backups/
   sudo ossutil sync /opt/scm/data/uploads/ oss://<存储桶>/scm/uploads/
   ```

   腾讯云是 `sudo coscli sync /opt/scm/backups/ cos://<存储桶>/scm/backups/ -r`，上传目录同理。
4. 没问题就加成每天 4:00 的定时任务（`sudo crontab -e`），命令同上；cron 里的命令要写完整路径（`which ossutil` 能看到）。

不管哪种做法，每个月看一次异地的最新备份是不是当天的；第 8 节的恢复演练也拿异地的备份做一次。备份里是全部业务数据，异地那边同样要控制谁能看。

## 6. 每周升级

收到新版本的升级包以后：

```bash
cd ~
sha256sum -c scm-2026.11.21.tar.gz.sha256
tar -xzf scm-2026.11.21.tar.gz
cd scm-2026.11.21
sudo ./scripts/upgrade.sh
```

升级脚本会：

1. 检查新版本比现在的新。
2. 载入新镜像。
3. 备份数据库到 `backups/pre-upgrade/`（文件名带升级前的版本号，留最近 5 个）。**备份失败就停下来，什么都不改。**
4. 更新安装目录里的文件，重启应用。`.env`、证书、数据、`trusted-proxies.conf` 都不会被覆盖。
5. 等新版本起来，清理旧镜像（留最近 3 个版本，回滚用）。

停机大约一分钟。这期间打开的页面会提示"系统正在升级或重启，请稍等一分钟再试"，升级好以后让大家刷新一下页面。放在晚上或者没人用系统的时候做。

中间漏了几个版本也没关系，直接升到最新的就行。升级完，解压出来的目录可以删掉。

新版本没起来时，脚本会打印最近 100 行日志和回滚的办法：把日志发给我们，需要的话先照第 7 节回到旧版本。

## 7. 回滚和恢复

### 7.1 退回上一个版本

新版本有严重问题、等不及修复时：

```bash
cd /opt/scm
sudo docker image ls scm-app                 # 看本机还有哪些版本（留着最近 3 个）
sudo sed -i 's/^SCM_VERSION=.*/SCM_VERSION=<上一个版本>/' .env
sudo docker compose up -d
```

数据不受影响：每个新版本对数据库只加表、加字段，旧版本照样能用。问题修好以后，照第 6 节升级到修复后的版本。

### 7.2 用备份恢复数据库

数据被误删、改乱了，或者新版本把数据弄坏了（先照 7.1 退回旧版本，再恢复升级前的备份）：

```bash
sudo ls -lh /opt/scm/backups/daily/ /opt/scm/backups/pre-upgrade/
sudo /opt/scm/scripts/restore.sh /opt/scm/backups/pre-upgrade/<备份文件>
```

- 要输入"恢复"两个字确认。脚本会先停应用，把现在的库再备份一份到 `backups/pre-restore/`（以防选错了文件），然后恢复、启动。
- **备份之后录入的数据会丢掉。** 只是误删了几条数据的话，不要整库恢复，联系我们从备份里单独找回来。
- 上传的文件不受影响。恢复以后所有人要重新登录。

### 7.3 整台服务器坏了

1. 照第 1 节准备一台新服务器。
2. 找我们要**当前版本的完整包**，照第 2 节安装。
3. 从异地把上传的文件拷回来，交给应用的用户（uid 10001）：

   ```bash
   sudo rsync -a <异地的 uploads 目录>/ /opt/scm/data/uploads/
   sudo chown -R 10001:10001 /opt/scm/data/uploads
   ```

4. 把异地最新的一个数据库备份拷到服务器上，照 7.2 恢复。
5. 恢复以后，管理员的密码是坏掉之前改过的那个，不是新 `.env` 里的初始密码。

## 8. 恢复演练

没恢复过的备份不算备份。**正式上线前必须演练一次，之后每个月一次：**

```bash
sudo /opt/scm/scripts/check-restore.sh
```

它把 `backups/daily/` 里最新的备份恢复到一个临时库，逐张表数行数，和线上的库对比，最后删掉临时库。不停应用、不碰线上的库，系统照常可以用。也可以指定一个备份文件，比如从异地拷回来的：`sudo /opt/scm/scripts/check-restore.sh <备份文件>`。

最后显示"演练通过"就没问题。线上的行数一般比备份多（备份以后又录了数据）；业务表线上比备份少，把输出发给我们。每次的结果记在 `backups/backup.log` 里。

## 9. 常见问题

### 端口被占用

安装时提示"端口 80 已经被别的程序占了"：

```bash
sudo ss -ltnp 'sport = :80'      # 看是哪个程序
```

不能停掉它的话，换个端口：改 `/opt/scm/.env` 里的 `SCM_HTTP_PORT`（比如 8080），再执行一次 `sudo ./scripts/install.sh`，安全组也放行新端口。

### 内存不够，应用反复重启

`sudo docker compose ps` 里 app 一直是 `Restarting`，或者 `sudo dmesg | grep -i oom` 里有记录：内存不够。最好换成 4G 以上的机器；临时可以加 2G 交换空间：

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 忘了管理员密码

```bash
sudo /opt/scm/scripts/reset-admin-password.sh
```

它给 admin 生成一个新的随机密码，同时启用 admin、清掉登录失败计数（输错 5 次被锁的也能马上登录）。新密码只显示一次：远程协助的话先停止屏幕共享，再按回车显示。登录后马上改掉。

其他人忘了密码，由管理员在"用户管理"里重置。

### 时间不对

- 页面上的时间都按北京时间显示，和服务器的时区设置无关。
- 差几分钟：服务器的时钟不准，看 1.4 节。
- 差 8 小时：告诉我们。
- 备份时间 `BACKUP_TIME` 也按北京时间。

### 上传失败

- 提示文件太大：单个文件最大 10MB。
- 前面有入口（4.2）：入口的请求大小上限要不小于 11MB。
- 上传成功了但图片显示不出来，或者一上传就报错：上传目录的属主不对，执行 `sudo chown -R 10001:10001 /opt/scm/data/uploads`。
- 硬盘满了：`df -h /opt/scm`。

### 页面一直提示"系统正在升级或重启"

Nginx 连不上应用。看应用的状态和日志：

```bash
cd /opt/scm
sudo docker compose ps
sudo docker compose logs --tail 100 app
```

常见原因：硬盘满了、内存不够、数据库没起来。解决不了就把日志发给我们。

### 页面打不开

1. `sudo docker compose ps`：web 是不是 `Up`。
2. 在服务器上 `curl -I http://127.0.0.1/`（端口不是 80 要带上）：返回 `200`（HTTPS 模式是 `301`）说明系统没问题，查安全组和网络。

### 用户报错时说了一个错误编号

```bash
cd /opt/scm
sudo grep -A 30 <错误编号> logs/scm*.log
```

把找到的内容和版本号（登录页底部或右上角的用户菜单里，或者 `sudo grep SCM_VERSION /opt/scm/.env`）发给我们。`logs/` 里留着最近 30 天的应用日志。

### 备份失败，或者首页出现红色的备份提示

刚装好时提示"还没有任何备份"是正常的：装好时已经过了 `BACKUP_TIME`，会马上备份一次；还没到，就等到 `BACKUP_TIME` 才备份。不想等可以手动备份一次（命令在本节最后）。别的情况按下面查：

```bash
sudo tail -n 20 /opt/scm/backups/backup.log
cd /opt/scm && sudo docker compose logs --tail 50 backup
```

最常见的原因是硬盘满了。处理好以后手动备份一次：`sudo /opt/scm/scripts/backup.sh`。

### 装好以后，服务器连不上公司内网的某些地址

Docker 默认占用 `172.17.0.0/16` 等网段，可能和公司内网冲突。在 `/opt/scm/compose.override.yml`（没有就新建）里换一个公司没用到的网段：

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 10.250.0.0/24
```

然后 `cd /opt/scm && sudo docker compose down && sudo docker compose up -d`。

### 不要把这些发给别人

- `.env` 的内容。
- `docker compose config` 的输出：它会把 `.env` 里的密码一起打印出来。要给我们看状态，发 `docker compose ps` 和日志就够了。

## 10. 卸载

```bash
cd /opt/scm
sudo docker compose down
```

服务都停掉、容器删掉了，但数据、备份都还在 `/opt/scm` 下面：脚本不替你删数据。确定都不要了（先确认异地有一份备份）：

```bash
sudo rm -rf /opt/scm
sudo docker image rm $(sudo docker image ls --filter label=project=scm -q)
sudo docker image rm postgres:16 redis:7        # 服务器上别的程序也用这两个镜像的话，跳过这一行
```

## 附录 B：.env 里的配置

改了以后执行 `cd /opt/scm && sudo docker compose up -d` 生效。

| 项 | 默认 | 说明 |
|---|---|---|
| `SCM_VERSION` | 包的版本 | 安装、升级脚本自动改；只有回滚时手动改（7.1） |
| `SCM_HTTP_PORT` | 80 | HTTP 端口。只让本机的程序访问时可以写 `127.0.0.1:8080` |
| `SCM_HTTPS_PORT` | 443 | HTTPS 端口，`https` 模式才用 |
| `SCM_WEB_MODE` | `http` | `http` 或 `https`，见第 4 节 |
| `POSTGRES_PASSWORD` | 随机生成 | 数据库密码。**装好以后不要改**：只在第一次建库时生效，改了应用就连不上数据库 |
| `REDIS_PASSWORD` | 随机生成 | Redis 密码 |
| `JWT_SECRET` | 随机生成 | 登录令牌的签名密钥。改了以后所有人要重新登录 |
| `INIT_ADMIN_PASSWORD` | 随机生成 | 管理员初始密码，只在第一次启动时用 |
| `BACKUP_TIME` | `02:30` | 每天几点备份，北京时间 |
| `BACKUP_KEEP_DAYS` | 7 | 每天的备份留几天 |

## 附录 C：常用命令

都在 `/opt/scm` 里执行：

```bash
sudo docker compose ps                         # 各服务的状态
sudo docker compose logs --tail 100 app        # 应用最近的日志
sudo docker compose logs --tail 50 web         # Nginx 的访问日志
sudo docker compose restart app                # 重启应用
sudo docker compose up -d                      # 改了 .env 以后让它生效
sudo ./scripts/backup.sh                       # 手动备份一次
sudo tail -n 20 backups/backup.log             # 最近的备份记录
sudo docker compose exec postgres psql -U scm  # 进数据库（只查不改；要改数据先问我们）
```
